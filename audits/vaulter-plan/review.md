## Что можно перепроверить сегодня

Команды запускаются из корня Vaulter. Первая проверяет сами примеры и приложенный SQL-результат без сети, рабочих сервисов и доступа к пользовательской БД. Нужен Python 3 с пакетом `jsonschema` (проверено на 4.26.0). Для остальных прогонов ниже указаны отдельные предусловия.

```bash
python3 plan/checks/verify-fixtures.py
```

## Точечное ревью Grok

20 ноября 2026 года `grok-4.7-build` получил три отдельных запроса. Для аренды переданы PHP-исходники на ревизии `b230f6e27`, для Sheets и SDK — выдержки из целевого контракта в момент проверки. В протоколе сохранены вопросы, перечни файлов, контрольные суммы запросов и полные ответы. [Протокол Grok](evidence/grok-review.json)

| Участок | Вывод и проверка |
| --- | --- |
| Публикация checkpoint | Исходный PHP сверял границу снимка с текущим концом журнала. При ошибочной отметке компактора это позволяет объявить покрытой позднюю правку. Штатный Hub использует реально прочитанную позицию. В целевой схеме записывается верхняя позиция выданной аренды. На PostgreSQL публикация 42 с арендой до 41 отклонена, публикация 41 сохранила байты и pending для 42. Прогон PHP с реальным Hub входит в 2.2-B. [Проверка](../../plan/checks/collaboration/lease-schema.sql) |
| Повтор изменения книги | Grok подтвердил порядок проверки прав, ключа и ранее зафиксированного исхода. SQL-корпус воспроизводит возврат квитанции предыдущего поколения, срок повтора и отказ просроченному исполнителю до и после выдачи новой аренды. HTTP-тесты 4.2 и 6.1 должны проверить счётчики вызовов расчёта и записи в журнал. [Сценарий](../../plan/spec/implementation/workbook-flow.md) |
| Доказательство `office.verify` | Grok сверил профили text/formula и семантику `at_commit` и `current`. Форму ответа проверяет схема. Адаптер обязан связать квитанцию с командой и сверить формулы, значения, порядок целей и маркер с данными владельца. Отдельная локальная проверка показала, что два числовых литерала в поле формул проходили схему. Теперь этот пример отклоняется. [Контракт](../../plan/spec/agent-sdk.md) · [Проверки](../../plan/checks/verify-fixtures.py) |

## Локальный прогон исходной версии

20 ноября 2026 года базовый потребитель создан из чистого Laravel без приватного токена и без `path`-репозиториев Composer. Пять ZIP Vaulter выбраны из семи артефактов штатного сборщика публичного канала с тестовым номером `1.0.0`. Три ZIP Packman подготовлены отдельно из соседнего checkout `a5a5442` с тестовым номером `0.1.1`. Проверка выполнена до публикации релиза. Доступность реального дистрибутива Packman из канала FlexCms остаётся отдельным условием приёмки.

| Что запускали | Результат |
| --- | --- |
| PHP 8.4.27, Composer 2.9.3, чистый Laravel skeleton 13.11.0, framework 13.43.0, отдельный SQLite | Разрешились метапакет, четыре базовых PHP-пакета и Packman core/plugins/schema. `package:discover`, миграции и `vaulter:install --migrate` прошли. В этом профиле 27 таблиц с префиксом `v_` |
| `vaulter:doctor --json` на чистом skeleton | Исходное `auth:sanctum` дало одну ошибку отсутствующего guard. После явной привязки маршрутов к установленному `auth:web` — 30 успешных проверок, 0 ошибок, 3 предупреждения из-за SQLite, кэша array и синхронной очереди. В эталонном потребителе объявить используемый guard и middleware сессии/токена |
| HTTP-ядро Laravel, стандартный permission driver `database`, пользователи и записи в SQLite | Владелец создал документ (201), прочитал версию 1 с ETag, сохранил версию 2 (200). По старому ETag сервер ответил 412 `document_state_mismatch`. Читатель прочитал документ (200), при записи получил 403 `permission_denied`. Повторное чтение дало версию 2 и первую сохранённую правку. В этом прогоне пользователи были назначены в guard самим тестом |
| Node 26.13.1, npm, Vue-пакет | 31 тест в трёх файлах прошёл, Vue/TypeScript и Vite собрали bundle, `npm pack` создал архив. У читателя реальный редактор открылся read-only, принудительный PUT вернул 403. В стенде использован стандартный `auth.basic` только для доставки тестового пользователя через HTTP |
