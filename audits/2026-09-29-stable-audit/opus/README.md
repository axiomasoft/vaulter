## Главное в десяти строках

1. **Сначала корректность (F1, T0):** транзакции идут не на то соединение (N01), ключи хоста типизированы стратегией
   Vaulter (N02), CAS теряет область (E1), листинг раскрывает запрещённые узлы (N08), дерево не защищено от
   «папки внутри файла» и гонки циклов (N05), ошибки дают 500 (N11), события схлопываются (E8).
2. **Публичный API всегда авторизует**: `Vaulter::drive($owner)->actingAs($user)->nodes()->move(...)`; доверенный путь —
   явный `asSystem($reason)`. HTTP и Filament — клиенты того же API (паритет по построению).
3. **Словарь без коллизий**: Storage → **Drive**, Panel → **Profile**, Version → **Revision**,
   HostRoleDriver/PermissionResolver → **PermissionDriver**; `FileHandler` остаётся.
4. **Пакеты не дробятся**: честные зависимости (documents и filament требуют drive), AzGuard уходит из core,
   добавляется metapackage `axioma-studio/vaulter`.
5. **Профиль — рантайм-политика** (загрузки, квота, драйвер прав, типы документов); неработающий own-tables режим удаляется.
6. **Документы**: агрегат `v_documents` симметричен `v_files`, реестр типов документов с версиями схемы,
   безопасный fallback при удалённом расширении, fencing коллаборации через `collab_epoch`.
7. **Точная видимость без materialized ACL**: пакетная свёртка по общей цепочке предков, O(1) запросов на страницу.
8. **События**: occurrence id, activity + outbox в той же транзакции, слушатели хоста — после commit, единый `EventType`.
9. **REST v1**: `/api/vaulter/v1`, имена маршрутов, типизированные коллекции (`nodes/`, `files/`, `documents/`), RFC 9457,
   ETag по `sequence`, OpenAPI как источник TS-типов.
10. **Эксплуатация**: `vaulter:doctor`, автопланировщик, генераторы, тест-кит для хоста и авторов расширений, release-гейты
    на собранных артефактах.

## Отличия от предыдущих проходов

- От аудита: не убираю Eloquent, не делю конфиг на 8 файлов, не переименовываю `FileHandler` и Actions, не ввожу
  `Workspace` (в коде слово уже значит «владелец»); исправляю фактические ошибки аудита (after-commit, cursor, unique).
- От Codex: принимаю рамку «обещаний», но довожу до решений; переименования делаю только там, где есть конкретная
  коллизия; для листинга выбираю пакетную оценку вместо materialized read-model; нахожу 28 дефектов, которые меняют
  порядок работ.

## Границы этого прохода

- Прочитаны исходники всех PHP-пакетов, маршруты, схема, конфиги, тесты (выборочно), ADR, Vue-клиент (структура,
  реестр, типы). Хаб — только структура.
- **Не запускались** тесты, CI, установка зависимостей, PostgreSQL-конкурентность, S3, хаб. Все «подтверждено» —
  статические цепочки в коде с путями и строками; динамическая проверка — сценарии [14-verification.md](14-verification.md).
- Не проверены полностью: шаринг (кроме видимости), SSRF-защита webhooks (кроме списка тестов), производительность.
- Связь с mAInd из контейнера не проверена (`maind` не установлен) — см. 15.

## Как превратить в план

1. Создать `plans/VLT-1.0/plan.md` по протоколу проекта; фазы и пункты — из [13-workstreams.md](13-workstreams.md)
   без изменения нумерации (P-номера используются в ссылках сценариев).
2. В `Execution Rules` перенести общие правила из 13, в `Decision Log` — ссылки на D01–D40 (не копировать тексты).
3. Для каждого пункта исполнитель читает только указанные разделы досье (они адресованы §-ссылками).
4. Пункты с маршрутизацией opus не отдавать младшим моделям без готовой спецификации в `findings/`.
