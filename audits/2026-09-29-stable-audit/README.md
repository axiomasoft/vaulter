# Vaulter — независимая проработка перед проектированием

Дата: **2026-09-29**. Автор: Codex. Следующий проход: **Opus 5.5**.

Это исследовательский пакет к [исходному аудиту](../2026-09-29-stable-audit.md), а не утверждённая архитектура и не план реализации. Он подготовлен с учётом запроса владельца: компактные собственные выводы, широкая внешняя база, материалы для следующего синтеза без повторного поискового прохода.

## Как читать

5. [Исследовательский архив](research/README.md): запросы и ответы Perplexity по отдельным направлениям, включая не вошедшие в основной текст варианты.

## Главная мысль

Стабильность Vaulter стоит определять через обещания пользователю: права одинаково работают на всех публичных входах; данные переживают сбой и обновление; расширение можно установить и удалить без потери документов; пакет устанавливается вне собственного монорепозитория. Перемещения классов и новые имена полезны, когда помогают этим обещаниям.

Я бы развивал четыре опоры: **контекст операции и общие политики**, **сохранность данных и событий**, **контракт формата документа**, **совместимость потребителей**. Из исходного аудита не следует необходимость одновременно менять ORM, все названия, структуру пакетов и REST URL.

## Основание и границы

- Исходный аудит ссылается на `8f07701866a69d8790fda5dc1fe9bbd9287be6fd`; локальный HEAD — `67fe5244206297eea9d1c921820e2883874d7179`. `git diff --stat` между ними показывает только добавление исходного аудита: проверенный прикладной код одинаков.
- Прочитаны сам аудит, относящиеся к выводам реализации, ADR и существующие тесты. Статический вывод помечен отдельно от динамического воспроизведения.
- Тесты, CI, установка зависимостей и production-интеграции в этом проходе **не запускались**. Наличие тестового файла не означает успешного прогона.
- Меняется только эта папка. Исходный аудит, код и существующие решения проекта сохраняются для независимого сопоставления.
- Внешние источники проверялись 2026-09-29. Для трёх прочитанных файлов OSS зафиксированы commit и hash; ссылки на живую документацию не являются фиксацией совместимой версии зависимости.
- Объём базы: 13 поисковых запросов Perplexity, 30 карточек практик с первоисточниками, 16 сценариев проверки. Локальные ссылки, JSON с revisions и отсутствие trailing whitespace проверены; недоступные/ошибочные поисковые материалы отмечены отдельно.

Opus может добавить `05-opus-review.md` со своей оценкой и разногласиями. Сохранение первого прохода отдельно позволит видеть, какие решения действительно прошли независимую проверку.
