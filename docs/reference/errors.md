# Error codes

Every failure of a `/v1` route is an [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)
`application/problem+json` response:

```json
{
  "type": "https://github.com/axiomasoft/vaulter/blob/main/docs/reference/errors.md#node_name_conflict",
  "title": "Node name conflict",
  "status": 409,
  "code": "node_name_conflict",
  "detail": "A node with this name already exists in the folder.",
  "retryable": "never",
  "request_id": "01J…",
  "errors": null,
  "meta": {}
}
```

`code` is a stable contract (SemVer): branch on it, never on `title` or `detail`, which are
localized (`Content-Language`) and may change. `errors` is a Laravel field map and is set for
`validation_failed` and for errors tied to one field. `meta` carries machine-readable extras such
as `reason` and never storage paths, tenant ids, tokens or SQL. A response always repeats the
request id in `X-Request-Id`. A status without a Vaulter code answers `http_<status>`
(for example `http_503`), with a standard reason phrase as `title`.

`retryable` says whether the same request may be repeated: `never` as it is, `after_refetch`
once the client re-read the resource (a stale precondition), or `with_backoff` later, honouring
`Retry-After` when the response carries it. The client decides; the server never retries for it.
**Receipt** is the policy of [idempotent operations](/concepts/idempotency): a `cacheable` refusal is
stored under the `Idempotency-Key` and replayed to a retry, a `never` refusal (authentication,
visibility, validation, preconditions, rate limits, server failures) is rolled back with the key.
**Module** is the module that declares the code; its codes disappear when the module is disabled.

This page is generated by `php artisan vaulter:errors:reference`; `--check` exits 1 when it is
out of date. For handling errors in PHP see the [error guide](/guides/errors).
