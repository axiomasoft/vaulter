# Operation catalogue

Every mutating write goes through the [operation pipeline](/concepts/operations) under a name
(`<module>.<group>.<verb>`). Each active module declares a **policy** for every name it owns
([ADR-0032](/adr/0032-operation-catalog-and-concurrency)); the kernel collects them into the
`OperationCatalog`. `OperationRunner::write()` refuses a mutating operation whose name is not in
the catalogue with an `UnknownOperationException` — before the claim of a key and before the
transaction — so a new write cannot ship without saying how it is protected from lost updates and
from retries. Two installed modules declaring the same name is an invalid module graph.

Print the catalogue of the installed application:

```bash
php artisan vaulter:operations          # Markdown table
php artisan vaulter:operations --json   # {"operations": [{operation, module, aggregate, ...}]}
```

## Policies

**Concurrency** — how a write is protected from a concurrent one ([Concurrency](/reference/concurrency)):

| Value | Meaning |
|---|---|
| `if_match` | changes an existing aggregate by its own version; `If-Match` is required (`428` without it, `412` for a stale tag) |
| `append` | creates a new row; there is no version to compare, so no `If-Match` |
| `natural` | an absolute set or a membership change; repeating it gives the same outcome (star, retention flag) |
| `state_machine` | a transition checked against the current state under a lock (uploads) |
| `generation` | fenced by the collaboration generation (`409 collaboration_*`) |
| `row_identity` | removes an immutable row by id; the second attempt is `404` |

**Idempotency** — how a retry is made safe ([Idempotency](/concepts/idempotency)):

| Value | Meaning |
|---|---|
| `receipt` | the write is claimed and stored under an `Idempotency-Key`; the route carries the key middleware |
| `natural` | a repeat without a key has no second effect |
| `conditional` | a repeat answers by its precondition (a content `PUT` repeated with the same `If-Match` is `412`) |
| `protocol` | a machine protocol with its own de-duplication (the collaboration hub, Tus offsets) |

## Checks

Each module with operations carries an `OperationPolicyCoverageTest`: every operation name in its
sources is in the catalogue; every mutating `vaulter.v1.*` route of the package belongs to exactly
one policy; every `receipt` route carries the `Idempotency-Key` middleware; every `if_match` route
answers `428` without `If-Match`.
