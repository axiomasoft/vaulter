# Экспорт и удаление tenant

Процедура для владельца host-приложения. Страница описывает действия, но не разрешает и не исполняет их.

## Симптом

Tenant запрашивает переносимый экспорт/удаление либо drive остаётся в состоянии `deleting`.

## Диагностика без изменений

Проверьте tenant, полномочия, retention/legal holds и полный список его drives средствами host-приложения. Учтите общие ссылки. Для каждого проверенного id замените `DRIVE_ID`:
<!-- snippet: shell -->

```bash
php artisan vaulter:drives:purge --drive=DRIVE_ID --dry-run
php artisan vaulter:revisions:prune --drive=DRIVE_ID --dry-run
```
Purge preview охватывает лишь drives уже в deleting; пустой вывод не доказывает отсутствие данных tenant. Сверьте состояния/числа в read-only отчётах host. Отдельной метрики завершения tenant export нет.

## Ограниченное действие

Универсальной команды tenant export нет. Владелец host должен реализовать и проверить авторизованный экспорт метаданных, revisions и связанного содержимого с манифестом/хешами до удаления. Purge и retention не являются экспортом. До удаления требуются явное разрешение владельца, проверенная защищённая копия, согласование retention/holds и окончательный список drive id.

Существующим host workflow переведите только одобренные drives в deleting. После проверки preview авторизованный оператор может выполнить:
<!-- snippet: shell -->

```bash
php artisan vaulter:drives:purge --drive=DRIVE_ID --sync
```
Команда продолжает purge синхронно: шаг обрабатывает до 100 детей корня drive, каждый может быть поддеревом. Удаляются дерево, revisions и ссылки. `--sync` работает до завершения purge drive, без лимита времени или общего числа узлов. Ограничьте окно обслуживания указанными drives: tenant selector у команды нет. Revision retention удаляет лишь подходящие non-current revisions. Общие blob живут пока есть pins, физические байты могут оставаться до GC. Activity/outbox сохраняются: это не гарантия полного стирания tenant.

## Проверка результата

Сверьте утверждённый список drives с оставшимися строками/ссылками. До принятия удаления проверьте хеши экспорта и разрешённый доступ. Перечислите остаточные activity/outbox, копии и host-owned данные с их retention и владельцами. Отсутствие drive row не доказывает стирание всех данных/байтов tenant.

## Откат

До purge отменяйте через поддерживаемый host workflow, если он есть. После purge команды undelete нет: остановите writers и восстановите согласованную копию с явного разрешения владельца. Не восстанавливайте общий store ради одного tenant без оценки влияния на остальных.
