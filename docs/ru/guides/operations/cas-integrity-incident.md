# Инцидент целостности CAS

Процедура для владельца host-приложения. Страница описывает действия, но не разрешает и не исполняет их.

## Симптом

Загрузка возвращает `content_unavailable` (423), заполнен `integrity_failed_at` либо scrub сообщает missing/size/digest.

## Диагностика без изменений

Определите фактический dedup scope по конфигурации и ссылкам. Tenant scope подходит лишь при соответствующем сохранённом scope. Замените `TENANT_ID` проверенным id либо используйте фактический drive/off scope.
<!-- snippet: shell -->

```bash
php artisan vaulter:doctor --json --check=media.blobs.integrity
```

<!-- snippet: shell -->

```bash
php artisan vaulter:blobs:scrub --dry-run --scope='tenant:TENANT_ID' --limit=100 --max-bytes=104857600 --max-seconds=30
```
Если метрики подключены, изучите `vaulter_blobs_scrub_failed_total` по reason и счётчики checked/bytes. Запишите id, непрочитанные объекты и stop reason. Exit 0 относится лишь к выборке, exit 1 включает ошибки чтения, exit 2 означает неверные опции.

## Ограниченное действие

До замены байтов или изменения corruption state получите явное разрешение владельца и проверенную резервную копию/версию объекта. Изолируйте затронутые записи/выдачу, сохраните повреждённую версию как доказательство. `--dry-run` лишь читает и сообщает: не маркирует и не лечит. Обычный scrub сохраняет статус целостности, но тоже не восстанавливает байты. Общей CLI-команды heal нет. Восстановите проверенные исходные байты из копии и используйте поддерживаемый ingest того же SHA-256 в тот же scope для снятия отметки под blob lock. Не очищайте failure timestamps вручную ради обхода отказа выдачи. Работу с объектами согласуйте с владельцем storage. См. [целостность blob](/ru/guides/blob-integrity).

## Проверка результата

Сверьте размер и SHA-256 с доверенным манифестом. Повторите ограниченный scrub и убедитесь, что конкретные id посещены. Проверьте снятие отметки поддерживаемым recovery и правильные байты при разрешённом скачивании. Чужие scopes и pins не должны измениться. Чистая выборка не квалифицирует весь store.

## Откат

При неуспехе сохраняйте изоляцию. Сохраните повреждённую версию и журналы; если ремонт невозможен, с разрешения владельца вернитесь к последнему проверенному согласованному набору БД/объектов. Не выдавайте повреждённые байты и не удаляйте pins для подавления сигнала.
