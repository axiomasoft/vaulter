# Сбои доставки вебхуков и повторная отправка

Сначала отличите **нет доставки** от **неуспешной доставки**:

- нет строки `v_webhook_deliveries` для события: relay не разложил его — проверьте `core.outbox.lag` и `core.outbox.consumer_gaps` и что `vaulter:relay` в расписании;
- строка `dead`: endpoint отвечал ошибкой или таймаутом, пока не кончились попытки.

<!-- snippet: shell -->

```bash
php artisan vaulter:doctor --check=core.webhooks.deliveries
```

Отправьте dead-доставки снова. Повтор сохраняет **тот же `webhook-id`**, поэтому получатель,
дедуплицирующий по нему, остаётся корректным:

<!-- snippet: shell -->

```bash
php artisan vaulter:webhooks:redeliver --endpoint=12 --since="2026-10-01" --status=dead
```

Получатели должны принимать повторное событие.

## Диагностика и восстановление

1. Запишите идентификаторы события, доставки и endpoint, HTTP-статус и безопасную категорию последней ошибки. Сверьте журналы получателя по `webhook-id`. Исключите секреты подписи и реквизиты URL.
2. Восстановите получателя, DNS или сетевой маршрут и проверьте разрешённость всех DNS-ответов. Используйте абсолютный HTTP(S) URL со стандартным портом, затем проверьте подписанную доставку без перенаправления.
3. Повторите доставки за минимально необходимый период для одного endpoint. Проверьте итоговый статус, дедупликацию у получателя и прохождение новых доставок.
