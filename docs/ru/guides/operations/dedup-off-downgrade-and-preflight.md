# Dedup off, понижение и preflight

`vaulter-media.dedup.scope` — `tenant` (по умолчанию), `drive` или `off`. Каждый блоб сохраняет `scope_key`, под
которым был закоммичен, поэтому смена настройки оставляет существующие блобы валидными и влияет только на новые
загрузки: при `drive` или `off` байты, уже лежащие в более широкой области, не разделяются с новыми загрузками.

Смените настройку и проверьте доктором:

<!-- snippet: shell -->

```bash
php artisan vaulter:doctor --production
```

Перед понижением области в production смотрите проверку `media.dedup.scope` в отчёте доктора.

## Диагностика и восстановление

1. Проверьте активную область дедупликации через doctor и значение `scope_key` у недавно созданного блоба. Сверьте конфигурацию HTTP-процессов и воркеров.
2. Оцените запас места по объёму недавних загрузок. Разверните настройку одновременно для всех писателей, пересоберите кеш конфигурации и перезапустите воркеры.
3. Загрузите одинаковый небольшой файл в два диска тестового tenant. Сверьте адреса блобов с целевой областью и проверьте скачивание старых и новых файлов.
4. При проблемах с местом или изоляцией восстановите прежнюю область и перезапустите воркеры. После сверки дайте штатному CAS GC удалить блобы без ссылок.
