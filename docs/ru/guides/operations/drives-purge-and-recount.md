# Purge и recount дисков

Диск в статусе `deleting` удаляется плановой задачей. Если сообщается `drive.drives.deleting_stuck`,
посмотрите и выполните purge вручную:

<!-- snippet: shell -->

```bash
php artisan vaulter:drives:purge --dry-run --drive=7
```

<!-- snippet: shell -->

```bash
php artisan vaulter:drives:purge --drive=7 --sync
```

Использованные байты — счётчик. `drive.drives.usage_drift` значит, что он расходится с сохранёнными
ревизиями; сначала сообщите о расхождении, потом исправляйте:

<!-- snippet: shell -->

```bash
php artisan vaulter:drives:recount --dry-run --drive=7
```

<!-- snippet: shell -->

```bash
php artisan vaulter:drives:recount --drive=7
```

Без `--drive` обе команды действуют на все диски — такие запуски всегда сначала в режиме просмотра.

## Диагностика и восстановление

1. Запишите идентификаторы tenant и диска, статус, время запроса на удаление и результат последней задачи очистки. Проверьте планировщик и очередь.
2. Просмотрите план очистки одного диска. После проверки решения об удалении и срока хранения запустите синхронную очистку для этого диска. Прерванную очистку можно повторить после устранения сбоя базы или хранилища.
3. При расхождении счётчика сделайте предварительный пересчёт и сравните его с сохранёнными ревизиями. Исправьте только затронутый диск, затем повторите предварительный запуск и проверьте вывод doctor.
