# Откат выпуска

Процедура для владельца host-приложения. Страница описывает действия, но не разрешает и не исполняет их.

## Симптом

После deployment возникают регрессии, ошибки, несовместимые jobs либо невозможность читать данные.

## Диагностика без изменений

Зафиксируйте версии, lockfile/digest, последний исправный release, историю миграций и редактированные коды ошибок.
<!-- snippet: shell -->

```bash
php artisan vaulter:doctor --json --check=core.schema
```
Сопоставьте старый код с текущей схемой, сохранёнными payloads и jobs. Doctor не доказывает совместимость старой версии. Прочитайте реальные up/down и преобразования данных.

## Ограниченное действие

До отката или замены данных требуются явное разрешение владельца и проверенная согласованная копия БД/blob/ключей. Остановите writers, workers и плановые задания. На disposable-копии текущих данных проверьте предыдущий закреплённый release. Если он совместим, разверните известный исправный immutable artifact/lockfile обычным host-процессом с нужными config/ключами; запускайте совместимые workers после проверки.

Откат кода отделён от отката DDL/данных. Даже аддитивная forward migration может иметь разрушительный down. `migrate:rollback` не является общим production-восстановлением: допустим лишь в явно разрешённой disposable-репетиции после оценки потери данных. Если старый код несовместим, предпочтительны проверенный forward fix или согласованное восстановление проверенной точки по решению владельца.

## Проверка результата

Перед переключением подтвердите фактический version/digest, схему, разрешённые чтения/записи и совместимость очередей в recovery-среде. После открытия трафика отслеживайте исходный код ошибки и результаты доставок. При восстановлении точки укажите потерянные записи/повторные эффекты. Зелёный doctor сам по себе не доказывает совместимость release.

## Откат

Сохраните оба артефакта и checkpoint до изменений. При неуспехе остановите writers и вернитесь к выбранному владельцем совместимому набору code/config/data. Не переключайте версии вслепую против несовместимой схемы и не повторяйте jobs без анализа. См. [восстановление миграции](./migration-recovery) и [backup](./backup-and-restore).
