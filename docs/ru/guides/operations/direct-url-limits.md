# Лимиты direct URL

При `vaulter-drive.downloads.delivery_mode = direct_signed` скачивание — подписанный URL хранилища,
который Vaulter не проксирует:

- URL работает, пока не пройдёт `vaulter-drive.downloads.direct_ttl_seconds` (по умолчанию 60);
- **отзыв доступа, перенос в корзину или удаление файла не аннулирует уже выданный URL** — срок ограничен только TTL;
- запрос видит хранилище, а не Vaulter, поэтому аудит и rate limits Vaulter не применяются.

Держите TTL настолько коротким, насколько терпят клиенты. Когда отзыв должен действовать сразу,
используйте режим `strict` по умолчанию, где каждое скачивание проходит проверку прав:

<!-- snippet: config -->

```php
return [
    'downloads' => ['delivery_mode' => 'strict'],
];
```

## Диагностика и восстановление

1. С тестовой учётной записи получите URL, запишите HTTP-статус, хост хранилища, время выдачи и срок действия. Удалите подписанную строку запроса из материалов инцидента.
2. Отзовите доступ и проверьте отказ API при выдаче новой ссылки. По окончании TTL проверьте, что хранилище отклоняет старую ссылку.
3. При инциденте включите режим `strict`, пересоберите кеш конфигурации и перезапустите HTTP-воркеры. Проверьте авторизацию новых запросов и истечение последней выданной ссылки. Проверьте журнал хранилища за период действия ссылки.
