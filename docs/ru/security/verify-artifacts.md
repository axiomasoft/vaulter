# Проверка артефактов релиза

Каждый поток релиза публикует ОДИН принятый артефакт; публикатор его не пересобирает. Решение и его границы —
[ADR-0038](/adr/0038-supply-chain-and-artifact-verification).

| Поток | Принятый артефакт | Что проверяет публикатор |
| --- | --- | --- |
| PHP | подготовленная запись split из `scripts/release/build-artifacts.php` (дерево и коммит split, карта содержимого, ZIP, SBOM, `SHA256SUMS`, resolution, digest политики и инструмента) | `--require-approved` сверяет байты внешнего одобрения с защищённым `VAULTER_PREPARED_APPROVAL_SHA256` и связывает каждое поле идентичности; `--materialize-split` собирает коммит только из подготовленных байтов; push атомарный и никогда не принудительный |
| npm | единственный tgz из pack-задачи (без секретов) | `scripts/release/artifact-gate.py npm` сначала сверяет байты внешнего одобрения с защищённым `VAULTER_ARTIFACT_APPROVAL_SHA256`, затем требует, чтобы sha256, integrity, имя, версия и consumer-evidence tgz были ровно теми, что принял этот документ; только после этого `npm publish --ignore-scripts` запускается на проверенном файле |
| OCI | протестированный digest манифеста | `scripts/release/artifact-gate.py oci`, та же аутентификация, до любого входа в реестр: digest `sha256:` (не тег), равный одобренному протестированному, те же платформы, SBOM, digest политики и инструмента и видимость; приватный канал требует назначения, проверенного и одобренного как приватное |

## Ручная проверка

1. Пересчитайте SHA-256 полученного файла и сравните с `SHA256SUMS` (там ZIP и SBOM, но не сам файл).
2. Для npm после авторизованной публикации сравните `npm view <name>@<version> dist.integrity` с записанным `integrity`; до неё идентичность ожидает подтверждения.
3. Для OCI разрешите тег в digest и сравните с протестированным.

## Границы

- Приватная npm-линия требует `--channel private` и назначения, проверенного как приватное И принятого одобрением как приватное; публичная, непроверенная или отсутствующая видимость отказывает даже при валидных байтах одобрения. Доступ (`restricted`/`public`) берётся только из проверенной записи.
- `SHA256SUMS` — контрольная сумма, не подпись. Аттестации происхождения есть только при `vars.VAULTER_ATTESTATIONS` = `true`; при `false` происхождение **недоступно**, артефакт не подписан.
- Packagist может перепаковать ZIP: сравнивайте байты файлов и source/dist ref, а не наш хеш архива.
- Контур, выпускающий одобрение, защищённые переменные (`VAULTER_PREPARED_APPROVAL_SHA256`, `VAULTER_ARTIFACT_APPROVAL_SHA256`), реальная квалификация, подписи, целостность в реестре и установки — работа владельца (P8.2), они не настроены. Репозиторий одобрений не создаёт; без одобрения любой публикатор отказывает.
