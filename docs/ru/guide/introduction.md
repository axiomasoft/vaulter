# Что такое Vaulter?

**Vaulter** — встраиваемая система управления документами и файлами для Laravel. Вы
подключаете её к существующему приложению — она приносит файловый менеджер в стиле Google
Drive, редактор документов на TipTap с историей версий и совместное редактирование в реальном
времени — а все решения об авторизации делегирует обратно вашей системе ролей.

Vaulter поставляется двумя пакетами:

- **`axioma-studio/vaulter-core`** — Laravel-пакет (модели, REST API, CAS, ACL, Artisan-команды).
- **`@vaulter/vue`** — компоненты Vue 3 + TypeScript, composable-функции и API-клиент.

Админ-плагин для Filament 5 (`axioma-studio/vaulter-filament`) поставляется отдельно.

## Подойдёт ли мне?

Vaulter уместен, когда нужно **встроить** диск в собственный продукт, а не подключать
отдельный SaaS:

- У вас уже есть пользователи, тенанты и роли — Vaulter авторизует через *вашу* систему, своей
  аутентификации/логина у него нет.
- Вам нужны файлы **и** богатые документы в одном дереве (а не две отдельные фичи).
- Нужна изоляция по сущностям: диск на проект, на организацию, на пользователя — без отдельной
  миграции под каждый.
- Важны стоимость хранения и целостность: дедупликация по содержимому и безопасный сборщик
  мусора уже встроены.

Если нужно лишь прикрепить один PDF к модели — Vaulter избыточен, возьмите медиа-библиотеку.
(Почему у Vaulter *собственное* хранилище контента, а не `spatie/laravel-medialibrary`,
зафиксировано в [ADR-0008](/adr/0008-media-library-decision).)

## Ключевые концепции

Это существительные, которые встречаются по всей документации и в коде.

| Концепция | Что это |
|---|---|
| **Storage Panel** | Именованный конфиг-конверт, привязанный к любой сущности приложения. Решает, какие фичи включены, какой драйвер прав, стратегию идентификаторов и (опционально) собственные таблицы — поверх общей схемы `v_*`, по умолчанию **без миграций**. |
| **Storage** | Конкретная строка-диск (`v_storages`) для одной сущности в рамках панели. `Vaulter::for($entity)` находит-или-создаёт её и подготавливает корневую папку. |
| **Node (узел)** | Запись в едином дереве (`v_nodes`): **папка**, **файл**, **документ** или **ярлык**. Одно дерево на хранилище, с корнем в корневой папке. |
| **Blob (блоб)** | Контент-адресуемые байты за файлом (`v_blobs`). Ключ — `sha256`, дедупликация в настраиваемой области, освобождение двухфазным сборщиком мусора. |
| **ACL / AccessResolver** | Собственный движок эффективных прав Vaulter. Сворачивает гранты на узлы (`v_node_grants`) со сменным **драйвером ролей хоста** и отвечает «можно ли этому актору это действие?». |
| **Document handler** | Шов расширяемости по форматам. Реестр маршрутизирует узел к нужному обработчику (TipTap, превью, только-скачать…) по mime → расширению → возможностям. Новый формат — это один класс плюс одна строка в конфиге. |

### Storage Panel → Storage → Node → Blob

Модель данных вкладывается аккуратно:

```
Сущность приложения  (App\Models\Project, Organization, User …)
   └── Storage Panel        конфиг-конверт, выбирается по имени
        └── Storage          v_storages — один диск для этой сущности
             └── Дерево узлов v_nodes — папки / файлы / документы / ярлыки
                  └── File    v_files → версия файла → Blob (v_blobs, байты по sha256)
```

Одна сущность может владеть несколькими хранилищами — по одному на панель. Внутри хранилища
всё лежит в **одном** дереве, поэтому папка может содержать и бинарные файлы, и редактируемые
документы.

### Авторизация: две полосы

Vaulter делит авторизацию на часть, которой **владеет сам**, и часть, которую вы **подключаете**:

1. **`AccessResolver`** — принадлежит Vaulter и **не** сменяем. Выполняет канонический алгоритм
   поверх `v_node_grants` (гранты-ACL на узлы, с наследованием по поддереву и вето-запретом).
2. **Драйвер ролей хоста** — *сменяем*. Это полоса, отвечающая «какая роль у актора в этом
   workspace?». В комплекте автономный драйвер `database`, либо переключитесь на `gate`,
   `spatie`, `azgard` или свой.

Поэтому Vaulter не нужен собственный логин: роли приходят из вашего приложения через драйвер, а
resolver комбинирует их с грантами на узлы. Решение зафиксировано в
[ADR-0002](/adr/0002-authorization-delegation) и [ADR-0007](/adr/0007-pluggable-authorization).

## Фасад `Vaulter` с высоты птичьего полёта

Всё, что обращено к хосту, идёт через фасад `Vaulter` (`Vaulter\Facades\Vaulter`,
автоматический алиас `Vaulter`). Методы, которые понадобятся чаще всего:

```php
use Vaulter\Facades\Vaulter;

// Открыть Drive-хэндл для сущности (находит-или-создаёт её хранилище + корневую папку).
$drive = Vaulter::for($project);                 // DriveContext
$drive = Vaulter::for($project, 'project_drive'); // …в именованной панели

// Резолв панелей.
Vaulter::panel('project_drive');                  // Panel
Vaulter::panels();                                // PanelRegistry

// Расширение пакета в рантайме.
Vaulter::registerHandler(MyPdfHandler::class);    // новый формат документа
Vaulter::registerExporter(new PdfExporter());     // новый формат экспорта
Vaulter::resolvePermissionsWith($resolver);       // легаси-резолвер на документном пути

// Резолв драйвера совместного редактирования.
Vaulter::driver();                                // CollaborationDriver
```

Полная поверхность — в [справочнике API](/ru/reference/facade).

## Чего Vaulter не делает

- Не реализует аутентификацию/логин — интегрируется через драйвер ролей хоста и ваш guard.
- Не заводит свои таблицы пользователей/ролей — они остаются в вашем приложении.
