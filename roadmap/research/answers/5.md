# Vaulter Spreadsheet Editor — исследование V2

## Резюме решения и что изменилось относительно V1

**Дата среза: 20 ноября 2026 года.** Для первого браузерного прототипа Vaulter я рекомендую реализовать **два варианта на одном и том же host-контракте**, но основным кандидатом сделать **Univer Sheets 1.5.2**, а контрольным — **Handsontable 18.1.2 + HyperFormula 3.5.0**. На текущем наборе требований Univer лучше совпадает с моделью именно *книги*: у него из коробки есть листы, формульный UI, строка формул, множественные выделения, snapshot книги, команды/undo, number formats и возможность вынести формульный расчёт в Worker; Facade API специально построен поверх командной модели, а `FRange.setValues()`/`setFormulas()` идут через тот же механизм изменения документа, которым пользуется UI. citeturn580894search11turn713341search0turn713341search1turn191598search0

Handsontable остаётся очень серьёзным вторым кандидатом, особенно если доступность с экранными дикторами станет обязательным критерием: это DOM-таблица с виртуализацией строк и столбцов, явными ARIA-ролями и заявленным регулярным тестированием NVDA, JAWS и VoiceOver. В 18.1 появились дополнительные accessibility-настройки, в частности `ariaTags`, а документация перечисляет известные ограничения вместо общего маркетингового обещания. citeturn580894search6turn580894search7turn730800search6turn730800search7

При этом Handsontable нужно рассматривать именно как **конструктор книги**, а не готовую замену Excel-подобного редактора. В 18.x уже есть `SheetsBar`, и HyperFormula умеет межлистовые ссылки, но строку формул, способ показа исходной формулы выбранной ячейки, модель серверных патчей, привязку URL к выделению, хостовую историю версий и семантику конфликта Vaulter всё равно придётся проектировать самостоятельно. Формульный плагин позволяет увидеть формулу при редактировании ячейки, но это не заменяет постоянно видимую Excel-подобную formula bar. citeturn307275search2turn307275search3turn580894search9

Есть ещё одно существенное различие, которое влияет на решение для закрытого облака. Открытая часть Web SDK Univer опубликована под Apache-2.0, и официальный репозиторий прямо относит к open-source core архитектуру, formula/rendering engines, Facade APIs и Sheets/Docs editing; коммерческие плагины, Server SDK и AI SDK лицензируются отдельно. Следовательно, для Vaulter не требуется покупать Server SDK только ради собственного Laravel-хранилища, собственных ревизий и серверного agent API, если используются лишь open-source Web SDK-компоненты. citeturn578407search6turn704259search9 Handsontable, напротив, в production коммерческого продукта требует коммерческой лицензии; HyperFormula 3.x доступна по GPLv3 либо proprietary license, поэтому для закрытого клиентского JS-бандла облачной CRM разумно исходить из необходимости коммерческой лицензии и для неё, а не полагаться на GPL-сборку. citeturn924865search5turn730800search3turn924865search7

**Про V1.** В доступном мне контексте нет самого исходного отчёта V1: предыдущая реплика только объявляла исследование и обещала будущий отчёт. Поэтому дословный diff V1→V2 невозможен. Ниже я сохраняю исходную постановку и трактую V2 как расширенную версию предполагаемого первого прохода. Новые по сравнению с тем, что было заявлено ранее, выводы здесь следующие: подтверждён точный текущий стек версий; обнаружен `SheetsBar` в Handsontable 18.x; подтверждены новые licensing/entitlement изменения Handsontable 18.1; подтверждена HyperFormula 3.5.0 от 9 октября 2026 года; отдельно выявлен сильный accessibility-разрыв в пользу Handsontable; найден официальный Worker-путь Univer; уточнено, что `save()` Univer нельзя читать, пока не завершён активный cell editor; и формализован host-протокол для agent patch/echo suppression/selection/undo. citeturn704259search2turn730800search0turn580894search3turn713341search2

Самая важная неопределённость Univer — **доступность реальной сетки для screen reader**. Canvas2D является фундаментом его rendering engine, а официальная архитектурная статья описывает hit testing, Viewport и исключение объектов вне видимой области, но не обещает семантическую ARIA-таблицу, аналогичную DOM Handsontable. Поэтому нельзя переносить accessibility-заявления Handsontable на Univer по аналогии. citeturn580894search1turn580894search4

DOM против Canvas здесь — не абстрактная дискуссия. Handsontable поддерживает небольшой набор `<td>` для viewport и переиспользует их при прокрутке; отключение virtualization через `renderAllRows`/`renderAllColumns` резко увеличивает DOM и допустимо лишь ради специальных accessibility-компромиссов. citeturn580894search6turn580894search7turn580894search8 Univer, наоборот, рисует содержимое Canvas2D и сам вычисляет viewport/skeleton. Это особенно полезно при большой разреженной книге и сложном форматировании, но ухудшает возможность полагаться на браузерную семантику элементов. citeturn580894search1turn580894search4

## Три пользовательских истории — пошаговая модель

### Менеджер, формула агента и параллельное E2

Начальное состояние после Excel paste:

```text
A          B      C       D       E
1 Статья   План   Факт
2 Аренда   100    110
3 Связь     60     50
```

Пользователь выделяет `D2:D3`. Host не должен отправлять агенту внутренний объект selection конкретной библиотеки. Он превращает выделение в стабильный Vaulter reference:

```json
{
  "documentId": "book-42",
  "revision": 17,
  "sheetId": "sheet-budget",
  "a1": "D2:D3"
}
```

У Univer active range читается через `FWorksheet.getActiveRange()` / selection list и может быть восстановлен вызовом `setActiveRange()` или `activate()`. citeturn191598search1turn191598search0 У Handsontable аналогом является `getSelected()` / `getSelectedRange()` и `selectCell()`. citeturn924865search0turn704259search1

В API агент получает **не snapshot браузера**, а revision 17 на сервере. Он вычисляет патч:

```json
{
  "baseRevision": 17,
  "ops": [
    {"sheetId":"sheet-budget","range":"D2","formula":"=C2-B2"},
    {"sheetId":"sheet-budget","range":"D3","formula":"=C3-B3"}
  ]
}
```

Пока агент работает, пользователь вводит `проверено` в `E2`. Это локальное изменение создаёт dirty state относительно 17. Критически важно не блокировать grid на время agent job: пользователь продолжает работу в книге.

Правильный серверный результат — не «вернуть новую книгу и заменить snapshot», а вернуть **accepted patch + revision relation**. Если E2 не пересекается с D2:D3, сервер применяет агентский патч поверх текущей ревизии и создаёт ревизию, содержащую обе ветки. На клиент приходит patch только D2:D3 и новая revision id. Это продуктовая логика Vaulter; ни Univer, ни Handsontable не должны быть системой разрешения Laravel-конфликта.

При поступлении результата пользователь должен увидеть:

```text
D2  10     formula bar: =C2-B2
D3 -10
E2  проверено
```

Текущее выделение **не надо насильно переводить на D2:D3**, если пользователь после отправки задачи ушёл в E2/E3. Вместо этого Vaulter показывает краткое состояние задания «Готово: изменены D2:D3» и визуальный highlight затронутого диапазона; кнопка «Перейти» уже переводит selection. Это не характеристика библиотеки, а рекомендуемая UX-политика, чтобы background job не крал keyboard focus.

Для Univer внешний patch нужно применять через Facade API, например `sheet.getRange('D2:D3').setFormulas(...)`, а не мутировать snapshot: документация прямо предупреждает, что snapshot — только данные, и непосредственное изменение snapshot не обновляет runtime/UI. citeturn713341search0turn191598search0 Для Handsontable следует передавать custom `source`, например `vaulter:remote`, в API изменения и в `afterChange` отбрасывать этот source; официальный hooks guide специально рекомендует custom source, поскольку обычный `setDataAtCell()` иначе приходит как `source === 'edit'` и его невозможно отличить от ручного ввода. citeturn713341search8

**Undo должен оставаться пользовательским.** Agent patch — состояние сервера, а не «последний жест пользователя». Поэтому рекомендую не давать удалённому патчу занимать верхушку пользовательского Ctrl+Z. В Handsontable это можно реализовать adapter-level подавлением записи remote operation в UndoRedo через stack hooks; plugin документирует `beforeUndoStackChange`. citeturn713341search6 В Univer все Facade edits проходят через command/undo path, поэтому для прототипа надо экспериментально проверить способ выполнения remote mutation без попадания в пользовательский undo stack. Официальная документация подтверждает command/undo основу, но не даёт в исследованных примерах готового «remote, not undoable» Facade helper. citeturn713341search1turn713341search3 Если чистого API нет, adapter обязан хранить **Vaulter local undo journal** для пользовательских действий или перехватывать command execution options — это один из главных spike-вопросов прототипа.

Если вкладку закрыли до окончания задачи, browser instance исчезает, но agent job остаётся серверным. При повторном открытии Vaulter загружает **последнюю серверную ревизию**, а не старую revision 17; если агент уже закончил, D2:D3 приходят сразу. Если ещё нет — UI восстанавливает pending task по `documentId/taskId` и позже применяет result patch. Selection можно восстанавливать отдельно из host UI state (`sheetId + ranges + activeCell`) после `Steady`, потому что Univer предупреждает, что часть Facade API не работает надёжно сразу после создания workbook, до lifecycle `Rendered/Steady`. citeturn578407search1 Undo stack после полного закрытия вкладки **не следует обещать сохранять**, если Vaulter специально его не сериализует: библиотечный in-memory undo — это состояние редактора, а не revision history.

### Paste 100×100, одно Undo и конфликт второй вкладки

Пользователь вставляет прямоугольник 100×100 — 10 000 ячеек — в середину разреженного листа. Clipboard event должен попасть в adapter как **одна user transaction**. Univer имеет `BeforeClipboardPaste` и `ClipboardPasted`, Handsontable — `afterPaste(data, coords)` и `source === 'CopyPaste.paste'`. citeturn713341search2turn713341search7turn713341search8 Host журналирует transaction id и dirty range, но не создаёт 10 000 HTTP mutations.

После paste формульный engine пересчитывает зависимые ячейки. В Univer формульный расчёт можно вынести в Web Worker, при этом rendering/UI остаются на main thread. citeturn580894search3 HyperFormula поддерживает batch operations и сама рекомендует batch для тяжёлых `setCellContents`/`setSheetContent`, чтобы сократить перерасчёт. citeturn924865search9 Для Handsontable изменения UI следует группировать его batch API и не провоцировать лишние renders; его renderer перерисовывает весь текущий viewport, а не одну клетку. citeturn580894search6

Пользователь нажимает Ctrl+Z. В acceptance test весь 100×100 paste должен исчезнуть **одним действием** и selection вернуться к диапазону операции. Handsontable явно документирует, что multi-cell data action хранится как одно действие и при undo восстанавливает полный selection range. citeturn713341search6 Для Univer это надо подтвердить именно браузерным paste-тестом: command system является основой undo, но granularity конкретного clipboard command лучше не предполагать. citeturn713341search0

Далее пользователь меняет одну клетку, например `H410 = 37`. В это время вкладка B уже сохранила новую серверную ревизию 19, а вкладка A всё ещё основывается на 18. Vaulter отправляет:

```text
PUT /documents/book-42
If-Match: revision-18

patch: H410 = 37
```

Сервер отвечает `409/412` с `currentRevision=19` и, желательно, diff metadata.

Grid при этом **не сбрасывается**. Экран переходит в состояние:

```text
Несохранённые изменения
Другая вкладка сохранила более новую версию.

[Сравнить] [Повторить поверх новой версии] [Сохранить как копию]
```

Если диапазоны не пересекаются, хост может предложить безопасный rebase. Если пересекаются — обязательное сравнение. Само наличие 409/412, серверный merge и содержимое revision diff — ответственность Vaulter, поскольку обе библиотеки являются client grid/runtime, а не вашим optimistic-locking сервером.

Адаптер должен различать четыре класса сигналов:

| Сигнал | Пример | Отправлять серверу? |
|---|---|---|
| **selection** | пользователь выбрал `H410:J420` | нет; только UI state / agent context |
| **local change** | edit / paste / undo | да, как dirty transaction |
| **remote change** | agent patch / rebased server patch | нет |
| **server ack** | revision 18→20 | нет; только очистить acknowledged dirty set |

Это особенно просто в Handsontable: `afterChange(changes, source)` имеет source, а custom source официально предусмотрен для предотвращения feedback loop. citeturn713341search8 В Univer следует слушать `CommandExecuted` / `SheetValueChanged`, но host должен добавить собственный origin token вокруг выполняемого remote application; `CommandExecuted` exposes command `options`, однако готовая семантика Vaulter-origin в API не заявлена. citeturn713341search3turn578407search2

При сохранении Univer есть тонкость: активный cell editor ещё может не записать ввод в snapshot. Документация прямо рекомендует сначала `await fWorkbook.endEditingAsync(true)`, затем `fWorkbook.save()`. citeturn713341search2 Это должно войти в adapter contract и e2e-test. Для Handsontable аналогичный test должен явно завершать editor (`finishEditing`) перед сериализацией source data, иначе возможны гонки между DOM editor и host save.

### Tiptap: ссылка, preview и embedded grid

Для первого релиза я рекомендую **не вставлять полноценный grid editor внутрь Tiptap**. В документ нужно вставлять атомарный узел `bookRangePreview` с идентичностью источника и с собственным неизменяемым snapshot-preview.

Рекомендуемые attrs:

```json
{
  "bookId": "book-42",
  "sheetId": "sheet-budget",
  "range": "A1:C2",
  "sourceRevision": 27,
  "snapshot": [
    ["Статья", "План", "Факт"],
    ["Аренда", 100, 110]
  ],
  "snapshotFormats": {...}
}
```

Tiptap специально разделяет NodeView и экспорт: NodeView отвечает за интерактивное отображение в editor, а `renderHTML` — за HTML output. NodeView может работать и в read-only editor. citeturn908698search1turn908698search4 Для такого preview оптимален `atom: true`, чтобы ProseMirror рассматривал блок как единое целое и текстовый cursor не попадал внутрь. citeturn908698search2 Vue-компонент подключается через `VueNodeViewRenderer`; node attrs доступны реактивно и могут меняться через `updateAttributes`. citeturn908698search0

Если читатель урока **не имеет доступа к книге**, он всё равно видит snapshot, сохранённый внутри урока, если автор при вставке имел право публиковать этот диапазон. Нельзя во время чтения делать скрытый live-fetch книги, иначе preview станет каналом обхода permissions. Это решение Vaulter, а не Tiptap API.

Если исходный лист позже удалён, автор видит:

```text
[Снимок диапазона A1:C2]
Источник недоступен или удалён
Снимок из ревизии 27

[Найти новый источник] [Оставить как статический]
```

В экспорт HTML/PDF должен попасть **сам snapshot table**, а не только `bookId` или SPA-placeholder. Tiptap документация подчёркивает, что NodeView не является HTML export и разработчик полностью контролирует `renderHTML`; поэтому экспорт должен сериализовать семантическую `<table>` либо эквивалентное static representation. citeturn908698search1turn908698search5

Сравнение трёх вариантов:

| Вставка в Tiptap | Реализация | Фокус | Copy | Undo Tiptap | Права | Рекомендация |
|---|---|---|---|---|---|---|
| **Ссылка** | простой atom/link | тривиально | URL | одна node operation | источник проверяется при переходе | недостаточно: читатель без доступа ничего не увидит |
| **Read-only preview** | atom NodeView + static snapshot | ProseMirror не входит внутрь grid | можно дать HTML table/TSV copy | undo вставки/удаления preview остаётся Tiptap | snapshot контролируется публикацией | **первый релиз** |
| **Editable embedded grid** | полноценный Univer/HOT instance в NodeView | конфликт двух keyboard editors | сложный clipboard routing | два независимых undo stack | двойная permission model | отложить |

Editable grid внутри текста создаёт особенно неприятную проблему: Ctrl+Z, Tab, стрелки, clipboard и IME должны маршрутизироваться либо в ProseMirror, либо во внутреннюю книгу; Tiptap предупреждает, что custom NodeViews обязаны корректно сохранять selection/IME/caret behavior. citeturn908698search4 Это большой объём UI-инфраструктуры без пользы для первого сценария.

## Архитектура Vue, agent patches и код предпочтительного варианта

Граница должна проходить не вокруг API конкретной библиотеки, а вокруг **Vaulter Spreadsheet Host Adapter**:

```ts
interface WorkbookAdapter {
  mount(el: HTMLElement, snapshot: VaulterWorkbook): Promise<void>
  unmount(): Promise<void>

  open(snapshot: VaulterWorkbook): Promise<void>
  capture(): Promise<VaulterWorkbook>

  getSelection(): SelectionRef
  setSelection(ref: SelectionRef): void
  onSelection(cb: (ref: SelectionRef) => void): Dispose

  onLocalChange(cb: (tx: LocalTransaction) => void): Dispose
  applyRemotePatch(patch: ServerPatch): Promise<void>

  focus(): void
}
```

В публичной CMS импортировать этот интерфейс можно, но пакет реализации spreadsheet extension должен отсутствовать. Router/feature registry делает:

```ts
if (features.spreadsheets) {
  const { createSpreadsheetEditor } =
    await import('@vaulter-cloud/spreadsheet-univer')
}
```

Так CMS core не получает ни Univer/React/RxJS, ни Handsontable/HyperFormula в production bundle. Это особенно важно для лицензионной границы Handsontable и для сохранения открытого CMS-репозитория независимым от закрытых extensions.

Для **Univer 1.5.2** рабочий skeleton выглядит так; применён API, документированный в текущей Facade reference и официальной Vue-интеграции. citeturn704259search6turn191598search0turn191598search1

```ts
// UniverWorkbookAdapter.ts
import type { IDisposable } from '@univerjs/core'

export class UniverWorkbookAdapter {
  private univer: any
  private api: any
  private disposables: IDisposable[] = []
  private applyingRemote = 0

  async mount(container: HTMLElement, snapshot: any) {
    const [
      presets,
      sheetsCore,
      ruLocale,
    ] = await Promise.all([
      import('@univerjs/presets'),
      import('@univerjs/preset-sheets-core'),
      import('@univerjs/preset-sheets-core/locales/ru-RU'),
    ])

    // CSS отдельным lazy chunk; Vite может вынести его вместе с route chunk.
    await import('@univerjs/preset-sheets-core/lib/index.css')

    const {
      createUniver,
      LocaleType,
      mergeLocales,
    } = presets

    const { UniverSheetsCorePreset } = sheetsCore

    const { univer, univerAPI } = createUniver({
      locale: LocaleType.RU_RU,
      locales: {
        [LocaleType.RU_RU]: mergeLocales(ruLocale.default),
      },
      presets: [
        UniverSheetsCorePreset({
          container,
          formulaBar: true,
          // Для benchmark-варианта:
          // workerURL: new Worker(
          //   new URL('./univer.worker.ts', import.meta.url),
          //   { type: 'module' },
          // ),
        }),
      ],
    })

    this.univer = univer
    this.api = univerAPI

    const book = univerAPI.createWorkbook(snapshot)

    // Selection — отдельный канал, не dirty change.
    this.disposables.push(
      book.onSelectionChange((ranges: any[]) => {
        this.emitSelection(
          ranges.map(r => ({
            sheetId: book.getActiveSheet().getSheetId(),
            range: r,
          }))
        )
      })
    )

    // Один низкоуровневый observer для host journal.
    this.disposables.push(
      book.onCommandExecuted((command: any) => {
        if (this.applyingRemote > 0) return
        if (!this.isPersistentContentCommand(command)) return
        this.emitLocalCommand(command)
      })
    )
  }

  async applyRemotePatch(patch: {
    sheetName: string
    range: string
    formulas?: string[][]
    values?: unknown[][]
  }) {
    const book = this.api.getActiveWorkbook()
    const sheet = book.getSheetByName(patch.sheetName)
    if (!sheet) throw new Error(`Unknown sheet ${patch.sheetName}`)

    this.applyingRemote++
    try {
      const range = sheet.getRange(patch.range)

      if (patch.formulas) {
        range.setFormulas(patch.formulas)
      } else if (patch.values) {
        range.setValues(patch.values as any)
      }
    } finally {
      this.applyingRemote--
    }
  }

  async capture() {
    const book = this.api.getActiveWorkbook()
    if (!book) throw new Error('Workbook is not open')

    // Критично: commit активного cell editor перед snapshot.
    await book.endEditingAsync(true)

    return book.save()
  }

  async restoreSelection(sheetName: string, a1: string) {
    const book = this.api.getActiveWorkbook()
    const sheet = book.getSheetByName(sheetName)
    if (!sheet) return

    sheet.activate()
    sheet.getRange(a1).activate()
  }

  async unmount() {
    for (const d of this.disposables.splice(0)) d.dispose()

    this.api = undefined
    this.univer?.dispose()
    this.univer = undefined
  }

  // Host-owned:
  private emitSelection(_: unknown) {}
  private emitLocalCommand(_: unknown) {}
  private isPersistentContentCommand(_: unknown) { return true }
}
```

Официальный Vue guide требует создавать Univer после mount контейнера и вызывать `univer.dispose()` перед unmount; также он отдельно предупреждает не помещать экземпляры Univer/FUniver под Vue Proxy. citeturn578407search0turn704259search6 `FRange.setFormulas()` принимает прямоугольную `string[][]`, `FRange.setValues()` — 2D или sparse matrix, что удобно для agent patch. citeturn191598search0

Однако приведённый `applyingRemote` — только **минимальный prototype echo guard**. Для production лучше передавать уникальный `originId` в command execution options, если выбранная команда/API это допускает, и вести `pendingLocalTxIds`, потому что формульный recalculation может испускать дополнительные downstream events уже после синхронного вызова. Это нужно проверить instrumented test, а не считать решённым только счётчиком.

Смена книги должна происходить одним из двух способов: либо dispose текущего unit и create нового unit внутри единственного Univer runtime, либо dispose всего runtime, если жизненный цикл route короткий. Для испытания памяти я бы **намеренно проверил оба режима**. Facade docs указывает `disposeUnit()` как правильный путь выгрузки owning unit, а полный Vue example использует `univer.dispose()` при разрушении компонента. citeturn191598search1turn704259search6

Сохранение «без потери фокуса» означает не обычную кнопку, которая blur'ит grid, а host command. Сначала надо завершить активное cell edit программно, снять snapshot и затем восстановить selection/focus; Univer прямо документирует проблему snapshot до `endEditingAsync(true)`. citeturn713341search2 Для autosave можно вообще не трогать DOM-focus: при завершённом edit snapshot снимается в фоне; если пользователь в процессе набора, autosave откладывается до edit-ended event.

У Handsontable аналогичная граница компактнее Vue-wise, но больше логики окажется в host. `HotTable` предоставляет `hotInstance` через template ref. citeturn704259search1 HyperFormula instance в Vue обязательно надо оборачивать `markRaw()`, иначе Vue Proxy мешает его internal state и производительности. citeturn578407search9 Для remote patch:

```ts
hot.setDataAtCell(row, col, value, 'vaulter:remote')

hot.addHook('afterChange', (changes, source) => {
  if (!changes) return
  if (source === 'vaulter:remote') return
  sendLocalTransaction(changes, source)
})
```

Именно такой custom-source подход поддерживается официальным hooks guide. citeturn713341search8

### Что точно разрабатывает Vaulter

Не библиотека, а ваш host должен предоставить: version/revision protocol Laravel; optimistic lock и rebase policy; agent job lifecycle; stable selection reference; result highlight; remote/local origin tracking; user-only undo policy; save queue; conflict UI; feature-gated lazy loading; permission mapping; published range snapshot; Tiptap NodeView; export renderer; telemetry/benchmark harness; a11y fallback для preview; и способ сериализации library-specific snapshot в ваш versioned JSON envelope.

## Одинаковый прогон двух реализаций, метрики и критерии смены

Ни одно число ниже не является результатом измерения. **Фактических Vaulter benchmark results пока нет.** Маркетинговые показатели вроде «50–60 FPS до миллионов cells» на сайте Univer не следует считать Vaulter-измерениями; они не воспроизводят вашу workbook density, формулы, Vue host, browser и hardware. citeturn580894search0

Тестовая книга должна иметь **100 000 непустых клеток и 10 000 формул**. Для сравнения генерируется один нейтральный Vaulter fixture и конвертируется в оба engine format. Нужны минимум три листа, межлистовые зависимости, 10k formulas, sparse regions, строки, числа, dates, number formats и блок 100×100, куда выполняется paste.

Фиксируется одинаковая среда: одна версия Chromium, аппарат, viewport, cold cache и warm cache; по возможности добавить Firefox и Safari как compatibility smoke. Univer официально компилируется с target Chrome 88 и заявляет поддержку Edge ≥88, Firefox ≥90, Chrome ≥88, Safari ≥14.1; для некоторых сред нужен `Intl.Segmenter` polyfill. citeturn578407search3

Измеряемые показатели:

| Метрика | Как измерять |
|---|---|
| **Дополнительная загрузка** | Vite manifest + gzip/brotli size всех chunks, появляющихся только после открытия книги; отдельно JS, CSS, worker |
| **Time to first input** | `performance.mark('open-click')` → первый момент, когда click cell + typing реально меняет editor |
| **Workbook ready** | mount → API lifecycle steady / HOT afterInit+first render |
| **100×100 paste latency** | `paste` event timestamp → последняя mutation/recalc/render; отдельно main-thread и formula completion |
| **Recalc latency** | mutation одной входной клетки → обновились все ожидаемые dependent results |
| **Long tasks** | `PerformanceObserver({type:'longtask'})`; считать count, total duration, max duration >50 ms |
| **Interaction delay** | Event Timing API для keydown/click во время recalculation |
| **Memory** | `performance.measureUserAgentSpecificMemory()` там, где доступно, плюс Chrome heap snapshots |
| **20 open/close cycles** | baseline → открыть/закрыть 20 разных workbooks → GC → retained heap / detached DOM / workers / listeners |
| **Undo paste** | paste 10k → один Ctrl+Z; проверка exact data + selection |
| **Remote patch latency** | WebSocket/mock server arrival → видимое изменение range |
| **Selection stability** | remote patch во время user selection/edit → selection/focus invariant |
| **Screen reader** | NVDA + Chrome/Firefox, JAWS + Chrome, VoiceOver + Safari: cell coordinates/value/headers/edit mode |
| **IME** | ru-RU Windows + macOS: кириллица, composition, F2/double click, formula + Cyrillic sheet name |

Для Univer следует прогнать **две конфигурации**: formula engine main thread и официальный Worker. Worker path специально существует, чтобы снять compute-heavy formula work с main thread. citeturn580894search3 Для Handsontable отдельно проверить DOM virtualization default и accessibility-mode настройки, которые увеличивают объём rendered DOM; официальная документация предупреждает, что `renderAllRows`/`renderAllColumns` фактически выключают virtualization. citeturn730800search6turn580894search6

Chrome trace следует сохранять как artifact вместе с fixture hash, package lock и commit прототипа. Для каждой операции записываются медиана, p95 и max минимум после серии повторений; cold-load и warm-load нельзя смешивать.

### Browser experiments для неизвестных мест

Минимальный spike suite должен включать следующие проверки:

1. **Univer screen reader:** NVDA перемещается стрелками A1→B1→B2; проверяем, объявляются ли coordinate/header/value и edit mode. Если нет — это не «minor bug», а решение уровня продукта.
2. **Univer remote undo:** ручной E2 → remote D2:D3 → Ctrl+Z. Ожидается отмена E2, не agent patch.
3. **Оба кандидата Excel HTML paste:** Excel desktop → 100×100 с числами, отрицательными значениями, датами и формулами; сравнить clipboard MIME и resulting data.
4. **IME:** кириллица «проверено», composition replacement, формула после русского ввода.
5. **Save while editing:** ввести значение и, не нажимая Enter, инициировать autosave.
6. **Close/reopen:** job pending, dispose editor, complete server patch, remount snapshot.
7. **Echo test:** remote patch должен породить UI update, но ни одного outbound mutation.
8. **Memory:** после 20 mount/dispose не остаются formula workers, observers, large workbook arrays или detached nodes.

### Когда сменить основного кандидата

**С Univer на Handsontable + HyperFormula** стоит переходить, если хотя бы один из следующих пунктов подтвердится в одинаковом прототипе:

- screen reader не может надёжно читать координату, значение и edit state клеток, а WCAG/enterprise accessibility является launch requirement;
- невозможно отделить remote agent patch от пользовательского undo без форка внутренних command API;
- worker/recalc на 100k/10k всё равно даёт недопустимые long tasks относительно HOT;
- bundle/runtime React+RxJS становится неприемлемым для архитектуры CMS extension;
- lifecycle после 20 книг даёт подтверждённый устойчивый retained-memory рост, которого нет у HOT;
- нужный вам API оказывается только в Pro-модуле с лицензией/серверной архитектурой, противоречащей модели Vaulter.

**С Handsontable обратно на Univer** выбор становится практически обязательным, если:

- собственная formula bar + workbook semantics + sheet lifecycle начинают превращаться в отдельный spreadsheet product;
- необходимость сохранить Excel-like UX потребует слишком много host-кода вокруг Data Grid;
- HyperFormula main-thread recalculation на вашем fixture даёт значительно хуже interaction latency, а перенос расчёта в Worker становится отдельным большим проектом;
- commercial licensing Handsontable + HyperFormula не подходит модели распространения закрытых CRM/education extensions;
- несколько sheet/grid states и общий undo/agent patch protocol оказываются заметно сложнее, чем Univer command model.

### Итог

Для **первого реального прототипа Vaulter** я бы выбрал **Univer Sheets 1.5.2** и сохранил Handsontable 18.1.2 + HyperFormula 3.5.0 как обязательный контрольный implementation.
