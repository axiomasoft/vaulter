## Классификация (это и есть ТЗ фазы P2)

Полный перечень — `P0.2-drive-escaped.txt` (780 строк, формат `СТАТУС|файл:строка|мутатор`).

### A. Незапиненный контракт данных — самая крупная и самая ценная группа

`RemoveArrayItem` — 237 выживших, и это **не косметика**. Мутатор выбрасывает элемент из массива, и
никто не замечает:

| где | что не проверено |
|:--|:--|
| `Webhooks/RecordsDriveOutbox.php` (41) | форма payload'а исходящего события — ключи можно удалять, тесты зелёные |
| `Activity/RecordsDriveActivity.php` (31) | форма `context` аудит-записи |
| `Http/Requests/Uploads/CreateUploadSessionRequest.php` (29) | **правила валидации** — можно снять правило, запрос всё равно пройдёт тесты |
| `Actions/CopyNodeAction.php` (22) | набор копируемых полей узла |
| `Http/Resources/StorageResource.php` (17) | набор полей в API-ответе |
| `Http/Requests/UploadFileRequest.php` (12) | правила валидации |

Это прямые дыры: внешний контракт (payload вебхука, поля API-ресурса, правила валидации) не
зафиксирован ни одним тестом. Снять правило валидации и не уронить сьют — ровно тот класс, который
mutation-тестирование и обязан ловить. **Лечится тестами, не игнорами.**

### B. Контрактные тексты

`ConcatRemove*` / `ConcatSwitchSides` (104) — почти целиком тексты исключений (`src/Exceptions/*`,
87 выживших на 7 классов). Вопрос по каждому классу: текст сообщения — это контракт (уходит в
API-ответ / в docs) или внутренняя строка? Если контракт — тест ассертит сообщение, мутант умирает
законно. Если нет — точечный `@pest-mutate-ignore` с причиной, строкой в Completion Notes.

### C. Вывод команд

`Console/PurgeTrashCommand.php` (23) + `SweepUploadsCommand.php` (17): `$this->info(sprintf(...))`,
плюрализация `day`/`days`. Вывод консольной команды — часть её контракта (на него смотрит оператор и
парсят скрипты). Ассертить через `artisan(...)->expectsOutput(...)`.

### D. Поведенческие дыры — точечные, но самые опасные

Разрозненные `IdenticalToNotIdentical`, `SmallerOrEqualToSmaller`, `IncrementInteger` в граничных
условиях. Проверенный руками пример (P0.1 §1): `Uploads/TusUploadHandler.php:171`

```php
if ($max === 0 || $size <= $max) { return; }
```

Дефолт `vaulter.uploads.max_bytes` = 5 GiB, тесты знают только значения 10 и 1 000 000 — **никто не
ставит `max_bytes = 0` (безлимит) и никто не бьёт в точную границу `$size == $max`**. Поэтому мутанты
`0 → ±1`, `=== → !==`, `<= → <` неотличимы от оригинала. Это реальная дыра: конфигурация «загрузки без
лимита» не проверена вообще.

## Порядок работ в P2 (предложение)

1. **A — контракты данных.** Наибольший выигрыш на тест: один тест, ассертящий полную форму payload'а
   outbox-события, убивает десятки `RemoveArrayItem` разом. Аналогично — `context` активности, поля
   `StorageResource`, правила валидации в Request'ах.
2. **D — поведенческие дыры.** Мало по числу, максимум по риску: границы, безлимитные конфигурации,
   негативные ветки.
3. **C — вывод команд.** Дёшево и однозначно.
4. **B — тексты исключений.** Последними: сначала решить по каждому классу, контракт это или нет.
   Решение — строкой в Completion Notes, а не молча игнором.
