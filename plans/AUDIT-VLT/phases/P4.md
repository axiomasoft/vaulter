### P4.1 — Индексы под фактические запросы

**Status:** 🟢 Done
**Intent:** Построить опись пяти горячих запросов пакета (обход грантов, activity-фид, dedup-ключ CAS-блобов, sweeper загрузок, purge корзины), для каждого выписать колонки `WHERE`/`JOIN`/`ORDER BY`, и сверить их с фактическими индексами в миграциях `packages/core/database/migrations/*` (и в `PanelTablesBuilder` для панельных таблиц). Каждой паре «запрос ↔ индекс» дать вердикт: индекс покрывает (`✅ pass` с `file:line` определения индекса) / индекс отсутствует или частичен (`❌ fail`/`⚠ partial` → находка).
**Why:** Индекс, не соответствующий фактическому предикату, превращает O(log n) в seq-scan под ростом данных — тихий регресс, невидимый на пустой тестовой БД (T4: adjacency-CTE полностью материализует промежуточные результаты, стоимость растёт с глубиной). Обход грантов и activity-фид выполняются на каждый листинг; dedup-lookup — на каждый commit CAS; sweeper/purge гоняются по расписанию по всей таблице. Отсутствие индекса под эти пути — Major/Minor по цене (частота × размер таблицы), а не косметика.
**Scope Included:** `packages/core/database/migrations/*` (определения `->index()`/`->unique()`), `packages/core/src/Repositories/Access/GrantReadRepository.php`, `packages/core/src/Access/AccessResolver.php` (обход предков как запрос по `v_node_grants`/`v_nodes`), `packages/core/src/Repositories/Activity/ActivityReadRepository.php`, `packages/core/src/Repositories/Cas/BlobStoreRepository.php` (dedup-lookup по `sha256`), `packages/drive/src/Console/SweepUploadsCommand.php` + `packages/drive/src/Uploads/Repositories/UploadSessionReadRepository.php`, `packages/drive/src/Console/PurgeTrashCommand.php`, `packages/core/src/Schema/PanelTablesBuilder.php` (индексы панельных таблиц).

### P4.2 — N+1, рекурсивные обходы дерева, курсорная пагинация

**Status:** 🟠 Done with deviations
**Intent:** Проверить три источника latency-регресса на путях чтения: (а) N+1 в листингах/ресурсах (eager-load дочерних/грантов/блобов вместо ленивого); (б) рекурсивные обходы дерева `staudenmeir/laravel-adjacency-list` (`ancestors`/`descendants`) — есть ли потолок глубины (`withMaxDepth`) и детект циклов (`enableCycleDetection`), иначе цикл в `parent_id` = DoS/зависание; (в) пагинация фидов — offset (`->paginate()`, drift + O(n) на глубоких страницах) vs keyset/cursor (`->cursorPaginate()`). Каждой точке дать вердикт по `file:line`.
**Why:** N+1 в листинге узлов множит запросы на число элементов страницы — линейный регресс, скрытый на малых фикстурах. По T4 (`findings/P0.2-rag-supplement.md`): без `withMaxDepth()` пакет обходит весь достижимый подграф, `whereDepth()` фильтрует ПОСЛЕ построения полного поддерева (рекурсию не режет), а cycle-detection ВЫКЛЮЧЕН по умолчанию — цикл в данных даёт бесконечную/раздутую рекурсию по движку (PG: `max_stack_depth`/`statement_timeout`; SQLite: лимит 1000). Offset-пагинация фида даёт дубли/пропуски при конкурентных вставках и деградирует на глубоких страницах (норма keyset-пагинации для фидов — стабильна, скилл `php:cursor-pagination-design`).
