## 2. Находки

### F-P1.2-01 — Gate/Azgard-драйверы молча игнорируют v_node_grants, адресованные ролям/группам · Severity: Minor · Уверенность: high

**Где:** `packages/core/src/Drivers/Permission/GatePermissionResolver.php:102-109`, `packages/core/src/Drivers/Permission/AzgardPermissionResolver.php:125-132` (`subjectsFor()` → `[Subject(actor)]`).
**Что:** Под драйверами `gate` и `azgard` `subjectsFor()` возвращает ТОЛЬКО самого актора. `AccessResolver` строит `WHERE (subject_type, subject_id) IN (...)` из этого списка, поэтому строка `v_node_grants`, адресованная роли/группе/команде, никогда не попадает в выборку и молча не даёт эффекта — тогда как ADR-0007 (стр. 20-21) декларирует контракт `subjectsFor` как «actor → users + roles + teams».
**Почему опасно:** Направление отказа — БЕЗОПАСНОЕ (fail-closed: доступ не поднимается, а не поднимается лишний). Цена — функциональная и «тихая»: оператор, выдавший папку роли `subject_type=role` под gate/azgard-драйвером, получает молчаливое неисполнение гранта без ошибки/предупреждения; расхождение с задокументированным поведением спатие-лейна порождает разные результаты одного и того же ACL на разных драйверах.
**Доказательство:** `AzgardPermissionResolver.php:125-132`:
```php
public function subjectsFor(Authorizable $actor): array
{
    if (!$actor instanceof Model) { return []; }
    return [Subject::ofModel($actor)];
}
```
Аналогично `GatePermissionResolver.php:104-108`. Тест `VaulterResolverIntegrationTest.php:78-86` подтверждает: `subjectsFor` содержит ровно 1 элемент (актор).
**Норма, которая нарушена:** S1.2 (per-subject-свёртка: разрешение вычисляется по пользователь+группы+роли) — под gate/azgard роли/группы из свёртки выпадают. Расхождение с ADR-0007 стр. 20-21.
**Сверка с ADR:** ограничение ЗАДОКУМЕНТИРОВАНО в докблоках драйверов (`AzgardPermissionResolver.php:47-51,116-122`, `GatePermissionResolver.php:24-27,95-98`) и в мастер-плане §6, но САМ ADR-0007 не выносит для gate/azgard исключения из общего контракта `subjectsFor` — лёгкий дрейф «ADR описывает более полное поведение, чем поставляют gate/azgard». Решение сознательное (Gate не перечисляет роли, AzGuard — per-resource) → по Code Guidance класс «ограничение задокументировано» → **Minor**.
**Рекомендация:** (1) внести оговорку в ADR-0007, что gate/azgard-лейны сужают `subjectsFor` до `[actor]` (роль/групповые гранты требуют подкласса, добавляющего Subjects); (2) рассмотреть fail-loud-предупреждение при попытке выдать грант на `subject_type=role/team` под драйвером, чей `subjectsFor` их не энумерит (иначе оператор не узнает о молчаливом неисполнении).

### F-P1.2-02 — Docblock `GatePermissionResolver::gateAllows` обещает несуществующий catch · Severity: Nit · Уверенность: high

**Где:** `packages/core/src/Drivers/Permission/GatePermissionResolver.php:121-131`.
**Что:** Докблок утверждает «swallowing a missing-ability exception as "not allowed" so an unconfigured host gate never throws into the resolver», но тело метода — один вызов `Gate::forUser($actor)->allows($ability, $arguments)` без `try/catch`. `Gate::allows()` для неопределённой ability не бросает исключение (возвращает false), поэтому поведение fail-closed сохраняется — но комментарий вводит в заблуждение о механизме.
**Почему опасно:** Не влияет на безопасность (fail-closed сохранён). Цена — сопровождение: читатель может полагаться на несуществующую защиту от исключений; если хостовый `Gate::before`/резолвер ability реально бросит (кастомная логика), исключение уйдёт наружу из резолвера вопреки обещанию докблока.
**Доказательство:** `GatePermissionResolver.php:128-131`:
```php
private function gateAllows(Authorizable $actor, string $ability, array $arguments): bool
{
    return Gate::forUser($actor)->allows($ability, $arguments);
}
```
**Норма, которая нарушена:** внутренняя (docblock ≠ код); прямой RAG-нормы нет.
**Сверка с ADR:** не относится к ADR — дефект документации.
**Рекомендация:** либо привести докблок в соответствие (убрать упоминание swallow), либо, если инвариант «резолвер никогда не бросает из-за хостового гейта» желателен, реально обернуть вызов в `try/catch (\Throwable) { return false; }` — как это сделано в `SpatiePermissionResolver::actorHasPermission():216-222`.
