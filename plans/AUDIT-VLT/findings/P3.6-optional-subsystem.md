## 2. Находки

### F-P3.6-01 — Install-гайд надстройки противоречит коду и сам себе о том, какой транспорт — дефолт · Severity: Major · Уверенность: high

**Где:**
- `packages/core/config/vaulter.php:627-642` (докблок) и `:653` (`'driver' => env('VAULTER_COLLAB_DRIVER', 'hocuspocus'),`)
- `packages/core/src/Support/Config.php:713-718` (`collaborationDriverName()`, кодовый fallback `'reverb'`)
- `docs/guide/collaboration.md:30` (таблица «`reverb` (default) … None — pure Laravel»), `:38-43` («Start with Reverb»), `:52` (код-сэмпл `env('VAULTER_COLLAB_DRIVER', 'reverb')`)
- `docs/guide/hocuspocus-server.md:6-8` («Reverb is not a collaboration transport… the `reverb` collaboration driver is deprecated»)
- `docs/adr/0001-collaboration-transport.md:15-16` (`ReverbCollaborationDriver` (**default**) … No Node service»)

**Что:** Четыре источника истины о том, какой collab-транспорт активен по умолчанию и требует ли базовое включение collab Docker/Node-сервиса, дают ТРИ РАЗНЫХ ответа: (1) фактический дефолт конфига — `hocuspocus` (config/vaulter.php:653, требует внешний Node-хаб + `firebase/php-jwt` + секрет — `HocuspocusNodeCollaborationDriver.php:41-48` бросает `CollaborationConfigException` при их отсутствии); (2) `docs/guide/collaboration.md` утверждает обратное — таблица и код-сэмпл в этом же файле говорят, что дефолт `reverb`, «no extra service»; (3) `docs/guide/hocuspocus-server.md` соглашается с кодом — `hocuspocus` рекомендован, `reverb` «deprecated»; (4) `ADR-0001` (нормативное архитектурное решение, на которое ссылается сам `collaboration.md`) фиксирует `reverb` как **default** и `hocuspocus` как **optional**, симметрично `collaboration.md`, но противоречит `hocuspocus-server.md` и текущему коду. Дополнительно `Config::collaborationDriverName()` (`Config.php:715`) несёт кодовый fallback-дефолт `'reverb'`, отличный от реального дефолта конфиг-файла `'hocuspocus'` — практически недостижимый (конфиг-ключ всегда присутствует после `mergeConfigFrom`/публикации), но сам факт расхождения — симптом той же путаницы внутри кодовой базы.

**Почему опасно:** Хост, читающий `docs/guide/collaboration.md` (единственный явно указанный «entry point» для включения collab по D13/D14 — «включается по отдельному гайду»), спроектирует деплой БЕЗ `hocuspocus-server`, ожидая, что дефолтный `reverb`-путь «просто заработает». Как только он включит `document_versions` без явной установки `collaboration.driver=reverb`, реальный дефолт (`hocuspocus`) активируется и `CollaborationSessionService::issue()` → `HocuspocusNodeCollaborationDriver::issueSession()` бросит `CollaborationConfigException` при первом обращении к `nodes/{node}/collab/token` (нет `firebase/php-jwt` и/или `drivers.hocuspocus.secret`) — путь, который гайд явно обещал «no extra service». Это прямое нарушение продуктового требования D13 («базовый путь включения collab документирован и предсказуем») на уровне DX/операционной надёжности установки надстройки, а не просто опечатка в тексте.

**Доказательство:**
```
// packages/core/config/vaulter.php:627-642 (докблок)
|   'hocuspocus' — the RECOMMENDED collaborative-editing transport (default).
|   'reverb'     — DEPRECATED for Yjs document editing. ... Kept only for
|                  backward compatibility; use 'hocuspocus' for collaboration.
// packages/core/config/vaulter.php:653
'driver' => env('VAULTER_COLLAB_DRIVER', 'hocuspocus'),
```
```
// docs/guide/collaboration.md:30 (таблица)
| **`reverb`** (default) | Yjs over Laravel Reverb (private broadcast channel) | None — pure Laravel | ...
// docs/guide/collaboration.md:52 (код-сэмпл в том же файле)
'driver' => env('VAULTER_COLLAB_DRIVER', 'reverb'),   // reverb | hocuspocus
```
```

```
```

- `HocuspocusCollaborationDriver` (**optional**) — targets an external Node hub
```

**Норма, которая нарушена:** D13/D14 (collab — надстройка с документированным путём включения, предсказуемым дефолтом) · E7.1 («composer require обязан работать без публикации... дефолты должны быть разумными и однозначными»).

**Сверка с ADR:** `docs/adr/0001-collaboration-transport.md` фиксирует `reverb` как сознательный дефолт — это СОВПАДАЕТ с текстом `docs/guide/collaboration.md`, но РАСХОДИТСЯ с фактическим кодом (`config/vaulter.php:653`) и со вторым гайдом (`hocuspocus-server.md`), которые независимо и согласованно объявляют `hocuspocus` рекомендованным дефолтом (докблок в `config/vaulter.php` даёт явное техническое обоснование: Reverb не умеет server-side content gating и read-only enforcement для Yjs). Это классифицируется по D5 как **«ADR устарел»** — код и один из двух гайдов явно отражают более позднее, обоснованное архитектурное решение сместить дефолт на `hocuspocus`, но ADR-0001 не был обновлён, чтобы это решение зафиксировать. Подтверждено git-историей, не только текстовым сопоставлением: `git log --oneline -- docs/adr/0001-collaboration-transport.md` показывает файл нетронутым с `f07d53d`/`80e3369` (изначальный M1); переключение дефолта сделано ПОЗЖЕ, коммитом `9200e51` («Realtime collaboration e2e (Hocuspocus) + 2 fixes + driver re-scope (#21)», подкоммит `refactor(collab): default to hocuspocus, deprecate Reverb as a Yjs transport») — с явным техническим обоснованием в теле коммита и в докблоке конфига, но `git show 9200e51 -- docs/adr/0001-collaboration-transport.md` пуст: ADR в этом коммите не правился. Это не забытая синхронизация мелкой правки, а осознанное архитектурное решение, проведённое через код и не проведённое через ADR — учебный случай D5. Однако сам факт, что `docs/guide/collaboration.md` (не ADR, а именно operator-facing гайд) содержит НЕВЕРНЫЙ код-сэмпл, не совпадающий ни с текущим кодом, ни с текущим намерением проекта (согласно `hocuspocus-server.md`), — самостоятельный DX-дефект гайда, не покрываемый классификацией «ADR устарел».

**Консолидация дублей (фазовое ревью 2026-07-10):** тот же корневой факт (`config/vaulter.php:653` дефолт vs `docs/adr/0001-collaboration-transport.md:16`) изначально был заведён ВТОРОЙ раз как `F-P3.5-02` (item P3.5, чеклист `C1b`) с ПРОТИВОПОЛОЖНОЙ классификацией («реализация разошлась с ADR» = дефект конфига, а не «ADR устарел»). Ревью фазы отклонило это как дубль с конфликтующей классификацией по D5. Разбор git-истории (см. выше) однозначно подтверждает классификацию ИМЕННО этого item'а («ADR устарел») — `F-P3.5-02` снят, `plans/AUDIT-VLT/findings/P3.5-driver-seams.md` (`C1b`) теперь ссылается сюда (`ref. F-P3.6-01`). В `REGISTER.md` по этому корневому факту заносится ровно одна строка — `F-P3.6-01`.

**Рекомендация:** Минимальное исправление — обновить `docs/guide/collaboration.md` (таблицу и код-сэмпл `driver` default) на `hocuspocus`, синхронизировать формулировки с `hocuspocus-server.md`; ревизовать `ADR-0001` записью о смене дефолта (или новым ADR, дополняющим 0001) с обоснованием, уже присутствующим в докблоке `config/vaulter.php:635-642`; привести кодовый fallback `Config::collaborationDriverName()` (`Config.php:715`) к `'hocuspocus'` для консистентности (даже если недостижим на практике).

## 3. Не проверено / ограничения

- `docker compose -f hocuspocus-server/docker-compose.yml up -d` не запускался — функциональная проверка живого collab-соединения (JWT handshake, `onAuthenticate`/`onStoreDocument`) вне read-only-границ P3 (это предмет F-P1.6-02/03 и потенциального E2E-стенда, не этого item'а).
- Полный грep всех 6 драйверных швов на предмет аналогичных default-рассинхронов (не только collab) НЕ проводился — за рамками Scope Included P3.6 (это вход P3.5, где уже есть отдельная матрица швов; здесь фиксируется только collab-специфичный случай).
- `C5` ограничен статическим чтением провайдеров; фактический `vendor:publish --tag=vaulter-config` в контексте P3.6 не прогонялся (уже прогнан и задокументирован в P2.2/P2.4, не дублируется).
- Legacy Document-центричная collab-линия (`VaulterManager::driver()`, `v_documents`-модель, упомянутая в `collaboration.md:15-21` как сосуществующая с node-lane) НЕ проверялась отдельно — Required Reads item'а указывают только на node-tree лейн (`NodeCollaborationDriverManager`); расхождение дефолта распространяется на обе линии одинаково (общий config-ключ `vaulter.collaboration.driver`), но legacy-лейн код (`VaulterManager::driver()`) не читался построчно.
