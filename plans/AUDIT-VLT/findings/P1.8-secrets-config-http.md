## 2. Находки

### F-P1.8-01 — Публичные маршруты без rate-limit · Severity: Major · Уверенность: high

**Где:** `packages/core/routes/api.php` (группа `share/{token}*` — только `ResolveShareToken`), `packages/drive/routes/drive.php` (tus `resumable-uploads/{upload_id}` HEAD/PATCH/DELETE), `packages/documents/routes/documents.php` (`collab/authenticate`, `collab/store`); отсутствие throttle во всём `packages/*/src` и `packages/*/routes`.
**Что:** Ни один маршрут пакета не несёт `throttle`-middleware, и в коде нет ни одного `RateLimiter`. Публичные (без `auth`) маршруты — публичный share-link, tus-чанки, collab-handshake, webhook-приёмники — открыты для неограниченного числа запросов.
**Почему опасно:** Публичный `GET share/{token}` без лимита допускает перебор share-токенов (даже при высокой энтропии — онлайн-brute + отсутствие лок-аута) и bulk-выкачку разделённого контента одним аккаунтом/анонимом (G4.4). tus `PATCH` без лимита — DoS дорогими записями. collab/webhook-приёмники без лимита — усиление нагрузки на бэкенд. Хост может добавить throttle в свою группу `api`, но пакет этого не гарантирует и не документирует как обязательное.
**Доказательство:** `grep -rn "throttle\|RateLimiter\|Limit::" packages/*/src` → пустой вывод; `grep -rn "throttle" packages/*/routes/` → пустой вывод. repro `C15: route files declare no throttle middleware` — passed.
**Норма, которая нарушена:** `findings/P0-audit-gaps.md` §1 #2 (rate-limit на публичных маршрутах; Laravel 12 `throttle` + `RateLimiter::for`); плановый критерий C15 («полное отсутствие throttle на публичном share = Major»).
**Сверка с ADR:** ADR по rate-limit в `docs/adr/*` нет — решение не сознательное, дефект (не «ADR устарел»).
**Рекомендация:** Смонтировать `throttle:*`-middleware на публичные группы (share/tus/collab/webhook-in) с лимитом из конфига; в `docs/reference/rest-api.md` зафиксировать, что хост обязан обеспечить throttle на группе `api`.

### F-P1.8-02 — `$guarded = []` во всех 16 моделях пакета · Severity: Minor · Уверенность: high

**Где:** все модели: `packages/core/src/Models/{Drive/Node.php:64, Drive/Storage.php:47, Drive/File.php:39, Drive/FileVersion.php:45, Cas/Blob.php:54, Drive/FileVersionBlob.php:29, Access/NodeGrant.php:57, Sharing/NodeShare.php:60, Activity/Activity.php:56, Webhooks/Outbox.php:41, Webhooks/WebhookEndpoint.php:39, Webhooks/WebhookDelivery.php:40}`; `packages/drive/src/Uploads/Models/{UploadSession.php:59, UploadPart.php:35}`; `packages/documents/src/Models/{NodeComment.php:48, NodeDocumentVersion.php:54}`.
**Что:** Каждая модель объявляет `protected $guarded = []` (mass-assignment полностью открыт) и не задаёт `$fillable`. Запрещённый паттерн C6.
**Почему опасно:** Сам по себе латентный дефект-«footgun»: если любой код (в т.ч. будущий или хост-подкласс) выполнит `Model::create($request->validated())`/`->fill($input)`, атакующий сможет задать служебные колонки (`tenant_id`, `owner_type/owner_id`, `signing_secret`, `token_hash`, `granted_by`, `use_count`, `status`). В текущих write-путях эксплуатируемого стока НЕ найдено: репозитории заполняют явными серверными массивами (`NodeShareStoreRepository.php:43` `fill([...фикс.ключи...])`; `WebhookEndpointStoreRepository.php:28` `create([...фикс...])`, `:61` `forceFill`). Поэтому Minor, а не Major.
**Доказательство:** `grep -rn 'guarded = \[\]' packages/*/src` → 16 совпадений (см. §1 C6); отсутствие `$fillable` подтверждено пофайловым грепом.
**Норма, которая нарушена:** плановый C6 («`$guarded = []` в модели, доступной из HTTP-слоя — запрещённый паттерн»); E7/E5 (защита инвариантов модели пакета от хоста).
**Сверка с ADR:** прямого ADR о mass-assignment-политике нет; `HasExtraData` (D13, escape-hatch) объясняет открытость `extra_data`, но не оправдывает `$guarded=[]` на служебных колонках. Дефект.
**Рекомендация:** Задать явный `$fillable` (или `$guarded` со списком служебных колонок: `id`, `*_id` морфы, `token_hash`, `signing_secret`, `use_count`, `status`, `tenant_id`) на каждой модели; write-пути уже используют явные массивы, регрессий не будет.

### F-P1.8-03 — LIKE-инъекция wildcard в поиске по имени узла · Severity: Minor · Уверенность: high

**Где:** `packages/core/src/Repositories/Drive/NodeReadRepository.php:176` (метод `search`).
**Что:** `->whereRaw('lower(name) like ?', ['%'.mb_strtolower($term).'%'])` — `$term` связан плейсхолдером (SQL-инъекции нет), но спецсимволы `LIKE` (`%`, `_`, а на некоторых драйверах `\`) внутри `$term` не экранируются. Пользователь управляет паттерном сопоставления.
**Почему опасно:** Не обход авторизации (результат сужается `narrowToAccessible` — P0.3 §2.1), но: (1) `%`/`_` расширяют выборку сверх намерения (`_` = любой символ, `%` = всё), (2) патологические паттерны (`%_%_%_%…`) на большом дереве дают дорогой скан — locи-DoS-вектор. Это ось безопасности (инъекция в семантику запроса), не P4.
**Доказательство:** `grep -rn "whereRaw" packages/core/src/Repositories/Drive/NodeReadRepository.php` → `:176 ->whereRaw('lower(name) like ?', ['%'.mb_strtolower($term).'%'])`; экранирования `%`/`_` в методе нет.
**Норма, которая нарушена:** плановый C8 («поиск по имени узла экранирует `%`/`_` в `LIKE`»).
**Сверка с ADR:** ADR о поиске нет — дефект.
**Рекомендация:** Экранировать `%`/`_`/`\` в `$term` перед конкатенацией (напр. `addcslashes($term, '%_\\')` + `... like ? escape '\'`), либо использовать полнотекстовый индекс §2.2 с экранированным вводом.

### F-P1.8-04 — Нет гайда по CORS для REST-поверхности пакета · Severity: Minor · Уверенность: medium

**Где:** `docs/reference/rest-api.md` (нет секции CORS), `README.md`, `docs/guide/installation.md`; дефолт `packages/core/config/vaulter.php:550` `route_prefix = 'api/vaulter'`.
**Что:** Маршруты пакета монтируются под `api/vaulter` → попадают под дефолтный Laravel `config/cors.php` `paths=['api/*']` с `allowed_origins=['*']` (который в Laravel 11/12 не публикуется, но действует). Документация пакета предупреждает о CORS только для collab-хаба (CSWSH), но не для REST-API.
**Почему опасно:** С `allowed_origins:['*']` любой сторонний origin может из браузера читать ответы API. При токен-аутентификации хоста практический риск ограничен (браузер не приложит чужой bearer автоматически, `supports_credentials` в дефолте `false` блокирует cookie-cross-origin) → Minor. Но потребитель, полагающийся на cookie/сессию (vue-клиент шлёт `credentials:'same-origin'` — `docs/guide/vue.md:79`), должен знать о поверхности и сузить `allowed_origins`.
**Доказательство:** `grep -rniE "cors|allowed_origins" docs/ README.md` → совпадения только про `VAULTER_COLLAB_ALLOWED_ORIGINS` (хаб); REST-CORS не упомянут.
**Норма, которая нарушена:** `findings/P0-audit-gaps.md` §1 #6 (CORS `api/*` + `*`); плановый C16.
**Сверка с ADR:** нет ADR о CORS — дефект (пробел документации).
**Рекомендация:** Добавить в `docs/reference/rest-api.md` абзац: маршруты под `api/vaulter` попадают под `cors.php` (`api/*`, origins `*`); хост обязан сузить `allowed_origins` до своих origin и указать, какие origin нужны `@vaulter/vue`.

### F-P1.8-05 — Reference docker-compose хаба тянет образ по тегу `latest` · Severity: Minor · Уверенность: high

**Где:** `hocuspocus-server/docker-compose.yml:12` `image: ghcr.io/axioma-studio/vaulter-hocuspocus:latest`.
**Что:** Поставляемый reference-compose коллаб-хаба использует плавающий тег `latest` вместо пиннинга по версии/`@sha256`. (Дополнительно `e2e/docker-compose.yml:12` `POSTGRES_PASSWORD: secret` — но это одноразовый e2e-стенд, Nit.)
**Почему опасно:** `latest` невоспроизводим и снимает supply-chain-контроль: потребитель, скопировавший compose, при каждом pull получает неизвестную версию образа (риск подмены/регрессии). Митигация: коммент в файле явно советует «pin `@sha256:…` in prod».
**Доказательство:** `hocuspocus-server/docker-compose.yml:12` (см. §1 C5).
**Норма, которая нарушена:** плановый C5 («образы пинятся по тегу, не `latest`»); supply-chain-гигиена (пересечение с P4.4).
**Сверка с ADR:** нет ADR — дефект/DX-небрежность reference-деплоя.
**Рекомендация:** В reference-compose использовать конкретный тег версии (`:<version>`), а в проде — `@sha256`; e2e-пароль оставить как есть (стенд), либо через env.

## 3. Не проверено / ограничения

- **CI-секреты (`.github/`)** — вне границ D1 (Scope Excluded item'а); не проверялись.
- **C14 (Activity `context`)** — источники `context` (`RecordsActivity`/`RecordsDriveActivity`, все вызовы `RecordActivityCommand`) не трассированы исчерпывающе; вердикт `pass` основан на грепе и природе фида (метаданные операций над узлами), но полный обход всех продюсеров context не делался.
- **Repro** — по установленному в P1.3/P1.5/P1.7 ограничению харнесса repro-путь не привязан к TestCase (нет boot Laravel-приложения), поэтому C10/C11/C12/C15 подтверждены статически (source-level string/regex), а не рантайм feature-запросом анонимного клиента. Утверждение «анонимный запрос → 403» опирается на карту P0.3 + `docs/reference/rest-api.md:34`, не на рантайм-прогон.
- **Полнота C6-эксплуатируемости** — обход ВСЕХ HTTP write-путей на предмет `create($request->…)` не исчерпывающий: проверены репозитории записи (явные массивы) и грепы `request->all()`; вывод «эксплуатируемого стока нет» — medium-уверенность на достижимость, high — на наличие паттерна.
- **`extra_data` из HTTP** — не найден путь записи в пакете; поведение при хост-подклассе, пишущем `extra_data` из request, не воспроизводилось.
