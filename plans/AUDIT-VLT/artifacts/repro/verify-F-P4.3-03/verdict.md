# Верификация F-P4.3-03 (скептик-раунд)

**Претензия:** мутационный гейт `infection.json5` отключён — `minMsi`/`minCoveredMsi`
= 0 (строки 9-10), поэтому Infection не проваливает прогон ни при какой доле
выживших мутантов.

## Метод

1. Прочитан `infection.json5` целиком (10 строк, весь файл) — не только строки 9-10.
2. Прочитан класс, который Infection реально использует для решения «провалить
   CI или нет»: `vendor/infection/infection/src/Metrics/MinMsiChecker.php`.
3. Написан и прогнан прямой repro через `/usr/bin/php8.4 vendor/bin/pest` —
   `MinMsiGateTest.php` в этой же папке, конструирует `MinMsiChecker` ровно с
   параметрами из `infection.json5:9-10` и бьёт в него худшим возможным
   результатом прогона (MSI=0%, 100 выживших мутантов).
4. Проверены места, где мог бы существовать порог/защита выше по стеку:
   `.github/workflows/mutation.yml` (единственный CI-джоб, гоняющий Infection),
   `Makefile:23`, `composer.json:66` (`"mutate": "vendor/bin/infection --threads=4"`).
5. Проверено наличие ADR, оправдывающего решение: `find docs/adr` + grep по
   `minMsi`/`mutation` вне `plans/AUDIT-VLT` — ничего не найдено.

## Факты

1. `infection.json5:9-10` дословно: `"minMsi": 0, "minCoveredMsi": 0`.
2. `MinMsiChecker::isMsiInsufficient()` (строка 108-111):
   `return $this->minMsi > 0 && $msi < $this->minMsi;` — при `minMsi === 0.0`
   выражение коротко замыкается на `false` **при любом `$msi`**, включая `0.0`.
   Симметрично для `isCoveredCodeMsiInsufficient()`. Это не домысел — это
   буквальная семантика библиотеки, прочитанная из её исходника.
3. Repro `MinMsiGateTest.php` подтверждает это эмпирически:
   - тест 1 — `MinMsiChecker` с параметрами репозитория (`minMsi=0`,
     `minCoveredMsi=0`) НЕ бросает исключение при `msi=0.0`, `coveredCodeMsi=0.0`,
     100 мутантов (то есть на 100% выживших мутантах) — PASS.
   - тест 2 (контрольный) — тот же класс с ненулевыми порогами (`50.0`/`50.0`)
     на тех же входных данных бросает `MinMsiCheckFailed` — PASS. Это исключает
     версию «класс вообще не проверяет», значит дело именно в занулённых
     значениях конфига.
   - Прогон: `{"tool":"pest","result":"passed","tests":2,"passed":2,"assertions":2}`.
4. `.github/workflows/mutation.yml:3-5` — джоб помечен как advisory
   (`|| true` на шаге `Run Infection`, строка 59) и не блокирует PR (триггеры —
   только `push: main` и `workflow_dispatch`). Это независимая вторая причина,
   почему CI не падает, но она НЕ покрывает локальный путь: `make`/
   `composer run mutate` вызывают `vendor/bin/infection` без `|| true` — там
   единственная защита от «зелёного» прогона на 0% MSI — это как раз
   `minMsi`/`minCoveredMsi` в `infection.json5`, и она отключена.
5. ADR, оправдывающего `minMsi: 0` как сознательное решение, не найдено ни в
   `docs/adr/*.md`, ни где-либо вне `plans/AUDIT-VLT`.
6. Норма `P4.3 C4` (`findings/P0-audit-gaps.md:28,66`) прямо запрещает
   трактовать `minMsi: 0` как приемлемое «потому что проект молодой» — то есть
   аудит уже заранее закрыл потенциальную отговорку.

## Проверенные гипотезы опровержения — все не подтвердились

- **Защита выше по стеку?** Нет — `mutation.yml`'s `|| true` защищает только
  CI-джоб, но не локальный/composer-путь; и даже для CI это отдельный,
  независимый механизм non-blocking, а не альтернативный гейт с реальным
  порогом.
- **Недостижимый код?** Нет — `infection.json5` — это единственный конфиг
  Infection в репозитории, читается при каждом запуске `vendor/bin/infection`.
- **Неверно понятая семантика библиотеки?** Нет — прочитан и эмпирически
  прогнан исходник `MinMsiChecker`; семантика ровно такая, как в находке.
- **ADR о сознательном решении?** Не найден.
- **Тестовый/стаб-код вместо продакшн-пути?** Нет — `infection.json5` в корне
  репозитория — это и есть продакшн-конфиг тулинга, используемый и в CI, и
  локально (`make`, `composer run mutate`).

## Вывод

Опровергнуть находку не удалось. Технический факт подтверждён на трёх
независимых уровнях: (1) буквальное чтение конфига, (2) чтение исходника
библиотеки, (3) эмпирический repro через `pest`, показывающий, что гейт
пропускает 100%-выживших-мутантов молча, а идентичный класс с ненулевыми
порогами на тех же данных — падает. Norm P4.3 C4 нарушена буквально; ADR,
исключений в фиче-флагах или защиты выше по стеку нет.

**Вердикт: находка НЕ опровергнута (refuted=false). Severity — keep (Major).**
