## Implemented fidelity path

- `p7_product_ops.py` replaces the labelled fault-proxy GET with the operation named by each cell. It prepares run-scoped authenticated storage/upload fixtures and calls the real tus PATCH, multipart part/complete, abort, folder/outbox mutation and sweeper HTTP/Artisan seams. CAS staging, a bounded write and the advisory-lock/outbox mutation use a small registered load command because they have no public HTTP surface.
- Each upload attempt samples its exact `v_upload_sessions`, `v_upload_parts`, `v_blobs` and `v_outbox` identities, including received bytes and terminal upload status. The harness reads the matching server-generated object key and records both DB→object and object→DB reconciliation; expected absence is distinct from a missing required object or an orphan. V2 evidence carries a separate full run marker because the product's object key correctly contains a server UUID rather than a client run ID. Outcomes and byte counts come from the actual response, command exit and persisted size; accepted/committed values are no longer hardcoded. A fixture refuses to reuse an actor that already owns a live storage, protecting scoped cleanup.
- Primary-transition cells migrate and route the app to the isolated HA database before fixture creation. Route-only app recreates explicitly skip entrypoint migrations after that bootstrap, so they neither target an incompatible HA database nor run `migrate:fresh` against the base stand on return. After the injector promotion barrier, the operation runs through `pgbouncer-ha`; rows are sampled from the promoted standby before revert. The base app route is restored before recovery probes. Final cleanup performs a fail-closed isolated HA revert with the run-specific state before stopping that lab. This is only a local isolated promotion path, not a host/AWS HA guarantee.
- ENOSPC fills the dedicated tmpfs, then the `write` probe performs a real `fopen`/`fwrite`/`fflush` against that mount. `cas-stage` uses the real `Sha256ContentStore`; `spill` sends a 3 MiB tus body. `enospc-then-retry` reverts the mount before a second operation with a different ordinal/request identity. Cleanup removes only the attempt's rows, upload objects and two bounded write paths.
- Every attempt now requires `/up=200`, `/ready=200` and a `/metrics` response containing Vaulter exposition before fault attribution. The live verifier also requires `up{job="vaulter-sut"}=1`, v2 product-operation evidence and distinct ENOSPC retries. The historical P7 tree cannot satisfy this gate.

No P6 metric, stored P6 verdict or R09/R10 telemetry is consumed by this implementation. B02's independent Astra re-review remains pending exactly as required.
