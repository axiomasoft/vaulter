## Changed evidence sources

- Dispatcher and worker use the same run/cell/attempt context. `JobQueueing` records the pre-push timestamp; `JobQueued` remains successful enqueue confirmation. UUID joins measure enqueue-start → processing and processing → processed. The queue-wait measurement is a conservative upper bound including Redis enqueue I/O, not delivery age. Default `queue=null` resolves through the configured connection queue.
- Each cell starts with a clean endpoint/delivery fixture and exactly two workers. Control endpoints match their complete URL, including cell and sink profile. Serial and concurrent duplicate controls use disjoint UUID windows. Sink records request run/cell/event/slot and appends ordinal using only the ledger tail.
- Laravel cache-backed `queue:pause/continue` fences fixture cleanup. This image has **no pcntl**; SIGUSR2 kills a detached worker and the configured worker timeout is not an enforced pcntl timer. After reserved jobs finish, the serial sink must answer `/health` before fixtures can be deleted. Timed-out sink requests otherwise contaminate subsequent cells.
- Failed jobs are identified by UUID, payload SHA-256, payload class, command class, exception class and failed timestamp, without writing serialized payloads/secrets. Per-cell and volume before/after identities provide deltas. Package business-dead counts remain separate.
- The volume captures every relay tick for the actual 10,000-row backlog with 20 active endpoints and every bounded retry tick for 5,000 due rows, then drains the real Redis queue. OS peak RSS comes from `/usr/bin/time`; PHP peak is recorded separately.
- A metrics run opens before load; raw `up` range and scrape timestamps establish continuity. A versioned v2 verifier recomputes joins, failure deltas, sink counts, volume completion and SLO results; a later passing attempt cannot erase an earlier RED. Historical v1 verification is preserved.
- Product bursts now insert the declared 20/100/200 events, including timeout cells. The named slow-under-timeout profile uses the approved SLO-61 50 ms sink. The fixed single-process PHP sink remains a throughput limitation; its ceiling must not be attributed to package code.
