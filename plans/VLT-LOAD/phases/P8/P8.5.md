**Intent:** Реализовать метрики `slo-gates.md` §5.3 — фон, очереди, приборка unbounded-scan'ов:
outbox (`backlog` gauge / `stage`/`relay`/`relayed` / **`endpoints_scanned_total`** seam L-05), webhook
(`queue_wait`/`delivery`/`delivered`/`failed` / `retry_tick` / **`retry_lockset_rows`** seam L-04), sweep

RSS любой фоновой команды), `vaulter_pg_lock_wait_seconds`.
**Why:** Питает SLO-55…81. Seam'ы `*_batch_rows`/`*_lockset_rows`/`endpoints_scanned_total` — единственный
способ доказать деградацию L-02…L-05 на «грязных» объёмах (млн сессий/orphan/outbox) в P5/P6.
**Scope Included:** инструментация точек §5.3 из спеки; `command_peak_memory_bytes` — общий хелпер для всех
фоновых команд (лейбл `command`); Fake-ассерт на каждую метрику.

регистрация команд в расписании (L-08 — хост-долг/RUNBOOK).

**Implementation Rules:** `endpoints_scanned_total` инкрементируется на КАЖДЫЙ endpoint, перебранный в
`subscribedEndpoints()` на одну outbox-строку (обнажает O(endpoints)). `retry_lockset_rows` — число строк,
залоченных `claimDue()` за тик (histogram). `sweep_batch_rows`/`gc_batch_rows` — размер батча за тик
(обнажает отсутствие limit/чекпоинта). `command_peak_memory_bytes` — host listener на console termination, `memory_get_peak_usage(true)`, run-max
в shared registry (`observability-spec.md` §7); лейбл `command` — artisan signatures §9 (`vaulter:sweep-uploads`, …). `pg_lock_wait_seconds` — harness script, не package
`MetricsRecorder`. Остальные package-метрики — через инжектированный recorder.

только считает, не батчит (батчинг = фикс L-02/L-04, dev-срез). **Анти-подгонка:** `*_batch_rows` — это
именно то число, что доказывает unbounded-scan; не «оценка», а фактический счётчик обработанных строк за
тик. Каждая метрика — свой Fake-тест. Инъекция конструктором; для `Console`-команд — через контейнер в

аддитивен, D11 неприменим (D31).
