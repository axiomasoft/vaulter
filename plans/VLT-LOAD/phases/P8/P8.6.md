### P8.6 — Health в load SUT: `/up` liveness + `/ready` DB/S3/queue

**Intent:** Дать харнессу P2 два независимых сигнала: Laravel-native `/up` подтверждает жизнь процесса,
а SUT-owned `/ready` подтверждает готовность DB, S3 sentinel и настроенного queue connection и отвечает
200/503 машинно-читаемым результатом (D36).

**Why:** Один `/up` не отличает доступный PHP-процесс от приложения, неспособного обслуживать Vaulter.
Без негативных readiness-проверок нагрузочный запуск может принять отказ зависимости за SLO-регрессию.

**Scope Included:** включение `/up` в `load/`; route/controller/service `/ready` только в `load/`;
ограниченные по времени и неразрушающие проверки DB `SELECT 1`, S3 sentinel `exists`; Redis queue
driver + `queue-worker` service; heartbeat job в очереди `load-health`; positive test и три независимых
negative tests (DB, S3, queue=redis-down **или** worker-stopped **или** heartbeat-timeout).

**Scope Excluded:** код/route/API в `packages/core`; зависимость или `suggest` на
`spatie/laravel-health`; dashboard/history/alerts; проверка произвольной инфраструктуры хоста.

**Inputs:** `plans/VLT-LOAD/slo-gates.md` §5.4 ·
`plans/VLT-LOAD/findings/P8-rag-otel-health.md` (актуальная Laravel-проверка) · D36 ·
SUT `load/` и его compose/config/tests из P2.2 · `plans/VLT-LOAD/observability-spec.md` health-раздел.

**Files:** `load/app/Http/Controllers/ReadyController.php`; `load/app/Jobs/LoadQueueHeartbeat.php`; `load/app/LoadServiceProvider.php` (`/up`, `/ready`); `load/docker-compose.load.yml` (`redis`, `queue-worker`); `load/docker/Dockerfile.app` (PHP Redis extension); `load/app/testbench.load.yaml`; `load/tests/` (positive + DB/S3/queue-down + stale-ACK nonce). Файлы `packages/*` не меняются.

**Required Reads:** (1) `plans/VLT-LOAD/slo-gates.md` §5.4;
(2) `plans/VLT-LOAD/findings/P8-rag-otel-health.md`;
(3) `plans/VLT-LOAD/observability-spec.md` health-раздел;
(4) актуальные `load/compose*.yml`, `load/app/`, `load/tests/` и Completion Notes P2.2.

**Implementation Rules:** `/up` — стандартный health route текущей версии Laravel и не вызывает
readiness probes. `/ready` запускает все три дешёвые проверки с явным bounded timeout на connect/read
драйвера, не создаёт и не удаляет **доменные** данные (единственная health-мутация — TTL cache key
heartbeat) и возвращает стабильную схему `status` + component states; итог 503 при любом failure.
S3 проверяется через заранее созданный sentinel, а не list-bucket. Queue: `QUEUE_CONNECTION=redis`,
очередь `load-health`, nonce-scoped cache key `vaulter:queue-ready:{nonce}` с one-shot consume
(`observability-spec.md` §4); `sync`/`Queue::size()`/чужой ACK не являются readiness. Детали
credentials и drivers остаются в SUT config/env.

**Code Guidance:** Не добавлять условно наследуемые Spatie-классы в reusable package: отсутствие
optional dependency должно оставлять весь `packages/core` compile-time surface валидным. В negative
tests отключать ровно одну зависимость и доказывать, что `/up` и `/ready` различаются по смыслу.

**Validation:** `/up` = 200 при живом процессе; `/ready` = 200 при доступных DB/S3/queue; четыре отдельные
проверки дают `/ready` = 503 при отказе DB, S3, queue **или stale-ACK nonce** и называют компонент; `/up` при отказе внешней
зависимости остаётся process-liveness; тесты load SUT зелёные; diff не содержит `packages/*`.

**Deliverables:** `/up` и `/ready` в `load/`, bounded DB/S3/queue probes, load-owned config/schema при
необходимости и positive/negative tests.
