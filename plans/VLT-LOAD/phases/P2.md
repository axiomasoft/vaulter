# P2 — Нагрузочный харнесс: инструмент + профили трафика (гейт P3–P7)

## Phase Context

> СКЕЛЕТ — не детализирован, разворачивается /task:plan-design VLT-LOAD P2

**Blueprint (зафиксирован в P0, 2026-07-13).**

**Цель.** Собрать воспроизводимый генератор нагрузки под tus/S3/tree/queue-сценарии.

**Артефакты.**
- `plans/VLT-LOAD/harness.md` — решение по инструменту (D2: k6) + сборка кастомного бинарника
  (D3: `xk6-fasthttp` + D4: `xk6-output-prometheus-remote`) + как гоняем (локально / k6 Operator k8s).
- `load/` (тест-инфра, вне пакета): реализация эталонного стенда по спеке `reference-env.md` (P1.1) —
  `docker-compose.load.yml` с cpuset-раскладкой (D13) — и k6-скрипты сценариев:
  - `tus-upload.js` — POST create → PATCH offset+chunk → resume-ветка (HEAD offset, докачка) →
    инъекция обрыва на середине.
  - `s3-multipart.js` — CreateMultipartUpload → UploadPart×N → Complete/Abort (SigV4 в скрипте).
  - `download.js` — конкуррентные стримы (нагрузка на FPM-воркеры).
  - `tree.js` — children/subtree/breadcrumb/move на предзаполненном дереве.
  - `mixed.js` — реалистичный микс (доли — из `operations-catalog.md`, P1.2) + think-time + error-injection.
- Профили трафика: `smoke-perf` (PR) и `regression` (nightly) по спеке `slo-gates.md` (P1.4);
  baseline (1×), ramp, spike-бёрст, soak, stress (до обрыва).
- `load/seed/` — команды предзаполнения БД/стораджа до объёмного конверта тира (P1.1, D10).
- Пороги в сценариях — **из `slo-gates.md`**, не изобретаются здесь.
- Измерить **CV** ключевых метрик на `ubuntu-latest` (≥5 прогонов) и подтвердить/пересмотреть δ
  относительного гейта класса B (P1.4 оставил δ как гипотезу).

**DoD.** Кастомный k6-бинарник собран и стримит 5-ГиБ тело **без OOM генератора** (доказать замером
RSS процесса k6); каждый сценарий гоняется и пишет метрики в Prometheus; seed воспроизводит объёмный
конверт; профили параметризованы (VU/duration/rps из env); δ и CV измерены. Прогон 1× baseline зелёный.

**Риск.** Стоковый k6 → OOM на multi-GB (RAG-2). Митигация: D3 (fasthttp/chunk), проверка RSS в DoD.
Второй риск: SigV4/tus руками → баги харнесса маскируют/выдумывают проблемы. Митигация: контрактный
smoke каждого сценария против реального эндпоинта до нагрузки.

**Опора.** RAG-1/2/3 (`findings/P0-rag-load-tooling.md`), RAG-6/7 (`findings/P1-rag-slo-ci-gate.md`),
§1.2 (tus/S3 семантика: offset, part replace, complete), артефакты P1.

**Порядок.** После P1. Гейт для P3–P7.
