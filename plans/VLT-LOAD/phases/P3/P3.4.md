### P3.4 — N+1/recursive CTE synthesis и DB-profile verdict

**Intent:** Свести workload, query traces, actual plans и index review в один проверяемый
`db-profile.md`, подтвердить application multiplicity и выпустить отдельные debt rows без исправления
горячих путей.
**Why:** Raw plans не отвечают, сколько раз запрос вызван внутри одной операции и что делать дальше.
Фаза завершена только когда все OP/top-20/hotspots имеют verdict, а предложение индекса не маскирует
N+1 или неверную кардинальность.
**Scope Included:** per-operation duplicate fingerprint/SQL-count analysis; N+1 proof с code anchor;
recursive CTE calls/loops/rows visited; разбор top-20; сводка восьми hot table families;
index/extended-statistics/query-shape candidates; severity/confidence/owner package; отдельный backlog
для dev-срезов; limitations и cache/environment statement.
**Scope Excluded:** исправления; реальный DDL; обещания tier M/L; p95 из pg_stat_statements; перенос
неподтверждённых гипотез в accepted decisions.
**Inputs:** `plans/VLT-LOAD/phases/P3/P3.2.state.md`;
`plans/VLT-LOAD/phases/P3/P3.3.state.md`;
`plans/VLT-LOAD/artifacts/P3/operation-coverage.json`;
`plans/VLT-LOAD/artifacts/P3/pgss-top20.json`;
`plans/VLT-LOAD/artifacts/P3/index-review.json`;
`plans/VLT-LOAD/artifacts/P3/hypopg-candidates.json`;
`plans/VLT-LOAD/operations-catalog.md`; `plans/VLT-LOAD/slo.md`.
**Files:** `plans/VLT-LOAD/db-profile.md`, `plans/VLT-LOAD/findings/P3-db-profile.md`.
**Required Reads:** (1) `plans/VLT-LOAD/phases/P3/P3.2.md` and `P3.3.md` with GREEN terminal evidence;
(2) all validated `plans/VLT-LOAD/artifacts/P3/` carriers;
(3) `plans/VLT-LOAD/operations-catalog.md`;
(4) `plans/VLT-LOAD/slo.md` P3-linked rows;
(5) `plans/VLT-LOAD/findings/P3-rag-postgres-profiling.md`;
(6) source anchors named by confirmed multiplicity/index findings;
(7) D11 and D41 current decisions.
**Implementation Rules:** `db-profile.md` begins with environment/run/dataset/cache validity, then
OP coverage, top-20, plan cards, index review, N+1/CTE, candidates and limitations. Every claim links
to raw evidence id and code anchor. N+1 requires repeated fingerprint within one request/job plus
source-level loop/relation cause; high global calls alone are insufficient. Recursive CTE verdict
records calls per OP, `Recursive Union`/`WorkTable Scan` loops and visited/returned rows. Debt row has
stable id `L-P3-nn`, severity, confidence, affected OP/SLO, owner package, evidence ids, candidate
remediation and D11 gate. RAG markers distinguish external methodology from repository/run facts.
**Code Guidance:** Separate `observed`, `inferred`, and `candidate`; never write “index-fast” from
cost-only HypoPG. If an OP lacks a safe actual plan, retain explicit limitation and keep P3 open
unless it is classified `no-db`/`trace-only` by contract. Avoid duplicated prose: raw numbers live in
artifacts, report carries compact tables and decisions. L-05/L-06 are updated by new evidence but
not silently relabelled if the run is invalid.
**Validation:** coverage parity 47/47 OP; top-20 parity 20/20; mandatory hotspots present; each
non-justified seq scan/N+1/N-CTE/cardinality miss maps to one debt row; every debt evidence id resolves;
no `packages/*` edits in P3 diff; Markdown link/path check; P3 profile validator against final report;
plan-lint/downstream checks green.
**Deliverables:** `db-profile.md` as the P3 verdict and `findings/P3-db-profile.md` as the bounded,
evidence-linked remediation backlog.
