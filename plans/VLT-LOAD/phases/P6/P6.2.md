### P6.2 — Controlled sink, queue fixtures и semantic matrix

**Intent:** Добавить изолированный webhook sink, disposable fixtures и точную матрицу relay/retry/
duplicate/backoff/DLQ cases.
**Why:** Seeded `.invalid` endpoints и aggregate counters не дают реальных POST, fan-out multiplicity,
timeout occupancy или receiver-side dedupe evidence.
**Scope Included:** sink profiles 2xx/500/delay/hang with run-scoped ledger; load-only outbound guard
restricted to sink; fixture prepare/cleanup; 0/1/all subscription density; 10k outbox/5k due tier-S;
200/1000 endpoint and 50k/500k probes; 1×/5×/10× ingress; synchronized overlapping ticks;
intentional duplicate job serial/concurrent; backoff→dead→endpoint-disable state controls; matrix tests.
**Scope Excluded:** live authoritative run; public package behavior; Internet endpoints; Redis/DB/
network outage (P7); retry batching/index fix; full tier M/L claim; secrets in artifacts.

**Implementation Rules:** Fixture IDs and event_ids are deterministic per run; cleanup is exact-run
or disposable-snapshot scoped. Sink accepts only the stand network and records no signature/body.
`hang` must still be bounded by an outer harness deadline. State-machine controls record the real
configured backoff delta before making the row due; clock manipulation is explicit and never used
for elapsed-time SLO. Concurrent duplicate jobs share one delivery but distinct queue UUIDs. Every
case declares expected invariants, not expected performance verdict.
**Code Guidance:** Preserve the tier-S worker count/config for product cells. An intentionally bad
`timeout >= retry_after` control may use an isolated queue/worker and is mechanism-only. Do not use
`Bus::fake`, sync queue or mocked HTTP in live cases. Fan-out factor is measured from deliveries/jobs,
not inferred from endpoint count alone. Snapshot restore precedes each destructive cardinality case.
**Validation:** load Pest tests prove sink profiles, guard restriction, idempotent fixtures, exact
cleanup and backoff/dead/disable preparation; static validator covers every plane × case × required
axis; S0 contract run executes one 2xx, one failure, one overlap and one duplicate control; post-run
checks detect missing/extra delivery rows, queue jobs and sink receives.
**Deliverables:** controlled sink, safe load-only routing, reproducible queue fixtures, complete
semantic matrix and integrity assertions.
