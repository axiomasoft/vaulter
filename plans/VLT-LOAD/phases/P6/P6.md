# P6 — Семантика очередей под завалом

## Phase Context

**Цель.** Доказать под реальным Redis worker и PostgreSQL, как Vaulter ведёт себя при 1×/5×/10×
подаче событий, большом outbox/retry backlog, медленном получателе и overlapping relay/retry ticks.
P6 измеряет relay, queue и package-owned retry/DLQ как разные очереди и не исправляет L-04/L-05.

**Входной контракт.** P2 владеет disposable stand/seed, P8.5 — server-side outbox/webhook seams,
P8.7 — run-scoped exposition. D41 запрещает исполнение до GREEN/accepted результата единственного
полного `task:plan-audit VLT-LOAD design`. До live run P8.5 producer-state должен быть штатно
reconciled; ошибочный
или отсутствующий metric не заменяется нулём, а исключается из evidence с raw fallback.

**Четыре плоскости evidence.** (1) `product-realistic` — реальные Artisan ticks, Redis workers и
контролируемый HTTP sink, только она потребляет SLO-58…66 и end-to-end ≤10 s; (2)
`overlap-control` — синхронные relay/retry ticks и intentional duplicate jobs, проверяющие dispatch/
HTTP multiplicity без throughput claim; (3) `state-machine-control` — реальные job executions с
принудительным переводом `next_retry_at` в due между попытками, чтобы проверить backoff/dead/disable
без ожидания 40 минут; (4) `dirty-cardinality-probe` — 200/1000 endpoints и 50k/500k due rows на
tier-S host, не выдаваемые за tier M/L SLO.

**Границы семантики.** Package retry живёт в `v_webhook_deliveries`; Laravel Redis `retry_after` и
worker timeout — отдельный lease. Поэтому DB terminal state, queue dispatch и фактический HTTP POST
считаются отдельно. Serial terminal no-op не считается доказательством concurrent exactly-once.
`failed_jobs` отражает uncaught/worker failures, а не package `failed|dead`, потому что
`DeliverWebhook` записывает transport/HTTP failure и возвращается успешно.

**Матрица.** Tier S: 2 workers, sink 50 ms, outbox 10k, endpoints 20, due retries 5k; ingress
20/100/200 events/s (1×/5×/10×), fan-out density 0/1/all subscribed, 2xx/500/slow-under-timeout/
over-timeout sink profiles. Overlap: 2 relay + 2 retry ticks через barrier; duplicate job serial и
concurrent. Cardinality controls: endpoints 200/1000 и due 50k/500k по одному valid attempt после
snapshot restore. Каждый результат несёт fan-out factor, поэтому rows/s не смешивается с jobs/s.

**Evidence.** Один `run_id` связывает DB counts/transitions, Redis pending/reserved/delayed samples,
Laravel queue lifecycle UUID/attempt timeline, worker PID/restarts, sink request ledger с `event_id`,
P8 Prometheus, command RSS и PostgreSQL lock snapshots. `delivery.created_at` не используется как
retry enqueue time; queue wait выводится из фактической enqueue→processing пары.

**Выходы.** Raw evidence — `artifacts/P6/`; итог — `queue-report.md`; долги L-04/L-05 и новые
`L-P6-nn` — `findings/P6-queue-semantics.md`. Ни один `packages/*/src` файл P6 не изменяет.

**Порядок.** P6.1 строит queue lane/validator → P6.2 sink, fixtures и case matrix → P6.3 выполняет
immutable tier-S run family → P6.4 выпускает report/debt. P6.1–P6.2 — recommended implementation
batch; P6.3–P6.4 — recommended manual batch.
