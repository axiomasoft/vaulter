# P8 — Наблюдаемость: метрики + трейсы (seam'ы с нуля) (гейт P3–P7 по минимуму)

## Phase Context

> СКЕЛЕТ — не детализирован, разворачивается /task:plan-design VLT-LOAD P8

**Blueprint (зафиксирован в P0, 2026-07-13; уточнён P1 2026-07-14).**

**Цель.** Узнавать о нагрузке из метрик, а не от пользователей. Сегодня наблюдаемости в пакете нет
(ни Horizon, ни spatie-health, ни `/up`, ни метрик, ни трейсинга) — фаза **создаёт seam'ы**, а не
подключает дашборд к существующему.

**Ключевое уточнение из P1:** список **P8-минимума больше не изобретается здесь** — он выводится в
item'е P1.4 из колонки «Prometheus-метрика» таблицы `slo-gates.md` (иначе вердикт «SLO нарушен»
опять не на чем строить — D9). Фаза P8 этот список **реализует**.

**Артефакты.**
- `plans/VLT-LOAD/observability-spec.md` — что инструментируем и какими seam'ами:
  - Метрики (Prometheus через OTel Collector): `upload_bytes_total`, `upload_session_active`(gauge),
    `patch_conflict_total`(409), `blob_dedup_hit_total`, `gc_swept_total`/`gc_duration_seconds`,
    `sweep_expired_total`/`sweep_skipped_total`, `outbox_backlog`(gauge), `webhook_delivery_seconds`
    (hist), `webhook_dlq_total`, `tree_query_seconds`(hist), `collab_session_active`(gauge) —
    **сверить с P8-минимумом из `slo-gates.md`, расхождение объяснить**.
  - Трейсы (OTel PHP SDK → OTLP Collector → Tempo/Jaeger): HTTP→Controller→Action→repo; спаны на
    PATCH/putPart/complete/commit/GC/sweep/relay; атрибуты upload_id/node_id/tenant/attempt.
  - Health: `/up` liveness + readiness (БД/S3/очередь) — spatie/laravel-health кандидат
    (skill `laravel-testing:health-checks`). Часть P8-минимума: без него харнесс P2 не отличит
    «упало» от «недоступно».
- Спека seam'ов в пакетном `src/` (это **единственный код-выход VLT-LOAD**, отдельными dev-срезами):
  где вешаются таймеры/счётчики без хард-зависимости на конкретный backend (контракт-шов, как AzGuard).

**DoD (двухступенчатый — гейт срабатывает на P8-минимуме, не на полном закрытии фазы).**
- **P8-минимум (гейт P3–P7):** реализован ровно список из `slo-gates.md` (P1.4) — таймеры/счётчики
  латентности на горячих путях каждого класса SLO + seam'ы на unbounded-scan'ы (`## 7`) + `/up`.
  Без этого набора P3–P7 не стартуют замер (D9, `## 4` — P8 гейт, не «параллельна»).
- **Полное закрытие фазы:** остаток спеки (трейсы, редкие метрики) — после того как P3–P7 показали
  приоритет; дополняется, не блокирует уже идущие фазы.

**Риск.** OTel PHP + FPM overhead под нагрузкой сам искажает замер. Митигация: sampling, замер
overhead'а инструментации отдельным прогоном (with/without).

**Опора.** §1.2 (наблюдаемость=absent, unbounded-scan'ы), RAG-5 (OTel→Collector→Prometheus/Tempo),
`slo-gates.md` (P1.4 — раздел «P8-минимум»), skill `architect:observability-design`,
`laravel-testing:health-checks`, D9.

**Порядок.** Стартует сразу после P2. **P8-минимум обязан быть готов до старта P3–P7.** Полное
закрытие фазы — последним, после того как P3–P7 показали приоритеты инструментации.
