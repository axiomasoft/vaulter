### P5.1 — Concurrency lane, synchronized actors и evidence validator

**Intent:** Построить воспроизводимый tier-S lane, который синхронно запускает до 201 акторов и
раздельно сохраняет product, PostgreSQL-lock и PgBouncer-queue evidence.
**Why:** k6 latency не различает ожидание FPM, свободного PgBouncer backend и DB-lock; NOWAIT вообще
может завершиться до poll. Без barrier, raw snapshots и typed plane artificial storm нельзя
интерпретировать как продуктовый contention verdict.
**Scope Included:** run/cell/attempt manifest; barrier/readiness; axes `plane`, `surface`, `shape`,
`N`; `N=1/8/32/200/201`; direct-SQL control runner; bounded polling `pg_locks`/`pg_stat_activity`/
`pg_blocking_pids`; deadlock/log deltas; PgBouncer `SHOW POOLS`/`SHOW STATS`; k6/Prometheus links;
schema validator; positive/truncated/cross-run/plane-confusion fixtures; dry-run/run/verify CLI.
**Scope Excluded:** product scenarios/fixtures; live matrix; package code; pool tuning; production
connections; утверждение, что SQL-control равен HTTP path; исправление P8.5 collector.

**Implementation Rules:** Plane enum is closed: `product-realistic`, `product-worst-case`,
`primitive-control`, `dirty-cardinality-probe`. Every observation binds run/cell/attempt, PID/client,
monotonic timestamp and source snapshot. PostgreSQL poll ≤100 ms while a cell is active; before/after
deadlock counters and log cursor are mandatory. `pg_blocking_pids()` owns blocker relation; a manual
`pg_locks` self-join is diagnostic only. PgBouncer snapshots preserve `cl_waiting`, `sv_active`,
`maxwait`, `avg_wait_time` and configured limits. Missing sample is `evidence-invalid`, never zero.
SQL controls use dedicated disposable credentials/database and rollback; no DDL/data outside exact
fixture scope. Artifacts publish atomically only after verify.
**Code Guidance:** Keep DB-lock wait, PgBouncer wait, HTTP duration and barrier skew as separate
fields. For NOWAIT, derive refusal from product status/metric and exact attempt count, not sampling.
Use transaction-scoped advisory locks only; session locks are forbidden with transaction pooling.
Redact DSN/password/query parameters and cap log excerpts. `N=201` is a boundary control, not a
supported workload claim.
**Validation:** `sh -n` on three scripts; `python3 -m unittest load/gates/test_p5_concurrency.py`;
validator accepts complete fixture and rejects missing pre/post counters, duplicate cell id,
cross-run sample, untyped plane, impossible blocker PID, non-monotonic time and truncated JSONL;
`TIER=S ./load/scripts/p5-concurrency.sh dry-run` emits exact axes and performs no Docker/DB write;
compose config and PgBouncer admin query syntax are checked against the current stand.
**Deliverables:** synchronized orchestration lane, raw PG/PgBouncer collectors, typed evidence schema,
negative fixtures and documented dry-run/verify workflow.
