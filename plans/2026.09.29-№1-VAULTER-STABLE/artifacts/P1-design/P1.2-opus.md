## 01-review.md — 4. Новые находки (не было ни в аудите, ни у Codex) / N04 (S2). Документ без `parent_id` становится вторым корнем и выпадает из листинга

- `01:1d2c276b`

`DocumentNodeController::store` передаёт `parent = null`, `CreateDocumentNodeAction` пишет `parent_id = NULL`
(строка 62), тогда как Drive кладёт такие узлы в корневую папку. `GET storages/{storage}/nodes` листает детей
корня — документ не виден. Уникальность имён `(parent_id, lower(name)) WHERE ...` не защищает `parent_id IS NULL`
(NULL различны), поэтому одинаковые имена «корней» допустимы.


## 01-review.md — 4. Новые находки (не было ни в аудите, ни у Codex) / N05 (S1). Инварианты дерева не проверяются; гонка циклов при move

- `01:c2d82bd7`

Ни одно Action не проверяет, что назначение — **активная папка того же drive**: можно переместить/скопировать
узел, создать папку или загрузить файл «внутрь» файла, документа или удалённой в корзину папки (PHP API и HTTP с
чужим `parent_id` в пределах storage). `MoveNodeAction::assertNoCycle` выполняется **до** транзакции и без
блокировок (строки 44, 54): параллельные `A→B` и `B→A` оба проходят проверку и образуют цикл.


## 02-decisions.md — D13 — Инварианты дерева и имён · T0

- `02:81aee054`

**Решение (проверяются в Actions, под блокировкой):**

- `02:2b4f5dee`

- родитель/назначение — **активная (не в корзине) папка того же drive**; корень нельзя
  переместить, переименовать, удалить в корзину или скопировать как узел;

- `02:d5604734`

- `parent_id IS NULL` допустим **только** у корня drive (уникальный частичный индекс
  `(drive_id) WHERE parent_id IS NULL` на PG/SQLite, generated column на MySQL — как у существующего
  sibling-unique) — закрывает N04;

- `02:89a6935c`

- move берёт `VaulterDatabase::lockTree($driveId)` (advisory lock на PG, `SELECT ... FOR UPDATE`
  строки drive на MySQL/SQLite) и проверяет цикл внутри транзакции (N05);

- `02:3b185534`

- имена: NFC-нормализация (`Normalizer`, при отсутствии `intl` — doctor warning), запрет
  разделителей и управляющих символов, длина ≤ 255 байт UTF-8, сравнение уникальности
  по `lower(name)` как сейчас;

## 08-data-model-and-migration.md — 5. Порядок блокировок (D21)

- `08:bd2319dc`

```
1. VaulterDatabase::lockTree(drive)            — только операции, меняющие структуру (move, restore, purge поддерева, delete drive)
2. SELECT … FOR UPDATE узлов по возрастанию id  — узел операции и назначение
3. SELECT … FOR UPDATE агрегата                 — v_files / v_documents (ревизии, голова)
4. UPDATE v_drives … used_bytes (условный)      — квота
5. VaulterDatabase::advisoryLock("cas:{scope_key}:{sha256}") — commit blob
```

- `08:e141b7f4`

Операция не берёт блокировку уровня N после блокировки уровня M > N. Тест на PG: два параллельных сценария с
пересекающимися ресурсами завершаются без deadlock или с одним ретраем.
