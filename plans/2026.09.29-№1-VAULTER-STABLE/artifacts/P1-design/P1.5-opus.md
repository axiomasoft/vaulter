## 01-review.md — 4. Новые находки (не было ни в аудите, ни у Codex) / N02 (S1). Колонки ключей хоста типизированы стратегией ID Vaulter

- `01:5368342b`

`v_storages.owner_id`, `v_node_grants.subject_id`, все `tenant_id` создаются `$ids->reference()`, а все
actor-колонки (`created_by`, `owner_id` узла, `trashed_by`, `granted_by`, `actor_id`) — `$ids->actor()`
(`packages/core/src/Schema/UlidIds.php:31-39`, `AutoIncrementIds.php:22-30`, `PanelTablesBuilder.php:164,218`).
Это ключи **хоста**, а не Vaulter. По умолчанию (`ids.default = ulid`) они `char(26)`: хост с UUID-ключами
пользователей/проектов/ролей (36 символов) получает ошибку вставки на PostgreSQL; при `bigint` — хост с
ULID/UUID-пользователями не может ни выдать grant, ни записать аудит.


## 02-decisions.md — D20 — CAS: беспотерьная область дедупликации · T0

- `02:8faad32b`

**Решение.**

- `02:6fd49a70`

- `Vaulter\ValueObjects\Cas\BlobScope`: `global()`, `tenant(string)`, `drive(string)`;
  `key()` → `global` | `tenant:{id}` | `drive:{id}` (id — строка без преобразований).

- `02:a727345d`

- `BlobStore::commit(mixed $stream, BlobScope $scope, ?string $disk = null): Blob`.

- `02:c6d163c2`

- `v_blobs.scope_key varchar(191) NOT NULL`, `UNIQUE(scope_key, sha256)` заменяет пару
  «unique по колонкам scope + отдельный unique storage_key» (NULL больше не участвует).

- `02:579e2a66`

- Физический ключ объекта: `{scope-segment}/{sha[0:2]}/{sha}` с URL-safe сегментом; reconciler
  распознаёт старые (`s{int}`, `t{int}`, `snull`, `tnull`) и новые ключи, включая UUID с дефисами.

- `02:6464dc87`

- `vaulter:blobs:repair-scopes --dry-run|--execute`: инвентаризация объектов в `snull/tnull`,
  вывод правильной области из связей ревизия→файл→узел→drive, проверка sha256, копирование в
  новые области, атомарное переключение ссылок, удержание старого объекта до GC. Неизвестный
  тенант не угадывается (отчёт, ручное решение).

- `02:8b5cbc5d` — _P1.5 — disk из строки blob при чтении; doctor-проверка изоляции дисков — P7.1_

- `blob.disk` — авторитетен для чтения; дедупликация между дисками при `scope=global|tenant`
  допустима (ADR-0012 остаётся), изоляция дисков профилей требует `dedup.scope = drive` —
  doctor это проверяет.

## 09-integrity-and-security.md — 7. CAS-сага и сборка мусора

- `09:30049801`

Порядок commit (без изменений по сути, фиксируется в документации): stage → sha256 → advisory lock
`(scope_key, sha256)` → найти blob (resurrect, если tombstoned) или promote объекта (`ifNoneMatch`) и вставить
строку → edge → SQL commit. Откат SQL после promote оставляет объект-сироту; `vaulter:blobs:reconcile`
удаляет сирот старше `orphan_grace_hours`, перепроверяя отсутствие строки под той же блокировкой. GC:
mark/sweep как сейчас, но все блокировки и транзакции — через `VaulterDatabase` (N01).

- `09:9f12a2c4`

Дополнительно:

- `09:da882554`

- ключ объекта строится из `BlobScope::key()`; reconciler распознаёт старые форматы (`s\d+`, `t\d+`, `snull`,
  `tnull`) и новые (`g`, `t-{urlsafe}`, `d-{urlsafe}`), включая UUID с дефисами;
