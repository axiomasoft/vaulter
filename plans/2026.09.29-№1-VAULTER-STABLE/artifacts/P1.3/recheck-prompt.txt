## Findings

### 1. Major — batch ancestor walk drops grants that `effectiveGrants()` still applies

**Location:** `packages/core/src/Repositories/Drive/NodeReadRepository.php:179-181` (`ancestorChains`), compared with `packages/core/src/Access/AccessResolver.php:658-679` (`ancestorChain`).

**Trigger:** A node has more than 64 ancestors and `inherit_grants` stays true along that path. A subtree deny (or the only allow) sits on an ancestor above that cut. The usual leak is a host role allow, such as Reader, plus that far deny.

**Consequence:** `evaluateMany()` never loads that ancestor, so the role allow is not vetoed. Children, search, trash, shared, folder `show` children, and the Filament table can return the node’s name, size, and MIME. `AccessResolver::can(View)` still denies it, because `ancestors()` keeps walking. The mirror case hides a node whose only allow is above the cut, so a direct open succeeds and the listing omits it.

**Evidence:** The new CTE seeds the parent at depth 0 and stops with `c.depth < DEFAULT_MAX_DEPTH - 1` (`64 - 1`). That keeps ancestors 1 through 64 and drops the 65th. `effectiveGrants()` uses staudenmeir `ancestors()`, which seeds the parent at depth `-1` and then subtracts. `withMaxDepth(64)` compiles `"depth" < 64`. Every negative depth satisfies that predicate, so the walk continues to the root (or the database recursion limit). `EvaluateManyEquivalenceTest` only builds trees of depth ≤ 5, so this split stays green.

**Repair:** Make `ancestorChains()` cover the same ancestors as `ancestorChain()`. The positive `c.depth < 63` bound is tighter than the live `ancestors()` walk. Add one equivalence tree deeper than 64 whose deciding grant sits on the root.

### 2. Major — official shared client still pages with `page` / `total`

**Location:** `packages/vue/src/composables/useSharedNodes.ts:47-89` and `packages/vue/src/client.ts:152-158`, against `packages/drive/src/Http/Controllers/NodeController.php:76-86` and `364-376`.

**Trigger:** `GET /shared` now returns `meta.next_cursor`, `per_page`, and `scanned`, and omits `current_page`, `last_page`, and `total`. `useSharedNodes` still calls `client.nodes.shared({ page })` and sets `hasMore` from `current_page < last_page`.

**Consequence:** The first page still loads, because the API ignores `page` and returns the first cursor page. `hasMore` stays false, and `loadMore()` returns without a request. Shared nodes past the first page never appear in `@vaulter/vue`. `useNodes` already follows `next_cursor`; only the shared composable is still on the old envelope.

**Repair:** Point `shared()` and `useSharedNodes` at the same cursor envelope as the other listings (`CursorMeta`, send `cursor`, stop when `next_cursor` is null). That client lives outside the P1.3 PHP file list; the in-repo client is still wrong after this API change.

/**
 * Read-side queries over the v_nodes adjacency tree (§2.2 / H.4). Tree reads use
 * the staudenmeir recursive relationships (descendants/ancestors), always bounded
 * by treeOf(storage) and — for bulk descents — withMaxDepth, never the BANNED
 * whereHas('descendants') / withCount('descendants') which break on MariaDB and
 * degrade on Postgres (H.4 arch-ban).
 *
 * queryForUser()/constrainToAccessible() narrow grant-authoritative drivers to
 * candidate IDs. Candidates require exact AccessResolver evaluation before display;
 * the REST listings and Filament table apply that after fetching each page.
 */
final class NodeReadRepository
{
    /**
     * The maximum recursion depth for bulk subtree descents — file managers live
     * at depth ≤ ~20 (§1.5), so this caps a pathological tree without an explicit
     * caller bound.
     */
    public const int DEFAULT_MAX_DEPTH = 64;

    /**
     * Keep small sets bound, with room for storage, parent and cursor bindings even
     * on SQLite builds limited to 999 variables. Larger sets use escaped SQL literals
     * and add no bindings, regardless of the number of grant-reachable nodes.
     */
    private const int WHERE_IN_BIND_LIMIT = 900;

    public function __construct(
        private readonly AccessResolver $access,
        private readonly HostRoleDriverManager $drivers,
        private readonly GrantReadRepository $grants,
        private readonly MetricsRecorder $metrics,
    ) {}

    public function find(int|string $id): ?Node
    {
        return $this->query()->find($id);
    }

    /**
     * Every live (non-trashed, non-deleted) node in a storage's tree.
     *
     * @return Builder<Node>
     */
    public function forStorage(Storage $storage): Builder
    {
        return $this->query()
            ->treeOf($storage->id)
            ->whereNull('trashed_at');
    }

    /**
     * Direct children of a folder (or the storage root when $parent is null),
     * ordered by the manual sibling position then name.
     *
     * @return Builder<Node>
     */
    public function children(Storage $storage, ?Node $parent): Builder
    {
        return $this->metrics->timing(
            name: 'vaulter_tree_query_duration_seconds',
            operation: fn (): Builder => $this->query()
                ->treeOf($storage->id)
                ->whereNull('trashed_at')
                ->where('parent_id', $parent?->id)
                ->orderBy('position')
                ->orderBy('name')
                ->orderBy('id'),
            labels: [
                'query_kind' => 'children',
                'tier' => LoadTier::label(),
            ],
        );
    }

    /**
     * Whether the node is its drive's root — the one node without a parent, which
     * tree operations never take as an operand.

    public function isRoot(Node $node): bool
    {
        $rootId = $node->storage->root_node_id;

        return $rootId !== null && Identity::stringify($node->getKey()) === Identity::stringify($rootId);
    }

    /**
     * @param  list<int|string>               $parentIds
     * @return array<string, list<\stdClass>>
     */
    public function ancestorChains(array $parentIds): array
    {
        if ($parentIds === []) {
            return [];
        }
        /** @var \Staudenmeir\LaravelAdjacencyList\Eloquent\Builder<Node> $query */
        $query = $this->query();
        $connection = app(VaulterDatabase::class)->connection();
        $grammar = $query->getExpressionGrammar();
        $table = $connection->getQueryGrammar()->wrapTable($query->getModel()->getTable());
        $separator = $query->getModel()->getPathSeparator();
        $initialPath = $grammar->compileInitialPath('id', '__acl_path');
        $seed = $this->whereKeyInBounded($query, $parentIds)
            ->select(['id', 'parent_id', 'storage_id', 'inherit_grants'])->selectRaw('id as origin, 0 as depth');
        // Match ancestors()'s ascend semantics, including its database-specific
        // cycle guard. withMaxDepth(+64) does not limit negative ancestor depths.
        $path = $grammar->compileRecursivePath('n.id', 'c.__acl_path');
        $cycle = $grammar->compileCycleDetection('n.id', 'c.__acl_path');
        $sql = 'WITH RECURSIVE chain AS (SELECT seed.*, '.$initialPath.' FROM ('.$seed->toSql().') seed
            UNION ALL SELECT n.id, n.parent_id, n.storage_id, n.inherit_grants, c.origin, c.depth + 1, '.$path.'
            FROM '.$table.' n JOIN chain c ON n.id = c.parent_id AND n.storage_id = c.storage_id
            WHERE c.inherit_grants = ? AND NOT ('.$cycle.') AND n.deleted_at IS NULL)
            SELECT * FROM chain ORDER BY origin, depth';
        $rows = $connection->select($sql, [
            ...$seed->getBindings(),
            ...$grammar->getRecursivePathBindings($separator),
            true,
            ...$grammar->getCycleDetectionBindings($separator),
        ]);
        $chains = [];
        foreach ($rows as $row) {
            if (!$row instanceof \stdClass || (!is_string($row->origin) && !is_int($row->origin))) {
                throw new \LogicException('Invalid ancestor chain row.');
            }
            $chains[Identity::stringify($row->origin)][] = $row;
        }

        return $chains;
    }

    public function ancestors(Node $node): Collection

    /**
     * Name search within a storage tree (live nodes only). Matches a case-folded
     * substring of the node name — the §2.2 search index backs this.
     *
     * The caller-supplied term is untrusted (F-P1.8-03): `LIKE` metacharacters
     * (`%`, `_`, `\`) are escaped BEFORE the substring wildcards are wrapped
     * around it, with an explicit `ESCAPE '\'` clause — a raw `%`/`_` in the
     * term is matched LITERALLY, never as a wildcard, on both SQLite and
     * PostgreSQL. Case-folding happens first so escaping never touches
     * multibyte case-mapping. `orderBy('id')` is a stable tie-breaker
     * (F-P4.2-05, VLT-REMED P4.3): `name` is unique only per-parent (ADR-0005)
     * and this method searches across the WHOLE tree, so cursorPaginate()'s
     * keyset would otherwise skip/duplicate rows across a page boundary that
     * lands on two nodes sharing a name in different folders.
     *
     * @return Builder<Node>
     */
    public function search(Storage $storage, string $term): Builder
    {
        return $this->metrics->timing(
            name: 'vaulter_tree_query_duration_seconds',
            operation: function () use ($storage, $term): Builder {
                $escaped = addcslashes(mb_strtolower($term), '%_\\');

                return $this->query()
                    ->treeOf($storage->id)
                    ->whereNull('trashed_at')
                    ->whereRaw("lower(name) like ? escape '\\'", ['%'.$escaped.'%'])
                    ->orderBy('name')
                    ->orderBy('id');
            },
            labels: [
                'query_kind' => 'search',
                'tier' => LoadTier::label(),
            ],
        );
    }

    /**
     * The trash view: trashed (but not yet permanently deleted) nodes in a
     * storage, newest first. `orderByDesc('id')` is a stable tie-breaker
     * (F-P4.2-05, VLT-REMED P4.3): several nodes trashed by the same
     * operation/request share an identical trashed_at timestamp, so
     * cursorPaginate()'s keyset would otherwise skip/duplicate rows on that
     * page boundary.
     *
     * @return Builder<Node>
     */
    public function trashed(Storage $storage): Builder
    {
        return $this->query()
            ->treeOf($storage->id)
            ->whereNotNull('trashed_at')
            ->orderByDesc('trashed_at')
            ->orderByDesc('id');
    }

    /**
     * The trashed nodes whose trashed_at is at or before $threshold — the
     * purge-trash candidates past their retention window (§2.10). Only ROOTS of a
     * trash operation are returned: a node whose own parent is itself trashed is
     * skipped, because force-deleting an ancestor's subtree already reclaims it (so
     * a child is never purged twice). Returns a Builder so the command chunks it.
     *
     * @return Builder<Node>
     */
    public function trashedBefore(Carbon $threshold): Builder
    {
        $model = Config::nodeModel();
        $table = (new $model)->getTable();

        return $this->query()
            ->whereNotNull('trashed_at')
            ->where('trashed_at', '<=', $threshold)
            // Skip descendants whose own parent is also trashed — the trashed
            // ancestor is the purge root and its subtree force-delete covers them.
            ->whereNotExists(static function (QueryBuilder $sub) use ($table): void {
                $sub->selectRaw('1')
                    ->from($table.' as parent_node')
                    ->whereColumn('parent_node.id', $table.'.parent_id')
                    ->whereNotNull('parent_node.trashed_at');
            })
            ->orderBy('trashed_at');
    }

    /**
     * Whether a live sibling already owns $name under $parentId in this storage
     * (case-insensitive) — the §2.2 sibling-unique predicate the Actions check
     * before create/move/rename. $ignoreId excludes the node being renamed in
     * place. Uses a direct EXISTS, NOT a recursive descendant aggregate (H.4).
     */
    public function siblingNameExists(
        Storage $storage,
        int|string|null $parentId,
        string $name,
        int|string|null $ignoreId = null,
    ): bool {
        $query = $this->query()
            ->treeOf($storage->id)
            ->where('parent_id', $parentId)
            ->whereNull('trashed_at')
            ->whereRaw('lower(name) = ?', [mb_strtolower($name)]);

        if ($ignoreId !== null) {
            $query->whereKeyNot($ignoreId);
        }

        return $query->exists();
    }

    /**
     * The STANDALONE public seam (master plan P1 #3): the live (non-trashed) nodes an
     * actor may reach, as a Builder for pagination / Filament. It is the named entry
     * for "give me this actor's nodes" = the live-nodes base + constrainToAccessible.
     * A caller that needs its own trashed-state control (the children cursor below, or
     * the Filament table whose Trashed filter flips trashed_at) composes
     * {@see constrainToAccessible()} on its own base instead.
     *
     * When grant-filtering applies (see {@see grantFilteringApplies()}) the base is
     * constrained to the actor's CANDIDATE accessible node ids; otherwise the base is
     * returned UNCHANGED (open listing — the host's roles govern).
     *
     * The candidate set is the grant ANCHORS for the actor's subject-set UNION the
     * descendants of every SUBTREE-scoped anchor (an item-scoped anchor contributes
     * only its own node). It is a deliberate SUPERSET: it does NOT apply the deny-veto
     * or the inherit_grants cut-off in SQL, so a node a nearer deny revokes can still
     * be in the set. The candidate-set listing semantic is documented on
     * {@see constrainToAccessible()}; per-ACTION authorization stays EXACT via the
     * {@see AccessResolver} on every mutation/show.
     *
     * @return Builder<Node>
     */
    public function queryForUser(Authorizable $actor): Builder
    {
        $base = $this->query()->whereNull('trashed_at');

        return $this->constrainToAccessible($base, $actor);
    }

    /**
     * Constrain an ALREADY-BUILT node query to the actor's grant-reachable candidate
     * set (P1 #3), WITHOUT imposing the live/trashed filter — so a caller that owns
     * its own trashed-state handling (the children cursor; the Filament table, whose
     * Trashed filter flips trashed_at) composes the access narrowing on top of its own
     * query. A no-op when grant-filtering does not apply (open drivers); forces an
     * empty result when it applies and the actor reaches no candidate.
     *
     * This SQL prefilter deliberately admits denied candidates. Apply exact batch
     * AccessResolver evaluation before display.
     *
     * Generic over the concrete model so a Node-typed base (the core listing paths) and
     * a Filament resource's `Builder<Model>` both compose without a variance clash — the
     * narrowing is key-based, never model-specific.
     *
     * @template TModel of Model
     *
     * @param  Builder<TModel> $query
     * @return Builder<TModel>
     */
    public function constrainToAccessible(Builder $query, Authorizable $actor): Builder
    {
        if (!$this->grantFilteringApplies()) {
            return $query;
        }

        $candidateIds = $this->candidateNodeIds($actor);

        if ($candidateIds === []) {
            return $query->whereRaw('1 = 0');
        }

        return $this->whereKeyInBounded($query, $candidateIds);
    }

    /**
     * Narrow an already-loaded set of nodes to the ones the actor may actually View,
     * delegating to the AccessResolver (the EXACT deny-veto / inherit-cutoff gate,
     * H.2). This is the correctness companion to the SUPERSET candidate query: a
     * caller lists candidates cheaply, then runs the page through here.
     *
     * @param  iterable<Node> $nodes
     * @return list<Node>
     */
    public function filterViewable(Authorizable $actor, iterable $nodes): array
    {
        return $this->access->filterSharedWith($actor, $nodes);
    }

    /**
     * The "shared with me" top-level view (§2.6 / H.2): the nodes the actor holds a
     * live allow-grant on, RE-RESOLVED through the full algorithm so a nearer deny
     * that revokes a row excludes it (the EXACT gate, over a bounded candidate set —
     * unlike the candidate-SQL listings). Cross-storage by nature: the subject index
     * is not storage-bound.
     *
     * Eager-loads the storage relation so the per-candidate re-resolution does NOT
     * fire one storage query per node: the {@see AccessResolver} prefers an
     * already-loaded `storage` relation over a per-node lookup, so this `with('storage')`
     * spares the gate's per-node storage query (and the NodeResource reads the same
     * relation). Without it the eager-load would be dead weight.
     *
     * @return Collection<int, Node>
     */
    public function sharedWith(Authorizable $actor): Collection
    {
        $candidateIds = $this->access->sharedNodeIds($actor);

        if ($candidateIds === []) {
            /** @var Collection<int, Node> $empty */
            $empty = new Collection;

            return $empty;
        }

        $base = $this->query()
            ->whereNull('trashed_at')
            ->with('storage');

        /** @var Collection<int, Node> $candidates */
        $candidates = $this->whereKeyInBounded($base, $candidateIds)->get();

        /** @var Collection<int, Node> $visible */
        $visible = new Collection($this->filterViewable($actor, $candidates));

        return $visible;
    }

    /**
     * Whether the access-aware grant narrowing applies to a listing. It does ONLY
     * when the 'grants' feature is on AND the active permission driver is
     * {@see GrantAuthoritativeDriver} with {@see GrantAuthoritativeDriver::isGrantAuthoritative()}
     * true — i.e. treats v_node_grants as the SOLE authority for read-visibility (the
     * standalone {@see DatabasePermissionResolver}).
     *
     * The gate keys on the CAPABILITY, NOT on the driver KEY string: a host that
     * SUBCLASSES DatabasePermissionResolver under the same 'database' key to add a
     * role/team lane or a super-admin override() confers access on nodes with NO grant
     * anchor — so it overrides isGrantAuthoritative() to return false (the interface is
     * inherited and cannot be un-declared), and the listing stays OPEN. For the
     * gate/spatie/azgard/null drivers the host's roles govern and v_node_grants is not
     * the source of truth, so a grant-id constraint would WRONGLY hide nodes the host
     * role lane allows; they don't implement the capability either ⇒ listing stays OPEN
     * (the safe default that never wrongly hides).
     *
     * Public so a caller listing a page through a NON-queryForUser path (the children
     * cursor, the Filament table) can decide whether to narrow the query to the
     * candidate set up front.
     */
    public function grantFilteringApplies(): bool
    {
        $driver = $this->drivers->driver();

        return Config::featureEnabled('grants')
            && $driver instanceof GrantAuthoritativeDriver
            && $driver->isGrantAuthoritative();
    }

    /**
     * The actor's candidate accessible node ids: the grant anchors UNION the
     * descendants of every SUBTREE-scoped anchor. Item-scoped anchors contribute
     * only their own node. A SUPERSET — see {@see queryForUser()}.
     *
     * PUBLIC (F-P1.10-01): {@see constrainToAccessible()} narrows a query by the
     * NODE model's own primary key, which only fits a Node-shaped listing. The
     * Filament panel's non-Node resources (grant/share/activity/storage) key off a
     * DIFFERENT column (node_id / target_id / root_node_id), so they call this
     * directly to build their own `whereIn` — same candidate set, same
     * grantFilteringApplies() gate, no duplicated grant-resolution logic.
     *
     * @return list<int|string>
     */
    public function candidateNodeIds(Authorizable $actor): array
    {
        $subjects = $this->drivers->driver()->subjectsFor($actor);
        $anchors = $this->grants->allowAnchorsFor(subjects: $subjects, now: Carbon::now());

        if ($anchors->isEmpty()) {
            return [];
        }

        /** @var array<string, int|string> $ids */
        $ids = [];
        /** @var array<string, int|string> $subtreeAnchorIds */
        $subtreeAnchorIds = [];

        foreach ($anchors as $anchor) {
            $ids[Identity::stringify($anchor->node_id)] = $anchor->node_id;

            if ($anchor->scope === GrantScope::Subtree) {
                // Dedup by stringified key: the same subtree anchor can appear under
                // several subjects, but it seeds the descent exactly once.
                $subtreeAnchorIds[Identity::stringify($anchor->node_id)] = $anchor->node_id;
            }
        }

        foreach ($this->descendantIdsOf(array_values($subtreeAnchorIds)) as $descendantId) {
            $ids[Identity::stringify($descendantId)] = $descendantId;
        }

        return array_values($ids);
    }

    /**
     * The descendant node ids BELOW the given subtree anchors, via the staudenmeir
     * recursive CTE, bounded by withMaxDepth — H.4, never whereHas('descendants') /
     * withCount('descendants'). KEY-ONLY: the only full models hydrated are the anchors
     * themselves (bounded by the actor's grant count, NOT the subtree size); each
     * anchor's descendant subtree is pulled with ->pluck(key) — node KEYS, never
     * hydrated Node models — so a wide subtree never inflates memory.
     *
     * One recursive descent per anchor: the Node model REPURPOSES the staudenmeir
     * treeOf scope as a storage filter (scopeTreeOf(storageId)), so the multi-root
     * single-seed descent is not available here; the per-anchor loop stays, but the
     * anchor set is already deduped by the caller and only keys are read.
     *
     * @param  list<int|string> $anchorIds
     * @return list<int|string>
     */
    private function descendantIdsOf(array $anchorIds): array
    {
        if ($anchorIds === []) {
            return [];
        }

        $model = Config::nodeModel();
        $keyName = (new $model)->getKeyName();

        /** @var Collection<int, Node> $anchors */
        $anchors = $this->whereKeyInBounded($model::query(), $anchorIds)->get();

        /** @var list<int|string> $ids */
        $ids = [];

        foreach ($anchors as $anchor) {
            $this->metrics->histogram(
                name: 'vaulter_tree_cte_anchors',
                value: 1,
                labels: ['tier' => LoadTier::label()],
            );

            /** @var list<int|string> $descendantKeys */
            $descendantKeys = $model::withMaxDepth(
                self::DEFAULT_MAX_DEPTH,
                static fn (): array => $anchor->descendants()->pluck($keyName)->all(),
            );

            foreach ($descendantKeys as $descendantKey) {
                $ids[] = $descendantKey;
            }
        }

        return $ids;
    }

    /**
     * Bound the ID list's contribution to the statement-wide parameter count.
     * OR-ing whereIn chunks still binds every ID in one statement. Above the small
     * set budget, Laravel's connection escape() safely quotes each value through
     * the read PDO driver. No integer casts: ULIDs and bigint strings retain their
     * exact values. The predicate remains one AND-ed IN condition, so existing
     * storage/scopes, ordering and SQL cursor pagination keep their semantics.
     *
     * @template TModel of Model
     *
     * @param  Builder<TModel>  $query
     * @param  list<int|string> $ids
     * @return Builder<TModel>
     */
    private function whereKeyInBounded(Builder $query, array $ids): Builder
    {
        $keyName = $query->getModel()->getKeyName();

        if (count($ids) <= self::WHERE_IN_BIND_LIMIT) {
            return $query->whereIn($keyName, $ids);
        }

        return $query->whereRaw(new EscapedKeySet($keyName, $ids));
    }

    /**
     * @return Builder<Node>
     */
    private function query(): Builder
    {
        $model = Config::nodeModel();

        return $model::query();
    }
}

/**
 * The Vaulter-OWNED, NON-swappable effective-permission engine (master plan H.2).
 * It runs the canonical algorithm over v_node_grants combined with the pluggable
 * {@see HostRoleDriver}, and is the single authority every Policy / DriveContext /
 * Resource asks. It is deliberately NOT a contract and NOT swappable — only the
 * host-role lane (the driver) is.
 *
 * THE ALGORITHM (H.2 — implemented EXACTLY):
 *   1. Host override (super-admin) — absolute, both directions.
 *   2. Walk ancestors nearest-first, BOUNDED to the workspace/storage root (never
 *      cross storage_id), collecting direct + scope=subtree grants for the
 *      subject-set (from HostRoleDriver::subjectsFor); STOP at the first ancestor
 *      with inherit_grants=false.
 *   3. aclAllow = max(allow levels/bits); deniedBits = OR of deny bits (a deny
 *      denies that level and everything it implies); a NEARER explicit allow
 *      pierces a FARTHER inherited deny (ADR-0007). An inherit_grants=false node is
 *      a wall for grants ABOVE it (they are cut off), NOT an absolute barrier for a
 *      deny sitting ON it: a nearer explicit allow BELOW the wall still pierces that
 *      deny, exactly as it would any other inherited deny — ADR-0007 gives the wall
 *      no exception. (An absolute, un-pierceable wall-deny would be a separate
 *      product decision, not the current behaviour.)
 *   4. granted = max(aclAllow, roleAllow) where roleAllow comes from
 *      HostRoleDriver::resolve.
 *   5. FINAL VETO pass: if deniedBits covers the requested ability → DENY
 *      regardless of role grant.
 *
 * Expiry is read-time (filtered in the grant query). The ancestor walk uses the
 * staudenmeir ancestor relation bounded to the storage root — no whereHas /
 * withCount('descendants') (H.4 arch-ban).
 */
final class AccessResolver
{
    public function __construct(
        private readonly HostRoleDriverManager $drivers,
        private readonly GrantReadRepository $grants,
        private readonly StorageReadRepository $storages,
    ) {}

    /**
     * May the actor perform the ability on the node? The public authorization
     * entry point Policies and the DriveContext call.
     */
    public function can(Authorizable $actor, Ability $ability, Node $node): bool
    {
        return $this->effectiveGrants($actor, $node)->allows($ability);
    }

    /**
     * Run the full effective-permission algorithm for (actor, node) and return the
     * folded GrantSet (allow-mask, deny-mask, level + any super override). This is
     * the one place the algorithm lives; can()/abilitiesFor() read its result.
     */
    public function effectiveGrants(Authorizable $actor, Node $node): GrantSet
    {
        $driver = $this->drivers->driver();
        $storage = $this->storageOf($node);
        $scope = $this->scopeFor($storage, $node);

        // ── H.2 step 1: host override (super-admin) — absolute, both directions.
        $override = $driver->override($actor, $scope);

        if ($override === Effect::Allow) {
            return GrantSet::superAllowed();
        }

        if ($override === Effect::Deny) {
            return GrantSet::superDenied();
        }

        $subjects = $driver->subjectsFor($actor);

        // ── H.2 steps 2 + 3: the ACL allow-mask + deny-mask from the bounded walk.
        [$aclAllowBits, $deniedBits, $aclLevel] = $this->resolveAcl(node: $node, subjects: $subjects);

        // ── H.2 step 4: granted = max(aclAllow, roleAllow). The role lane can RAISE
        // the allow-mask but it is folded BEFORE the deny veto, so it cannot
        // resurrect a denied bit.
        [$roleAllowBits, $roleLevel] = $this->resolveRole(
            driver: $driver,
            actor: $actor,
            scope: $scope,
            subjects: $subjects,
        );

        $allowedBits = $aclAllowBits | $roleAllowBits;
        $level = $this->maxLevel($aclLevel, $roleLevel);

        // ── H.2 step 5: the FINAL veto is baked into GrantSet::allows() — an ability
        // whose required bits intersect deniedBits is denied regardless of allow.
        return new GrantSet(
            allowedBits: $allowedBits,
            deniedBits: $deniedBits,
            level: $level,
        );
    }

    /**
     * @param  iterable<Node>          $nodes
     * @return array<string, GrantSet>
     */
    public function evaluateMany(Authorizable $actor, iterable $nodes): array
    {
        $nodes = new Collection(is_array($nodes) ? $nodes : iterator_to_array($nodes));
        if ($nodes->isEmpty()) {
            return [];
        }
        $nodes->loadMissing('storage');
        $driver = $this->drivers->driver();
        $groups = [];
        foreach ($nodes as $node) {
            $key = json_encode([Identity::stringify($node->storage_id), $node->owner_id === null ? null : Identity::stringify($node->owner_id)], JSON_THROW_ON_ERROR);
            $groups[$key][] = $node;
        }
        $sets = [];
        $pending = [];
        $scopes = [];
        foreach ($groups as $key => $group) {
            $scope = $this->scopeFor($this->storageOf($group[0]), $group[0]);
            $override = $driver->override($actor, $scope);
            if ($override !== null) {
                foreach ($group as $node) {
                    $sets[Identity::stringify($node->id)] = $override === Effect::Allow ? GrantSet::superAllowed() : GrantSet::superDenied();
                }

                continue;
            }
            $scopes[$key] = $scope;
            foreach ($group as $node) {
                $pending[] = [$node, $key];
            }
        }
        if ($pending === []) {
            return $sets;
        }
        $subjects = $driver->subjectsFor($actor);
        $roles = [];
        foreach ($scopes as $key => $scope) {
            $roles[$key] = $this->resolveRole($driver, $actor, $scope, $subjects);
        }
        $parentIds = [];
        $ids = [];
        foreach ($pending as [$node]) {
            $ids[] = $node->id;
            if ($node->inherit_grants && $node->parent_id !== null) {
                $parentIds[] = $node->parent_id;
            }
        }
        $chains = $subjects === [] ? [] : app(NodeReadRepository::class)->ancestorChains(array_values(array_unique($parentIds)));
        foreach ($chains as $chain) {
            foreach ($chain as $row) {
                if (!is_int($row->id) && !is_string($row->id)) {
                    throw new \LogicException('Invalid ancestor identity.');
                }
                $ids[] = $row->id;
            }
        }
        $byNode = [];
        if ($subjects !== []) {
            foreach ($this->grants->forSubjectsOnNodes(array_values(array_unique($ids)), $subjects, Carbon::now()) as $grant) {
                $byNode[Identity::stringify($grant->node_id)][] = $grant;
            }
        }
        $folder = new AclFolder;
        $inherited = [];
        foreach ($chains as $origin => $chain) {
            $depths = [];
            foreach ($chain as $row) {
                $depths[] = $this->grantMask($byNode[Identity::stringify($row->id)] ?? [], true);
            }
            $inherited[$origin] = $folder->foldChain($depths);
        }
        foreach ($pending as [$node, $key]) {
            $parentKey = Identity::stringify($node->parent_id);
            $chain = $chains[$parentKey] ?? [];
            $sameStorage = $chain !== [] && Identity::stringify($chain[0]->storage_id) === Identity::stringify($node->storage_id);
            $parent = $node->inherit_grants && $sameStorage ? $inherited[$parentKey] : AclMask::none();
            $own = $this->grantMask($byNode[Identity::stringify($node->id)] ?? [], false);
            $mask = $folder->applyOwn($parent, $own['allow'], $own['deny'], $own['level']);
            [$roleAllow, $roleLevel] = $roles[$key];
            $sets[Identity::stringify($node->id)] = new GrantSet(allowedBits: $mask->allowed | $roleAllow, deniedBits: $mask->denied, level: $this->maxLevel($mask->level, $roleLevel));
        }

        return $sets;
    }

    /** @param list<NodeGrant> $grants
     * @return array{allow:int, deny:int, level:?GrantLevel}
     */
    private function grantMask(array $grants, bool $inherited): array
    {
        $allow = 0;
        $deny = 0;
        $level = null;
        foreach ($grants as $grant) {
            if ($inherited && !$grant->scope->inheritsDownward()) {
                continue;
            }
            if ($grant->effect === Effect::Allow) {
                $allow |= $this->bitsFor($grant);
                $level = $this->maxLevel($level, $grant->level);
            } else {
                $deny |= $this->bitsFor($grant);
            }
        }

        return ['allow' => $allow, 'deny' => $deny, 'level' => $level];
    }

    /**
     * The UI ability flags for (actor, node) — every Ability mapped to whether the
     * actor may perform it (deny-veto applied). Fills the NodeResource "abilities"
     * object so the client renders only allowed actions.
     *
     * @return array<string, bool>
     */
    public function abilitiesFor(Authorizable $actor, Node $node): array
    {
        $grants = $this->effectiveGrants($actor, $node);

        $flags = [];

        foreach (Ability::cases() as $ability) {
            $flags[$ability->value] = $grants->allows($ability);
        }

        return $flags;
    }

    /**
     * DIAGNOSTIC "explain access" (F-P1.1-02 / S1.7): why does (actor, ability, node)
     * resolve the way it does? Returns the verdict, a machine-readable reason, the
     * folded allow/deny masks + level, and the provenance chain of every grant the
     * bounded walk visited (nearest-first, each tagged with its depth and whether it
     * counted). This runs a SEPARATE provenance-collecting pass and is NEVER called
     * from can()/effectiveGrants(), so the hot authorization path stays allocation-free
     * of this bookkeeping.
     */
    public function explain(Authorizable $actor, Ability $ability, Node $node): AccessExplanation
    {
        $driver = $this->drivers->driver();
        $storage = $this->storageOf($node);
        $scope = $this->scopeFor($storage, $node);

        $override = $driver->override($actor, $scope);

        if ($override === Effect::Allow) {
            return new AccessExplanation(
                allowed: true,
                ability: $ability,
                reason: AccessExplanation::REASON_SUPER_ALLOW,
                allowedBits: 0,
                deniedBits: 0,
                level: GrantLevel::Owner,
                aces: [],
            );
        }

        if ($override === Effect::Deny) {
            return new AccessExplanation(
                allowed: false,
                ability: $ability,
                reason: AccessExplanation::REASON_SUPER_DENY,
                allowedBits: 0,
                deniedBits: 0,
                level: null,
                aces: [],
            );
        }

        $subjects = $driver->subjectsFor($actor);

        [$aclAllowBits, $deniedBits, $aclLevel, $aces] = $this->resolveAclWithProvenance(
            node: $node,
            subjects: $subjects,
        );

        [$roleAllowBits, $roleLevel] = $this->resolveRole(
            driver: $driver,
            actor: $actor,
            scope: $scope,
            subjects: $subjects,
        );

        $allowedBits = $aclAllowBits | $roleAllowBits;
        $level = $this->maxLevel($aclLevel, $roleLevel);

        // Fold through the SAME GrantSet the hot path uses so the explained verdict
        // can never diverge from can()'s.
        $verdict = new GrantSet(allowedBits: $allowedBits, deniedBits: $deniedBits, level: $level);
        $allowed = $verdict->allows($ability);

        return new AccessExplanation(
            allowed: $allowed,
            ability: $ability,
            reason: $this->explainReason($allowed, $ability, $deniedBits),
            allowedBits: $allowedBits,
            deniedBits: $deniedBits,
            level: $level,
            aces: $aces,
        );
    }

    /**
     * May the actor create nodes in the storage's workspace? Delegates to the
     * host-role driver's workspace gate (the folder/upload create path has no
     * existing node to resolve against). canCreate for folders/uploads (§6).
     */
    public function canCreateInWorkspace(Authorizable $actor, Storage $storage): bool
    {
        return $this->drivers->driver()->canCreateInWorkspace(
            actor: $actor,
            workspaceType: $storage->owner_type,
            workspaceId: $storage->owner_id,
        );
    }

    /**
     * The "shared with me" view (§2.6 / H.2): the nodes an actor is granted any
     * access to, RE-RESOLVED through the full algorithm so a nearer deny that
     * revokes a row excludes it. The fast subject-index pass yields candidate node
     * ids; each candidate is then re-checked with can(View), because a deny nearer
     * the node may have revoked the visibility the raw grant implied.
     *
     * @param  iterable<Node> $candidates already-loaded candidate nodes (e.g. the
     *                                    nodes whose ids nodeIdsSharedWith returned)
     * @return list<Node>
     */
    public function filterSharedWith(Authorizable $actor, iterable $candidates): array
    {
        $visible = [];

        foreach ($candidates as $node) {
            if ($this->can($actor, Ability::View, $node)) {
                $visible[] = $node;
            }
        }

        return $visible;
    }

    /**
     * The candidate node ids an actor has a live allow-grant on — the fast
     * subject-index pass behind filterSharedWith (§2.6). The caller loads the nodes
     * and re-resolves them; this never decides visibility on its own.
     *
     * @return list<int|string>
     */
    public function sharedNodeIds(Authorizable $actor): array
    {
        $subjects = $this->drivers->driver()->subjectsFor($actor);

        return $this->grants->nodeIdsSharedWith(subjects: $subjects, now: Carbon::now());
    }

    /**
     * H.2 steps 2 + 3 — the ACL allow-mask, deny-mask and effective level from the
     * bounded ancestor walk.
     *
     * Walk order is nearest-first (the node itself, then its parents up to the
     * storage root). For each node visited we collect the live grants addressed to
     * the subject-set; only grants that APPLY at this node count:
     *   - a grant ON the node (any scope) applies to the node directly;
     *   - a grant on an ANCESTOR applies only when its scope is subtree.
     * The walk STOPS once it has consumed an ancestor whose inherit_grants=false:
     * that node's own grants still count, but nothing above it does (cut-off).
     *
     * deny semantics (the FINAL veto is absolute per depth): a deny is pierced ONLY
     * by an allow that sits STRICTLY NEARER (a smaller walk depth) — never by an
     * allow on the SAME node. So allow + deny on the same node ⇒ the deny wins
     * (same-node deny is an absolute veto, §2.6 / H.2 step 5). This is why we cannot
     * fold in a single pass over an UNORDERED grant set: a same-depth allow seen
     * before a same-depth deny must NOT swallow it. We instead bucket allow/deny
     * bits PER DEPTH, then fold from nearest to farthest, masking a deny only with
     * bits allowed at a strictly smaller depth. A deny on the cut-off (inherit_grants
     * =false) node sits at the FARTHEST depth of the bounded walk, so no grant ABOVE
     * it contributes — but a nearer explicit allow BELOW it still pierces that deny
     * (ADR-0007: a nearer allow beats a farther inherited deny; the wall gets no
     * exception).
     *
     * @param  list<Subject>                             $subjects
     * @return array{0: int, 1: int, 2: GrantLevel|null}
     */
    private function resolveAcl(Node $node, array $subjects): array
    {
        if ($subjects === []) {
            return [0, 0, null];
        }

        // The bounded ancestor chain, nearest-first: node, parent, …, root. The
        // staudenmeir ancestor relation is storage-scoped already (the tree lives
        // in one storage_id), so the walk never crosses workspaces.
        $chain = $this->ancestorChain($node);

        $nodeIds = array_map(static fn (Node $n): int|string => $n->id, $chain);

        $now = Carbon::now();
        $grants = $this->grants->forSubjectsOnNodes(nodeIds: $nodeIds, subjects: $subjects, now: $now);

        /** @var array<string, list<NodeGrant>> $byNode */
        $byNode = [];

        foreach ($grants as $grant) {
            $byNode[Identity::stringify($grant->node_id)][] = $grant;
        }

        // Phase 1 — bucket the allow/deny bits PER DEPTH (nearest = 0). We never let
        // a same-node allow and deny cancel here; they are kept apart so phase 2 can
        // apply "a deny is pierced only by a strictly-nearer allow".
        /** @var array<int, int> $allowByDepth */
        $allowByDepth = [];
        /** @var array<int, int> $denyByDepth */
        $denyByDepth = [];
        $level = null;

        foreach ($chain as $depth => $current) {
            $isSelf = $depth === 0;
            $rows = $byNode[Identity::stringify($current->id)] ?? [];

            foreach ($rows as $grant) {
                // An ancestor's grant only inherits down when scope=subtree; the
                // node's own grants always apply.
                if (!$isSelf && !$grant->scope->inheritsDownward()) {
                    continue;
                }

                $bits = $this->bitsFor($grant);

                if ($grant->effect === Effect::Allow) {
                    $allowByDepth[$depth] = ($allowByDepth[$depth] ?? 0) | $bits;
                    $level = $this->maxLevel($level, $grant->level);

                    continue;
                }

                $denyByDepth[$depth] = ($denyByDepth[$depth] ?? 0) | $bits;
            }

            // Cut-off: once we have consumed a node whose inheritance is severed,
            // nothing above it may contribute. The node's OWN grants (bucketed above)
            // already counted; a deny on this wall is only shielded from FARTHER
            // (above-wall) allows — the walk stops here so none exist — while a
            // nearer allow BELOW the wall still pierces it (ADR-0007, no wall exception).
            if (!$current->inherit_grants) {
                break;
            }
        }

        $mask = $this->foldDepths($chain, $allowByDepth, $denyByDepth, $level);

        return [$mask->allowed, $mask->denied, $mask->level];
    }

    /**
     * A provenance-collecting twin of resolveAcl() serving explain() (F-P1.1-02). It
     * folds the SAME allow/deny masks by the SAME rules (per-depth bucket, then a deny
     * pierced only by a strictly-nearer allow), but additionally records every visited
     * grant as an {@see AccessAce} — tagged with its walk depth and whether it counted
     * (an item-scoped ancestor grant is recorded with counted=false). It is kept apart
     * from resolveAcl() ON PURPOSE so the hot path carries no diagnostic bookkeeping.
     *
     * @param  list<Subject>                                                 $subjects
     * @return array{0: int, 1: int, 2: GrantLevel|null, 3: list<AccessAce>}
     */
    private function resolveAclWithProvenance(Node $node, array $subjects): array
    {
        if ($subjects === []) {
            return [0, 0, null, []];
        }

        $chain = $this->ancestorChain($node);

        $nodeIds = array_map(static fn (Node $n): int|string => $n->id, $chain);

        $now = Carbon::now();
        $grants = $this->grants->forSubjectsOnNodes(nodeIds: $nodeIds, subjects: $subjects, now: $now);

        /** @var array<string, list<NodeGrant>> $byNode */
        $byNode = [];

        foreach ($grants as $grant) {
            $byNode[Identity::stringify($grant->node_id)][] = $grant;
        }

        /** @var array<int, int> $allowByDepth */
        $allowByDepth = [];
        /** @var array<int, int> $denyByDepth */
        $denyByDepth = [];
        /** @var list<AccessAce> $aces */
        $aces = [];
        $level = null;

        foreach ($chain as $depth => $current) {
            $isSelf = $depth === 0;
            $rows = $byNode[Identity::stringify($current->id)] ?? [];

            foreach ($rows as $grant) {
                // A grant on an ancestor only inherits down when scope=subtree; the
                // node's own grants always apply. A non-counting row is still recorded
                // (counted=false) so the operator sees it was present but inert.
                $counted = $isSelf || $grant->scope->inheritsDownward();
                $bits = $this->bitsFor($grant);

                $aces[] = new AccessAce(
                    nodeId: $grant->node_id,
                    depth: $depth,
                    effect: $grant->effect,
                    scope: $grant->scope,
                    bits: $bits,
                    counted: $counted,
                );

                if (!$counted) {
                    continue;
                }

                if ($grant->effect === Effect::Allow) {
                    $allowByDepth[$depth] = ($allowByDepth[$depth] ?? 0) | $bits;
                    $level = $this->maxLevel($level, $grant->level);

                    continue;
                }

                $denyByDepth[$depth] = ($denyByDepth[$depth] ?? 0) | $bits;
            }

            if (!$current->inherit_grants) {
                break;
            }
        }

        $mask = $this->foldDepths($chain, $allowByDepth, $denyByDepth, $level);

        return [$mask->allowed, $mask->denied, $mask->level, $aces];
    }

    /**
     * The machine-readable reason for an explain() verdict: an allow, a deny-veto
     * (a required bit landed in the deny-mask), or simply no covering grant.
     */
    /**
     * @param list<Node>      $chain
     * @param array<int, int> $allows
     * @param array<int, int> $denies
     */
    private function foldDepths(array $chain, array $allows, array $denies, ?GrantLevel $level): AclMask
    {
        $depths = [];
        foreach ($chain as $depth => $current) {
            $depths[] = ['allow' => $allows[$depth] ?? 0, 'deny' => $denies[$depth] ?? 0, 'level' => $level];
            if (!$current->inherit_grants) {
                break;
            }
        }

        return (new AclFolder)->foldChain($depths);
    }

    private function explainReason(bool $allowed, Ability $ability, int $deniedBits): string
    {
        if ($allowed) {
            return AccessExplanation::REASON_ALLOW;
        }

        if (($deniedBits & $ability->requiredBits()) !== 0) {
            return AccessExplanation::REASON_DENY_VETO;
        }

        return AccessExplanation::REASON_NO_GRANT;
    }

    /**
     * H.2 step 4 input — the host-role allow-mask + level. A driver Decision RAISES
     * access (roleAllow); a driver-returned deny is folded the same way the ACL
     * deny path is, but per H.2 the role lane primarily contributes allows (the
     * final veto, computed from ACL deny, is what a role can never override).
     *
     * @param  list<Subject>                     $subjects
     * @return array{0: int, 1: GrantLevel|null}
     */
    private function resolveRole(
        HostRoleDriver $driver,
        Authorizable $actor,
        AclScope $scope,
        array $subjects,
    ): array {
        $bits = 0;
        $level = null;

        foreach ($subjects as $subject) {
            $decision = $driver->resolve($subject, $actor, $scope);

            if (!$decision instanceof Decision || !$decision->isAllow()) {
                continue;
            }

            $bits |= $decision->bits;
            $level = $this->maxLevel($level, $decision->level);
        }

        return [$bits, $level];
    }

    /**
     * The CRUDS bits a grant row confers: the explicit permissions bitmask when set,
     * else the level's bitmask. A row may carry both a level and extra bits — they
     * are OR-ed so a level grant plus an extra SHARE bit both count.
     */
    private function bitsFor(NodeGrant $grant): int
    {
        return $grant->level->bits() | $grant->permissions;
    }

    /**
     * The bounded ancestor chain nearest-first: the node, then each ancestor up to
     * the storage root (the staudenmeir ancestor relation, storage-scoped). Falls
     * back to a manual parent walk if the relation yields nothing (defensive — a
     * detached node still resolves against itself).
     *
     * Runs under withMaxDepth(NodeReadRepository::DEFAULT_MAX_DEPTH) — F-P4.2-01,
     * VLT-REMED P4.3: this method executes on EVERY authorization check
     * (can()/effectiveGrants()), so an unbounded recursive-CTE ancestor walk pays
     * its cost on every request and, on SQLite, can hit
     * SQLITE_MAX_RECURSION_DEPTH on a deep tree. ADR-0005 requires the same cap
     * symmetrically on both traversal directions; descendants()/subtree() already
     * carry it (NodeReadRepository), this was the missing ascend-side half.
     *
     * @return list<Node>
     */
    private function ancestorChain(Node $node): array
    {
        $chain = [$node];

        $model = Config::nodeModel();

        /** @var Collection<int, Node> $ancestors */
        $ancestors = $model::withMaxDepth(
            NodeReadRepository::DEFAULT_MAX_DEPTH,
            static fn (): Collection => $node->ancestors()->get(),
        );

        // ancestors() returns nearest-first already; bound it to the same storage so
        // a misconfigured tree can never escape the workspace (defence-in-depth on
        // top of the storage-scoped relation).
        foreach ($ancestors as $ancestor) {
            if ($ancestor->storage_id !== $node->storage_id) {
                break;
            }

            $chain[] = $ancestor;
        }

        return $chain;
    }

    private function maxLevel(?GrantLevel $a, ?GrantLevel $b): ?GrantLevel
    {
        if ($a === null) {
            return $b;
        }

        if ($b === null) {
            return $a;
        }

        return $a->max($b);
    }

    private function scopeFor(Storage $storage, Node $node): AclScope
    {
        $owner = $node->owner_id === null
            ? null
            : new Subject(type: $storage->owner_type, id: $node->owner_id);

        return new AclScope(
            panel: $storage->panel,
            workspaceType: $storage->owner_type,
            workspaceId: $storage->owner_id,
            nodeOwner: $owner,
        );
    }

    private function storageOf(Node $node): Storage
    {
        // Prefer an already-loaded storage relation (e.g. sharedWith eager-loads it)
        // so a bulk re-resolution does NOT fire one storage query per node; fall back
        // to the read repository for a node loaded without it.
        $storage = $node->relationLoaded('storage')
            ? $node->getRelation('storage')
            : $this->storages->find($node->storage_id);

        if (!$storage instanceof Storage) {
            // A node always belongs to a storage (FK cascade); a missing storage is
            // a corrupt state — deny by surfacing an empty workspace scope is unsafe,
            // so we fail loud rather than silently open.
            throw new \RuntimeException(sprintf(
                'Vaulter could not resolve the storage [%s] for node [%s].',
                Identity::stringify($node->storage_id),
                Identity::stringify($node->id),
            ));
        }

        return $storage;
    }
}
