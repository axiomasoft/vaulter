### P1.3 — Точная видимость листинга и поиска

**Intent:** Листинг детей, поиск, корзина, «shared with me», дети в `show` и Filament-таблица возвращают только узлы с
эффективным `View` для **любого** драйвера прав, без `total`, с курсором «последний просмотренный»; `abilities` страницы
считаются одним пакетным проходом с тем же результатом, что `effectiveGrants()` (N08, E10, N24, AD12; V09, V22).

**Why:** OPUS 13 P1.3, 02 D12, 09 §2–§3. Сегодня `NodeController::index/search/trashed`
(`packages/drive/src/Http/Controllers/NodeController.php:81–93, 309–331`) сужают выборку только «кандидатами по grant»
(`NodeReadRepository::constrainToAccessible`, `packages/core/src/Repositories/Drive/NodeReadRepository.php:378–391`) — надмножество
без deny-вето, а для драйверов `gate`/`spatie`/`azgard` сужения нет вовсе (`grantFilteringApplies`, строка 467): любой,
кто видит папку, видит имена/размеры/MIME всех детей. `NodeResource::abilities` (`packages/core/src/Http/Resources/Drive/NodeResource.php:139–149`)
вызывает `effectiveGrants()` с обходом предков на каждый узел страницы.

**Scope Included:**
1. `packages/core/src/Access/ValueObjects/AclMask.php` (new, `final readonly`): `int $allowed`, `int $denied`, `?GrantLevel $level`;
   `static none()`.
   `packages/core/src/Access/AclFolder.php` (new, `final class`, без состояния и SQL) — единственное место правил свёртки:
   - `foldChain(array $depths): AclMask` — вход `list<array{allow:int, deny:int, level:?GrantLevel}>`, индекс 0 — ближайший;
     `allowed` = объединение всех allow; `denied` = объединение `deny_d & ~(allow_0 | … | allow_{d-1})` (deny пробивается только
     строго более близким allow); `level` = максимум level allow-грантов. Это перенос фаз 1–2 текущего
     `AccessResolver::resolveAcl` (`packages/core/src/Access/AccessResolver.php:299–389`) без изменения семантики.
   - `applyOwn(AclMask $inherited, int $ownAllow, int $ownDeny, ?GrantLevel $ownLevel): AclMask` — 09 §2 п.5:
     `allowed = own.allow | P.allowed`; `denied = own.deny | (P.denied & ~own.allow)`; `level = max(own.level, P.level)`.
   `resolveAcl()` и `resolveAclWithProvenance()` переписываются на `AclFolder::foldChain()` (провенанс сохраняется).
2. `AccessResolver::evaluateMany(Authorizable $actor, iterable $nodes): array<string, GrantSet>` (ключ — `Identity::stringify(id)`):
   1) узлы группируются по `(storage_id, owner_id)`; для каждой группы один раз — `driver()->override($actor, $scope)` (Allow →
      `GrantSet::superAllowed()` всем узлам группы, Deny → `superDenied()`) и роль-лейн `resolveRole(...)`
      (`$scope = scopeFor($storage, $node)` первого узла группы; `AclScope` зависит от storage и владельца узла);
   2) `subjectsFor($actor)` — один раз; пустой список → ACL-маски `AclMask::none()` для всех (как `resolveAcl`);
   3) для уникальных `parent_id` страницы — одна рекурсивная CTE (новый `NodeReadRepository::ancestorChains(array $parentIds): array<string, list<Node-row>>`):
      `WITH RECURSIVE chain AS (SELECT id, parent_id, inherit_grants, id AS origin, 0 AS depth FROM <nodes> WHERE id IN (…)
      UNION ALL SELECT n.id, n.parent_id, n.inherit_grants, c.origin, c.depth + 1 FROM <nodes> n JOIN chain c ON n.id = c.parent_id
      WHERE c.inherit_grants = <true>)` — подъём останавливается после первого узла с `inherit_grants = false` (он сам входит);
   4) одна выборка grants: `GrantReadRepository::forSubjectsOnNodes(nodeIds: ids страницы ∪ ids всех цепочек, subjects, now)`
      (существующий метод; не истёкшие);
   5) для каждого родителя `P = foldChain(...)` по его цепочке, где на каждой глубине учитываются только grants со
      `scope->inheritsDownward()`; для каждого узла: `inherit_grants = false` → `P = AclMask::none()`, иначе `P` родителя;
      `acl = applyOwn(P, own.allow, own.deny, own.level)` (собственные grants узла любого scope);
   6) `GrantSet(allowedBits: acl.allowed | roleAllow, deniedBits: acl.denied, level: maxLevel(acl.level, roleLevel))`.
   Итого ≤ 3 SQL на страницу без роль-лейна драйвера (CTE, grants, storage — если не загружен `storage`).
3. `packages/core/src/Data/Drive/NodePage.php` (new) — точно по OPUS 05 §6: `final readonly class NodePage implements IteratorAggregate, Countable, JsonSerializable`,
   `__construct(public array $items, public ?string $nextCursor, public int $scanned)`, `hasMore(): bool`.
4. `packages/core/src/Access/ExactListing.php` (new, `final readonly`; зависимости `AccessResolver`, `VaulterDatabase`, `Encrypter`-ключ `app.key`):
   `page(?Authorizable $actor, Builder $candidates, array $order, int $perPage, ?string $cursor, string $context): NodePage`, где
   `$order` — `list<array{column:string, direction:'asc'|'desc'}>`, последний элемент всегда `id` в направлении сортировки.
   Алгоритм 09 §3: `last = decode(cursor)`; цикл, пока `count(visible) < perPage` и `scanned < Config::listingScanBudget()`:
   batch = `(clone $candidates)` + keyset «после `last`» (дизъюнкция `(a ⋚ x) OR (a = x AND b ⋚ y) OR … (… AND id ⋚ z)`, `⋚` = `>` для
   asc и `<` для desc) + `limit(perPage * 2)`; пустой → `last = null`, стоп; `grants = evaluateMany(actor, batch)`; узлы просматриваются по
   порядку, каждый просмотренный увеличивает `scanned` и становится `last`; видимые (`grants[id]->allows(Ability::View)`) идут в
   страницу, пока она не заполнится — тогда просмотр останавливается на этом узле. Выход по бюджету → `nextCursor = encode(last)`.
   Без актёра → пустая страница, `nextCursor = null`.
   Курсор: `base64url(json_encode(['c' => $context, 'k' => [значения order…]]))` + `.` + `base64url(hash_hmac('sha256', payload, app.key, true))`;
   неверная подпись или другой `$context` → `Vaulter\Exceptions\Nodes\InvalidCursorException` (new, `validation_failed`, 422,
   `errors.cursor`). `$context` = `"<kind>:<storage_id>:<parent_id|term-sha1|''>"`.
   `Config::listingScanBudget(): int` — `vaulter.listing.scan_budget`, по умолчанию 1000 (`packages/core/config/vaulter.php` блок `listing`, новый ключ).
