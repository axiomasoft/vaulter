## Recheck-1 findings
The prior deadlock was an inverted storage-row lock against quota updates. I am checking every action that still takes node locks or `adjustUsedBytes`, plus the restore parent lookup and the migration’s length and index paths.review: grok/grok-4.7 findings:2

1. **high** — `packages/drive/src/Actions/UploadFileAction.php:92` (same order at `packages/drive/src/Actions/CopyNodeAction.php:65`; the other side is `packages/drive/src/Actions/CreateFolderAction.php:45` and `packages/documents/src/Actions/Documents/CreateDocumentNodeAction.php:64`)
   - **Defect:** On MySQL/MariaDB, `lockBeforeQuota` takes an exclusive lock on the `storages` row (`packages/core/src/Support/TreeGuard.php:45`, `packages/core/src/Database/VaulterDatabase.php:49`) and only then locks the destination node. Create locks that node first and then `INSERT`s a child. `v_nodes.storage_id` references `v_storages.id` (`packages/core/src/Schema/PanelTablesBuilder.php:239`), so the insert takes a shared lock on the same storage row and holds it until commit. Move (`MoveNodeAction.php:53`), Restore (`RestoreNodeAction.php:47`) and ForceDelete (`ForceDeleteNodeAction.php:52`) already take that exclusive storage lock before any node lock, so they wait on Create the same way.
   - **Failure scenario:** T1 creates a folder in live folder F and locks F. T2 uploads into F (or copies into F), locks the storage row, and waits for F. T1's insert waits for a shared lock on that storage row. InnoDB aborts one transaction with error 1213. The same cycle happens when T2 moves into F, restores into F, or force-deletes F. Laravel retries the callback up to 3 times, then the request fails. PostgreSQL does not take this storage-row lock in `lockTree`, and SQLite has no row locks, so this cycle is MySQL/MariaDB.
   - **Fix:** On non-PostgreSQL drivers, take `lockTree` / `lockBeforeQuota` at the start of Create folder and Create document, before the parent node lock, so the exclusive storage lock is already held when the foreign key check runs.

2. **medium** — `packages/core/database/migrations/2026_10_01_000006_nodes_cleanup.php:150`
   - **Defect:** `freeName()` only shortens the base. The suffix is `" (legacy N)"` plus the whole extension, and a stored name may already be 255 bytes. When that suffix is longer than 255 bytes, `mb_strcut` is called with length 0 and the candidate is the suffix alone.
   - **Failure scenario:** A live second root is named `a` plus `.` plus 253 `b`s (255 bytes) and collides, case-insensitively, with a live child of the real root. The candidate is ` (legacy 1).` plus those 253 `b`s (265 bytes). PostgreSQL and MySQL reject the repair `UPDATE` (`22001` / `1406`), the transaction rolls back, and `up()` never reaches `addSingleRootIndex`. The new test uses a 4-byte `.txt` extension, so the candidate stays within 255.
   - **Fix:** If `strlen(suffix) > 255`, shorten the extension (keep the dot and a tail) until `strlen(candidate) <= 255`, then re-check `nameTaken`.

## Fix summary
1. TreeGuard::lockBeforeQuota renamed lockStorageFirst; on non-pgsql it calls lockTree (storage row FOR UPDATE). It is now the first statement in the transactions of CreateFolderAction, CreateDocumentNodeAction, UploadFileAction and CopyNodeAction — every transaction that inserts nodes or updates used_bytes. Move/Restore/ForceDelete take lockTree first. Rename/Trash only UPDATE non-FK columns of one locked node row. Move/Restore UPDATE parent_id to a row they already hold X-locked.
2. Migration freeName: if strlen(" (legacy N)" . extension) >= 255 the whole name is used as head and the extension dropped; candidate = mb_strcut(head, 0, 255 - strlen(marker . tail)) . marker . tail.

it('takes the storage row before node rows when the transaction inserts nodes or updates the quota', function (string $operation): void {
    $drive = DriveTestHelpers::drive();
    $folder = $drive->createFolder('Target');
    $source = $drive->upload(DriveTestHelpers::streamFor('bytes'), originalName: 'source.bin');
    $queries = [];

    Event::listen(QueryExecuted::class, function (QueryExecuted $query) use (&$queries): void {
        $queries[] = $query->sql;
    });

    match ($operation) {
        'create folder' => $drive->createFolder('Child', $folder),
        'upload' => $drive->upload(DriveTestHelpers::streamFor('x'), into: $folder, originalName: 'x.bin'),
        'copy' => $drive->copy($source, $folder),
    };

    $storageLock = array_key_first(array_filter($queries, static fn (string $sql): bool => str_starts_with($sql, 'select "id" from "v_storages"')));
    $nodeLock = array_key_first(array_filter($queries, static fn (string $sql): bool => str_contains($sql, 'from "v_nodes"') && str_contains($sql, 'order by')));

    // SQLite (like MySQL) implements the tree lock as the storage row.
    expect($storageLock)->not->toBeNull()
        ->and($nodeLock)->not->toBeNull()
        ->and($storageLock)->toBeLessThan($nodeLock);
})->with(['create folder', 'upload', 'copy']);
