## Что проверено и чисто

Реестр: ключ `vendor/name`, запрет чужого `vaulter/` по правилу EV324, дубликат, `replace`, `all()` по ключу, freeze в `booted` после `boot()` всех провайдеров, затем проверка `default_type`. `InvalidDefaultDocumentTypeTest` покрывает отказ и регистрацию в `boot()` по обе стороны от провайдера documents.

Неустановленный тип: `content` / revisions / copy / trash / purge сохраняют JSON; `update`, `snapshot`, `restore`, `export` дают `document_type_unavailable`. Копия несёт payload дословно. Презентация — `vaulter/unsupported`, `type_available=false`.

Схема новее типа на пути `content()` / `update()` / `DocumentPresenter`: `typeAvailable=true`, `editable=false`, 409 `document_content_degraded`. Старая схема поднимается on-read и не переписывает историю. Неизвестный узел TipTap (кейс `acmeWidget`) помечается `lossless=false`, и `update()` его не затирает.

Лимит на публичном `create`/`update` применяется декодером до записи. `vaulter/`-типы, профиль `documentTypes`, MIME документа `application/vnd.vaulter.document+json`. Файлы `.docx`/`.md`/`.xlsx` остаются preview/download.

Публичный API: из golden documents ушли `enabledDocumentTypes`, `spreadsheetsEnabled`, старый namespace реестра; `create($name, ?string $type = null)` и снятие `ContentCapabilities::$richText` описаны в `UPGRADE.md` и `CHANGELOG.md` (Unreleased). Туда же попали переносы `Content\*`, исключения экспорта, `KindPresenter`, поля `document_type` / `type_available`. Core-golden в этом коммите только пополняется снимками и DTO.

`ConfigNormalizer` переводит легаси-ключи с `E_USER_DEPRECATED`, склеивает дубликаты классов и конфликтует с уже переопределённым `vaulter-documents.types`.

D55: код совпадает с EV320–EV324 и EV326–EV329 (родительский `DocumentContent` в core до P4.4, default типа из конфига, экспорт через тип, тег `vaulter.kind_presenters`, first-party `vaulter/`, лимиты на все типы через декодер, HTTP-поле `type`). EV325 выполнен для неизвестного узла и не выполнен для находок 3.

D57: 13 строк `ledger-P4.tsv` совпадают с `opus-units.tsv` (`01:1c3d640e`, `02:e15b4066`, `02:7bf67b19`, `04:5bbb932e`, `06:53200da4`, `07:e40ce5c1`, `07:35c9e07d`, справочные `03:0065c62f`, `03:15134404`, `03:5c0723c5`, `03:8378be94`, плюс `02:27c3be4b` и `12:268fa6e9`). `12:630e43d3` (doctor) в P4.14 не передана. Чтение `^0.x` / `azguard-core` как `axiomasoft/azguard: ^1.0` не возвращает legacy и не спорит с D56. P4.14 ссылается на этот render.

Запись вне операции: в коммите поправлены только тестовые фикстуры media (`CasTestHelpers` / `BlobGcBatchTest`); боевой guard не ослаблен. Тесты по квитанциям не перезапускались.

## Вердикт

**request changes.** Путь `update()` для неизвестного узла и неустановленного типа держит запрет на потерю. При включённой коллаборации webhook снова открывает запись и сбрасывает `schema_version` в 1, так что защита newer-schema и degraded на рабочем состоянии обходится. Это нужно закрыть до приёмки P4.3.
