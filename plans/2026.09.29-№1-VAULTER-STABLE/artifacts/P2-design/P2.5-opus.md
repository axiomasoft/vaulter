## 02-decisions.md — D01 — Одно окно канона: 0.3.0, затем стабилизация до 1.0 · T1

- `02:a703fd23` — _жёсткие переименования — P2.1–P2.4; нормализатор — P2.5; upgrade схемы — P2.7; удаление ключей в 1.0 — P8.3_

**Решение.** Все переименования, изменения схемы и REST v1 выходят одним релизом **0.3.0**
(«canon break»). В PHP — жёсткие переименования без алиасов-обёрток (как в VLT-CANON:
пакет пре-1.0). Устаревшие **ключи конфигурации** читаются нормализатором с
`E_USER_DEPRECATED`-логом до 1.0 и удаляются в 1.0. Схема БД обновляется upgrade-миграцией
с сохранением данных. 1.0.0 выпускается, когда зелёные все гейты из
[12-operations-and-release.md](12-operations-and-release.md).

- `02:e4f87eb6` — _жёсткие переименования — P2.1–P2.4; нормализатор — P2.5; upgrade схемы — P2.7; удаление ключей в 1.0 — P8.3_

**Почему.** Двойная поверхность (новый API + deprecated-обёртки) удваивает работу исполнителей
и тестов; у 0.2.0 нет обязательств SemVer. Конфиг — исключение: он лежит в опубликованных
файлах хоста и ломается тихо.

- `02:d015b4ce` — _жёсткие переименования — P2.1–P2.4; нормализатор — P2.5; upgrade схемы — P2.7; удаление ключей в 1.0 — P8.3_

**Отвергнуто.** Постепенные переименования по одному в минорах (многократная миграция
потребителей); обёртки `@deprecated` для всех методов (аудит, этап 2).

## 07-configuration.md — (preamble)

- `07:3fc4aa83`

Решение: [D26](02-decisions.md#d26). Принципы:

- `07:ffc92c5c`

1. **Один файл на пакет-владелец**: `vaulter.php` (core), `vaulter-media.php`, `vaulter-drive.php`,
   `vaulter-documents.php`, `vaulter-azgard.php`, `vaulter-filament.php`. Пакет читает только свои ключи и ключи core.

- `07:72213d87`

2. **Ключи, влияющие на схему БД, — только в `vaulter.php`**: соединение, префикс таблиц, стратегия ID, тип
   ключей хоста, tenancy. Их изменение после миграции обнаруживает doctor.

- `07:3aeec79d`

3. **Один канонический ключ на понятие**; устаревшие ключи переводит `ConfigNormalizer` с
   `E_USER_DEPRECATED` до 1.0; при конфликте «старый и новый заданы по-разному» — `InvalidConfigurationException`.

- `07:96724f7a`

4. **Типизированный доступ**: каждый пакет имеет readonly-класс `Configuration\<Pkg>Config`, который **читает
   через** `Illuminate\Contracts\Config\Repository` (без кэширования — тесты с `config()->set()` продолжают
   работать) и возвращает типы. Прямой `config('vaulter…')` вне `Configuration\*` запрещён arch-тестом.

- `07:26d1fb65`

5. **Валидация при boot**: ошибки ключей безопасности — исключение во всех окружениях; наблюдаемость — warning в лог
   и null-реализация (как сейчас). Полный список проверок — doctor.

- `07:34a2986c`

6. Замыкания в конфиге запрещены; всё — FQCN или скаляры.
