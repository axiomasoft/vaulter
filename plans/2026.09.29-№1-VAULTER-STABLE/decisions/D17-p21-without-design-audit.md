# D17 — Исполнение P2.1 без design-аудита; адаптация реестра профилей

**Actor:** repository owner, текущая Codex-сессия, 2026-10-04.
**Evidence:** владелец отменил аудит («без аудита»), выбрал «Да, выполнять P2.1 без аудита»,
после предъявления `findings/P2.1-execution-preflight.md` потребовал «делай задачу!!!».

## Solution

1. Исполнять P2.1 по завершённому дизайну P2 без запуска design-аудита. Это ограниченное
   исключение из D03 для текущего перехода к P2.1; audit GREEN не объявляется и не создаётся.
2. Применить предложенную поправку `findings/P2.1-execution-preflight.md`: сохранить
   публичные методы реестра профилей, удалить вызов `booted()` и private validation
   удаляемых own-tables/models/pipes/resource настроек вместе с этим API. Удалить
   проверки удалённого API; сохранить config hydration, порядок регистрации, default
   override, unknown profile и остальные проверки сохраняемого поведения.
3. UPGRADE/CHANGELOG честно указывают: `booted()` раньше вызывался и теперь удалён.
   Утверждение N12 об отсутствии вызова не повторяется как факт; исходный OPUS сохраняется.
4. Иные неожиданные callers остаются предметом сверки. Названные callers реестра и
   удаляемого own-tables/schema API не являются причиной повторного запроса разрешения.
5. Изменения таблиц/колонок/значений событий остаются P2.7; прочая приёмка P2.1 сохранена.
   Push, hosted CI, публикация и новый аудит этим решением не разрешаются.

## Why

Владелец явно отменил аудит и подтвердил исполнение P2.1. Сохранение вызова booted()
при удалении метода ломало бы загрузку приложения; исправление caller необходимо
для выполнения утверждённого удаления API и не меняет остальные политики реестра.
