### P2.5 — Канонический конфиг и типизированный доступ

**Intent:** Каждый пакет читает конфигурацию только через свои `final readonly` классы `Configuration\*Config` поверх
`Illuminate\Contracts\Config\Repository`; файлы конфига разложены по пакетам-владельцам в канон 07; опубликованный конфиг
0.2 продолжает работать через `ConfigNormalizer` с `E_USER_DEPRECATED`, конфликт старого и нового ключа — исключение;
`ConfigValidator` проверяет ключи безопасности при boot; статический `Support\Config` удалён, `config('vaulter…')` вне
`Configuration` запрещён arch-тестом (V28).

**Why:** OPUS 13 P2.5, AD26, 07 §1–§7, 04 §1 п.6, N19, V28. Код `main` @ `938f0ea`: `Support/Config.php` — 1628 строк,
108 методов, ключи всех пакетов; ~170 файлов-носителей; `config('vaulter…')` напрямую в 50 файлах `src`; модули мёржат
свои дефолты под ключи core (`drive` → `vaulter.models`, `media` → `vaulter.cas`, documents — `vaulter.models`/`handlers`/`exporters`).

**Scope Included:**
1. Классы (полная карта метод → ключ → accessor — `artifacts/P2-design/P2.5-config-map.md` §А):
   core `packages/core/src/Configuration/{VaulterConfig,DatabaseConfig,IdsConfig,TenancyConfig,AccessConfig,RoutesConfig,ListingConfig,SharingConfig,DownloadsConfig,WebhooksConfig,ObservabilityConfig}.php`;
   `VaulterConfig` даёт секции (`database(): DatabaseConfig`, …) и `model(string)`, `featureEnabled(string)`,

   статических контекстах — `app(X::class)` (R15). Заменяются: `Support\GateConfig`, `Support\SpatieConfig` (→ `AccessConfig`),
   `Drive\Support\Uploads\UploadModels` (→ `DriveConfig`), `Documents\DocumentsModels` (→ `DocumentsConfig`); удаляются

3. `packages/core/src/Configuration/ConfigNormalizer.php` (§В досье, R12, R13, R22): `normalize(Repository $config, array $packageDefaults): void`,
   где `$packageDefaults` — массивы дефолтных файлов установленных пакетов (`require`), передаваемые providers через
   `ConfigNormalizer::registerDefaults(string $root, string $path)` в `register()`; запуск — `app->booting()` callback core
   provider (после всех merge); идемпотентен. Перевод значений: `dedup.scope 'storage' → 'drive'`, `id_type` → стратегия,

   `panels`/`default_panel` с классом, не реализующим `ProfileProvider`, → `InvalidConfigurationException('[Vaulter] … run php artisan vaulter:make:profile')`.
   `Vaulter\Exceptions\Configuration\InvalidConfigurationException` (new, extends `VaulterException`, код `invalid_configuration`, HTTP 500 не отдаётся — только boot).
4. `packages/core/src/Configuration/ConfigValidator.php` (§Д досье): `validate(VaulterConfig $config, Application $app): void`
   из `boot()` core provider; каждый модульный provider валидирует свои модели/классы в своём `boot()` через тот же класс
   (`ConfigValidator::assertModel(string $key, string $class, string $base)`, `assertImplements(...)`).
5. Потребители: все вызовы `Support\Config::*`, `GateConfig::*`, `SpatieConfig::*`, `AzgardConfig` (уже P2.4), `UploadModels::*`,
   `DocumentsModels::*` и прямые `config('vaulter…')`/`config('vaulter-…')` в `src`, `database/migrations`, `routes`
   переходят на accessor'ы §А. Модели: `getTable()` → `app(DatabaseConfig::class)->table('<entity>')`,
   `getConnectionName()` → `DatabaseConfig::connection()`.
6. Arch (04 §1 п.6, 07 принцип 4): в core, drive, documents, media, filament, azgard —
   `arch()->expect('Vaulter')->not->toUse(['config'])->ignoring('Vaulter\Configuration')` (и аналог для модулей с их
   namespace `…\Configuration`); дополнительно текстовый тест «нет `config('vaulter` и `config("vaulter` вне
   `*/Configuration/*` и `config/*.php`» по `src`, `database`, `routes` всех пакетов (ловит глобальную функцию, которую
   `toUse` может не увидеть). Allow-list: `DatabaseConfig::legacyTable` (сырое чтение `vaulter.table_names`) — внутри
   `Configuration`, исключение не требуется.
7. Тесты: `packages/core/tests/Configuration/{ConfigNormalizerTest,ConfigValidatorTest,VaulterConfigTest}.php`; V28 —

   канонических accessor'ов равны значениям 0.2; конфликт `connection='a'` + `database.connection='b'` → `InvalidConfigurationException`.

**Implementation Rules:**
- Accessor возвращает тот же тип и дефолт, что заменяемый метод (кроме изменений, перечисленных в §А и UPGRADE.md).
- `config()->set()` в тестах продолжает работать: никакого кэширования значений в объектах конфига.
- Нормализатор не трогает ключ, если пакет-владелец не установлен; повторный вызов не даёт повторных deprecation.
- Каждая строка §В — свой кейс в dataset `ConfigNormalizerTest` (тест на каждый устаревший ключ, 13 P2.5).
