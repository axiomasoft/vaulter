### P2.6 — Типы новых и переименованных колонок

**Intent:** Каждая колонка-ключ, созданная или переименованная в P2 (REF — ссылка на PK Vaulter по `ids.strategy`, HK —
ключ хоста по `ids.host_keys`), имеет тип 08 §2 при любой стратегии на свежей установке и после upgrade; расхождения
фактической схемы с ожидаемой перечисляет внутренний `KeyColumnInspector`, который doctor P7.1 обернёт в проверку
`core.schema.key_types` (R16).

**Why:** OPUS 13 P2.6, 08 §2, AD25; 03 §7 «Типы колонок-ключей хоста — D25». P1.7 типизировал HK-колонки 0.2; P2.7 добавил
REF/HK-колонки (`drive_id` ×4, `file_revision_id`, `target_node_id`, `result_node_id`, `result_revision_id`,
`v_outbox.drive_id`) и строковые (`aggregate_id varchar(64)`, `event_id varchar(26)`, `profile varchar(64)`).

**Scope Included:**
1. `packages/core/src/Schema/KeyColumnInspector.php` (new, `final class`, внутренний — `@internal`): конструктор
   `(VaulterDatabase $db, DatabaseConfig $database, IdsConfig $ids)`; `expected(): list<KeyColumnExpectation>` — полный список
   пар (таблица-сущность, колонка, вид `REF|HK|STRING`, длина для STRING) для всех HK-колонок P1.7 (27) и колонок п.«Why»;
   `mismatches(): list<KeyColumnMismatch>` — сравнение с `Schema::getColumns()` (`type_name`, длина) по драйверу: REF —
   тип PK стратегии (`IdStrategy::reference()`-эквивалент: bigint → `bigint`/`bigint unsigned`, ulid → `char(26)`/`bpchar`,
   uuid7 → `uuid`/`char(36)`), HK — `HostKeyColumns::sqlType()`, STRING — `varchar(N)`. Отсутствующая таблица/колонка —
   mismatch вида `missing`. Value objects `packages/core/src/Schema/ValueObjects/{KeyColumnExpectation,KeyColumnMismatch}.php`
   (`final readonly`).
2. Тесты `packages/core/tests/Schema/KeyColumnTypesTest.php` (dataset): для `ids.strategy` ∈ {bigint, ulid, uuid7} ×
   `ids.host_keys` ∈ {string, bigint} на fresh `migrate` (SQLite-драйвер — пропуск только этого теста с причиной
   «динамическая типизация»; PG и MySQL обязательны) → `mismatches() === []`. Upgrade: в `Canon03UpgradeTest` (P2.7) после
   `migrate` обоих дампов → `mismatches() === []`.
3. Если ожидаемый тип колонки по 08 §2 расходится с тем, что создаёт `SchemaBuilder` после P2.7, — исправление в
   `SchemaBuilder` и шагах миграции P2.7 (№2/№4/№9) в этом item с тестом; изменение решения 08 §2 — стоп и эскалация.

**Scope Excluded:** команда и `DoctorCheck` `core.schema.key_types` (P7.1); колонки `v_documents`/`v_document_revisions`/
`owned_by`/`sequence` (P4.1, P4.7 — их items дополняют `expected()`).
