### P0.3 — Фикстура данных 0.2

**Intent:** Воспроизводимо сгенерировать из кода тега `v0.2.0` дампы БД, содержащие все формы данных, которые
upgrade-миграции 0.2 → 0.3 (OPUS 08 §3) обязаны перенести или отвергнуть, для PostgreSQL, каждая — в стратегиях ID bigint и ulid (OPUS 13 P0.3: «drives (bigint/ulid)… дамп для PG и MySQL»; MySQL-часть — отказ D09: тег `v0.2.0` не устанавливается на MySQL 8).

**Why:** OPUS 13 P0.3; V15 (upgrade на фикстуре), V14 (`repair-scopes` на `legacy:snull`), миграции №1 (preflight), №5
(документы: все `format`), №6 (ремонт N04 «вторых корней»), №7 (`scope_key`), №8 (soft-deleted grants/shares); D02 п.3
(Q2: данные 0.2 возможны → строгие миграции обязательны).

**Implementation Rules:**
- Первые команды item (читают код тега без checkout): `git show v0.2.0:packages/core/config/vaulter.php` (блоки `ids`,
  `dedup`, `tenant`, `table_names`), `git show v0.2.0:packages/documents/src/Enums/Documents/DocumentType.php` (4 значения:
  `richtext`, `table`, `markdown`, `template`), `git ls-tree -r --name-only v0.2.0 packages/core/database packages/drive/database packages/documents/database`
  (миграции и фабрики 0.2). Имена таблиц в запросах Validation — из этих миграций.
- Сидер работает только против кода worktree `v0.2.0`; импорт классов текущего `main` запрещён.
- Исходная схема неизменна (D07): `PanelTablesBuilder::defineStorages` использует стратегию Vaulter для owner_id;
  `Schema/AutoIncrementIds::reference` создаёт unsignedBigInteger, `Schema/UlidIds::reference` — char(26).
  Поэтому bigint-дампы используют только `1/2/3`, ulid-дампы — три ULID из Scope. Сырые INSERT не обходят типы.
  Проверка произвольных строковых HK в bigint-схеме принадлежит P1.7/V23 после host-key migration; если исходная
  схема или типы расходятся с этими якорями тега — стоп и описание расхождения, схему фикстуры не менять.
- Старт — `scripts/db-preflight.sh pgsql` (MySQL-дампов нет по D09: `v0.2.0` не устанавливается на MySQL 8).
- Детерминизм обязателен: два последовательных запуска дают байт-идентичные файлы; источник недетерминизма (время,
  ULID, порядок строк, sequence) устраняется в сидере/флагах дампа, не пост-обработкой `sed`.
- Сырой SQL — только для форм, которые API 0.2 не создаёт (второй корень N04, soft-deleted строки, blobs с NULL-областью),
  с комментарием «почему».
- `build/` не коммитится (в `.gitignore`).

**Code Guidance:** проверка детерминизма —
`scripts/fixtures/make-v0.2-dump.sh && cp -r tests/fixtures/v0.2.0 build/fx1 && scripts/fixtures/make-v0.2-dump.sh && diff -r build/fx1 tests/fixtures/v0.2.0`
→ пусто. Формат строки `--verify`: `pgsql-bigint.sql: v_storages=3 v_nodes=31 v_file_versions=9 … OK`.

**Validation:**
- `scripts/fixtures/make-v0.2-dump.sh --verify` → exit 0; для каждого дампа строка `… OK`.
- Проверка детерминизма из Code Guidance → `diff -r` пусто.
- `grep -c "legacy\|parent_id" tests/fixtures/v0.2.0/README.md` ≥ 1 и таблица состава совпадает со Scope п.4 (ревью).
- На `pgsql-bigint.sql`: `SELECT count(*) FROM v_nodes WHERE parent_id IS NULL` > число storages (есть «второй корень»);
  `SELECT count(*) FROM v_node_grants WHERE deleted_at IS NOT NULL` ≥ 1; есть blobs с `storage_id IS NULL` — запросы и
  результаты в Completion Notes (имена таблиц — по фактической схеме v0.2.0).
- `--verify` в каждом из двух основных дампов проверяет ровно три storage и множество owner_id:
  bigint — `{1, 2, 3}`, ulid — три значения Scope. Совпадение типов/значений → exit 0; иной состав → exit 1.
- `bash -n scripts/fixtures/make-v0.2-dump.sh`; `scripts/php84 vendor/bin/pint --test scripts/fixtures` exit 0.
- Independent review: full (reviewer из `execution-sheet/v1`, строка B0-A) — проверяет покрытие форм 08 §3.
