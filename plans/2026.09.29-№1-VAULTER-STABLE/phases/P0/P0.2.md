### P0.2 — Харнесс конкурентности PostgreSQL

**Intent:** Дать всем пакетам один харнесс, который запускает N операций в **отдельных процессах на отдельных соединениях**
PostgreSQL, отпускает их барьером одновременно и возвращает исходы; доказать его пример-тестом и негативным контролем
(воспроизведённый lost update без блокировки) и включить в PG-лейн CI.

**Why:** OPUS 13 P0.2; сценарии V02, V03, V13, V17, V19, V20, V21 (P1.1, P1.2, P1.5, P1.6) требуют реальной гонки — SQLite
сериализует записи. Сейчас fork+барьер скопирован в `packages/drive/tests/Concurrency/TusConcurrentPatchTest.php`,
`TusPatchVsSweepRaceTest.php` и `packages/core/tests/Webhooks/ConcurrentDeliveryTest.php` (разные реализации); CI-лейн
`tests.yml:test-pgsql` ставит расширения `mbstring, pdo, pdo_pgsql, pgsql` — без `pcntl`/`posix` такие тесты пропускаются.

**Scope Included:**
1. `packages/core/tests/Concurrency/ForkRace.php` (namespace `Vaulter\Tests\Concurrency`, `final class`):
   - `public static function supported(?string $connection = null): bool` — драйвер соединения `pgsql` и есть
     `pcntl_fork`, `posix_kill`;
   - `public static function skipUnlessSupported(\PHPUnit\Framework\TestCase $test, ?string $connection = null): void`;
   - `/** @param list<\Closure(): mixed> $tasks @param list<string> $connections @return list<RaceOutcome> */
     public static function run(array $tasks, array $connections = [], int $timeoutMs = 10_000): array`.
   Алгоритм: временный каталог `sys_get_temp_dir()/vlt_race_<pid>_<rand>`; на каждую задачу `pcntl_fork`; **ребёнок** —
   `DB::purge()`+`DB::reconnect()` для каждого соединения из `$connections` (пусто → default), файл `ready.<i>`, ожидание
   `ready.*` = N (шаг 200 мкс, по истечении `$timeoutMs` — исход `barrier-timeout`), вызов задачи, запись
   `result.<i>` JSON `{ok, value, exception, message}` (`value` — только JSON-сериализуемое, иначе `exception =
   'ForkRace\\UnserializableValue'`), `posix_kill(getmypid(), SIGKILL)`; **родитель** — `pcntl_waitpid` с дедлайном
   `$timeoutMs + 5000` (просроченного ребёнка — `SIGKILL`, исход `timeout`), `DB::purge`+`reconnect` своих соединений,
   чтение результатов в порядке задач, удаление каталога.
2. `packages/core/tests/Concurrency/RaceOutcome.php` — `final readonly class RaceOutcome(bool $ok, mixed $value,
   ?string $exception, ?string $message)` + `public function failedWith(string $class): bool` (сравнение FQCN,
   `is_a($this->exception, $class, true)`).
3. `packages/core/tests/Concurrency/ForkRaceTest.php` (4 теста, каждый начинается `ForkRace::skipUnlessSupported($this)`):
   - **сериализация**: таблица `race_counter(id int pk, value int)` со строкой `(1, 0)`; две задачи в транзакции
     `SELECT value … FOR UPDATE` → `usleep(200_000)` → `UPDATE value = value + 1` → итог `2`, обе `ok`;
   - **негативный контроль (lost update)**: те же задачи без `FOR UPDATE`, запись `value = <прочитанное> + 1` → итог `1`
     — харнесс действительно даёт перекрытие;
   - **изоляция соединений**: задачи возвращают `select pg_backend_pid()` → два разных pid, оба ≠ pid родителя;
   - **исключение**: задача бросает `RuntimeException('boom')` → `ok=false`, `failedWith(RuntimeException::class)`,
     `message === 'boom'`; вторая задача — `ok`.
   Таблица создаётся/удаляется в тесте через `Schema::create`/`dropIfExists`.
4. `tests/Pest.php`: `uses(TestCase::class, DatabaseMigrations::class)->in($core.'/Concurrency');` (коммит фикстур виден
   детям; `RefreshDatabase` скрыл бы их транзакцией).
5. `packages/media/composer.json` `autoload-dev.psr-4`: `"Vaulter\\Tests\\": "../core/tests/"` (как у drive/documents) —
   чтобы V13 (P1.5) использовал харнесс.
6. CI: в `setup-php` jobs `tests.yml:test-pgsql`, `drive.yml:drive-pgsql`, `media.yml:media-pgsql`,
   `documents.yml:documents-pgsql` добавить `pcntl, posix` там, где их нет.
7. `CONTRIBUTING.md` — раздел «Тесты конкурентности»: когда нужен PG, пример `ForkRace::run`, команда локального прогона.

**Scope Excluded:** перевод существующих конкурентных тестов drive/webhooks на харнесс (делается пунктом P1, который их

**Authority:** routine

**Implementation Rules:**
- Ребёнок никогда не возвращается в PHPUnit: только `SIGKILL` самому себе (иначе дубль вывода и teardown).
- Родитель не использует унаследованный PDO после fork без `purge`+`reconnect`.
- Проверка `str_ends_with(DB::connection()->getDatabaseName(), '_test')` в `run()` — иначе `LogicException` (защита от
  прогона на рабочей БД).
- Задержка `usleep(200_000)` — только в тестах харнесса; сам харнесс синхронизирует только барьером.
- Стиль — существующие тесты core (Pest `it(...)`, `declare(strict_types=1)`, русские описания допустимы).

**Code Guidance:**

```php
$outcomes = ForkRace::run([
    fn () => DB::transaction(fn () => bump(lock: true)),
    fn () => DB::transaction(fn () => bump(lock: true)),
]);
expect(array_map(fn (RaceOutcome $o) => $o->ok, $outcomes))->toBe([true, true])
    ->and(DB::table('race_counter')->value('value'))->toBe(2);
```

Негативный контроль обязан падать при «сломанном» харнессе: временно заменить барьер на последовательный запуск
(дети по очереди `pcntl_waitpid` сразу после fork) → тест lost update краснеет (`2` вместо `1`); результат — строка в
Completion Notes, правка откатывается.
