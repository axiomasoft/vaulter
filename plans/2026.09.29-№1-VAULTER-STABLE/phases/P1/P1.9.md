### P1.9 — Стеки middleware и отказ от глобальных биндингов

**Intent:** Защищённые маршруты, публичные share-ссылки и server-to-server колбэки хаба получают три независимых стека
middleware, а параметры `{storage}`/`{node}` резолвятся только внутри маршрутов Vaulter — хост может добавить
`auth:sanctum`, не ломая публичные ссылки и хаб, и его собственные маршруты `{node}` не задеваются (N09, N10).

**Why:** OPUS 13 P1.9, 10 §2–§3, AD31 (часть); V25, V26. Сегодня все маршруты оборачиваются одним
`Config::middleware()` (`packages/core/routes/api.php:22–23`, `packages/drive/routes/drive.php:27–28`,
`packages/documents/routes/documents.php:27–28`), а `VaulterServiceProvider::registerRouteBindings()`
(`packages/core/src/VaulterServiceProvider.php:395–408`) регистрирует `Route::bind('storage'|'node')` для всего приложения.

**Scope Included:**
1. Конфиг `packages/core/config/vaulter.php`: удалить ключ `'middleware' => ['api', RecordVaulterRequestMetrics::class]`
   (строки 712–715) и добавить
   `'routes' => ['middleware' => ['authenticated' => ['api', 'auth:sanctum'], 'public' => ['api'], 'hub' => ['api']]]` (R7)
   с комментарием-блоком в стиле файла. `core/src/Support/Config.php`: `middleware()` удаляется; новые
   `authenticatedMiddleware(): array`, `publicMiddleware(): array`, `hubMiddleware(): array`. `authenticatedMiddleware()`:
   если `config('vaulter.middleware')` не null (опубликованный конфиг 0.2) — это значение, иначе
   `vaulter.routes.middleware.authenticated`. Каждый метод возвращает `stringList(...)` с добавленным в конец
   `RecordVaulterRequestMetrics::class`, если хост его не перечислил (дубликат не добавляется).
2. Маршруты (пути не меняются до P6.1):
   - `packages/core/routes/api.php`: группа `Route::prefix(Config::routePrefix())->middleware(Config::authenticatedMiddleware())`
     для grants/shares(owner)/activity/webhooks; отдельная группа `Route::prefix(Config::routePrefix())->middleware([...Config::publicMiddleware(), 'throttle:vaulter-public', ResolveShareToken::class])`
     для `share/{token}`, `share/{token}/nodes`, `share/{token}/download`;
   - `packages/drive/routes/drive.php`: группа с `Config::authenticatedMiddleware()`; `throttle:vaulter-uploads` для
     загрузок сохраняется;
   - `packages/documents/routes/documents.php`: защищённые маршруты — `Config::authenticatedMiddleware()`; `collab/authenticate`,
     `collab/store` — отдельная группа `[...Config::hubMiddleware(), 'throttle:vaulter-public', ResolveCollaborationCall::class]`
     с тем же условием `featureEnabled('document_versions') && collaborationEnabled()`.
3. Резолв параметров (R6):
   - `packages/core/src/Http/Support/HttpResourceResolver.php` (new, `final readonly`): `storage(int|string $id): Storage`
     (`StorageReadRepository` → не найдено → `StorageNotFoundException::forId`), `node(int|string $id): Node`
     (`NodeReadRepository::find` → не найдено → `NodeNotFoundException::forId`). Исключения — из P1.8. Ни один текущий
     маршрут не содержит одновременно `{storage}` и `{node}` (пути — `storages/{storage}/…` или `nodes/{node}/…`), поэтому
     проверка вложенности не нужна до P6.1.
   - `packages/core/src/Http/Middleware/ResolveVaulterRouteParameters.php` (new): для текущего маршрута, если параметр
     `storage` скалярный → `setParameter('storage', $resolver->storage(...))`; если `node` скалярный →
     `setParameter('node', $resolver->node(...))`. Добавляется во все группы п.2, где есть `SubstituteBindings`.
   - `VaulterServiceProvider`: удалить `registerRouteBindings()` и его вызов (строка 276); в `boot()` —
     `$kernel = $this->app->make(\Illuminate\Contracts\Http\Kernel::class); if ($kernel instanceof \Illuminate\Foundation\Http\Kernel) { $kernel->addToMiddlewarePriorityBefore(SubstituteBindings::class, ResolveVaulterRouteParameters::class); }`.
   - Сигнатуры контроллеров (`Storage $storage`, `Node $node`) не меняются: параметр уже модель, `SubstituteBindings` его не трогает.
4. Тесты:
   - V25 — `packages/documents/tests/Feature/MiddlewareStacksTest.php` (documents видит core-share и hub-маршруты):
     `laravel/sanctum` в `require-dev` `packages/documents/composer.json` (`^4.0`); конфиг
     `vaulter.middleware = null`, `vaulter.routes.middleware.authenticated = ['api', 'auth:sanctum']`; (а) `GET storages/{id}/nodes`
     без токена → 401; с `Sanctum::actingAs($user)` → 200; (б) `GET share/{token}` действующей ссылки без токена → 200;
     (в) `POST collab/authenticate` с валидным hub-JWT без токена → не 401 (ответ контроллера). Негативный контроль:
     временно добавить `Config::authenticatedMiddleware()` в группу share → (б) 401.
   - V26 — `packages/drive/tests/Feature/HostRouteBindingTest.php`: тестовая модель хоста `HostProject` (таблица
     `host_projects` создаётся в тесте) и маршрут `Route::get('/projects/{node}', fn (HostProject $node) => $node->getKey())`
     с `SubstituteBindings` → ответ — ключ `HostProject`; негативный контроль — временно вернуть `Route::bind('node', …)` → красный.
   - Резолвер (`packages/drive/tests/Feature/HostRouteBindingTest.php`): `GET storages/{несуществующий}/nodes` → 404,
     `json('code') = 'drive_not_found'`; `GET nodes/{несуществующий}` → 404, `json('code') = 'node_not_found'`.
   - Наследие: конфиг с `vaulter.middleware = ['api']` → применяется к защищённым маршрутам (`Config::authenticatedMiddleware()`
     = `['api', RecordVaulterRequestMetrics::class]`).
