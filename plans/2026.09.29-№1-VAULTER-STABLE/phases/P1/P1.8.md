### P1.8 — Нет HTTP 500 для доменных ошибок

**Intent:** Каждое доменное исключение Vaulter несёт стабильный машинный код и HTTP-статус из OPUS 10 §6 и
рендерится JSON-ответом `{message, code}` с этим статусом; ни одно доменное исключение не даёт 500 (N11, V24).

**Why:** OPUS 13 P1.8, AD29 (часть T0), 05 §11, 10 §6; V24. Сегодня `render()` есть у 7 из 26 исключений
(`CycleException`, `CrossStorageMoveException`, `NotADocumentNodeException`, … дают 500), тесты это закрепляют
(`packages/documents/tests/Document/DocumentNodeApiTest.php:98`, `packages/documents/tests/Collaboration/NodeCollaborationTokenTest.php:114`).
P1.2 (`InvalidDestinationException`, `NodeNotTrashedException`) и P1.9 (`NodeNotFoundException`) опираются на этот контракт.

**Scope Included:**
1. `packages/core/src/Exceptions/Contracts/ProblemException.php` — `interface ProblemException { public function problemCode(): string; public function httpStatus(): int; }`
   (`problemDetails()` добавляет P6.2).
2. `packages/core/src/Exceptions/VaulterException.php`: метод `render(Illuminate\Http\Request $request): JsonResponse|false` (R5):
   если `$this` не `ProblemException` → `false`; если не `$request->expectsJson()` и не `$request->is(trim(Config::routePrefix(), '/').'/*')` → `false`;
   иначе `new JsonResponse(['message' => $this->getMessage(), 'code' => $this->problemCode()] + $this->renderExtras(), $this->httpStatus())`,
   где `protected function renderExtras(): array` по умолчанию `[]`. Метод `docs()` не меняется (URL — P1.11).
3. Каждое исключение ниже реализует `ProblemException` (константы кода/статуса в классе). Существующие `render()` удаляются;
   их дополнительные ключи переносятся в `renderExtras()` (`NodeNameConflictException` — `['errors' => ['name' => [$this->getMessage()]]]`,
   `OffsetMismatchException` — его текущие поля тела и заголовки tus сохраняются: заголовки — через переопределённый `render()`,
   который вызывает `parent::render()` и добавляет те же заголовки):

   | Класс (текущее имя) | Код | HTTP |
   |:--|:--|:--|
   | `Vaulter\Exceptions\Access\PermissionDeniedException` | `permission_denied` | 403 |
   | `Vaulter\Exceptions\Nodes\NodeNameConflictException` | `node_name_conflict` | 409 (было 422) |
   | `Vaulter\Drive\Exceptions\CycleException` | `node_move_cycle` | 409 |
   | `Vaulter\Drive\Exceptions\CrossStorageMoveException` | `cross_drive_operation` | 409 |
   | `Vaulter\Drive\Exceptions\QuotaExceededException` | `quota_exceeded` | 413 |
   | `Vaulter\Drive\Exceptions\UploadConflictException` | `upload_conflict` | 409 |
   | `Vaulter\Drive\Exceptions\StagedUploadMissingException` | `upload_conflict` | 409 |
   | `Vaulter\Drive\Exceptions\OffsetMismatchException` | `upload_offset_mismatch` | 409 |
   | `Vaulter\Drive\Exceptions\UploadContentMismatchException` | `upload_rejected` (`renderExtras`: `['reason' => 'mime_mismatch']`) | 422 (было 415) |
   | `Vaulter\Documents\Exceptions\NotADocumentNodeException` | `not_a_document` | 409 |
   | `Vaulter\Documents\Exceptions\UnknownDocumentTypeException` | `unknown_document_type` | 422 |
   | `Vaulter\Documents\Exceptions\InvalidTipTapContentException` | `invalid_document_content` (`reason` = `'invalid_tiptap'`) | 422 |

   | `Vaulter\Exceptions\Access\UnenumerableGrantSubjectException` | `validation_failed` (`errors.subject_type`) | 422 |
   | `Vaulter\Exceptions\Panels\UnknownPanelException` | `unknown_profile` | 422 |
   | новый `Vaulter\Exceptions\Nodes\NodeNotFoundException` (`forId(int|string $id)`) | `node_not_found` | 404 |
   | новый `Vaulter\Exceptions\Nodes\StorageNotFoundException` (`forId(int|string $id)`) | `drive_not_found` | 404 |

   умолчанию Laravel): `MissingHostRoleDriverException`, `InvalidPanelException`, `UnknownIdStrategyException`,
   `MissingPackageException`, `TenantIsolationNotConfiguredException`, `CollaborationConfigException`,
   `WebhookResponseTooLargeException` (только в фоне доставки). Новые исключения P1.2/P1.9 реализуют контракт сразу.
4. `docs/guide/errors.md` — таблица «код → HTTP → исключение» для строк п.3; `CHANGELOG.md [Unreleased]` (Changed:
   `node_name_conflict` 422 → 409, `upload_content_mismatch` 415 → 422 `upload_rejected`; Fixed: N11); `UPGRADE.md`
   (те же «было → стало», AD29); golden `PublicApiSnapshotTest`.
5. Тест V24 — `packages/documents/tests/Document/DomainExceptionStatusTest.php`: dataset из всех 20 классов таблицы п.3
   (экземпляр через именованный конструктор каждого класса); тестовый маршрут под `Config::routePrefix().'/__v24'`,
   бросающий экземпляр; `getJson` → статус из таблицы, `json('code')` = код, статус ≠ 500. Плюс arch-тесты
   «реализует `ProblemException`» в `packages/core/tests/Arch/ArchTest.php` (`Vaulter\Exceptions\*`),
   `packages/drive/tests/Arch/ArchTest.php` (`Vaulter\Drive\Exceptions\*`) и `packages/documents/tests/Arch/ArchTest.php`
   (`Vaulter\Documents\Exceptions\*`), с `->ignoring([...])` ровно для списка «не доменные» п.3 и базового `VaulterException`.
6. Тесты, закреплявшие старые статусы, переписываются на статус и код таблицы: `DocumentNodeApiTest.php:98`,
   `NodeCollaborationTokenTest.php:114` (500 → 409 `not_a_document`) и каждый тест, который упадёт в гейтах пакетов
   только из-за статуса/тела исключения из п.3 (422 конфликта имени → 409 + `code`; 415 → 422).

**Implementation Rules:**
- Коды — ровно из таблицы п.3 (это SemVer-контракт OPUS 10 §6); новый код вне таблицы — стоп и эскалация.
- Текст `getMessage()` не меняется.
- Изменение теста допустимо только если он падает из-за статуса/тела исключения таблицы п.3; любое другое падение —
  стоп и описание.
- PHP-вызов (не HTTP) получает то же исключение, что и раньше: `render()` влияет только на HTTP.
