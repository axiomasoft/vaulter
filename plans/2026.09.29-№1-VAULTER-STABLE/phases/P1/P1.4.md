### P1.4 — Идентичность событий в outbox

**Intent:** Каждое доменное событие получает собственный `eventId` (ULID) при создании, и outbox идемпотентен только по
этому occurrence id: разные команды никогда не схлопываются, повтор того же события — одна строка (E8, V06).

**Why:** OPUS 13 P1.4, AD22 (идентичность — T0); V06. Сегодня `event_id` — ключ состояния
(`packages/drive/src/Webhooks/RecordsDriveOutbox.php:151` `node.renamed:{id}:{name}`, `:185` `node.trashed:{id}`,
`packages/core/src/Webhooks/OutboxRecorder.php:50–115`), поэтому `A→B→A→B` даёт 2 строки rename вместо 3, а
`trash→restore→trash` — 2 строки lifecycle вместо 3.

**Scope Included:**
1. Все 23 класса событий (`find packages/core/src/Events packages/drive/src/Events packages/documents/src/Events -name '*.php' | wc -l` → `23`)
   получают публичное readonly-свойство `public string $eventId;` и последний параметр конструктора
   `?string $eventId = null`; тело конструктора: `$this->eventId = $eventId ?? (string) \Illuminate\Support\Str::ulid();`.
   Остальные параметры и их порядок не меняются (именованные аргументы во всех `new <Event>(…)` остаются валидными).
2. `packages/core/src/Webhooks/OutboxRecorder.php`: `stage(…, string $key, …)` → параметр переименовывается в
   `string $eventId`; проверка `where('event_id', $eventId)->exists()` и запись `event_id`/`payload.event_id` — этим значением.
   Методы `recordGrantCreated|recordGrantRevoked|recordShareCreated|recordShareRevoked` передают `$event->eventId`.
3. `packages/drive/src/Webhooks/RecordsDriveOutbox.php`: все 10 обработчиков с `key:` (`handleStorageCreated` … `handleNodeForceDeleted`)
   передают `eventId: $event->eventId` вместо строковых `key:` (строки 62, 78, 96, 115, 134, 151, 168, 185, 201, 224);
   state-ключи удаляются вместе с `md5(implode(…))` для force-delete.
4. Тест V06 — `packages/drive/tests/Feature/OutboxEventIdentityTest.php` (SQLite достаточно): при включённой фиче
   `reliability` (`Config::featureEnabled('reliability')` подписывает outbox-подписчиков) — (а) rename A→B→A→B через `DriveContext::rename` → в `Config::table('outbox')` ровно 3 строки
   с topic rename, `event_id` попарно различны и каждый — 26-символьный ULID; (б) trash→restore→trash → 3 строки
   lifecycle (2 trashed + 1 restored), различные `event_id`; (в) повторная отправка одного и того же объекта события
   (`event($e)` дважды) → 1 строка. Тест в `packages/core/tests/Webhooks/OutboxStagingTest.php`: grant created/revoked
   дважды с одинаковыми параметрами → 2 + 2 строки (раньше revoked схлопывался ключом subject).
   Повтор доставки: существующий `packages/core/tests/Webhooks/OutboxRelayTest.php` дополняется проверкой, что повторный
   relay/retry одной строки отправляет тот же `event_id` в теле.
5. `CHANGELOG.md [Unreleased]` (Fixed: E8; Changed: `event_id` — ULID события, не ключ состояния), `UPGRADE.md`
   (потребители webhooks дедуплицируют по `event_id`, значения теперь ULID), golden `PublicApiSnapshotTest`
   (публичные свойства событий).
