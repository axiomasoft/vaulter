### P1.1 — Соединение Vaulter для транзакций и блокировок

**Intent:** Все транзакции, блокировки и after-commit колбэки Vaulter идут через одно соединение
`Vaulter\Database\VaulterDatabase`, совпадающее с соединением моделей и схемы, так что настроенный
`vaulter.connection ≠ default` не лишает операции атомарности (N01, D25).

**Why:** OPUS 13 P1.1, 08 §4, AD25; V17. Сегодня модели и схема читают `vaulter.connection`
(`core/src/Models/Concerns/ResolvesVaulterConnection.php`, `core/src/Schema/PanelTablesBuilder.php:43–56`), а ~45 файлов
`src` вызывают `DB::transaction`/`DB::connection()`/`DB::statement` на соединении по умолчанию
(`core/src/Cas/BlobLock.php:92` берёт advisory lock на чужой сессии). P1.2, P1.5, P1.6 строятся на этом классе.

**Scope Included:**
1. `packages/core/src/Database/VaulterDatabase.php` — `final class VaulterDatabase` (singleton в
   `VaulterServiceProvider::register()`), конструктор `(Illuminate\Database\DatabaseManager $db)`:
   - `connection(): Illuminate\Database\Connection` → `$this->db->connection(Config::connection())` (R1: ключ
     `vaulter.connection`, null = соединение по умолчанию);
   - `driver(): string` → `$this->connection()->getDriverName()` (`pgsql|mysql|mariadb|sqlite`);
   - `transaction(Closure $callback, int $attempts = 3): mixed` → `$this->connection()->transaction($callback, $attempts)` (R4);
   - `lockTree(int|string $storageId): void` — требует открытую транзакцию на этом соединении (`transactionLevel() > 0`,
     иначе `LogicException('[Vaulter] lockTree() must run inside VaulterDatabase::transaction().')`); PG:
     `SELECT pg_advisory_xact_lock(hashtext(?))` с ключом `'vaulter:tree:'.$storageId`; mysql/mariadb/sqlite:
     `SELECT id FROM <Config::table('storages')> WHERE id = ? FOR UPDATE` (SQLite — тот же запрос без `FOR UPDATE`,
     писатель и так единственный). Имя параметра — `$storageId` (текущее имя; канон `driveId` — P2.1);
   - `advisoryLock(string $key): void` — то же требование транзакции; PG: `SELECT pg_advisory_xact_lock(hashtext(?))`
     с `$key`; иначе no-op (MySQL — `FOR UPDATE` строки в вызывающем, SQLite — единственный писатель; поведение
     `BlobLock` сохраняется);
   - `afterCommit(Closure $callback): void` → `$this->connection()->afterCommit($callback)`.
2. `core/src/Cas/BlobLock.php`: зависимость `VaulterDatabase`; `acquire()` → `advisoryLock($scope.'|'.$sha256)`
   (формат ключа не меняется до P1.5); `driver()` → `VaulterDatabase::driver()`.
3. Замена фасада `DB` во всех файлах `src` кроме `core/src/Database/` и `core/src/Schema/`: `DB::transaction(` →
   `$this->database->transaction(`; `DB::connection()`/`DB::table()`/`DB::statement()`/`DB::select()`/`DB::raw()` →
   `$this->database->connection()->…`; `DB::afterCommit(` → `$this->database->afterCommit(`. `VaulterDatabase` внедряется
   конструктором (readonly-классы — новым promoted-параметром `private VaulterDatabase $database`). Ожидаемый инвентарь —

   `Repositories/Drive/NodeStoreRepository.php`; drive — `Repositories/Uploads/{UploadPartStoreRepository,UploadSessionStoreRepository}.php`,

   `Actions/Uploads/CommitUploadAction.php`, `Actions/{UploadFileAction,TrashNodeAction,RestoreNodeAction,RenameNodeAction,MoveNodeAction,ForceDeleteNodeAction,CreateFolderAction,CopyNodeAction}.php`,
   `Models/Uploads/UploadPart.php`; documents —

**Implementation Rules:**
- Семантика операций не меняется: только соединение. Порядок и границы существующих транзакций сохраняются.
- `transaction()` вкладывается так же, как `DB::transaction` (Laravel savepoints); ретраи — только внешней транзакции.
- После замены ни один файл `src` вне `core/src/Database/` и `core/src/Schema/` не содержит `Illuminate\Support\Facades\DB`
  (проверка — Code Guidance п.1 печатает пусто).
- `RecordsOutbox::safely()` и `RecordsDriveOutbox::safely()` сохраняют поведение «ошибка outbox логируется, мутация не
  откатывается» (изменение — P5.1, Q8).
- Если инвентарь Code Guidance п.1 до правки печатает файл вне списка Scope п.3 — стоп и описание расхождения.

**Code Guidance:**
1. Инвентарь: `grep -rlE 'Facades\\DB\b|\bDB::' packages/*/src --include=*.php | grep -v -e '^packages/core/src/Database/' -e '^packages/core/src/Schema/' | sort`
   до правки → ровно 44 файла Scope п.3; после → пусто.
2. V17 (`DedicatedConnectionTest`, PG, `ForkRace::skipUnlessSupported($this)`): в `getEnvironmentSetUp` добавить
   соединение `vaulter` = копия `database.connections.pgsql`, `vaulter.connection = 'vaulter'`; (а) действие
   `CreateFolderAction` с подменённым `NodeStoreRepository`, бросающим после `create()`, → строк в `Config::table('nodes')`
   через соединение `vaulter` не прибавилось; (б) внутри `VaulterDatabase::transaction()` вызвать `BlobLock::acquire('s1', str_repeat('a', 64))`
   и в том же замыкании выполнить на соединении `vaulter`
   `SELECT count(*) FROM pg_locks WHERE locktype = 'advisory' AND pid = pg_backend_pid()` → `1`, а на соединении `pgsql`
   тот же запрос → `0`. Негативный контроль: временно вернуть в `BlobLock::acquire()` вызов `DB::statement(...)` — тест (б) красный.
