## Findings

**1. Major — repair and GC mark acquire the same CAS locks in opposite orders.** `packages/media/src/Console/RepairBlobScopesCommand.php:120-123` vs `packages/media/src/Cas/BlobGarbageCollector.php:344-346`. Introduced.

`commit`, sweep, and orphan prune each take one `cas:{scope_key}:{sha256}` lock. Mark is different: on PostgreSQL it locks every candidate in the batch in `hashtext` order inside one transaction. Repair always takes two locks, the legacy source and the target, after `sort(..., SORT_STRING)`.

`ref_count` stays 0 until reconcile, including blobs that already have edges, so both rows are normal mark candidates. After the upgrade this is the usual mixed state: a `legacy:snull` or `legacy:tnull` blob, and a `drive:{id}` or `tenant:{id}` blob for the same sha256 created by a new upload or an older numeric row.

Trigger: `vaulter:gc-blobs` during `vaulter:blobs:repair-scopes --execute`, with both rows in one mark batch of 1000 and `hashtext('cas:legacy:…')` ordered opposite to `hashtext('cas:drive:…')` (about half of pairs; `drive:` sorts before `legacy:`). Mark holds the legacy key and waits for the drive key. Repair holds the drive key and waits for the legacy key. PostgreSQL aborts one transaction with `40P01`. Mark has no deadlock retry, so the GC batch fails. Repair retries the whole copy up to three times and can still exit 1. The rolled-back transaction does not drop bytes, but both operators stop. On MySQL the advisory lock is a no-op; the same window deadlocks when the target row id is lower than the source id, because repair locks the source row and then the target row, while mark locks the batch by primary key.

`commit` against repair does not deadlock: a writer takes only one CAS lock, and both sides take the tree lock before any CAS lock.

**2. Minor — required V14 dry-run check is not what the test asserts.** `packages/media/tests/Cas/RepairBlobScopesCommandTest.php:12663`. Introduced test gap, not a product logic bug by itself.

The spec says a `legacy:snull` blob with edges in storages A and B prints two `move` rows. The test only checks that the output contains the substring `move`. One row would still pass. The command does group by target key, so two storages should produce two rows, but the acceptance test does not lock that.

**3. Minor — the guide’s opening diagram still shows only the old key.** `docs/guide/storage-and-blobs.md` (mental model: `"<scope>/ab/cd/<sha256>"`). The later scope section is correct (`g|t-|d-` plus the legacy two-shard layout). `ContentStore::keyFor`’s docblock still describes only `ab/cd`. Operators following the diagram will misread new paths. Not a runtime bug.

## What holds

`BlobScope` keeps ids as raw strings. UUID, ULID, leading zeroes, `/`, and `équipe` round-trip; non-canonical segments are rejected. The unit tests for that passed on PostgreSQL (20 passed in `upgrade-unit-pg`, including migration №7 on the bigint and ulid fixtures).

New commits lock and insert on `scope_key`, not nullable `tenant_id`/`storage_id`. `forUpload` maps null tenant to `global()` and does not use `is_numeric`. Existing rows keep their `storage_key` and `disk`. Re-promotion writes to the row’s path, not to a newly computed `keyFor`, so old `global/…` and `t12/…` objects stay authoritative. Orphan decisions use that full path, then `keyFor(fromSegment(segment), sha) === path`, so a legacy object and a new-layout object for the same `scope_key` are not treated as the same file.

Migration №7 fills `scope_key`, sets NOT NULL, adds `{table}_scope_sha_uniq`, and only then drops `{table}_dedup_uniq`. A unique conflict leaves the old index in place. `down()` restores the dedup index from the current `dedup.scope` before dropping `scope_key`. It does not move objects. `Config::table()` still honors prefix and `table_names`.

Repair is one mode or exit 2, batches of 100, and one transaction per target. It checks the source sha256, copies only through the target row’s path, verifies the target bytes, retargets `file_version_blobs.blob_id` and `file_versions.blob_id`, recounts `ref_count` from edges, and leaves the old object for GC. `hash_mismatch` does not set the failure exit. A thrown copy is exit 1 and a later `--execute` only sees edges that are still on the legacy blob. `legacy:tnull` with a null storage tenant becomes `global`. Unreferenced blobs are reported and not changed. The journal line is the specified JSON, written after commit.

### packages/core/src/Cas/BlobLock.php
<?php

declare(strict_types=1);

namespace Vaulter\Cas;

use Vaulter\Database\VaulterDatabase;

/**
 * The per-(scope, sha256) liveness lock (H.3 safety invariant). EVERY transaction
 * that changes the liveness of a content address — upload-commit, GC-mark,
 * GC-sweep — takes this lock as its FIRST statement and makes every liveness
 * decision from rows read AFTER the lock. That is what makes online GC safe
 * against a concurrent re-commit (a commit that wins the lock resurrects a
 * tombstoned blob before the sweep can see it; a sweep that wins the lock
 * re-checks edge existence before deleting).
 *
 * Per driver:
 *  - pgsql : pg_advisory_xact_lock(hashtext(scope||sha256)) — a real mutex held
 *            for the whole transaction, the GC-vs-upload backbone.
 *  - mysql : there is no transaction-advisory lock that survives like PG's, so we
 *            rely on SELECT … FOR UPDATE on the blob row inside the caller's
 *            transaction; this helper is a no-op and BlobStore locks the row.
 *  - sqlite: single-writer — the transaction itself serialises; no-op here.
 *
 * The UNIQUE (scope, sha256) constraint is the portable backbone that holds on
 * ALL three drivers even when this advisory lock is a no-op.
 */
final class BlobLock
{
    public function __construct(private readonly VaulterDatabase $database) {}

    /**
     * Take the per-(scope, sha256) advisory lock for the current transaction.
     * Must be called as the first statement inside $this->database->transaction().
     */
    public function acquire(string $scope, string $sha256): void
    {
        $this->database->advisoryLock('cas:'.$scope.':'.$sha256);
    }

    /**
     * Acquire multiple CAS keys in the database's lock order, including hash
     * collisions. Every operation needing multiple addresses uses this order.
     *
     * @param list<string> $keys full cas:{scope_key}:{sha256} keys
     */
    public function acquireMany(array $keys): void
    {
        if (!$this->isPostgres() || $keys === []) {
            return;
        }

        $this->database->connection()->select(
            'SELECT pg_advisory_xact_lock(lock_key) FROM '
            .'(SELECT DISTINCT hashtext(value) AS lock_key '
            .'FROM jsonb_array_elements_text(CAST(? AS jsonb)) ORDER BY lock_key) AS locks',
            [json_encode($keys, JSON_THROW_ON_ERROR)],
        );
    }

    /**
     * Whether the active connection uses pessimistic row locks (FOR UPDATE) as the
     * lock mechanism — i.e. MySQL/MariaDB. PG uses the advisory lock above; SQLite
     * uses single-writer and ignores FOR UPDATE.
     */
    public function usesRowLock(): bool
    {
        return in_array($this->driver(), ['mysql', 'mariadb'], strict: true);
    }

    /**
     * Whether a critical section that takes this lock but performs NO database WRITE
     * is still serialised against a concurrent transaction by THIS driver.
     *
     * The orphan prune is exactly such a section (it re-reads under the lock, then
     * deletes BYTES off disk — no row write). It is safe only when the lock alone
     * orders it against a concurrent BlobStore::commit of the same content:
     *
     *  - pgsql : pg_advisory_xact_lock() is a real mutex held for the whole tx — a
     *            commit of the same (scope,sha256) blocks on it ⇒ serialised.
     *  - mysql : findByStorageKey(lock: true) issues SELECT … FOR UPDATE, so the
     *            recheck contends with the concurrent INSERT ⇒ serialised.
     *  - sqlite: acquire() is a no-op AND FOR UPDATE is ignored, so a read-only
     *            critical section never engages SQLite's single-writer lock — a
     *            concurrent commit can INSERT the owning row between the recheck and
     *            the byte delete. NOT serialised; the prune must be refused (the GC
     *            is unaffected — it does a real markDeleting() write that forces the
     *            write lock).
     */
    public function serializesCriticalSection(): bool
    {
        return $this->isPostgres() || $this->usesRowLock();
    }

    public function isPostgres(): bool
    {
        return $this->driver() === 'pgsql';
    }

    private function driver(): string
    {
        return $this->database->driver();
    }
}

namespace Vaulter\Contracts\Cas;

use Vaulter\ValueObjects\Cas\BlobScope;

/**
 * The low-level byte side of the CAS (H.3): stage an incoming stream to a local
 * seekable temp file (hashing those durable bytes server-side), then promote the
 * staged bytes to their canonical scope-qualified key. The high-level
 * find-or-create / dedup / GC lifecycle is BlobStore — ContentStore knows only
 * bytes, hashes and keys, never the v_blobs row.
 */
interface ContentStore
{
    /**
     * Drain the incoming stream into a local seekable temp file and recompute its
     * sha256 from the staged bytes (never the live stream / client hash / S3
     * ETag).
     *
     * @param resource $stream
     */
    public function stage(mixed $stream): StagedObject;

    /**
     * Promote staged bytes to the canonical CAS key on the given disk. Idempotent
     * and concurrency-safe: when the object already exists (another uploader of
     * the same bytes won) the promotion is a no-op rather than a fatal — the
     * driver uses If-None-Match: * where supported and treats 412/409 as "already
     * there". After promotion the staged temp file may be discarded.
     */
    public function promote(StagedObject $staged, string $key, ?string $disk = null): void;

    /**
     * A read stream over the canonical object at $key, or null when absent.
     *
     * @return resource|null
     */
    public function get(string $key, ?string $disk = null): mixed;

    public function exists(string $key, ?string $disk = null): bool;

    public function delete(string $key, ?string $disk = null): void;

    /**
     * Build "<scope>/ab/<sha256>" for new scopes, or preserve the legacy
     * "<scope>/ab/cd/<sha256>" layout for legacy scopes.
     * (H.3): the scope segment keeps two dedup scopes from ever sharing one
     * physical object, so one scope's GC can never delete another's live bytes.
     */
    public function keyFor(BlobScope $scope, string $sha256): string;

<?php

declare(strict_types=1);

namespace Vaulter\Media\Cas;

use Illuminate\Database\Eloquent\Builder;
use Illuminate\Database\Eloquent\Collection;
use Illuminate\Database\QueryException;
use Throwable;
use Vaulter\Cas\BlobLock;
use Vaulter\Contracts\Cas\ContentStore;
use Vaulter\Contracts\Observability\MetricsRecorder;
use Vaulter\Database\VaulterDatabase;
use Vaulter\Enums\Cas\BlobStatus;
use Vaulter\Models\Cas\Blob;
use Vaulter\Repositories\Cas\BlobStoreRepository;
use Vaulter\Repositories\Drive\FileVersionBlobStoreRepository;
use Vaulter\Support\Config;

/**
 * Two-phase, race-safe blob GC (H.3). It is ACL-blind — liveness ≠ the viewer's
 * rights, so a node a user cannot see still pins its blob; GC runs as the system
 * with no panel/workspace context.
 *
 *  PHASE 1 (mark): scan committed ∧ ref_count(cache)=0 (reconciliation rebuilds
 *  that cache from the edge table, so a blob qualifies once its last edge is
 *  detached and reconciled), then under the per-(scope,sha256) lock RE-VERIFY no
 *  live edge exists in v_file_version_blobs before tombstoning (grace deadline =
 *  now + grace, armed here so the sweep cannot delete within the grace window).
 *
 *  PHASE 2 (sweep): take tombstoned blobs past grace, RE-VERIFY under the lock
 *  (a resurrection may have flipped them back to committed), → deleting →
 *  physical delete (scope-qualified key, no cross-scope deletion) → deleted
 *  (idempotent tombstone). On PostgreSQL the sweep runs SERIALIZABLE with
 *  retry-on-40001.
 *
 * The advisory lock + UNIQUE (scope, sha256) + resurrection are what make this
 * safe against a concurrent upload-commit: whichever transaction wins the lock
 * acts on rows the other will then re-read; a commit resurrects before a sweep
 * can delete, a sweep that wins re-checks edges before deleting.
 */
final readonly class BlobGarbageCollector
{
    private const int BATCH_SIZE = 1000;

    private const int MAX_SERIALIZATION_RETRIES = 5;

    public function __construct(
        private ContentStore $content,
        private BlobLock $lock,
        private BlobStoreRepository $blobs,
        private FileVersionBlobStoreRepository $edges,
        private MetricsRecorder $metrics,
        private VaulterDatabase $database,
    ) {}

    /**
     * Run both phases and return a per-phase tally.
     *
     * @return array{tombstoned: int, swept: int, skipped: int}
     */
    public function collect(int $graceHours = 0): array
    {
        $grace = Config::gcGraceHours($graceHours);

        $mark = $this->mark(graceHours: $grace);
        $sweep = $this->sweep();

        return [
            'tombstoned' => $mark['tombstoned'],
            'swept' => $sweep['swept'],
            'skipped' => $mark['skipped'] + $sweep['skipped'],
        ];
    }

    /**
     * PHASE 1 — tombstone committed blobs that are genuinely unreferenced.
     *
     * @return array{tombstoned: int, skipped: int}
     */
    public function mark(int $graceHours): array
    {
        $tombstoned = 0;
        $skipped = 0;

        $this->metrics->timing(
            name: 'vaulter_gc_duration_seconds',
            operation: function () use ($graceHours, &$tombstoned, &$skipped): void {
                foreach ($this->candidateBatches(static fn (Builder $q): Builder => $q->garbageCollectable()) as $batch) {
                    $marked = $this->markBatch($batch, $graceHours);
                    $tombstoned += $marked;
                    $skipped += $batch->count() - $marked;

                    $this->metrics->histogram(name: 'vaulter_gc_batch_rows', value: $batch->count());
                    $this->metrics->counter(name: 'vaulter_gc_rows_scanned_total', amount: $batch->count());
                }
            },
            labels: ['phase' => 'mark'],
        );

        return ['tombstoned' => $tombstoned, 'skipped' => $skipped];
    }

    /**
     * PHASE 2 — sweep tombstoned blobs past their grace and physically delete.
     *
     * @return array{swept: int, skipped: int}
     */
    public function sweep(): array
    {
        $swept = 0;
        $skipped = 0;
        $hadBatch = false;

        $this->metrics->timing(
            name: 'vaulter_gc_duration_seconds',
            operation: function () use (&$swept, &$skipped, &$hadBatch): void {
                foreach ($this->candidateBatches(static fn (Builder $q): Builder => $q->sweepable()) as $batch) {
                    $hadBatch = true;
                    $batchSwept = 0;

                    foreach ($batch as $candidate) {
                        $deleted = $this->serializable(fn (): bool => $this->lockedTransaction($candidate, function (Blob $blob): bool {
                            // (the body runs inside a SERIALIZABLE transaction on PG — see
                            // serializable()/lockedTransaction(): the isolation level is set as
                            // the FIRST statement inside the transaction, before the lock.)
                            // A resurrection between scan and lock flips it back to committed —
                            // never delete then.
                            if ($blob->status !== BlobStatus::Tombstoned) {
                                return false;
                            }

                            if ($this->edges->hasLiveEdge($blob)) {
                                return false;
                            }

                            if ($blob->delete_after_at === null || $blob->delete_after_at->isFuture()) {
                                return false;
                            }

                            // Claim it, delete the scope-qualified object, finalise the
                            // idempotent tombstone. A missing object is fine — markDeleted is
                            // idempotent.
                            $this->blobs->markDeleting($blob);
                            $this->content->delete($blob->storage_key, $blob->disk);
                            $this->blobs->markDeleted($blob);

                            return true;
                        }, serializable: true));

                        $deleted ? $batchSwept++ : $skipped++;
                    }

                    $swept += $batchSwept;
                    $this->metrics->histogram(name: 'vaulter_gc_batch_rows', value: $batch->count());
                    $this->metrics->counter(name: 'vaulter_gc_objects_deleted_total', amount: $batchSwept);
                }
            },
            labels: ['phase' => 'sweep'],
        );

        if (!$hadBatch) {
            $this->metrics->counter(name: 'vaulter_gc_objects_deleted_total', amount: 0);
        }

        return ['swept' => $swept, 'skipped' => $skipped];
    }

    /**
     * Sweep PENDING blobs from a crashed staging (H.3): a pending row older than
     * the grace window whose commit never finished and that carries no edge. Its
     * (possibly partial) object is deleted and the row is finalised as a deleted
     * tombstone, all under the lock so a slow-but-live commit is not stolen.
     *
     * @return array{swept: int, skipped: int}
     */
    public function sweepPending(int $graceHours = 0): array
    {
        $grace = Config::gcGraceHours($graceHours);
        $cutoff = now()->subHours($grace);
        $swept = 0;
        $skipped = 0;

        $batches = $this->candidateBatches(static fn (Builder $q): Builder => $q
            ->where('status', BlobStatus::Pending->value)
            ->where('first_seen_at', '<', $cutoff));

        foreach ($batches as $batch) {
            foreach ($batch as $candidate) {
                // Symmetry with sweep() (F-P1.5-02): the pending-sweep runs its unit
                // SERIALIZABLE on PostgreSQL with retry-on-40001, so a transient
                // serialization failure under concurrent GC is retried rather than
                // propagated as a QueryException that aborts the whole pass.
                $acted = $this->serializable(fn (): bool => $this->lockedTransaction($candidate, function (Blob $blob) use ($cutoff): bool {
                    if ($blob->status !== BlobStatus::Pending) {
                        return false;
                    }

                    // A pending row that grew an edge (a commit landing right now) is
                    // live — leave it.
                    if ($this->edges->hasLiveEdge($blob)) {
                        return false;
                    }

                    if ($blob->first_seen_at !== null && $blob->first_seen_at->greaterThanOrEqualTo($cutoff)) {
                        return false;
                    }

                    $this->blobs->markDeleting($blob);
                    $this->content->delete($blob->storage_key, $blob->disk);
                    $this->blobs->markDeleted($blob);

                    return true;
                }, serializable: true));

                $acted ? $swept++ : $skipped++;
            }

            $this->metrics->histogram(name: 'vaulter_gc_batch_rows', value: $batch->count());
        }

        return ['swept' => $swept, 'skipped' => $skipped];
    }

    /**
     * Run a single-blob critical section inside a transaction whose first
     * statement is the per-(scope,sha256) lock, re-reading the row FOR UPDATE on
     * MySQL. The callback receives the locked, fresh row and returns whether it
     * acted.
     *
     * When $serializable is set on PostgreSQL the isolation level is raised as the
     * VERY FIRST statement inside the open transaction block — the only place
     * `SET TRANSACTION` takes effect on PG (issued outside a block it warns and is
     * ignored). It precedes even the advisory lock, which is allowed: SET
     * TRANSACTION only forbids a prior data statement, not a prior SET.
     *
     * The raise is skipped when this is NOT a top-level transaction (transactionLevel
     * > 1) — i.e. the GC unit runs nested inside a caller's open transaction (a host
     * wrapping the sweep, or RefreshDatabase in tests). PostgreSQL forbids changing the
     * isolation level once a transaction has issued a data statement, so SET would 25001;
     * the only valid behaviour is to inherit the enclosing transaction's isolation. The
     * advisory lock + FOR UPDATE still serialise the critical section either way.
     *
     * @param \Closure(Blob): bool $work
     */
    private function lockedTransaction(Blob $candidate, \Closure $work, bool $serializable = false): bool
    {
        return $this->database->transaction(function () use ($candidate, $work, $serializable): bool {
            if ($serializable && $this->lock->isPostgres() && $this->database->connection()->transactionLevel() <= 1) {
                $this->database->connection()->statement('SET TRANSACTION ISOLATION LEVEL SERIALIZABLE');
            }

            $this->lock->acquire(scope: $this->scopeFor($candidate), sha256: $candidate->sha256);

            $fresh = $this->blobs->lockForUpdate($candidate);

            return $work($fresh);
        });
    }

    /**
     * On PostgreSQL run the unit SERIALIZABLE and retry on a 40001 serialization
     * failure (H.3) — the isolation level itself is raised INSIDE the transaction
     * (see lockedTransaction), this only drives the retry loop. On MySQL/SQLite the
     * FOR-UPDATE/single-writer path already serialises, so run once.
     *
     * @param \Closure(): bool $unit
     */
    private function serializable(\Closure $unit): bool
    {
        if (!$this->lock->isPostgres()) {
            return $unit();
        }

        $attempt = 0;

        while (true) {
            try {
                return $unit();
            } catch (QueryException $exception) {
                $attempt++;

                if (!$this->isSerializationFailure($exception) || $attempt >= self::MAX_SERIALIZATION_RETRIES) {
                    throw $exception;
                }
            }
        }
    }

    private function isSerializationFailure(Throwable $exception): bool
    {
        // PostgreSQL serialization_failure → SQLSTATE 40001.
        return str_contains($exception->getMessage(), '40001');
    }

    /**
     * The scope discriminator for a blob's advisory lock — the same segment baked
     * into its storage_key, so GC and commit lock the same liveness unit.
     */
    private function scopeFor(Blob $blob): string
    {
        return $blob->scope_key;
    }

    /**
     * Lock before reading state/liveness, but amortise the transaction and reads
     * over a bounded batch. Keep repository writes so model events still fire.
     *
     * @param Collection<int, Blob> $batch
     */
    private function markBatch(Collection $batch, int $graceHours): int
    {
        $model = Config::blobModel();

        // Custom models/observers may change another candidate while saving.
        // Preserve the per-row fresh liveness check for those extension points.
        if ($model !== Blob::class || $this->hasBlobListeners()) {
            $marked = 0;

            foreach ($batch as $candidate) {
                $acted = $this->lockedTransaction($candidate, function (Blob $blob) use ($graceHours): bool {
                    if ($blob->status !== BlobStatus::Committed || $this->edges->hasLiveEdge($blob)) {
                        return false;
                    }

                    $this->blobs->tombstone(blob: $blob, graceHours: $graceHours);

                    return true;
                });

                $marked += (int) $acted;
            }

            return $marked;
        }

        return $this->database->transaction(function () use ($batch, $graceHours): int {
            if ($this->lock->isPostgres()) {
                $keys = array_values($batch->map(fn (Blob $blob): string => 'cas:'.$this->scopeFor($blob).':'.$blob->sha256)->all());

                $this->lock->acquireMany($keys);
            }

            $model = Config::blobModel();
            $query = $model::query()->whereKey($batch->modelKeys())->orderBy((new $model)->getKeyName());

            if ($this->lock->usesRowLock()) {
                $query->forceIndex('PRIMARY')->lockForUpdate();
            }

            $fresh = $query->get();
            $edgeModel = Config::fileVersionBlobModel();
            /** @var \Illuminate\Support\Collection<int, int|string> $liveIds */
            $liveIds = $edgeModel::query()->whereIn('blob_id', $batch->modelKeys())->distinct()->pluck('blob_id');
            $live = array_fill_keys($liveIds->all(), true);
            $marked = 0;

            foreach ($fresh as $blob) {
                if ($blob->status !== BlobStatus::Committed) {
                    continue;
                }

                if (isset($live[$blob->id])) {
                    continue;
                }

                $this->blobs->tombstone(blob: $blob, graceHours: $graceHours);
                $marked++;
            }

            return $marked;
        });
    }

    private function hasBlobListeners(): bool
    {
        $dispatcher = Blob::getEventDispatcher();

        return array_any(
            ['retrieved', 'saving', 'saved', 'updating', 'updated'],
            static fn (string $event): bool => $dispatcher?->hasListeners('eloquent.'.$event.': '.Blob::class) ?? false,
        );
    }

    /**
     * Scan by key, never offset: processed and skipped rows both advance the
     * checkpoint even though status changes remove rows from the candidate set.
     * A phase-start high-water key keeps inserts from extending a pass forever.
     * Queries and materialised batches hold at most BATCH_SIZE rows, as the
     * system (no panel/workspace — GC is ACL-blind).
     *
     * @param  \Closure(Builder<Blob>): Builder<Blob> $scope
     * @return iterable<Collection<int, Blob>>
     */
    private function candidateBatches(\Closure $scope): iterable
    {
        $model = Config::blobModel();
        $query = $scope($model::query());
        $key = $query->getModel()->getKeyName();
        $upper = (clone $query)->reorder($key, 'desc')->value($key);

        if ($upper === null) {
            return;
        }

        $last = null;

        do {
            $page = (clone $query)->where($key, '<=', $upper)->reorder($key)->limit(self::BATCH_SIZE);

            if ($last !== null) {
                $page->where($key, '>', $last);
            }

            $batch = $page->get();

            if ($batch->isEmpty()) {
                return;
            }

            $last = $batch->last()->getKey();

            yield $batch;
        } while ($batch->count() === self::BATCH_SIZE);
    }
}


### packages/media/src/Console/RepairBlobScopesCommand.php
<?php

declare(strict_types=1);

namespace Vaulter\Media\Console;

use Illuminate\Console\Command;
use Illuminate\Database\Query\Builder;
use Illuminate\Support\Collection;
use RuntimeException;
use Throwable;
use Vaulter\Cas\BlobLock;
use Vaulter\Contracts\Cas\ContentStore;
use Vaulter\Database\VaulterDatabase;
use Vaulter\Models\Cas\Blob;
use Vaulter\Repositories\Cas\BlobStoreRepository;
use Vaulter\Support\Config;
use Vaulter\ValueObjects\Cas\BlobScope;

final class RepairBlobScopesCommand extends Command
{
    protected $signature = 'vaulter:blobs:repair-scopes {--dry-run} {--execute}';

    protected $description = 'Copy legacy mixed-scope blobs to their lossless scopes and atomically redirect revision edges';

    public function handle(VaulterDatabase $database, ContentStore $content, BlobStoreRepository $blobs, BlobLock $lock): int
    {
        if ((bool) $this->option('dry-run') === (bool) $this->option('execute')) {
            $this->error('Select exactly one of --dry-run or --execute.');

            return self::INVALID;
        }

        $repaired = 0;
        $skipped = 0;
        $failed = false;
        $model = Config::blobModel();
        $model::query()->whereIn('scope_key', ['legacy:snull', 'legacy:tnull'])->chunkById(100, function ($batch) use ($database, $content, $blobs, $lock, &$repaired, &$skipped, &$failed): void {
            $rows = [];
            foreach ($batch as $blob) {
                $references = $this->referenceRows($database, $blob);
                $groups = $references->groupBy(function ($ref) use ($blob): string {
                    return $this->target($blob, (string) $ref->storage_id, $ref->tenant_id === null ? null : (string) $ref->tenant_id)->key();
                });
                if ($groups->isEmpty()) {
                    $rows[] = [$blob->getKey(), $blob->sha256, $blob->scope_key, '—', 0, '—', 'unreferenced'];
                    $skipped++;
                }

                foreach ($groups as $refs) {
                    $first = $refs->first() ?? throw new RuntimeException('Missing scope repair reference.');
                    $scope = $this->target($blob, (string) $first->storage_id, $first->tenant_id === null ? null : (string) $first->tenant_id);
                    $action = 'move';
                    try {
                        if ($this->option('execute')) {
                            $action = $this->repair($database, $content, $blobs, $lock, $blob, $scope, array_values(array_unique($refs->map(static fn ($ref): string => (string) $ref->storage_id)->all())));
                            $action === 'move' ? $repaired++ : $skipped++;
                        } elseif (!$this->validObject($content, $blob->storage_key, $blob->disk, $blob->sha256)) {
                            $action = 'hash_mismatch';
                            $skipped++;
                        }
                    } catch (Throwable $exception) {
                        $action = 'error';
                        $failed = true;
                        $skipped++;
                        $this->error($exception->getMessage());
                    }
                    $rows[] = [$blob->getKey(), $blob->sha256, $blob->scope_key, $refs->pluck('storage_id')->unique()->implode(','), $refs->count(), $scope->key(), $action];
                }
            }
            $this->table(['blob_id', 'sha256', 'scope_key', 'storage_id', 'refs', 'target', 'action'], $rows);
        });
        $this->info("Repaired: {$repaired}, skipped: {$skipped}");

        return $failed ? self::FAILURE : self::SUCCESS;
    }

    /**
     * @param  list<string>|null                                                                                   $storageIds
     * @return Collection<int, object{version_id: int|string, storage_id: int|string, tenant_id: int|string|null}>
     */
    private function referenceRows(VaulterDatabase $database, Blob $blob, ?array $storageIds = null): Collection
    {
        $query = $this->references($database, $blob);
        if ($storageIds !== null) {
            $query->whereIn('storages.id', $storageIds);
        }
        /** @var Collection<int, object{version_id: int|string, storage_id: int|string, tenant_id: int|string|null}> $rows */
        $rows = $query->get();

        return $rows;
    }

    private function references(VaulterDatabase $database, Blob $blob): Builder
    {
        return $database->connection()->table(Config::table('file_version_blobs').' as edges')
            ->join(Config::table('file_versions').' as versions', 'versions.id', '=', 'edges.file_version_id')
            ->join(Config::table('files').' as files', 'files.id', '=', 'versions.file_id')
            ->join(Config::table('nodes').' as nodes', 'nodes.id', '=', 'files.node_id')
            ->join(Config::table('storages').' as storages', 'storages.id', '=', 'nodes.storage_id')
            ->where('edges.blob_id', $blob->getKey())
            ->select(['versions.id as version_id', 'storages.id as storage_id', 'storages.tenant_id']);
    }

    private function target(Blob $blob, string $storageId, ?string $tenantId): BlobScope
    {
        return $blob->scope_key === 'legacy:snull' ? BlobScope::drive($storageId)
            : ($tenantId === null ? BlobScope::global() : BlobScope::tenant($tenantId));
    }

    /** @param list<string> $storageIds */
    private function repair(VaulterDatabase $database, ContentStore $content, BlobStoreRepository $blobs, BlobLock $lock, Blob $candidate, BlobScope $scope, array $storageIds): string
    {
        return $database->transaction(function () use ($database, $content, $blobs, $lock, $candidate, $scope, $storageIds): string {
            // Follow the tree-before-CAS order so uploads and purge cannot change
            // this revision chain while the repair redirects its edges.
            sort($storageIds, SORT_STRING);
            foreach ($storageIds as $id) {
                $database->lockTree($id);
            }
            $keys = ['cas:'.$candidate->scope_key.':'.$candidate->sha256, 'cas:'.$scope->key().':'.$candidate->sha256];
            $lock->acquireMany($keys);
            if ($lock->usesRowLock()) {
                // Match GC's primary-key scan before the repository locks either
                // row individually. Force the index to avoid a filesort lock order.
                $model = Config::blobModel();
                $model::query()->where('sha256', $candidate->sha256)
                    ->whereIn('scope_key', [$candidate->scope_key, $scope->key()])
                    ->orderBy((new $model)->getKeyName())->forceIndex('PRIMARY')->lockForUpdate()->get();
            }
            $old = $blobs->lockForUpdate($candidate);
            $refs = $this->referenceRows($database, $old, $storageIds)
                ->filter(fn ($ref): bool => $this->target($old, (string) $ref->storage_id, $ref->tenant_id === null ? null : (string) $ref->tenant_id)->key() === $scope->key());
            if ($refs->isEmpty()) {
                return 'unreferenced';
            }

            $stream = $content->get($old->storage_key, $old->disk);
            if (!is_resource($stream)) {
                return 'hash_mismatch';
            }
            try {
                $staged = $content->stage($stream);
            } finally {
                fclose($stream);
            }
            try {
                if (!hash_equals($old->sha256, $staged->sha256())) {
                    return 'hash_mismatch';
                }
                $result = $blobs->findOrCreate($old->sha256, $staged->sizeBytes(), $content->keyFor($scope, $old->sha256), $old->disk, $scope, $scope->tenantId(), $scope->storageId());
                $target = $result['blob'];
                $content->promote($staged, $target->storage_key, $target->disk);
                if (!$this->validObject($content, $target->storage_key, $target->disk, $old->sha256)) {
                    throw new RuntimeException('Repair target bytes failed SHA-256 verification.');
                }
                $db = $database->connection();
                $edges = $db->table(Config::table('file_version_blobs'));
                $count = $edges->whereIn('file_version_id', $refs->pluck('version_id')->unique()->all())->where('blob_id', $old->getKey())->update(['blob_id' => $target->getKey()]);
                $db->table(Config::table('file_versions'))->whereIn('id', $refs->pluck('version_id')->unique()->all())
                    ->where('blob_id', $old->getKey())->update(['blob_id' => $target->getKey()]);
                // ref_count is a cache: repair from live edges rather than decrement
                // a possibly stale cache below zero.
                foreach ([$old, $target] as $blob) {
                    $blobs->setRefCount($blob, $db->table(Config::table('file_version_blobs'))->where('blob_id', $blob->getKey())->count());
                }
                $entry = json_encode(['ts' => now()->toIso8601String(), 'blob_id' => $old->getKey(), 'target' => $scope->key(), 'action' => 'move', 'edges' => $count], JSON_THROW_ON_ERROR)."\n";
                $database->afterCommit(static function () use ($entry): void {
                    $dir = storage_path('logs');
                    if (!is_dir($dir) && !mkdir($dir, 0o755, true) && !is_dir($dir)) {
                        throw new RuntimeException('Cannot create scope repair log directory.');
                    }
                    if (file_put_contents($dir.'/vaulter-repair-scopes.log', $entry, FILE_APPEND | LOCK_EX) === false) {
                        throw new RuntimeException('Cannot append scope repair log.');
                    }
                });

                return 'move';
            } finally {
                $staged->discard();
            }
        });
    }

    private function validObject(ContentStore $content, string $key, string $disk, string $sha256): bool
    {
        $stream = $content->get($key, $disk);
        if (!is_resource($stream)) {
            return false;
        }
        try {
            $hash = hash_init('sha256');
            while (!feof($stream)) {
                $buffer = fread($stream, 1_048_576);
                if ($buffer === false) {
                    return false;
                }
                hash_update($hash, $buffer);
            }

            return hash_equals($sha256, hash_final($hash));
        } finally {
            fclose($stream);
        }
    }
}
