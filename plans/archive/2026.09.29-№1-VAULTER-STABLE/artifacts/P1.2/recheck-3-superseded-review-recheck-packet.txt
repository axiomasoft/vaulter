   - **Defect:** Restore locks the trashed node and the root, then locks the original parent in a second `lockForUpdate`. Trash locks that parent first and the subtree `UPDATE` then locks every descendant, including rows that already have `trashed_at` (`descendantsAndSelf()` returns them). Trash never calls `lockTree`, so Restore's tree lock does not separate the two transactions. The parent and the descendant are locked in opposite orders. Move locks its node and destination in ascending id order after `lockTree`, which meets Trash's parent-then-descendant order whenever the moved id sorts first.
   - **Failure scenario:** Folder P contains file C, C is already in the trash, and `trashed_from_parent_id` is P. T1 trashes P and locks P. T2 restores C, locks C, and waits for P. T1's subtree `UPDATE` waits for C. PostgreSQL aborts one transaction with `40P01`; MySQL/MariaDB abort one with `1213`. The same abort happens when T1 trashes P and T2 moves an older descendant N (`N.id` sorts before `P.id`) into P: Move holds N and waits for P, Trash holds P and waits for N. `VaulterDatabase::transaction()` retries the callback up to 3 times, then the request fails. SQLite has no row locks, so this cycle is PostgreSQL and MySQL/MariaDB.
   - **Fix:** Call `lockTree` as the first statement inside Trash's transaction, before the node lock, so Trash, Restore, and Move all take the tree lock before any node row lock.

## Fix
TrashNodeAction now calls VaulterDatabase::lockTree($node->storage_id) as the first statement inside its transaction, before locking the node row and before the subtree UPDATE. Lock acquisition summary after the fix:

    57	                ids: collect($ids),

## Order regression test
it('takes the storage row before node rows when the transaction inserts nodes, updates the quota or trashes a subtree', function (string $operation): void {
    $drive = DriveTestHelpers::drive();
    $folder = $drive->createFolder('Target');
    $source = $drive->upload(DriveTestHelpers::streamFor('bytes'), originalName: 'source.bin');
    $queries = [];

    Event::listen(QueryExecuted::class, function (QueryExecuted $query) use (&$queries): void {
        $queries[] = $query->sql;
    });

    match ($operation) {
        'create folder' => $drive->createFolder('Child', $folder),
        'upload' => $drive->upload(DriveTestHelpers::streamFor('x'), into: $folder, originalName: 'x.bin'),
        'copy' => $drive->copy($source, $folder),
        'trash' => $drive->trash($folder),
    };

    $storageLock = array_key_first(array_filter($queries, static fn (string $sql): bool => str_starts_with($sql, 'select "id" from "v_storages"')));
    $nodeLock = array_key_first(array_filter($queries, static fn (string $sql): bool => str_contains($sql, 'from "v_nodes"') && str_contains($sql, 'order by')));

    // SQLite (like MySQL) implements the tree lock as the storage row.
    expect($storageLock)->not->toBeNull()
        ->and($nodeLock)->not->toBeNull()
        ->and($storageLock)->toBeLessThan($nodeLock);
})->with(['create folder', 'upload', 'copy', 'trash']);
