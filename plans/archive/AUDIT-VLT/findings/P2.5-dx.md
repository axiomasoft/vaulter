## 2. Находки

### F-P2.5-01 — `vaulter:prune-webhooks` полностью отсутствует в `docs/reference/commands.md` · Severity: Major · Уверенность: high

**Где:** `docs/reference/commands.md:9-24` (перечень команд); `packages/core/src/Console/PruneWebhooksCommand.php:1-58` (реальная команда); `packages/core/src/VaulterServiceProvider.php:18,46` (регистрация)
**Что:** `VaulterServiceProvider` регистрирует девятую package-команду `vaulter:prune-webhooks` (удаление settled outbox-строк и terminal webhook-доставок старше retention-окна — предотвращает неограниченный рост `v_outbox`/`v_webhook_deliveries`). `docs/reference/commands.md` заявляет «nine Artisan commands: an install command … plus eight package commands» и перечисляет ровно 9 строк — но подставляет туда `vaulter:install` вместо девятой package-команды; `vaulter:prune-webhooks` не упомянута нигде в файле.
**Почему опасно:** это команда для GC — без неё `v_outbox`/`v_webhook_deliveries` растут неограниченно у любого хоста с включённой `reliability`. `docs/reference/commands.md:202-215` («Scheduling») даёт «representative schedule» с шестью командами, включающими `vaulter:reconcile-blobs` (weekly), но НЕ включает `vaulter:prune-webhooks` — оператор, буквально следующий референсу, никогда не запланирует prune и получит неограниченно растущие таблицы аудита доставки.
**Доказательство:**
```
$ find packages -path '*/vendor/*' -prune -o -path '*/src/Console/*.php' -print | wc -l
9
$ grep -c "^| \`vaulter:" docs/reference/commands.md
9   # включая install — 8 package-команд документировано, а не 9
$ grep -n "prune-webhooks" docs/reference/commands.md
(пусто)
```
**Норма, которая нарушена:** `findings/P0-audit-gaps.md` §1 #13 (обязательная ось C7) — «расхождение в обе стороны = находка»; `findings/P0.1-baseline-inventory.md` §2д (9 команд, факт).
**Сверка с ADR:** нет ADR по документационному покрытию команд; не сознательное решение — дефект документации.
**Рекомендация:** добавить `vaulter:prune-webhooks` в таблицу и отдельную секцию `docs/reference/commands.md`, добавить в «representative schedule».

### F-P2.5-02 — `docs/reference/rest-api.md` пропускает 5 реальных маршрутов Drive-поверхности (`shared`, `nodes/{node}/comments` ×4) · Severity: Major · Уверенность: high

**Где:** `docs/reference/rest-api.md` (файл целиком — секции отсутствуют); реальные маршруты: `packages/drive/routes/drive.php` (`GET shared`), `packages/documents/routes/documents.php` (`NodeCommentController` ×4) — подтверждено в `findings/P0.3-attack-surface-map.md:52,89-92`
**Что:** Документ описывает REST-поверхность как «exhaustive, route-by-route reference» (`:10`), но не содержит ни `GET shared` (`NodeController@shared`, feature `grants` — кросс-storage «shared with me»), ни один из четырех Drive-native маршрутов комментариев (`GET/POST nodes/{node}/comments`, `POST .../resolve`, `DELETE .../{comment}`, feature `comments`). Вместо них документирован только параллельный LEGACY-путь `documents/{documentId}/comments` (§ «Legacy document API»). Таблица «Feature gates» (`:43-52`) тоже не называет `comments` и `grants` фиче-флагами, хотя обе реально гейтят маршруты (P0.3 §2).
**Почему опасно:** интегратор, читающий «exhaustive» референс, не узнает о существовании Drive-нативного комментирования и «shared with me» — единственный способ их обнаружить — читать исходник маршрутов напрямую, что противоречит цели референс-документации.
**Доказательство:**
```
$ grep -n "nodes/{node}/comments\|GET shared\b" docs/reference/rest-api.md
(пусто)
```
Сверка с `findings/P0.3-attack-surface-map.md:52` (`GET | shared | NodeController@shared | grants`) и `:89-92` (4 строки `NodeCommentController`).
**Норма, которая нарушена:** `findings/P0-audit-gaps.md` §1 #13; item'а собственная норма C8 («не описывает несуществующих и не пропускает существующих»).
**Сверка с ADR:** нет ADR по составу REST-референса; дефект документации, не архитектурное решение.
**Рекомендация:** добавить секции для `GET shared` и `NodeCommentController`-маршрутов; дополнить таблицу «Feature gates» строками `comments`/`grants`.

### F-P2.5-03 — 9 из 15 ссылок «Docs:» в исключениях ведут на несуществующие якоря `docs/guide/errors.md`; один документированный якорь — для удалённого класса · Severity: Major · Уверенность: high

**Где:** `packages/core/src/Exceptions/VaulterException.php:14-17` (генератор ссылки); все 15 непакетных `Exceptions/**`-классов; `docs/guide/errors.md:1-49`
**Что:** Каждое исключение пакета оканчивается на `Docs: https://…/errors.md#{anchor}` через `self::docs($anchor)`. Реально используемые якоря (`grep -rhoE "self::docs\('[a-z-]+'\)"` по всему `packages/**/src`, без vendor) — 15 уникальных значений. `docs/guide/errors.md` определяет только 8 секций-якорей. Пересечение — 6 (`permission-denied`, `unknown-document-type`, `invalid-tiptap-content`, `content-too-large`, `missing-jwt`, `missing-collab-secret`). Отсутствуют 9: `missing-host-role-driver`, `unknown-export-format`, `node-name-conflict`, `cross-storage-move`, `move-cycle`, `quota-exceeded`, `collab-webhook-unconfigured`, `document-version-not-found`, `not-a-document-node`. Дополнительно `errors.md:7-11` документирует `## document-not-found` для `DocumentNotFoundException` — класса с таким именем в `packages/**/src` (без vendor/tests) не существует.
**Почему опасно:** «Docs:» — это явно продаваемая часть DX-контракта пакета (`errors.md:3-5`: «carries a message … Docs: {url} where the URL points at the matching anchor below»). Пользователь, поймавший `MissingHostRoleDriverException`/`CrossStorageMoveException`/`CycleException`/`QuotaExceededException`/`NotADocumentNodeException` и т.д. (9 из 15 классов — 60% реальной поверхности исключений), переходит по ссылке на страницу БЕЗ соответствующего якоря браузер просто прокручивает в начало документа — диагностика обрывается на «Fix» в самом сообщении, обещанный доп.контекст недоступен.

### F-P2.5-07 — `@vaulter/vue`: `yjs` и `@tiptap/pm` в `dependencies` вместо `peerDependencies` (dual-instance риск); `version: "0.0.0"` не готова к осмысленной публикации · Severity: Major · Уверенность: high

**Где:** `packages/vue/package.json:3,51-57`
**Что:** `yjs` (держит `Y.Doc`-реестр — модульный синглтон, две копии библиотеки в одном рантайме расходятся по состоянию CRDT) и `@tiptap/pm` (держит ProseMirror-инстанс/схему — модульное состояние) объявлены в `dependencies`, а не в `peerDependencies`, при том что `vue` уже корректно вынесен в `peerDependencies`. Дополнительно `version: "0.0.0"` — пакет физически не готов к осмысленной первой публикации на npm (semver с версии `0.0.0` не несёт информации о совместимости).
**Почему опасно:** хост-приложение, само использующее TipTap/ProseMirror или Yjs (крайне вероятно для приложения, встраивающего Vaulter ради коллаборативного редактирования — то есть само же и создающее совпадающий стек), получит ВТОРУЮ копию этих библиотек через `node_modules` npm/bundler dedup edge-case (несовпадающие minor-версии избегают дедупа). Два инстанса `Y.Doc` для одного и того же документа не синхронизируют состояние между собой; два инстанса `prosemirror-state`/`prosemirror-model` дают `instanceof`-несовпадения между схемой хоста и схемой `@vaulter/vue` — трудноуловимый runtime-баг, не ошибка сборки.
**Доказательство:**
```json
// packages/vue/package.json:48-57
"peerDependencies": { "vue": "^3.4" },
"dependencies": {
  "@hocuspocus/provider": "^2.13",
  "@tiptap/pm": "^2.10",
  "@tiptap/starter-kit": "^2.10",
  "@tiptap/vue-3": "^2.10",
  "yjs": "^13.6"
}
```
**Норма, которая нарушена:** item'а C12 (dual-instance риск, «подтверждается тем, что библиотека держит модульное состояние») — риск подтверждён по формулировке Code Guidance ИМЕННО для `yjs`/`@tiptap/pm`. `@hocuspocus/provider`/`@tiptap/starter-kit`/`@tiptap/vue-3` — риск НЕ подтверждён этим item'ом, оставлены в `dependencies` без находки.
**Сверка с ADR:** нет ADR по составу `package.json` зависимостей Vue-пакета; не сознательное решение.
**Рекомендация:** перенести `yjs` и `@tiptap/pm` в `peerDependencies` (с диапазоном версий, совпадающим с реально протестированным), оставить остальные три в `dependencies`. Отдельно: `version: "0.0.0"` — зафиксировать как факт (не «баг», просто состояние «пакет ещё не готов к релизу»), не смешивать с dependency-находкой при ремедиации.

### F-P2.5-08 — `CONTRIBUTING.md` заявляет «PHPStan (level 8)», а `phpstan.neon` задаёт `level: max` · Severity: Minor · Уверенность: high
