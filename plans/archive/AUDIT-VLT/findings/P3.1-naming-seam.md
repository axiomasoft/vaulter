## 2. Находки

### F-P3.1-01 — Имя-политика узла захардкожена, кастомизация только форком · Severity: Minor · Уверенность: high

**Где:** `packages/core/src/Support/DriveNameRules.php:14-38`
**Что:** `DriveNameRules` — `final class` со статическими `rules()`/`messages()`; лимит `max:255`, паттерн запрета сепараторов и текст сообщения зашиты `private const`. Нет контракта в `Contracts/**` и нет config-ключа в `config/vaulter.php`, через который хост мог бы задать иной лимит длины, разрешённые символы или локализованное сообщение.
**Почему опасно:** Потребитель с другой политикой имён узла (иной лимит, доп. запрещённые символы, кастомное сообщение) не может настроить это через конфиг — единственный путь: форк файла или обёртка над `create/rename/upload/copy`-запросами, дублирующая правило. Цена — прямое противоречие заявленной оси P3 («потребитель со своей политикой имён... не должен форкать пакет»).
**Доказательство:**
```php
final class DriveNameRules
{
    private const string NO_SEPARATORS = 'regex:/^[^\/\\\\]+$/';

    public static function rules(): array
    {
        return ['required', 'string', 'max:255', self::NO_SEPARATORS];
    }
```
**Норма, которая нарушена:** E5.4 (`findings/P0-embeddable-laravel.md`) — требование параметризации политик там, где потребитель предсказуемо хочет иное поведение.
**Сверка с ADR:** Ни `0006`, ни `0004`, ни другой ADR не фиксирует сознательное решение «имя-политика узла не-swappable». Это не «ADR устарел» — это пробел шва.
**Рекомендация:** Вынести лимит длины и паттерн в `config('vaulter.drive.name_rules')` с текущими значениями как дефолт; `messages()` — через `trans()`/lang-файл (пересекается с F-P3.1-02).

### F-P3.1-02 — Сообщение валидатора имени — хардкод-строка, не lang-ключ · Severity: Nit · Уверенность: high

**Где:** `packages/core/src/Support/DriveNameRules.php:33-38`
**Что:** `messages()` возвращает английский литерал `'The name must not contain path separators (/ or \\).'` напрямую, не через `trans()`/`__()` и без lang-файла пакета.
**Почему опасно:** Хост с нелатинизированным UI не может локализовать это сообщение штатным механизмом Laravel (`lang/vendor/vaulter/...`) — только подменой всего `rules()`/`messages()` или собственного `FormRequest`.
**Доказательство:**
```php
public static function messages(): array
{
    return [
        'name.regex' => 'The name must not contain path separators (/ or \\).',
    ];
}
```
**Норма, которая нарушена:** DX-грань E5.4 (параметризация); в проекте нет явного заявления «english-only» — грепом по `docs/` (`i18n`/`localiz`/`english-only`) ничего не найдено.
**Сверка с ADR:** Нет ADR, фиксирующего english-only как продуктовое решение — не «ADR устарел», это отсутствующая мелочь.
**Рекомендация:** Завести `lang/vendor/vaulter/en/validation.php` ключ и подключить через `trans('vaulter::validation.name_no_separators')`.

### F-P3.1-03 — `storage_adapter`/`StorageAdapter` — заявленный шов мёртв, реальная CAS-persistence идёт мимо него · Severity: Minor · Уверенность: high

**Где:** `packages/core/src/Contracts/Cas/StorageAdapter.php:12-24`, `packages/core/src/Support/DefaultStorageAdapter.php:13-29`,
`packages/core/config/vaulter.php:357`, `packages/core/src/Support/Config.php:833-839`
**Что:** Пакет объявляет полный шов «контракт + дефолт-реализация + config-биндинг по FQCN» для `StorageAdapter`
(`Config::storageAdapterClass()` резолвит `config('vaulter.storage_adapter')`), но нигде в кодовой базе этот
резолвер не вызывается и контракт не биндится в контейнер ни в одном из трёх провайдеров
(`VaulterServiceProvider`/`VaulterMediaServiceProvider`/`VaulterDocumentsServiceProvider`). Реальная бинарная
persistence (CAS-запись/чтение/дедуп) идёт через параллельный, полностью независимый шов
`StorageDriver`/`ContentStore` (`FlysystemStorageDriver`, `Sha256ContentStore`), который `StorageAdapter` не
использует и на него не ссылается. `DefaultStorageAdapter` — буквально no-op-заглушка, докблок которой сам
называет её «Skeleton» из более раннего майлстоуна.
**Почему опасно:** Потребитель, читающий `Contracts/Cas/StorageAdapter.php` и ключ `storage_adapter` в конфиге,
резонно ожидает, что подмена этого биндинга повлияет на хранение бинарных вложений — и тратит время на реализацию
адаптера, который никогда не вызывается ни одним потребителем. Это DX-ловушка: заявленная точка расширения не
работает.
**Доказательство:**
```
$ grep -rn "StorageAdapter" packages/*/src
packages/core/src/Support/DefaultStorageAdapter.php
packages/core/src/Support/Config.php
packages/core/src/Contracts/Cas/StorageAdapter.php
$ grep -rn "StorageAdapter::class\|StorageAdapter \$\|StorageAdapter::" packages/*/src
packages/core/src/Support/Config.php:836:        $class = config('vaulter.storage_adapter', DefaultStorageAdapter::class);
```
`Config::storageAdapterClass()` определён (`Support/Config.php:833-839`), но не вызывается больше нигде в дереве
`packages/*/src` (второй grep не находит ни одного места, где возвращаемый FQCN инстанцируется или биндится).
**Норма, которая нарушена:** E7.1 (`findings/P0-embeddable-laravel.md`) — config-first ключ обязан реально
читаться и влиять на поведение, иначе это «advertised but unread» (та же категория дефекта, что и «мёртвый
ключ» из Code Guidance item'а, только на уровне резолвера, а не самого ключа).
**Сверка с ADR:** ADR-0006 описывает CAS через `StorageDriver`/Flysystem, не упоминает `StorageAdapter`
как активный шов — расхождение не является сознательным ADR-решением, это забытый артефакт более раннего
майлстоуна (докблок `DefaultStorageAdapter` сам это подтверждает: «Real binary persistence… is wired in a
later milestone»).
**Рекомендация:** Либо удалить `StorageAdapter`/`DefaultStorageAdapter`/`storage_adapter`-ключ как устаревший
артефакт домиграционного дизайна (deprecation-заметка при мажоре), либо реально подключить его в поток, для
которого он был задуман, и задокументировать отличие от `StorageDriver`.

### F-P3.1-04 — Имя экспортированного файла централизовано, но не является швом · Severity: Minor · Уверенность: high

**Где:** `packages/documents/src/Documents/NodeExportService.php:28,86-92`
**Что:** `filenameFor()` — приватный метод `final class NodeExportService`; выводит basename из `node->name` +
расширение экспортёра, с хардкод-фолбэком `'document'`, если basename пуст. Нет config-ключа и нет точки
расширения (интерфейс/callback), которой хост мог бы переопределить схему имени (например, добавить дату,
версию, санитизацию под чужую ФС).
**Почему опасно:** Хост, которому нужна другая схема имени экспортированного файла (напр. `"{name}-v{version}.{ext}"`),
не может этого сделать без форка `NodeExportService` целиком — сервис `final`, метод `private`.
**Доказательство:**
```php
private function filenameFor(Node $node, string $extension): string
{
    $base = pathinfo($node->name, PATHINFO_FILENAME);
    $base = $base === '' ? 'document' : $base;

    return $base.'.'.$extension;
}
```
**Норма, которая нарушена:** E5.4 (параметризация политик именования, там же, где заявлена ось P3 «filename при
скачивании/экспорте — швом или хардкодом»).
**Сверка с ADR:** ADR-0004 регламентирует формат контента (TipTap JSON) и версионирование, не схему имени
экспортируемого файла — нет ADR-решения, закрывающего этот пробел; не «ADR устарел».
**Рекомендация:** Вынести `filenameFor` в защищённый метод, переопределяемый через наследование, либо принять
опциональный `callable`/контракт `ExportFilenameResolver` с текущим поведением как дефолт.
