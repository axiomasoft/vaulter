## 2. Находки

### F-P1.6-01 — Realtime-collab не отделён собственным фиче-флагом (нарушение D13) · Severity: Major · Уверенность: high

**Где:** `packages/documents/routes/documents.php:42`, `:57`, `:87-92`; `packages/documents/src/VaulterDocumentsServiceProvider.php:117`; `packages/core/config/vaulter.php:171-191` (нет ключа collab), `:652-668` (секция `collaboration` без `enabled`).
**Что:** Клиентский `collab/token` и server-to-server webhook'и `collab/authenticate`/`collab/store` (а также приватный broadcast-канал) гейтятся ровно тем же флагом `features.document_versions`, что и базовое (не-realtime) редактирование документов (`content` GET/PATCH, версии). Отдельного флага collab (`collaboration.enabled` / `features.collaboration`) не существует. Следствие: включив редактирование документов, хост обязательно поднимает и всю realtime-поверхность; «базовое редактирование TipTap без realtime» как отдельный режим недостижимо.
**Почему опасно:** D13 — продуктовое требование владельца (2026-07-10): collab — **опциональная надстройка**, включаемая отдельным фиче-флагом, а базовая поставка = документохранилище + редактирование TipTap без realtime, без Node/Docker/секретов. Текущее связывание — то самое hard-wiring, которое D13 запрещает: каждый потребитель документов получает collab-эндпоинты (пусть fail-closed, но зарегистрированные), не может их отключить, и вынужден рассуждать об их безопасности, даже не используя collab. Это расширяет attack surface хоста, который collab не заказывал.
**Доказательство:** `routes/documents.php:87-92`:
```php
if (Config::featureEnabled('document_versions')) {
    Route::middleware(ResolveCollaborationCall::class)->group(static function (): void {
        Route::post('collab/authenticate', [NodeCollaborationController::class, 'authenticate']);
        Route::post('collab/store', [NodeCollaborationController::class, 'store']);
    });
}
```
repro `it('C18: у collab нет собственного фиче-флага …')` — `config('vaulter.collaboration.enabled')` и `config('vaulter.features.collaboration')` оба `null`, `features.document_versions` — единственный рычаг. Прогон:
`✓ it C18: у collab нет собственного фиче-флага — гейт общий с document_versions` (14 assertions passed).
**Норма, которая нарушена:** `plan.md` D13 («разделение, а не hard-wiring»; collab включается отдельным фиче-флагом); чеклист P1.6 `C18` («отсутствие гейта на любом из путей = Major»).
**Сверка с ADR:** `docs/adr/0001-collaboration-transport.md` описывает выбор транспорта (reverb/hocuspocus), но НЕ решает вопрос «collab как опциональная надстройка с отдельным флагом» — это решение D13, принятое позже ADR. Расхождение сознательным ADR-решением не покрыто ⇒ дефект (а не «ADR устарел»).
**Рекомендация:** Ввести отдельный флаг (`features.collaboration` или `collaboration.enabled`, дефолт `false`) и гейтить им `collab/token`, `collab/authenticate`, `collab/store`, `ResolveCollaborationCall`, broadcast-канал и регистрацию драйверов; оставить `document_versions` гейтом только для не-realtime редактирования и версий.

### F-P1.6-02 — Входящий collab-webhook без подписи тела и без защиты от replay · Severity: Major · Уверенность: medium

**Где:** `packages/documents/src/Collaboration/CollaborationCallResolver.php:31-78`; `packages/documents/src/Http/Middleware/ResolveCollaborationCall.php:42-101`.
**Что:** Server-to-server webhook'и (`collab/store` персистит Yjs-снапшот в узел) аутентифицируются статическим общим секретом в заголовке `X-Vaulter-Collab-Secret` (сравнение `hash_equals`) ИЛИ JWT bearer. Тело запроса (`yjs_state`, `node_id`) **не подписывается ни в одном из путей** — нет HMAC по сырому телу; нет timestamp в подписываемом содержимом и нет окна допуска; нет nonce/message-id для защиты от повторов.
**Почему опасно:** Норма C3.1/C3.3/C3.4 (`findings/P0-collab-seam.md`) требует HMAC по сырому телу + timestamp-окно + анти-replay для webhook, меняющего состояние документа. Без них: (1) секрет — статический bearer без срока, любой перехваченный `collab/store`-запрос воспроизводим бесконечно (перезапись документа устаревшим/произвольным снапшотом); (2) на JWT-пути replay ограничен лишь `exp` (TTL 3600 с) — в пределах часа тот же запрос можно повторить. Практический вход требует утечки секрета/JWT или MITM server-to-server TLS-трафика, что снижает вероятность, но норма явно квалифицирует отсутствие timestamp-окна как Major. Дополнительно тело не связано с аутентификатором, т.е. целостность полезной нагрузки не проверяется.
**Доказательство:** `CollaborationCallResolver.php:31-43` — единственная аутентификация тела отсутствует; секрет сверяется как есть:
```php
if ($sharedSecret !== null && is_string($presentedSecret)
    && hash_equals($sharedSecret, $presentedSecret)) {
    return CollaborationCall::bySecret();
}
return $this->resolveJwt($bearerToken);
```
Ни `$request->getContent()`, ни timestamp/nonce в `ResolveCollaborationCall.php` и резолвере не фигурируют.
**Норма, которая нарушена:** `findings/P0-collab-seam.md` §C3.1 (HMAC по сырому телу), §C3.3 (timestamp ±5 мин), §C3.4 (анти-replay по nonce); чеклист P1.6 `C4`, `C5` («отсутствие timestamp-окна = Major»).
**Сверка с ADR:** `docs/adr/0001-collaboration-transport.md` не описывает схему подписи webhook; сознательного решения «статический секрет вместо HMAC+timestamp» в ADR нет ⇒ дефект, не «ADR устарел».
**Рекомендация:** На server-to-server webhook добавить HMAC-SHA256 по `$request->getContent()` с включённым timestamp (заголовок `X-Vaulter-Collab-Timestamp`), окно ±5 мин и хранение виденных message-id на время окна; сравнение `hash_equals`. Как минимум — timestamp+окно для secret-пути, чтобы ограничить replay.

### F-P1.6-03 — Нет периодической проверки `exp`/ACL в течение живого collab-соединения · Severity: Minor · Уверенность: medium

**Где:** `hocuspocus-server/src/index.js:98-147` (только `onConnect`/`onAuthenticate`/`onStoreDocument`, без таймера); `packages/documents/src/Collaboration/CollaborationCallResolver.php:63`.
**Что:** `exp` JWT проверяется на handshake (`onAuthenticate` → Laravel `JWT::decode`) и при каждом `onStoreDocument` (тот же токен), но нет периодической проверки, закрывающей сокет по истечении токена или при отзыве прав в середине сессии. Живое Yjs-соединение синхронизирует правки напрямую по WS без переаутентификации до дисконнекта/дебаунс-store.
**Почему опасно:** Норма C5.1 требует проверять `exp` на handshake **и периодически**, C5.5 — реагировать на изменение ACL в середине сессии (refresh+reconnect). Без этого отзыв доступа/истечение токена enforce'ится не сразу: окно ограничено TTL токена (3600 с) плюс временем жизни соединения. Риск реальный, но ограниченный коротким TTL и опциональностью компонента.
**Доказательство:** В `hocuspocus-server/src/index.js` зарегистрированы только три хука (`buildServer` :170-183); ни `setInterval`, ни хук проверки `exp` по времени нет. `onStoreDocument` :127-147 переаутентифицирует лишь для персиста, не для live-sync.
**Норма, которая нарушена:** `findings/P0-collab-seam.md` §C5.1, §C5.5; чеклист P1.6 `C12`.
**Сверка с ADR:** ADR-0001 не фиксирует политику re-check живого соединения; это поведение штатного Hocuspocus (T3, `findings/P0.2-rag-supplement.md`). Дефект уровня «недостающий контроль», severity понижен до Minor с учётом короткого TTL и опциональности collab (D13).
**Рекомендация:** Держать `exp` коротким (уже 3600 с) и/или добавить серверный таймер, закрывающий соединение по `exp`; при изменении ACL — инициировать reconnect. Достаточно документировать окно и rely на короткий TTL, если периодическая проверка избыточна.

## 3. Не проверено / ограничения

- **Node-сервер не запускался** (нет live-стенда Hocuspocus в аудите): вердикты по `hocuspocus-server/src/*` (C1-Node, C9, C10-Origin, C12, C13-фильтрация) вынесены **чтением кода**, не рантайм-прогоном. C1 (allow-list) на Node неприменим — хаб не верифицирует JWT (`config.js:37-38`), а релеит в Laravel-webhook, где верификация и покрыта repro. Периодический re-check `exp` (C12) — статически подтверждено отсутствие хука; runtime-репро WS-таймера не делался.
- **C11** (token не в query) — опирается на контракт `@hocuspocus/provider` (токен in-band, T3), рантайм-перехват WS-кадров не выполнялся: уверенность medium.
- **Ротация ключей** (C1.4 два-ключевое окно) чеклистом P1.6 не адресована и в коде отсутствует — вне 20 строк этого item'а, отмечено для P1.8/бэклога.
