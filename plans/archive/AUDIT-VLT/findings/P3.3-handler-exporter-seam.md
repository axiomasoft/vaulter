## 2. Находки

### F-P3.3-01 — Асимметрия шва handler↔exporter: нет tagged-источника и нет null-object у экспортёра, runtime-регистрация экспортёра не принимает FQCN · Severity: Minor · Уверенность: high

**Где:** `packages/core/src/VaulterManager.php:142-193` (сравнить `registerHandler(DocumentHandler|string $handler)` со строки 142 и `registerExporter(DocumentExporter $exporter)` со строки 161); `packages/documents/src/Documents/DocumentHandlerRegistry.php:266-280` (`taggedHandlers()` — аналога у экспортёра нет); `packages/core/src/Contracts/Documents/DocumentExporter.php` (контракт без null-object).
**Что:** Оба шва расширяемы «одна класс + register», но идиомы регистрации разные: у handler'а — tagged-биндинг + config-список + runtime `FQCN|instance`, у экспортёра — только config-карта + runtime, причём runtime-метод принимает исключительно готовый инстанс (`DocumentExporter $exporter`), а не `DocumentExporter|class-string<DocumentExporter>`, как у `registerHandler`. У handler'а есть терминальный null-object (`DownloadOnlyHandler`), у экспортёра неизвестный формат — управляемое исключение (`UnknownExportFormatException`), а не null-object; это не дефект (иное дерево резолва: формат — явный ключ запроса, не выводится из файла), но это другая идиома «отсутствия совпадения».
**Почему опасно:** Потребитель, освоивший регистрацию через `Vaulter::registerHandler('App\\MyHandler::class')` (строкой, без предварительного `new`), у экспортёра получает `TypeError`, если попробует передать FQCN тем же способом — двойной стандарт DX (E3.1), обходится чтением сигнатуры, но ломает ожидание «одна модель регистрации для родственных швов».
**Доказательство:** таблица симметрии выше + repro `plans/AUDIT-VLT/artifacts/repro/P3.3/HandlerExporterSeamReproTest.php`, тест `C7: VaulterManager::registerExporter()…` — регистрация принимает только анонимный `new class implements DocumentExporter`, попытка передать строку класса потребовала бы отдельного `$container->make()` со стороны вызывающего кода (в отличие от `registerHandler`, который это делает сам, `packages/documents/src/Documents/DocumentHandlerRegistry.php:285-295`, `resolveInstance()`).
**Норма, которая нарушена:** E3.1 (единая идиома шва); Code Guidance P3.3: «Асимметрия handler↔exporter — Minor (двойной стандарт DX), НЕ Blocker, если оба шва по отдельности работают».
**Сверка с ADR:** `docs/adr/0004-content-format.md` описывает формат хранения/версионирование, но НЕ содержит решения о симметрии/идиоме регистрации handler vs exporter — асимметрия не является сознательным ADR-решением, это непокрытый ADR'ом дизайн-пробел, не «ADR устарел».
**Рекомендация:** привести `registerExporter()` к сигнатуре `DocumentExporter|class-string<DocumentExporter>` (резолв FQCN через контейнер, как у `registerHandler`); null-object для экспортёра не рекомендуется (текущее fail-loud исключение с подсказкой — корректный дизайн для явно запрошенного формата).

### F-P3.3-02 — Докблоки `HandlerRegistry`/`NodeHandlerResolver` заявляют «fails loudly with an install hint», которого не существует в коде · Severity: Minor · Уверенность: high

**Где:** `packages/core/src/Contracts/Documents/HandlerRegistry.php:13`; `packages/core/src/Contracts/Documents/NodeHandlerResolver.php:21-23`; фактическое поведение — `packages/core/src/VaulterManager.php:142-145` (`registerHandler()`: голый `$this->container->make(HandlerRegistry::class)`, без обёртки в кастомное исключение) и `packages/core/src/Http/Resources/Drive/NodeResource.php:122-129` (`handler()`: явная проверка `!app()->bound(NodeHandlerResolver::class)` → `return null`, резолв вообще не вызывается, если documents не установлен).
**Что:** Два докблока контрактов заявляют, что резолв контракта без установленного `vaulter-documents` «fails loudly with an install hint». Фактически: (а) для `NodeHandlerResolver` единственный реальный потребитель (`NodeResource::handler()`) явно ИЗБЕГАЕТ вызова резолва при отсутствии биндинга и молча возвращает `null` — путь «fail loudly» в проде никогда не исполняется, что прямо документировано в соседнем докблоке того же файла (`NodeResource.php:115-118`: «an absent binding degrades to null rather than throwing»); (б) для `HandlerRegistry` (`VaulterManager::registerHandler()`/`handlers()`) резолв через голый `container->make()` действительно бросает исключение при отсутствии биндинга, но это штатный `Illuminate\Contracts\Container\BindingResolutionException` («Target [...] is not instantiable») — общий контейнерный текст, а не кастомный «install hint». Грепом по `packages/core/src` и `packages/documents/src` на `InstallHint`/«install hint»/«composer require vaulter/documents» — ни одного такого сообщения не существует нигде в репозитории.
**Почему опасно:** Не безопасность — DX/доверие к докблоку. Разработчик хоста, читающий контракт (единственный источник документации для контракта без вендорной документации), ожидает содержательное сообщение с шагами установки при отсутствии пакета; получает либо молчаливый `null` (per NodeHandlerResolver — задокументированное в соседнем месте, но противоречащее самому контракту), либо голый Laravel-текст без какого-либо упоминания `vaulter-documents` (per HandlerRegistry). Code Guidance item'а прямо предупреждает: «Докблоки… НЕ являются доказательством» — этот случай именно такой.
**Доказательство:**
```
$ grep -rn "install hint\|InstallHint" packages/core/src packages/documents/src
packages/core/src/Contracts/Documents/NodeHandlerResolver.php:22: * fails loudly with an install hint. A folder node is never passed here — NodeResource
packages/core/src/Contracts/Documents/HandlerRegistry.php:13:     * resolving it fails loudly with an install hint.
```
(нет ни одного места, где такой install-hint-текст реально формируется; сравнить с `UnknownExportFormatException::forFormat()`, `packages/core/src/Exceptions/Documents/UnknownExportFormatException.php:14-24`, где install-hint-подобное сообщение — «Fix: register one via config(vaulter.exporters) or Vaulter::registerExporter(). Docs: …» — РЕАЛЬНО существует; это показывает, что паттерн пакету известен и реализуем, но не применён к `HandlerRegistry`/`NodeHandlerResolver`).
**Норма, которая нарушена:** E5.3 (пакет объявляет контракт, деградация должна быть внятной и задокументированной согласованно с фактическим поведением); внутренняя норма Code Guidance item'а о недоверии к докблокам как доказательству.
**Сверка с ADR:** нет применимого ADR — это не архитектурное решение, а расхождение докблока с фактическим поведением; не «ADR устарел».
**Рекомендация:** либо обернуть `container->make(HandlerRegistry::class)` в `VaulterManager::registerHandler()`/`handlers()` в кастомное исключение с install-hint текстом (по образцу `UnknownExportFormatException`), либо смягчить формулировку докблоков `HandlerRegistry`/`NodeHandlerResolver` до фактического поведения («resolving without vaulter-documents installed throws a generic container binding error / degrades to null for NodeHandlerResolver's NodeResource consumer»).
