## 2. Находки

### F-P4.3-01 — Ни один пакет не запрещает импорт `App\*`/хоста · Severity: Minor · Уверенность: high

**Где:** `packages/core/tests/Arch/ArchTest.php`, `packages/drive/tests/Arch/ArchTest.php`, `packages/media/tests/Arch/ArchTest.php`, `packages/documents/tests/Arch/ArchTest.php`, `packages/filament/tests/Arch/ArchTest.php` (весь файл каждого — правило отсутствует)
**Что:** Ни один из пяти arch-тестов не содержит правила вида `->not->toUse('App')`/аналога, запрещающего пакетному коду ссылаться на пространство имён хост-приложения.
**Почему опасно:** Пакет позиционируется как embeddable-библиотека (D1, E5.1); без структурного гейта случайная ссылка на `App\*` (например, при копипасте из хоста при разработке фичи) остаётся незамеченной до релиза и ломает установку в чистый хост без такого класса — регрессия автономности, которую должен ловить именно arch-тест, а не ревью.
**Доказательство:** `grep -n "App\\\\" packages/*/tests/Arch/ArchTest.php` → пустой вывод (0 совпадений) во всех пяти файлах.
**Норма, которая нарушена:** E5.1 (`findings/P0-embeddable-laravel.md`) — пакет не должен зависеть от хоста; P4.3 `C1`, Intent item'а требует явного arch-запрета.
**Сверка с ADR:** Ни один `docs/adr/*.md` не описывает исключение из E5.1 для этого запрета — не найдено сознательного решения не ставить гейт; классифицируется как дефект, а не «ADR устарел».
**Рекомендация:** В каждый `ArchTest.php` добавить `arch('… never depends on the host application')->expect('Vaulter\<Root>')->not->toUse('App');` (или через file-scan аналогично `coreReferencesTo()`, если namespace-графовая форма даёт ложные срабатывания на test-фикстурах).

### F-P4.3-02 — Нет arch-гейта на границу публичного API пакета (E3.1) · Severity: Minor · Уверенность: high

**Где:** те же пять `ArchTest.php` (правило отсутствует во всех)
**Что:** Ни один arch-тест не проверяет, что снаружи пакета видны только `Contracts/`/`Facades/`/`Data/`/`Events/`, а `Services/`/`Repositories/`/`Support/` остаются internal — только точечные правила по отдельным namespace (readonly/final/interfaces), не общий гейт видимости.
**Почему опасно:** Без структурного запрета внутренние классы (`Services/`, `Repositories/`, `Support/`) остаются случайно публичными; консьюмер молча начинает завязываться на internal-класс, и его последующее изменение становится breaking change без формального SemVer-сигнала (E3.2 — «кухонная раковина» в публичной поверхности делает эволюцию без breaking невозможной).
**Доказательство:** `grep -n "Services\|Repositories\|Support\|toOnlyBeUsedIn\|dependsOnlyOn" packages/*/tests/Arch/ArchTest.php` — единственные совпадения относятся к другим правилам (core: `use Vaulter\Repositories\Drive\NodeReadRepository` как импорт для `not->toUse(Request::class)`-проверки, спот-чек в списке FQCN, флоат-роут-исключение `Repositories => []` в domain-subfolder-тесте) — ни одно не проверяет видимость снаружи пакета.
**Норма, которая нарушена:** E3.1 (`findings/P0-embeddable-laravel.md`) — «Публичны только: тонкие фасады, контракты, DTO/VO, события. Всё прочее — внутреннее»; P4.3 `C3`.
**Сверка с ADR:** Не найдено ADR, объявляющего эту границу необязательной для arch-уровня.
**Рекомендация:** Добавить в каждый пакет arch-правило вида `expect('Vaulter\<Root>\Services')->toOnlyBeUsedIn('Vaulter\<Root>')` (Pest Arch `toOnlyBeUsedIn`) для internal-namespace'ов, либо file-scan аналог `coreReferencesTo()`, если тестовые фикстуры пакета сами используют internal-классы легитимно.

### F-P4.3-03 — Мутационный гейт `infection.json5` отключён (`minMsi`/`minCoveredMsi` = 0) · Severity: Major · Уверенность: high

**Где:** `infection.json5:9-10`
**Что:** `"minMsi": 0, "minCoveredMsi": 0` — при любой доле выживших мутантов Infection завершается успешно; порог не проваливает прогон ни при 0%, ни при 100% выживших мутантов.
**Почему опасно:** Мутационный гейт с нулевым порогом не выполняет функцию гейта — «тесты зелёные» перестаёт что-либо гарантировать про качество ассертов (скилл `quality:mutation-testing`: MSI-гейт — это и есть смысл Infection). Усугубляется тем, что `mutation.yml` и так `advisory only` с `|| true` (`.github/workflows/mutation.yml:59`) — двойное отсутствие enforcement.
**Доказательство:**
```json
"minMsi": 0,
"minCoveredMsi": 0
```
**Норма, которая нарушена:** Item P4.3 `C4`, Why-секция item'а: «мутационный гейт с `minMsi: 0`/`minCoveredMsi: 0` не проваливает CI ни при какой доле выживших мутантов». Code Guidance item'а прямо запрещает считать `minMsi: 0` приемлемым «потому что проект молодой».
**Сверка с ADR:** Не найдено ADR о сознательном отключении мутационного гейта; `.github/workflows/mutation.yml:3-5` («Advisory only … Not a PR blocker — mutation testing is expensive and should be reviewed after the test suite is stable») документирует НАМЕРЕНИЕ сделать job advisory, но не оправдывает `minMsi: 0` внутри самого `infection.json5` (даже advisory-прогон должен репортить реальный MSI, а не гарантированно проходить порог).
**Рекомендация:** Задать ненулевой `minMsi`/`minCoveredMsi` (минимально — текущий фактический MSI как baseline, дальше повышать); job может остаться advisory (`|| true`) на переходный период, но конфиг должен отражать реальный порог, а не декоративный ноль.

### F-P4.3-04 — Мутационный гейт покрывает только `packages/core/src`, остальные 4 PHP-пакета вне охвата · Severity: Minor · Уверенность: high

**Где:** `infection.json5:3-5`
**Что:** `"source": {"directories": ["packages/core/src"]}` — drive/media/documents/filament полностью исключены из мутационного прогона.
**Почему опасно:** Мутационное тестирование не даёт никакого сигнала о качестве тестов в 4 из 5 PHP-пакетов (включая CAS-слой `media`, помеченный в Why item'а как критичный по инвариантам); ложное ощущение покрытия для пакетов, фактически не проверяемых.
**Доказательство:** `infection.json5:3-5` дословно — `"directories": ["packages/core/src"]`.
**Норма, которая нарушена:** Item P4.3 `C5`.
**Сверка с ADR:** Не найдено ADR о сознательном ограничении охвата.
**Рекомендация:** Расширить `source.directories` на `packages/{drive,media,documents,filament}/src` (per-package `infection.json5` в каждом пакете — по аналогии с package-local `phpstan.neon`/`phpunit.xml` — или единый корневой конфиг со всеми пятью путями).

### F-P4.3-05 — `composer test:types` (100% type-coverage) объявлен, но не подключён ни к одному CI-гейту core · Severity: Minor · Уверенность: high

**Где:** `composer.json:60` (`"test:types": "vendor/bin/pest --type-coverage --min=100"`); отсутствие вызова в `.github/workflows/tests.yml`
**Что:** Скрипт `test:types` существует в корневом `composer.json`, но ни `.github/workflows/tests.yml`, ни `Makefile`, ни любой другой корневой workflow его не вызывают — 100%-type-coverage порог для `packages/core` объявлен, но нигде не гейтит CI. (Контраст: пакеты drive/media/documents/filament подключают `--type-coverage --min=100` в СВОИХ workflow — `drive.yml:57`, `documents.yml:59`, `media.yml:55`, `filament.yml:51` — только core лишён этого гейта в CI, хотя скрипт для него есть.)
**Почему опасно:** Порог, не подключённый к гейту, не защищает от регрессии — разработчик core может уронить type-coverage ниже 100%, PR пройдёт зелёным, метрика существует только «для галочки». Асимметрия с остальными 4 пакетами делает core именно тем местом, где этот конкретный гейт молча не работает.
**Доказательство:** `grep -rn "test:types\|type-coverage" .github/workflows/tests.yml` → пустой вывод; `grep -n "type-coverage" .github/workflows/{drive,documents,media,filament}.yml` → по одному совпадению в каждом (`--type-coverage --min=100`).
**Норма, которая нарушена:** Item P4.3 `C6`: «порог, не подключённый к гейту, = находка Minor».
**Сверка с ADR:** Не найдено ADR о намеренном исключении core из этого гейта.
**Рекомендация:** Добавить шаг `composer test:types` (или эквивалент `vendor/bin/pest --type-coverage --min=100`) в `.github/workflows/tests.yml` рядом с существующим `--coverage --min=80`, либо в `make ci`/`make test`.
