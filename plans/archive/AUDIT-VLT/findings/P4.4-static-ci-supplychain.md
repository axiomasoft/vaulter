## 2. Находки

### F-P4.4-01 — Rector не запускается ни в одном CI-workflow · Severity: Minor · Уверенность: high

**Где:** `.github/workflows/code-style.yml:1-44` (только Pint), `Makefile:16-20,25,32`, `composer.json:63-64`, `rector.php:10-14`, `README.md:105`
**Что:** `rector.php` настроен и доступен как `make rector`/`vendor/bin/rector process --dry-run`, `README.md:105` явно перечисляет Rector как часть `make ci`, но ни один файл в `.github/workflows/` не вызывает Rector ни разу — стиль-код-ревью в CI ограничен Pint.
**Почему опасно:** заявленный локальный гейт («composer install && make ci # Pint + PHPStan + Rector + Pest») не воспроизводится в PR-проверке: код, нарушающий Rector-правила (dead code, устаревшие конструкции), может слиться в `main`, пока разработчик не прогонит `make ci` вручную. Кроме того, `rector.php` даже при вызове покрывает ТОЛЬКО `packages/core/{src,database,tests}` — 5 из 6 пакетов вне охвата и локально.
**Доказательство:**
```
$ grep -rn "rector" .github/workflows/
(0 совпадений)
$ grep -n "rector" Makefile
16:rector: ## Run Rector dry-run (no changes)
17:	vendor/bin/rector --dry-run --no-progress-bar
25:quality: lint-check stan rector
32:ci: quality test
```
**Норма, которая нарушена:** P4.4 `C2` (Implementation Rules P4.md:169) — «pint.json и rector.php применяются ко всем пакетам… code-style.yml реально гоняет их в CI; неохваченный пакет = находка Minor».
**Сверка с ADR:** нет ADR, регулирующего Rector-охват CI; расхождение — не «ADR устарел», а дефект обвязки CI vs документированного локального workflow.
**Рекомендация:** добавить шаг `vendor/bin/rector --dry-run --no-progress-bar` в `code-style.yml` (или отдельный job); расширить `rector.php` `withPaths()` на остальные пять пакетов либо завести package-local `rector.php` по аналогии с `phpstan.neon`/`pint.json`.

### F-P4.4-02 — CI-матрица Laravel 12/13 покрывает только `vaulter-core`; Filament не тестируется ни против одной ячейки честно · Severity: Major · Уверенность: high

**Где:** `.github/workflows/tests.yml:15-24` (единственный матричный job), `.github/workflows/drive.yml:39-41`, `media.yml:37-39`, `documents.yml:41-43`, `permissions-azgard.yml:36-38`, `filament.yml:33-35`; `packages/filament/composer.json:29`
**Что:** Только `tests.yml` (пакет `vaulter-core`) явно форсирует обе заявленные комбинации (`php 8.4 × {laravel 12.*+testbench^10.0, laravel 13.*+testbench^11.0}`). CI пяти остальных пакетов (`drive`, `media`, `documents`, `permissions-azgard`, `filament`) делает голый `composer install` без матрицы — резолвится ровно ОДНА комбинация версий, детерминированная верхней допустимой границей констрейнта. Для `vaulter-filament` эта граница жёстко зафиксирована: `orchestra/testbench: ^11.0` (в отличие от `^10.0|^11.0` у остальных четырёх), т.е. CI Filament гарантированно резолвит только L13-ветку — L12-совместимость Filament (заявленная M2.2 как «рабочая в проде») не проверяется НИКОГДА, а именно L13-ветка (M2.3 — «дозревающая», зафиксированы реальные конфликты composer-констрейнтов `^5.0`+`^13.0`) проверяется CI молча, без явной фиксации версии и без предупреждения при провале установки.
**Почему опасно:** асимметрия матрицы, зафиксированная как факт в `findings/P4-matrix-supply-chain.md` §M3, реализуется в CI как **дыра покрытия**, а не просто «наблюдение»: заявленная поддержка Laravel 12 для drive/media/documents/permissions-azgard/filament никогда фактически не прогоняется, а единственная прогоняемая для filament ветка (L13) — именно та, где M2.3 документирует известные install-конфликты. Регресс на L12 для этих пяти пакетов будет обнаружен только пользователем в проде.
**Доказательство:**
```yaml
# filament.yml:33-35 — нет ни matrix, ни explicit laravel/framework require
      - name: Install dependencies
        working-directory: packages/filament
        run: composer install --prefer-dist --no-interaction --no-progress
```
```json
// packages/filament/composer.json:29
"orchestra/testbench": "^11.0",
```
**Норма, которая нарушена:** P4.4 `C3`/`C4` (Implementation Rules P4.md:170-171); `findings/P4-matrix-supply-chain.md` §M3 («Filament не входит ни в одну ячейку матрицы» — предсказание подтверждено).
**Сверка с ADR:** нет ADR, фиксирующего CI-стратегию сплит-пакетов как «одна версия на пакет, полная матрица только у core» — не найдено сознательного решения; вероятный технический долг split-CI (`monorepo-split.yml`), не продуктовое решение.
**Рекомендация:** добавить `matrix.include` (аналогичный `tests.yml`) как минимум в `filament.yml` и `documents.yml`/`drive.yml`/`media.yml`/`permissions-azgard.yml`, либо явно задокументировать, что split-пакеты поддерживают только верхнюю границу констрейнта, понизив заявленную матрицу.

### F-P4.4-03 — Политика поддерживаемых версий Testbench/Filament не объявлена · Severity: Minor · Уверенность: high

**Где:** `README.md:10-15`
**Что:** README объявляет таблицу компонентов (PHP, Laravel, Vue, Node), но не Testbench и не Filament-версию/минимальную Laravel-версию для Filament-плагина (M2.1: Filament v5 требует L11.28+, PHP 8.2+ — отличается от общего минимума пакета).
**Почему опасно:** пользователь, ставящий `axioma-studio/vaulter-filament` на Laravel 13, не находит нигде предупреждения о M2.3 (дозревающая поддержка) — единственный сигнал, если установка не пройдёт, будет composer-конфликт без контекста.
**Доказательство:** `README.md:10-15` — таблица без строки Testbench/Filament; `docs/` не содержит отдельного документа version-policy (grep по «supported version», «version policy», «version-support» — 0 попаданий вне `docs/plan/`).
**Норма, которая нарушена:** D12 (`plan.md` D12) — «матрица Laravel/Testbench/Filament не объявлена — её отсутствие проверяется и фиксируется находкой в P4.4 (не блокер плана)».
**Сверка с ADR:** нет отдельного ADR по версионной политике; это прямо предсказанная плановая находка (D12), не расхождение с ADR.
**Рекомендация:** добавить строку Testbench в таблицу README + отдельный абзац о Filament-совместимости (минимум L11.28+, предупреждение о ранней стадии L13-поддержки).

### F-P4.4-04 — `composer audit`: CVE-2025-45769 в `firebase/php-jwt` (используется в собственном collab-JWT минтинге) · Severity: Minor · Уверенность: medium

**Где:** `composer.json:30`, `packages/documents/composer.json:29` (констрейнт `^6.0`); использование — `packages/documents/src/Collaboration/HocuspocusNodeCollaborationDriver.php`
**Что:** `composer audit` сообщает advisory PKSA-y2cr-5h3j-g3ys / CVE-2025-45769 («weak encryption») для `firebase/php-jwt` версий `<7.0.0`; текущий констрейнт `^6.0` целиком попадает в затронутый диапазон.
**Почему опасно:** библиотека реально используется для минтинга JWT для realtime-collab хендшейка (не только в тестах) — уязвимость в криптографии токен-библиотеки напрямую бьёт по S-нормам P1.6/P1.7 (`F-P1.6-*`). Advisory классифицирован инструментом как `low`, порог item'а («high+») формально не достигнут — фиксирую отдельной Minor-строкой, а не как `C7 fail`, чтобы не завышать severity вопреки собственному инструменту.
**Доказательство:**
```
$ composer audit --no-interaction
Package: firebase/php-jwt | Severity: low | CVE-2025-45769
Affected versions: <7.0.0
```
(полный вывод — `plans/AUDIT-VLT/artifacts/repro/P4.4/composer-audit-root.txt`)
**Норма, которая нарушена:** P4.4 `C7` (Implementation Rules P4.md:174) — де-факто ниже официального порога находки («high+»), фиксируется как консервативная Minor-находка ввиду security-критичного пути использования.
**Сверка с ADR:** нет ADR по версионированию php-jwt; T1 (`P0.2-rag-supplement.md`) подтверждает `^6.0` как «актуальный мажор» на уровне API — расхождение не с ADR, а свежий CVE-факт после даты снимка T1.
**Рекомендация:** отслеживать релиз `firebase/php-jwt ^7.0` и поднять минимальную версию при выходе; краткосрочно — не блокер (severity `low`).

### F-P4.4-05 — `npm audit --audit-level=high` в `packages/vue`: critical RCE в devDependency `happy-dom` · Severity: Major · Уверенность: high

**Где:** `packages/vue/package.json:58-68` (`happy-dom`, `vite`, `vitest` в `devDependencies`)
**Что:** `npm audit --audit-level=high` в `packages/vue` возвращает 6 vulnerabilities: 3 moderate (`esbuild`/`vite`-цепочка), **1 high, 2 critical** — `happy-dom <=20.8.8` содержит GHSA-37j7-fg3j-429f (VM Context Escape → Remote Code Execution) и два смежных advisories (cookie/credentials leak, unsanitized module-name code-injection).

**Доказательство:**
```
happy-dom  <=20.8.8
Severity: critical

```
(полный вывод — `plans/AUDIT-VLT/artifacts/repro/P4.4/npm-audit-vue.txt`)

**Рекомендация:** `npm audit fix --force` подтягивает breaking-обновления (`vitest@4`, `happy-dom@20.10.6`) — оценить объём миграции тестов и обновить `devDependencies` в `packages/vue/package.json`.

## 3. Не проверено / ограничения

- **`composer.lock` недоступен для прямого чтения окружением** (permission-denied) — `composer audit` использует установленный `vendor/`/резолвер напрямую и вернул результат, но точный снимок фактически разрешённых версий (constraint → resolved) не сверен построчно; см. также `P0.2-rag-supplement.md` «Не проверено».
