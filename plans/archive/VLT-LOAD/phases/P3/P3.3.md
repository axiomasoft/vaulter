### P3.3 — Actual EXPLAIN, ревизия индексов и HypoPG-кандидаты

**Intent:** Для corpus P3.2 снять actual plans на representative parameter classes, проверить
горячие индексы и доказать/отклонить кандидатные индексы HypoPG без изменения schema.
**Why:** Сам факт Seq Scan или высокий mean не доказывает missing index. Нужны actual rows/loops,
buffers/temp/WAL, cardinality error и сравнение с planner-only hypothetical plan на том же dataset и
settings fingerprint.
**Scope Included:** top-20 + обязательные hotspots; safe actual EXPLAIN protocol; index inventory и
usage для восьми горячих table families; justified seq-scan verdict; estimate skew/temp spill/
repeated loops; HypoPG baseline/candidate pairs; candidate size estimate; write/WAL maintenance risk;
machine-readable cross-links к OP/query/code anchors.
**Scope Excluded:** `CREATE INDEX`, migrations, `ANALYZE` с altered statistics targets как постоянное
решение, planner GUC tuning ради зелёного плана, ltree/schema redesign, package code changes.
**Inputs:** `plans/VLT-LOAD/phases/P3/P3.2.state.md`;
`plans/VLT-LOAD/artifacts/P3/run-manifest.json`;
`plans/VLT-LOAD/artifacts/P3/pgss-top20.json`;

`plans/VLT-LOAD/artifacts/P3/operation-coverage.json`;

**Files:** `plans/VLT-LOAD/artifacts/P3/explain/`,

**Required Reads:** (1) `plans/VLT-LOAD/phases/P3/P3.2.md` and its GREEN terminal evidence;
(2) all validated `plans/VLT-LOAD/artifacts/P3/` P3.2 carriers;
(3) `plans/VLT-LOAD/findings/P3-rag-postgres-profiling.md`;

(6) query anchors resolved from `operations-catalog.md`, including
`NodeReadRepository::candidateNodeIds()` and `OutboxRelay::subscribedEndpoints()`.
**Implementation Rules:** Actual plan command is
`EXPLAIN (ANALYZE, BUFFERS, VERBOSE, SETTINGS, WAL, FORMAT JSON)` with bounded statement/lock
timeouts on disposable DB. DML runs inside rollback and records WAL/locks/cache effects; post-plan
dataset invariant must still match. Each plan stores query hash, OP ids, parameter class, settings,
planning/execution time, estimates/actual rows, loops, removed rows, buffers/temp/WAL and source
anchor. Seq Scan is `justified` only with selectivity/size evidence. HypoPG baseline и candidate
plain EXPLAIN выполняются в одной session; `ANALYZE` с hypothetical index запрещён. Candidate verdict
is one of `planner-rejected|planner-supported|superseded-by-existing`; none claims runtime gain.
**Code Guidance:** Prioritize cardinality-error × loops and buffers per returned row over node-name
grep. For composite/partial candidates record predicate implication, column order, estimated bytes,
covered OPs and write-hot penalty (`v_activity` GIN/B-tree especially). Existing index may be marked
redundant only as a debt hypothesis; P3 does not drop it. Generic/custom plan differences require
both representative and generic evidence, not a forced `enable_seqscan=off` plan.
**Validation:** every top-20 fingerprint and mandatory hotspot has ≥1 valid actual plan or explicit
unsafe/unresolvable rejection; every plan validates and matches P3.2 fingerprint; all eight hot
table families appear in index review; every candidate has baseline/candidate pair, session marker,
`hypopg_reset` proof and no ANALYZE; dataset invariant unchanged; no DDL outside `CREATE EXTENSION
hypopg` on disposable profile DB.
**Deliverables:** raw actual plans, complete hot-index inventory/review, and bounded HypoPG candidate
records with planner verdict and maintenance-risk metadata.
