### P3.1 — Воспроизводимый profiling lane и schema evidence

**Intent:** Построить load-only lane, который проверяет объём/статистику датасета, включает
`pg_stat_statements`/HypoPG, коррелирует Laravel queries с `LOAD_RUN_ID` и OP-id, безопасно снимает
JSON evidence и валидирует его до любого lab-прогона.
**Why:** Ручные `psql`-команды и произвольные EXPLAIN не воспроизводимы: они теряют fingerprint
окружения, смешивают seed с workload, раскрывают bindings и позволяют HypoPG-plan выдать за actual
ускорение. P3.2–P3.4 нужен один исполняемый и тестируемый контракт.
**Scope Included:** pinned HypoPG 1.4.1 в отдельном PostgreSQL-образе load-стенда; явные параметры
`pg_stat_statements` (`track=all`, достаточный `max`, planning по объявленному режиму), opt-in
`track_io_timing`; SQL preflight/reset/capture; load-host `DB::listen` recorder без raw bindings;
CLI-обвязка `prepare|capture|explain|hypopg|verify`; JSON schema/fixtures и unit tests; README runbook.
**Scope Excluded:** запуск авторитетного профиля; изменение seed-объёмов/SLO; global
`auto_explain.log_analyze`; production DB; реальные индексы/миграции; изменения `packages/*/src`.

**Implementation Rules:** `LOAD_DB_TRACE` по умолчанию off. Recorder сохраняет только `run_id`,
OP-id/command-id, connection, normalized SQL template hash, duration, ordinal и transaction marker;
bindings, rendered SQL, tokens/UUID/user/tenant values запрещены. SQL идёт direct-to-Postgres для
admin/preflight и через PgBouncer для workload. Reset фиксирует до/после
`pg_stat_statements_info`; `dealloc_delta>0` — hard invalidation. `track_io_timing` включается только
после `pg_test_timing`, значение/overhead входят в manifest. HypoPG живёт в одной сессии, используется
только с plain `EXPLAIN`, завершается `hypopg_reset()`. Все DML actual-plans разрешены только в
disposable clone с timeouts; rollback не выдаётся за отсутствие WAL/lock/cache effects.
**Code Guidance:** Переиспользовать `LOAD_RUN_ID`, `dataset_id` и operation vocabulary существующего
харнесса; не вводить второй каталог маршрутов. Python reader принимает только bounded JSON/JSONL,
отклоняет неизвестные поля, duplicate evidence keys и отсутствующий terminal marker. Shell script
использует `set -euo pipefail`, не печатает env/secrets и атомарно публикует run directory только
после `verify`. `auto_explain` допустим лишь как явно записанный fallback: sample rate, threshold и
`log_timing=off`; он не является default path.
**Validation:** `docker compose -f load/docker-compose.load.yml --env-file load/env/S0.env config`;
сборка profiling Postgres image; `CREATE EXTENSION pg_stat_statements` и `CREATE EXTENSION hypopg`
на disposable S0; `python3 -m unittest load/gates/test_p3_profile.py`; load Pest test recorder;
fixture-проверки reject raw bindings, HypoPG+ANALYZE, missing fingerprint/dealloc evidence и
write-EXPLAIN без disposable marker; `./load/scripts/p3-profile.sh prepare --tier S0 --dry-run`.
**Deliverables:** profiling Postgres image/config, SQL/CLI capture lane, privacy-safe query trace,
deterministic evidence validator/fixtures и документированный dry-run.
