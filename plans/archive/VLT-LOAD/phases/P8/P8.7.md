### P8.7 — Live gate P8-minimum и overhead instrumentation

**Intent:** Одним operator-run доказать, что P8-minimum доступен через живой Prometheus scrape,
каждая обязательная metric family имеет реальный trigger/evidence, gate reader вычисляет все
применимые строки, а enabled instrumentation укладывается в уже принятый δ и memory ceilings.
**Why:** Исторические implementation/fixture checks подтверждают wiring, но не подтверждают live
scrape, metric matrix, `perf-assert` или with/without overhead. Без этого P3–P7 не имеют проверенного
server-side measurement carrier.
**Scope Included:** bounded repair orchestration `p8-live-gate.sh`; один run-scoped S0 trigger/gate
run; живой `GET /metrics` из Prometheus job `vaulter-sut`; 50-family/type/label/trigger matrix;
96-row source/verdict matrix (`promql|k6`); class-A `perf-assert`; tier-S on/off pair на fingerprint
P2.8; RSS/latency overhead; immutable raw artifacts и closure finding.
**Scope Excluded:** новые metric families или SLO; package instrumentation; production backend;
Collector/Tempo/Jaeger deployment; подмена live series зарегистрированными zero-only fixtures;
исполнение P3–P7.

**Implementation Rules:** Operator owner is the manual P8.7 executor. Canonical commands are
`TIER=S0 ./load/scripts/p8-live-gate.sh gate --profile smoke-perf` and
`TIER=S ./load/scripts/p8-live-gate.sh overhead --baseline plans/VLT-LOAD/findings/P2.8-baseline-S.md`.
The wrapper must create one `LOAD_RUN_ID` before app/worker start, pass it to every producer and
consumer, finalize it once, and retain rejected attempts. Each of the 50 families needs schema
parity plus a recorded trigger and a non-stale scraped sample; conditional zero is admissible only
when the trigger ran and the expected zero outcome is proved. Every applicable class-A row must be
`pass|known-red|product-red`, never `not-checkable|not-evaluated`; class B remains k6-owned and must
resolve from the same summary. Product RED is distinct from evidence-invalid. Overhead compares
Null/off and enabled on the same dataset/images/cpuset fingerprint; GREEN requires existing δ=10%
and the already accepted memory ceilings, not a post-result threshold.
**Code Guidance:** Start with a 50-family trigger matrix, then run `perf-assert`, then the expensive
tier-S pair. A scrape of pre-registered zero series without trigger provenance is evidence-invalid.
Run-id mismatch, missing family/type/label, missing PromQL window, cross-run sample, unequal on/off
fingerprint, failed harness exit, or incomplete pair is evidence-invalid and returns P8.7. A valid
SLO product RED remains visible in `gate-matrix.json`; overhead above δ is a P8.7 acceptance RED and
must be repaired before P3. No raw IDs/secrets may enter artifacts.
**Validation:** `python3 -m unittest load/gates/test_p8_live_gate.py`;
`TIER=S0 ./load/scripts/p8-live-gate.sh gate --profile smoke-perf`;
`TIER=S ./load/scripts/p8-live-gate.sh overhead --baseline plans/VLT-LOAD/findings/P2.8-baseline-S.md`;
`python3 load/gates/p8_live_gate.py verify --artifacts plans/VLT-LOAD/artifacts/P8.7` twice with
byte-identical result; 50/50 trigger/scrape parity; zero applicable `not-checkable|not-evaluated`;
on/off fingerprint equality; δ≤10% and fixed memory ceilings; secret/UUID scan empty.
**Deliverables:** immutable live run manifest, 50-family metric matrix, 96-row gate-source matrix,
on/off overhead evidence and `findings/P8.7-gate-closure.md` with GREEN/RED/evidence-invalid rules.
