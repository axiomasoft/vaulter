# P5 — Конкуренция в масштабе: сотни контендеров

## Phase Context

**Цель.** Доказать поведение Vaulter при конкуренции, которую не покрывают двухпроцессные package-
тесты: NOWAIT-конфликты одной upload-сессии, блокирующий CAS-lock, параллельные reparent, насыщение
PgBouncer и sweep просроченных сессий одновременно с live PATCH. P5 не исправляет найденные горячие
пути: она сохраняет воспроизводимое evidence и выпускает bounded debt по D-LOAD-5/D11.

**Входной контракт.** P2 владеет disposable stand/seed/k6; P8.5 владеет server-side seams фоновых
команд и lock-wait collector; P8.7 — run-scoped Prometheus gate. D41 запрещает исполнение P5 до
GREEN/accepted `findings/D41-full-plan-audit.md`, штатной digest-bound reconciliation P8.5 и GREEN
live gate P8.7. Историческая минимальная journal-запись P8.5 не доказывает spec digest/write-site;
владельцем repair остаётся P8.5, пока новый terminal event не материализует byte-fresh GREEN state.

**Четыре плоскости evidence.** (1) `product-realistic` идёт через HTTP/Artisan с tier-native
конкуренцией и применяется к SLO; (2) `product-worst-case` намеренно направляет N клиентов на один
resource и характеризует защитный механизм, но его ожидаемые 409 не сравниваются с обычным бюджетом
≤5 %; (3) `primitive-control` использует прямой SQL только для доказательства lifetime/key collision/
pool queue и не выдаётся за product throughput; (4) `dirty-cardinality-probe` изолирует backlog
20 тыс./1 млн строк и не выдаёт tier-S host за live tier L. Каждая таблица и verdict несут одно из
этих значений.

**Матрица.** Авторитетный стенд — tier S. Ось насыщения `N=1/8/32/200` выводится из
`default_pool_size=8`, `4×pool=32`, `max_client_conn=200`; отдельный control `N=201` проверяет hard
client boundary. Product cases: одна/разные tus и S3 sessions; CAS normal/deterministic int4-
collision pair; disjoint/overlapping subtree move; collab issuance burst; live PATCH + sweeper.
Primitive controls: transaction-level lock release/try-lock, blocking CAS wait, PgBouncer queue/
timeout. Sweeper: tier-S 20 тыс. expired rows с тремя повторами и один targeted 1 млн probe на свежем
snapshot. `findings/P5-rag-postgres-concurrency.md` фиксирует первичные источники и границы claims.

**Evidence.** Raw `pg_locks` (`granted`, `waitstart`), `pg_stat_activity`, `pg_blocking_pids()`, delta
`pg_stat_database.deadlocks`, PostgreSQL lock/deadlock logs, PgBouncer `SHOW POOLS`/`SHOW STATS`, k6
summary, Prometheus/P8 series, command peak and integrity checks связываются одним `run_id`,
`dataset_id`, cell/attempt id. NOWAIT измеряется response/conflict counters; отсутствие строки в
`pg_locks` не превращается в нулевое ожидание. Pool wait и DB lock wait остаются разными рядами.

**Выходы.** Raw evidence — `artifacts/P5/`; итог — `concurrency-report.md`; новые долги —
`findings/P5-concurrency.md`. Ни один `packages/*/src` файл и ни один fix hot path в P5 не входят.

**Порядок.** P5.1 строит orchestration/collector/validator → P5.2 добавляет product fixtures и
scenario matrix → P5.3 выполняет tier-S run + bounded controls → P5.4 выпускает report/debt.
P5.1–P5.2 — recommended implementation batch; P5.3–P5.4 — recommended manual batch с одним
immutable run family.
