### P5.4 — Concurrency report, L-02/L-06/L-07 verdict и bounded debt

**Intent:** Свести P5.3 в проверяемый `concurrency-report.md`, отделить protocol conflict от pool/
DB waits и выпустить evidence-linked долги без исправления кода.
**Why:** Суммарный p95 или общий error rate скрывает причину: ожидаемый NOWAIT 409, ложная CAS
serialization, FPM queue, PgBouncer starvation и PostgreSQL deadlock требуют разных решений.
**Scope Included:** run validity; typed plane/cell tables; normal/worst-case upload conflicts;
CAS collision/control wait; tree/collab saturation; PG/PgBouncer queue attribution; deadlock/log
deltas; sweeper batch/RSS/time/drain projection; SLO mapping; L-02/L-06/L-07 disposition; new
`L-P5-nn`; confidence/limitations; exact dev-slice/D11 owner.
**Scope Excluded:** fixes/config tuning; tier M/L claims; treating 1m-on-S as tier L; combining SQL
control with product throughput; changing accepted thresholds; production rollout advice without
separate owner decision.
**Inputs:** `plans/VLT-LOAD/phases/P5/P5.3.state.md`;
`plans/VLT-LOAD/artifacts/P5/run-manifest.json`;
`plans/VLT-LOAD/artifacts/P5/matrix.json`;
`plans/VLT-LOAD/artifacts/P5/cell-verdicts.json`;
`plans/VLT-LOAD/slo.md`; `plans/VLT-LOAD/slo-gates.md`.
**Files:** `plans/VLT-LOAD/concurrency-report.md`, `plans/VLT-LOAD/findings/P5-concurrency.md`.
**Required Reads:** (1) P5.3 spec and GREEN terminal evidence `plans/VLT-LOAD/phases/P5/P5.3.md`;
(2) validated P5 raw carriers `plans/VLT-LOAD/artifacts/P5/observations.jsonl`;
(3) `findings/P5-rag-postgres-concurrency.md`; (4) P3 `db-profile.md` when already available,
otherwise explicit non-blocking `not-yet-produced` cross-reference; (5) SLO/error-budget rows
`plans/VLT-LOAD/slo.md`; (6) D8, D11, D31 and D41 current decisions; (7) source anchors for
RED/anomalous cells `plans/VLT-LOAD/artifacts/P5/cell-verdicts.json`.
**Implementation Rules:** Report begins with environment/evidence validity. Every row names plane,
surface, shape, N, repetition set and authoritative metric source. Product-realistic different-
resource 409 alone maps to ≤5 % budget; same-resource conflict ratio is a guard behavior. Pool wait
uses `cl_waiting/maxwait/avg_wait_time`, DB wait uses `waitstart`/blocker graph, deadlocks use counter+
log delta. L-02 needs 20k SLO-70 verdict plus separately labelled 1m cardinality evidence; no L SLO
claim. L-07 distinguishes proved key collision/false serialization from observed population
incidence. Each debt has severity, confidence, affected SLO, exact evidence ids, owner package,
candidate dev-slice and D11 gate. Any unexplained integrity failure blocks GREEN synthesis.
**Code Guidance:** Use “observed at N”, “mechanism control”, “targeted cardinality probe”; never
“hundreds reached the DB” when only client concurrency was 200. Do not average away timeout/OOM/
deadlock or subtract rejected attempts. A zero deadlock delta does not prove deadlock freedom outside
the tested graph. Keep current config facts separate from proposed tuning.
**Validation:** report validator requires 100 % matrix coverage and raw links; repetition policy and
plane/SLO compatibility pass; every RED/inconclusive cell maps to debt/limitation; L-02/L-06/L-07
each has explicit verdict; normal 409, deadlock and pool-boundary calculations recompute from raw;
Markdown/path/secret checks; no `packages/*` edits in P5 diff; plan-lint/downstream checks green or
only explicitly preserved pre-existing diagnostics.
**Deliverables:** `concurrency-report.md` as authoritative P5 interpretation and
`findings/P5-concurrency.md` as bounded remediation backlog.
