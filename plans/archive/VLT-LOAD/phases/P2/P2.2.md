### P2.2 — Стенд: `docker-compose.load.yml` + SUT-образ (nginx+php-fpm) + load-хост

**Intent:** Поднять эталонный стенд в `load/`: Postgres 16 + PgBouncer + MinIO + SUT (nginx + php-fpm
поверх testbench-скелета с пакетами vaulter) + Prometheus — с cpuset/`mem_limit`/`memswap_limit`
ровно по `reference-env.md` §1, параметризованный тиром (`S0` / `S` / `M`).
**Why:** Без стенда мерить нечего, а без **конверта** замер не привязан ни к чему (D12/D13). SUT
обязан быть nginx+php-fpm: `vendor/bin/testbench serve` — это `php artisan serve`, однопоточный dev-
сервер; на нём `pm.max_children` (8/32/96) и вся раскладка пула `slo.md` §0.1 — фикция (D28).
Существующий `e2e/docker-compose.yml` (testbench serve + hub + vite) — стенд коллаборации, не
нагрузочный: он переиспользуется **как образец провайдера хоста**, а не как SUT.
**Scope Included:** - `load/docker-compose.load.yml` — сервисы: `postgres` (16-alpine), `pgbouncer` (transaction-mode),
  `minio` + `minio-init` (создать бакет), `app` (nginx + php-fpm), `prometheus`
  (`--web.enable-remote-write-receiver`), `k6` (образ `grafana/k6`, пин минора). Ресурсы — `cpuset`,
  `mem_limit`, `memswap_limit` (равны), **`deploy.resources` запрещён** (E-5).
- `load/env/S0.env`, `load/env/S.env`, `load/env/M.env` — все числа тира: cpuset-строки,
  `mem_limit`, `pm.max_children`, параметры PG (§1.2), PgBouncer (§1.3), MinIO (§1.4).
- `load/docker/Dockerfile.app` — php 8.4-fpm + nginx (одним контейнером), расширения `pdo_pgsql`,
  `mbstring`; `memory_limit=512M`, `pm=static`, `pm.max_children=${PM_MAX_CHILDREN}`; document root —
  `vendor/orchestra/testbench-core/laravel/public`.
- `load/app/` — хост нагрузочного стенда (аналог `packages/core/tests/E2E/E2eServiceProvider.php`,
  но свой): `LoadServiceProvider` (включает фичи, ставит `vaulter.drivers.permission=database`,
  id-стратегию, S3-диск на MinIO), `LoadActingAs` middleware (актор из заголовка `X-Load-Actor` — k6
  ходит как N разных пользователей), маршрут `GET /load/health` (для healthcheck compose — `/up` в
  пакете нет, это фаза P8), `load/app/testbench.load.yaml`.
- Зависимость S3-драйвера: `league/flysystem-aws-s3-v3` — добавить в **корневой `require-dev`**
  (S3-multipart-путь без него не поднимается вовсе). Проверить path-style endpoint для MinIO.
- `load/scripts/up.sh` / `down.sh` — подъём с тиром: `TIER=S ./load/scripts/up.sh`.
- `load/README.md` — 20 строк: как поднять, как снести, где числа (ссылка на `reference-env.md`).
**Scope Excluded:** seed данных (P2.3); k6-скрипты (P2.4); пороги/perf-assert (P2.5); CI (P2.6);
любые правки `packages/*/src`; Hocuspocus-хаб и Vite (collab-сценарий P2.4 использует HTTP-выдачу
сессии OP-34, не сам ws-хаб — fan-out меряется в P5/P7, не здесь).
**Inputs:** `plans/VLT-LOAD/harness.md` (P2.1) §2; `reference-env.md` §0 (инварианты E-1…E-7), §1
(все числа), §5; `e2e/docker-compose.yml` + `e2e/docker/Dockerfile.laravel` +
`packages/core/tests/E2E/E2eServiceProvider.php` (образцы, не копипаста).
**Files:** `load/docker-compose.load.yml`, `load/env/{S0,S,M}.env`, `load/docker/Dockerfile.app`,
`load/docker/{nginx.conf,php-fpm.conf,php.ini}`, `load/app/**`, `load/scripts/{up.sh,down.sh}`,
`load/README.md`, `composer.json` (только `require-dev`), `.gitignore` (артефакты прогонов).
**Required Reads:** 1. `plans/VLT-LOAD/harness.md` — §2 (стенд), §7 (порядок прогона).
2. `plans/VLT-LOAD/reference-env.md` — §0, §1 целиком.
3. `e2e/docker-compose.yml` и `e2e/docker/Dockerfile.laravel` — что уже есть в репо.
4. `packages/core/tests/E2E/E2eServiceProvider.php` — как хост включает фичи/права/DB (образец
   для `LoadServiceProvider`).
5. `packages/core/src/Support/Config.php` + `packages/core/config/vaulter.php` — какие ключи реально
   существуют (диск, фичи, id-стратегия, `uploads.max_chunk_bytes`).
**Implementation Rules:** - Конверт задаётся **`cpuset`**, никогда `--cpus`/`cpu_quota` (E-1). `deploy.resources.limits` не
  использовать (E-5, читается только Swarm'ом).
- `mem_limit` == `memswap_limit` в каждом сервисе (E-2).
- Параметры PG берутся из cgroup-лимита (E-3) — числа §1.2 подставляются из `.env` тира, а не
  вычисляются в рантайме.
- cpuset lab-тиров кладётся на **физические** ядра, по одному потоку с ядра (L-2). Раскладка
  вычисляется командой `lscpu -e=CPU,CORE,MAXMHZ` и **фиксируется в `.env` тира**, а не угадывается.
  На этом боксе (i7-14700K): P-ядра — CPU 0–15 (пары HT), E-ядра — 16–27; тир S берёт 7 чётных
  CPU из 0–13 (по одному потоку с семи разных физических P-ядер), 14/15 — резерв хоста.
- Профиль `S0` (CI) — **без cpuset** (4 vCPU раннера), memory-лимиты по `reference-env.md` §4.1.
- Healthcheck у каждого сервиса; `depends_on: service_healthy` — цепочка postgres → app → k6.
- MinIO — отдельный том (не tmpfs, §1.4).
**Code Guidance:** - **Ни строки в `packages/*/src`.** Единственное исключение вне `load/` — `require-dev` в корневом
  `composer.json` (S3-драйвер) и `.gitignore`. Захотелось «заодно добавить `/up` в пакет» — стоп: это
  фаза P8.
- **Анти-самообман:** «поднялось» ≠ «работает». Item закрывается только когда через nginx проходит
  РЕАЛЬНЫЙ запрос к API vaulter (создание storage + узла) — не когда контейнер health-green.
- **Анти-подгонка:** если тир не помещается в железо (M на этом боксе — 12 однородных ядер нет), НЕ
  ужимать числа тира. Тир просто не запускается на этом хосте; в `load/README.md` пишется, что
  доступно (D25).
- **If-then:** если S3-драйвер не поднимается на MinIO (path-style/SigV4/endpoint) → это блокер
  сценариев OP-06/07 → эскалация по протоколу (`plan-protocol` §10), а не «отключим S3-сценарии».
- **If-then:** если `testbench`-скелет не отдаёт `public/index.php` под nginx — не изобретать свой
  bootstrap: эскалация (это выбор архитектуры SUT, D28).
**Validation:** - `docker compose -f load/docker-compose.load.yml --env-file load/env/S0.env config` — валиден,
  и в выводе **нет** `deploy:`/`cpus:` (E-1/E-5): `... config | grep -E "^\s+(cpus|deploy):" ; test $? -eq 1`.
- `TIER=S0 ./load/scripts/up.sh && docker compose -f load/docker-compose.load.yml ps` — все сервисы
  `healthy`.
- Сквозной запрос: `curl -fsS -H 'X-Load-Actor: 1' http://127.0.0.1:8080/api/vaulter/storages` → 200;
  создание storage+папки через API → 201 (команда фиксируется в `load/README.md`).
- `docker exec <app> php -m | grep -q pdo_pgsql` и `php -i | grep -q 'memory_limit => 512M'`.
- `docker inspect <app> --format '{{.HostConfig.CpusetCpus}} {{.HostConfig.Memory}} {{.HostConfig.MemorySwap}}'`
  на тире S — cpuset непустой, Memory == MemorySwap.
**Deliverables:** `load/` (compose, env-профили тиров, образ SUT, load-хост, скрипты, README);
`require-dev` с S3-драйвером.
