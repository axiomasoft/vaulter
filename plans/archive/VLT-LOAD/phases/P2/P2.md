# P2 — Нагрузочный харнесс: инструмент + профили трафика (гейт P3–P7)

## Phase Context

Фаза строит **генератор нагрузки и стенд**, на которых фазы P3–P7 будут снимать числа. Без неё SLO
из P1 остаются текстом: 81 обязательство и 97 гейтов (`slo.md`, `slo-gates.md`) не на чем вычислять.
P2 — гейт P3–P7 наравне с P8-минимумом.

**Фаза начинается с опровержения двух решений блупринта** (RAG:✅ 2026-07-14,
`findings/P2-rag-k6-harness.md`): xk6-fasthttp **не эмитит** `http_req_*`/`data_*` — то есть отменяет
метрики, на которых стоит весь гейт P1.4, и не документирует PATCH (а tus — это PATCH); Prometheus
remote-write **уже в ядре** k6 с v0.42. Плюс: ни один эндпоинт vaulter не принимает multi-GB тело
одним запросом (tus-чанк 8 MiB · S3-часть ≤ 64 MiB · single-shot ≤ 32 MiB · download — тело ответа).
Значит кастомный бинарник не нужен вовсе → **стоковый k6** (D22/D24), а 5-ГиБ фикстура заменяется
генерацией чанка в памяти + salt на сессию (D23) — иначе `k6/experimental/fs` положит 5 ГиБ в RSS
генератора.

**Что строим:** `load/` в этом же репо (D26) — docker-стенд по конверту `reference-env.md` §1
(cpuset, `mem_limit`, PgBouncer, MinIO, Prometheus), SUT = **nginx + php-fpm** поверх testbench-скелета
(`testbench serve` однопоточен — `pm.max_children` на нём не воспроизводим, D28), seed до объёмного
конверта §2, k6-сценарии по `operations-catalog.md`, две плоскости гейта (k6-thresholds + perf-assert,
D18) и CI-лейн S0.

**Границы (D-LOAD-4/5):** ни одной правки в `packages/*/src`. Найденные боттлнеки не чинятся
(L-01…L-08 — dev-срезы, D11). Метрики сервера — фаза P8; P2 лишь оставляет для них место и честно
помечает «метрики нет ⇒ SLO не проверяется».

**Тир прогонов (D25):** авторитетный — **S** на lab-box'е (7 физических P-ядер, `lscpu -e`); тир M
однородного cpuset'а на этом железе не получает (8 P + E-ядра) — гоняется только как класс A с
пометкой «латентность недостоверна»; L — экстраполяция. Публично обещанный README-тир M остаётся
**не подтверждённым прогоном** (`open-questions.md` **Q4**).

**Порядок items — строго последовательный:** P2.1 (решения → `harness.md`) → P2.2 (стенд) → P2.3
(seed) → P2.4 (сценарии) → P2.5 (гейт) → P2.6 (CI) → P2.7 (CV/δ) → P2.8 (DoD-прогон). Каждый следующий
читает Deliverables предыдущего — фаза манипулируется item-by-item, оркестрация не заявляется.

## Phase Handoff

**Фаза P2 закрыта — 8/8 (6 🟢 + P2.6/P2.7/P2.8 🟠 Done with deviations).** Харнесс построен,
провалидирован живыми прогонами на S0 (CI) и **тире S (lab-box, cpuset)**, и снял три измерения,
ради которых фаза существовала: (1) tus стримит (RSS плоский по размеру файла); (2) **CV латентности
на контролируемом стенде 2.0–2.7 % ≪ 10 % ⇒ δ=10 % на `lab` защитим** (P2.7 опроверг его только для
S0/CI); (3) **L-01 доказан прогоном** (`complete()` fatal на 500 MiB, `S3MultipartHandler.php:165`).
