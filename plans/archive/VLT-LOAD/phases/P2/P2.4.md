### P2.4 — k6-сценарии: библиотека + 7 сценариев + контрактный smoke

**Intent:** Написать k6-сценарии на **стоковом** k6, покрывающие операции, под которые P1 дал SLO:
tus-upload (+ resume/обрыв), s3-multipart (putPart/complete/abort), single-shot, download, tree
(листинг/поиск/мутация/move), docs+activity+collab, и `mixed` — реалистичный микс по долям
`operations-catalog.md`.
**Why:** Сценарий — это то, чем измеряется каждый SLO; имена метрик и тегов в нём **обязаны**
совпадать с гейт-таблицей (`slo-gates.md` §1–§3), иначе пороги молча не срабатывают ни на чём.
Контрактный smoke каждого сценария до нагрузки — потому что баг харнесса (не тот заголовок tus, не тот
offset) выдумывает или маскирует проблему системы; это прямой риск, названный в блупринте фазы.
**Scope Included:** - `load/k6/lib/`:
  - `config.js` — тир, base-url, VU-раскладка (§0.1 `slo.md`), think-time, длительности из env.
  - `auth.js` — актор (`X-Load-Actor`), пулы акторов (обычный / many-grant).
  - `fixtures.js` — **D23**: общий `ArrayBuffer` 8 MiB и 64 MiB, генерируется один раз в init;
    `saltedFirstChunk(sessionId)` — 16-байтовый salt в начале первого чанка (уникальный sha256).
  - `metrics.js` — `stream_throughput_mibs`, `upload_conflict_total`, `throttled_total`, `ttfb_ms`,
    `broadcast_lag_ms` (типы — как в `slo-gates.md` §1).
  - `expected.js` — `http.setResponseCallback(http.expectedStatuses({min:200,max:399}, 409, 429))`:
    409 (NOWAIT advisory-lock) и 429 (`throttle:vaulter-public`) — **протокол, не ошибка**
    (`slo.md` §0.4); они считаются своими счётчиками.
- Сценарии `load/k6/scenarios/`:
  1. `tus-upload.js` — `POST resumable-uploads` (OP-01) → N× `PATCH` по 8 MiB (OP-02) → ветка resume
     (обрыв на середине → `HEAD` offset → докачка, OP-03) → доля abort (OP-05).
  2. `s3-multipart.js` — создание сессии (тот же `POST`, `TusUploadController::create`) →
     `POST .../parts` ×N (OP-06) → `POST .../complete` (OP-07) / abort.
  3. `single-shot.js` — `POST storages/{storage}/uploads` (OP-17), файл ≤ 32 MiB (контракт D19).
  4. `download.js` — `GET nodes/{node}/download` / версия / share-ссылка (OP-08…10);
     **`discardResponseBodies: true`** (RAG-10) + throughput на стрим считается из размера файла и
     `res.timings`; 429 — в `throttled_total`.
  5. `tree.js` — children/shared/поиск/trash (OP-12…15), создание/переименование (OP-16, OP-19),
     move/copy/restore/trash (OP-20…24) на **many-grant** акторе (вход в L-06).
  6. `docs-collab.js` — чтение/автосейв контента (OP-28, OP-29), версии (OP-30…32), экспорт (OP-33),
     выдача collab-сессии (OP-34), комментарий (OP-38) + `broadcast_lag_ms` (если ws-подписка
     недоступна без хаба — метрика не эмитится, и это фиксируется, а не подделывается).
  7. `mixed.js` — три группы executor'ов (interactive / upload / download) с фиксированной
     конкуренцией и долями операций из `operations-catalog.md` + think-time.
- Контрактный smoke: `load/k6/smoke.js` (или `--vus 1 --iterations 1` на каждом сценарии) — каждый
  сценарий проходит против живого стенда, все `check()` зелёные, ни одного 4xx кроме ожидаемых.
- Фид активности (OP-25/26) — в `mixed.js` как интерактивная операция, обязательно **под фоновым
  писателем** (P2.3), иначе меряется фикция.
**Scope Excluded:** пороги (P2.5 — сценарии их только принимают из модуля); фоновые SLO-55…81 (у них
нет клиентского входа — плоскость perf-assert, P2.5); chaos/обрывы инфраструктуры (P7); ws-fan-out
Hocuspocus (P5/P7).
**Inputs:** `plans/VLT-LOAD/harness.md` (P2.1) §3–§5; `operations-catalog.md` (все OP + доли);
`slo.md` §0.1, §0.2, §0.4; `slo-gates.md` §1; манифест `dataset_id` (P2.3).
**Files:** `load/k6/lib/*.js`, `load/k6/scenarios/*.js`, `load/k6/smoke.js`.
**Required Reads:** 1. `plans/VLT-LOAD/harness.md` — §3 (фикстуры), §4 (executor'ы), §5 (метрики/теги).
2. `plans/VLT-LOAD/operations-catalog.md` — целиком (роуты + доли).
3. `packages/drive/src/Http/Controllers/Uploads/TusUploadController.php` — контракт tus: заголовки
   `Upload-Length`/`Upload-Offset`/`Tus-Resumable`, коды ответов, HEAD-offset (:67, :106, :134, :180).
4. `packages/drive/src/Http/Controllers/Uploads/S3MultipartController.php:56,85` — контракт putPart и
   complete (какие поля/номера частей ожидаются).
5. `packages/drive/src/Http/Controllers/DownloadController.php:47,59,112-140` — download-контракт.
6. `plans/VLT-LOAD/slo-gates.md` — §1 (имена метрик), §2 (сквозные пороги — G-4/G-5 считают 409/429).
**Implementation Rules:** - **Никаких дисковых фикстур и `open()`/`SharedArray` для тел** (D23/RAG-10): чанк — из общего
  `ArrayBuffer`; первый чанк сессии несёт salt. `SharedArray` допустим ТОЛЬКО для мелких id-списков
  из манифеста P2.3.
- Теги на каждом запросе: `scenario`, `tier`, `class` (`interactive`|`streaming`) — без них G-1/G-2 и
  строки §3 не матчатся.
- `stream_throughput_mibs` считается **в скрипте**: байты / длительность запроса (Trend), а не берётся
  из `data_sent` (он агрегатный, `slo-gates.md` §1).
- 409/429 — через `expected.js`, и **дополнительно** инкрементят `upload_conflict_total` /
  `throttled_total`. Помечать их «ошибкой» запрещено (`slo.md` §0.4).
- tus-resume моделируется честно: обрыв **в середине** чанка (прерывание итерации), затем `HEAD` →
  `Upload-Offset` → докачка с этого offset'а. «Сделаем вид, что resume — это просто новый PATCH» —
  подделка сценария.
- Сценарии параметризованы через env (`TIER`, `VUS_*`, `DURATION`, `FILE_SIZE`) — ни одного
  зашитого числа конкуренции.
**Code Guidance:** - **Анти-самообман №1 (главный риск фазы):** зелёный прогон при сломанном харнессе — худший исход.
  Поэтому item НЕ закрывается без контрактного smoke: 1 VU × 1 итерация каждого сценария против
  живого стенда, и **проверка результата в БД/сторадже** (файл появился, sha256 совпал, узел
  переехал) — а не только «HTTP 200».
- **Ожидаемый красный:** `s3-multipart.js` на большом файле **упадёт** (`complete()` держит весь файл
  в RAM — L-01, `slo.md` §5). Это **подтверждение находки, а не баг харнесса**: сценарий обязан
  пережить fatal сервера (5xx) и записать его как известный красный (`slo-gates.md` §6.4), а не быть
  «починен» уменьшением файла. Уменьшать размер, чтобы прошло, — подгонка.
- **Анти-подгонка:** думать «а давайте 409 считать успехом, чтобы checks были зелёные» запрещено:
  бюджеты G-4/G-5 существуют именно чтобы рост 409 был виден.
- **If-then:** контракт tus/S3 в коде расходится с ожиданием сценария (иные заголовки/коды) →
  сценарий подстраивается под КОД (код — SSOT), расхождение с `operations-catalog.md` фиксируется в
  Known Deviations как находка каталога.
- **If-then:** `broadcast_lag_ms` требует ws-подписки, которой без хаба нет → метрика **не эмитится**,
  строка SLO-34…36 (lag) помечается «не измеряется в P2, вход в P5» — не заполняется фиктивным числом.
**Validation:** - `docker compose … run k6 inspect load/k6/scenarios/<s>.js` — все сценарии парсятся.
- Контрактный smoke: `TIER=S0 ./load/scripts/run.sh smoke` → все `check()` зелёные,
  `http_req_failed` = 0 (кроме ожидаемых 409/429), выход 0.
- Пост-условия smoke в БД (SQL/artisan в контейнере): загруженный через tus файл существует, его
  `content_sha256` совпадает с посчитанным клиентом; узел после `move` сменил `parent_id`.
- `grep -RoE "(stream_throughput_mibs|upload_conflict_total|throttled_total|ttfb_ms|broadcast_lag_ms)" load/k6 | sort -u`
  — все пять имён присутствуют и совпадают с `slo-gates.md` §1.
**Deliverables:** библиотека + 7 сценариев + контрактный smoke, все — на стоковом k6.
