### P4.1 — Изолированный memory lane и evidence validator

**Intent:** Построить воспроизводимый tier-S lane, который привязывает один benchmark case к одному
PHP-FPM worker/process и собирает PHP allocator peak, process RSS/PSS и cgroup v2 breakdown без
смешения page cache с application heap.
**Why:** Текущая `vaulter_request_peak_memory_bytes` доказывает только PHP allocator peak. Без
worker/cgroup evidence O(file-size) heap, file cache, socket buffers и память генератора выглядят
одинаково, а короткий пик может исчезнуть между polling samples.
**Scope Included:** compose overlay/profile для fresh single-worker app; отдельный FPM pool/status;
read-only PID/cgroup sampler; before/during/after samples; `VmHWM` + `smaps_rollup`; cgroup
current/peak/stat/events; PHP/Prometheus capture; case/run manifest; schema validator; positive и
known-buffered negative fixtures; dry-run/run/verify CLI.
**Scope Excluded:** реальные 5 GiB прогоны; path fixtures; package production code; production FPM
config; host cache dropping; привилегированный sampler; интерпретация performance verdicts.

**Implementation Rules:** Только cgroup v2; отсутствие `smaps_rollup`, PSS fields, worker PID
uniqueness или read-only cgroup access — hard preflight failure. Fresh app-container на case;
`pm.max_children=1`; health/status не расходуют измеряемый worker. Sampler открывает target PID
identity (`pid` + starttime) один раз и отклоняет PID reuse. `/proc/<pid>/status` снимается до
destroy, поэтому `VmHWM` не зависит от polling frequency. Cgroup `memory.peak` читается только в
контексте fresh cgroup; FD-local reset не используется как cross-process truth. Samples содержат
monotonic timestamp, phase, PHP peak, VmRSS/VmHWM, PSS breakdown, cgroup breakdown/events и bytes.
Unknown/missing fields не становятся нулями. Artifacts публикуются атомарно после verify.
**Code Guidance:** Не использовать tmpfs для 5 GiB fixture/output; это само стало бы memory signal.
Не добавлять PID/run_id labels в package metrics. Sampler не получает write access к `/proc` или
cgroup controls. Synthetic validator fixture обязана различать рост `Pss_Anon` от роста только
`Pss_File`; cgroup total без breakdown не даёт heap verdict. CLI не печатает env/secrets.
**Validation:** `docker compose -f load/docker-compose.load.yml -f load/docker-compose.memory.yml
--env-file load/env/S0.env config`; `python3 -m unittest load/gates/test_p4_memory.py`;
validator принимает bounded fixture и отклоняет PID reuse, missing terminal sample, cgroup v1,
truncated JSONL, HTTP/client byte-accounting mismatch, server/object checksum mismatch и known
O(file-size) anonymous-memory fixture;
`TIER=S0 ./load/scripts/p4-memory.sh dry-run` не поднимает stand и не меняет dataset.
**Deliverables:** isolated memory compose/FPM profile, PID-safe sampler, deterministic schema/
validator fixtures и документированный dry-run/verify lane.
