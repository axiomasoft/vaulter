# D42 — Код без стенда, затем один необслуживаемый lab

**Actor:** owner/Dmitry Vostrikov, recorded by grok-4.7/high

**Evidence:** RAG:— owner directive 2026-09-23 в сессии P6.3: не ждать каждый lab внутри чата; остаток плана пройти код-отрезками, а тяжёлые прогоны запускать отдельно.

## Решение

1. Контракты замеров не ужимаются. 30-минутное окно 1×, три валидных повтора product-ячеек, cardinality probes и отдельные fault windows остаются как в item-спеках.
2. Lab-пункт идёт необслуживаемым прогоном. Сессия не сидит на ожидании стенда: как только артефакты пункта есть, следующий шаг — его отчёт, затем код следующего харнесса, и только потом следующий lab.
3. Эта сессия закрывает P6.3. Немедленный преемник — P6.4, отчёт по артефактам P6.3, без нового стенда.
4. Следующий код-отрезок — P7.1, затем P7.2. Старт P7.1 разрешён по terminal evidence P6.3. `queue-report.md` и `findings/P6-queue-semantics.md` обязательны до P7.3, не до P7.1. Если к старту P7.1 P6.4 уже закрыт, харнесс читает отчёт.
5. Следующий lab — только P7.3, на стенде, где нет открытого замера P6. P7.4 выпускается сразу по артефактам P7.3.
6. Следующий код-отрезок — P8.8, затем P8.9 и P8.10. Их нельзя начинать до terminal P7.4: выбор targets читает chaos report. Сразу после этого кода lab — P8.11.
7. P7.3 и P8.11 не сливаются в один прогон. Между ними лежит код P8.8–P8.10. Два lab не делят стенд одновременно с чужим замером.

## Почему

Последовательность «один пункт = один чат до конца стенда» растягивает остаток на дни, хотя харнесс P6 уже написан, а P6.4 и P7.4 — отчёты. Слить P6 и P7 на одном стенде нельзя: fault injection портит замер очереди. Вынести P8.8 раньше P7.4 тоже нельзя: item выбирает targets из отчётов P3–P7, включая chaos report. Экономия — в том, чтобы писать весь готовый код до запуска стенда и не держать чат на уже запущенном lab.

## Consequences

- P6.3 measurement contract не меняется.
- P7.1 больше не блокируется отсутствием `queue-report.md`; P7.3 по-прежнему требует P6.4 и P7.1–P7.2.
- P8.8–P8.11 сохраняют зависимость от P7.4.
- Execution Rules плана получают короткую ссылку на этот D42 после закрытия P6.3, чтобы не переписывать `plan.md` внутри уже снятого snapshot текущего attempt.
