### P1.8 — Секреты, конфиг и HTTP-поверхность

**Intent:** Закрыть остаточные security-оси: `env()` вне config, секреты в коде/логах/публикуемом конфиге и Docker-файлах, слабые дефолты, mass-assignment в моделях пакета, инъекции (SQL/`LIKE`), и маршруты без объектной авторизации из карты P0.3.
**Why:** Опубликованный конфиг попадает в репозиторий хоста — секрет в его дефолте утекает в git (RAG:✅ 2026-07-10 — `findings/P0-collab-seam.md` §C1.5, `findings/P0-embeddable-laravel.md` §E7.2). `env()` вне config ломается при `config:cache` и молча даёт `null` (частый источник fail-open). Маршрут без объектной авторизации — прямой A01:2025 (§S3.1).
**Scope Included:** `packages/core/config/vaulter.php` и все `packages/*/config/*.php`, `packages/*/src/**` (греп по `env(`), все `Models/**` пакетов (fillable/guarded/casts), `e2e/docker/**`, `e2e/docker-compose.yml`, `hocuspocus-server/{Dockerfile,docker-compose.yml}`, `.mcp.json.example`, `testbench.yaml`, маршруты со значением `отсутствует` в колонке «Авторизация» из `findings/P0.3-attack-surface-map.md`.
**Scope Excluded:** уже покрытые швы (P1.1–P1.7) — здесь только то, что они не проверяли; supply-chain зависимостей (P4.4); CI-секреты (`.github/`) — вне границ D1, зафиксировать в «Не проверено».
**Inputs:** `findings/P0.3-attack-surface-map.md` (подтаблица «маршруты без объектной авторизации») · `findings/P0-embeddable-laravel.md` §E7 · `findings/P0-collab-seam.md` §C1.
**Files:** создаёт `plans/AUDIT-VLT/findings/P1.8-secrets-config-http.md`.
**Required Reads:** 1) `plans/AUDIT-VLT/artifacts/finding-template.md` 2) `plans/AUDIT-VLT/findings/P0.3-attack-surface-map.md` 3) `plans/AUDIT-VLT/findings/P0-embeddable-laravel.md` 4) `packages/core/config/vaulter.php` (целиком) 5) `packages/documents/config/*.php` 6) `packages/drive/config/*.php` 7) `packages/media/config/*.php` 8) `packages/filament/config/*.php` 9) `packages/permissions-azgard/config/*.php` 10) `packages/core/src/Models/Concerns/HasExtraData.php` 11) `packages/core/src/Models/Concerns/HasVaulterKeys.php` 12) `packages/core/src/Http/Requests/VaulterFormRequest.php` 13) `e2e/docker-compose.yml` 14) `hocuspocus-server/Dockerfile` 15) `hocuspocus-server/docker-compose.yml` 16) `.mcp.json.example`
**Implementation Rules:** Закрытый чеклист:
`C1` `env()` вызывается ТОЛЬКО внутри `config/*.php`. Команда: `grep -rn "env(" packages/*/src | grep -v "/vendor/"` — любой хит = находка (Major: ломается при `config:cache`);
`C2` в публикуемом конфиге нет непустых дефолтов секретов (`webhook_secret`, `jwt secret`, ключи S3): дефолт — `null`/пустая строка + отказ при использовании, а не рабочее значение;
`C3` греп секретов в коде и Docker: `grep -rniE "(secret|password|token|api[_-]?key)\s*[:=]\s*['\"][^'\"]{8,}" packages/*/src packages/*/config e2e hocuspocus-server --include=*.php --include=*.ts --include=*.js --include=*.yml --include=Dockerfile` — каждый хит классифицировать (плейсхолдер / реальный секрет);
`C4` слабое хеширование: `grep -rn "md5(\|sha1(" packages/*/src` — использование для токенов/подписей = Major, для не-security ключей кэша = Nit;
`C5` `docker-compose.yml` (e2e и hocuspocus): нет захардкоженных паролей БД/секретов, порты не публикуются наружу без нужды, нет `privileged`, образы пинятся по тегу (не `latest`);
`C6` mass-assignment: у каждой модели пакета явно задан `$fillable` или `$guarded`; ЗАПРЕЩЁННЫЙ паттерн — `$guarded = []` в модели, доступной из HTTP-слоя. Проверить ВСЕ модели: `Node`, `Storage`, `File`, `FileVersion`, `Blob`, `FileVersionBlob`, `NodeGrant`, `NodeShare`, `Activity`, `Outbox`, `WebhookEndpoint`, `WebhookDelivery`, `UploadSession`, `UploadPart`, `NodeComment`, `NodeDocumentVersion`;
`C7` `HasExtraData`: JSON-колонка `extra_data` не позволяет протащить служебные ключи; при записи из HTTP фильтруется;
`C8` SQL/`LIKE`-инъекции: `grep -rn "whereRaw\|selectRaw\|DB::raw\|orderByRaw" packages/*/src` — каждый хит проверить на биндинги; поиск по имени узла экранирует `%`/`_` в `LIKE`;
`C9` сортировка/фильтрация из запроса не подставляется в `orderBy` без whitelist колонок;
`C10` каждый маршрут из подтаблицы «без объектной авторизации» (P0.3) получает вердикт: реально ли он публичный по замыслу (`share`, `collab-webhook`) или это дыра; дыра = Blocker/Major по достижимости;
`C11` `route_prefix` и `middleware` из конфига реально применяются; дефолтный `middleware: ['api']` не включает `auth` — задокументировано ли, что хост обязан добавить аутентификацию? Отсутствие такого предупреждения в README/reference = Major (fail-open по умолчанию у потребителя);
`C12` `VaulterFormRequest::authorize()` не возвращает `true` безусловно там, где авторизация не проверяется дальше в контроллере;
`C13` сообщения исключений (`Exceptions/**`) не раскрывают пути ФС, SQL и секреты;
`C14` `Activity`-фид не пишет секреты/токены в `context` (JSON).
Для `C10`, `C11`, `C12` — repro в `artifacts/repro/P1.8/` обязателен (feature-тест: анонимный запрос к маршруту).
**Code Guidance:** Каждая проверка `C1`, `C3`, `C4`, `C6`, `C8` — это **конкретная grep-команда**, чей фактический вывод цитируется в отчёте; «прогрепал, ничего не нашёл» без вывода команды = дефект исполнения. Пустой вывод грепа — валидный `✅ pass`, но команда и её вывод (пустой) всё равно приводятся. `C11` — концептуально самая опасная находка этого item'а: если пакет по умолчанию монтирует маршруты без `auth`, а документация об этом молчит, потребитель получит открытое хранилище. Проверить `docs/reference/rest-api.md` и `README.md` на явное предупреждение; отсутствие = Major (не Minor). ЗАПРЕЩЕНО заводить находки по стилю кода — это ось P4. Правки запрещены (D2). ЗАПРЕЩЕНО помечать 🟢, если хоть один маршрут из подтаблицы P0.3 остался без вердикта в `C10`.
