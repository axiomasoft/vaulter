# P0 — Research & Baseline

## Phase Context

Фаза готовит фундамент аудита: инвентаризацию поставляемой поверхности пакета, добивку
версионно-привязанных внешних фактов и карту точек входа (маршруты × middleware ×
policy × ability). Широкая RAG-верификация уже выполнена на этапе проектирования — её
результат лежит в `findings/P0-dms-security.md`, `findings/P0-upload-hardening.md`,
`findings/P0-collab-seam.md`, `findings/P0-embeddable-laravel.md` и является нормой,
против которой фазы P1–P4 сверяют код (D3). Схема находки и severity-шкала —
`artifacts/finding-template.md`; реестр находок — `findings/REGISTER.md` (append-only).

Фаза read-only (D2): ни один файл вне `plans/AUDIT-VLT/` не меняется. Инструменты
(pint/phpstan/pest) запускаются только в проверочном режиме.

Фаза завершена, когда: (1) `findings/P0.1-baseline-inventory.md` описывает все 7 пакетов,
конфиг-ключи, миграции, тесты и тулинг с фактическими числами; (2)
`findings/P0.2-rag-supplement.md` содержит проверенные версии и нормы, не покрытые
design-time RAG; (3) `findings/P0.3-attack-surface-map.md` даёт полную таблицу
HTTP-маршрутов с их middleware и проверками доступа. Артефакты P0 — обязательные
Required Reads для P1.

**Scope Included:** инвентаризация репозитория; RAG-добивка; карта HTTP-поверхности.
**Scope Excluded:** любые вердикты о дефектах (это работа P1–P4); чтение `vendor/`,
`node_modules/`; изменение кода и конфигов.

### P0.3 — Карта поверхности атаки: маршруты × middleware × авторизация

**Status:** ⬜ Not started
**Intent:** Построить исчерпывающую таблицу «HTTP-маршрут → контроллер@метод → middleware-стек → способ авторизации (Policy / AccessResolver / Ability / отсутствует)» по всем `routes/*.php` пакета и записать её в `findings/P0.3-attack-surface-map.md`.
**Why:** OWASP A01:2025 (Broken Access Control) требует объектной авторизации на КАЖДЫЙ запрос (RAG:✅ 2026-07-10 — `findings/P0-dms-security.md` §S3.1); проверить это без полной карты входных точек нельзя, а items P1.3/P1.4/P1.6/P1.8 стоят на ней как на входе.
**Scope Included:** `packages/core/routes/api.php`, `packages/drive/routes/drive.php`, `packages/documents/routes/documents.php`; регистрация маршрутов в `VaulterServiceProvider`/`VaulterDriveServiceProvider`/`VaulterDocumentsServiceProvider`; middleware в `packages/core/src/Http/Middleware/*`, `packages/documents/src/Http/Middleware/*`; политики `packages/core/src/Policies/*`.
**Scope Excluded:** Filament-ресурсы (`packages/filament`) — их поверхность разбирается в P2.5/P4.5; вердикты о дефектах (только фиксация факта «авторизация отсутствует» в колонке, без severity — заводить находки будет P1.8); фронтенд-роутинг.
**Inputs:** `findings/P0.1-baseline-inventory.md` (список файлов маршрутов) · `findings/P0-dms-security.md` (S3.1–S3.3).
**Files:** создаёт `plans/AUDIT-VLT/findings/P0.3-attack-surface-map.md`.
**Required Reads:** 1) `plans/AUDIT-VLT/findings/P0.1-baseline-inventory.md` 2) `packages/core/routes/api.php` 3) `packages/drive/routes/drive.php` 4) `packages/documents/routes/documents.php` 5) `packages/core/src/VaulterServiceProvider.php` 6) `packages/drive/src/VaulterDriveServiceProvider.php` 7) `packages/documents/src/VaulterDocumentsServiceProvider.php` 8) `packages/core/src/Http/Middleware/ResolveShareToken.php` 9) `packages/documents/src/Http/Middleware/ResolveCollaborationCall.php` 10) `packages/core/src/Policies/NodePolicy.php` 11) `packages/core/src/Policies/WebhookEndpointPolicy.php` 12) `packages/core/src/Enums/Access/Ability.php` 13) `packages/core/config/vaulter.php` (ключи `route_prefix`, `middleware`, `features`)
**Implementation Rules:** Одна строка таблицы на маршрут (метод + URI + имя). Колонки: `Метод | URI | Имя | Контроллер@метод | Feature-флаг (из config.features) | Middleware-стек (полный, включая групповой из config.middleware) | Авторизация | Модель-биндинг`. Колонка «Авторизация» заполняется ОДНИМ из значений: `Policy:<класс>@<метод>` · `AccessResolver::<метод>(<Ability>)` · `ShareToken` · `WebhookSecret|JWT` · `отсутствует` — значение подтверждается `file:line` в соседней колонке. Маршруты, зарегистрированные условно (`features()`), помечаются флагом. Использовать статическое чтение файлов; `php artisan route:list` в пакете без хоста недоступен — если удастся получить список через `vendor/bin/testbench route:list`, приложить его вывод в `artifacts/repro/P0.3/route-list.txt` как перекрёстную сверку (расхождение статики и рантайма — само по себе строка в «Не проверено / ограничения»).
**Code Guidance:** ЗАПРЕЩЕНО выводить авторизацию «по названию контроллера» — только по фактическому коду метода (`authorize()`, `Gate::`, `AccessResolver`, `$this->resolver->can(...)`), со ссылкой `file:line`. Пустая клетка недопустима: если способ не найден — писать `отсутствует` и это будет входом для P1.8, а не «наверное, есть в middleware». ЗАПРЕЩЕНО в этом item'е выставлять severity и заводить находки — это карта, а не вердикт (секция «Находки» = «— (карта, вердикты в P1)»). ЗАПРЕЩЕНО помечать item 🟢, если число строк таблицы меньше числа `Route::`-вызовов в трёх файлах маршрутов (сверить `grep -cE "Route::(get|post|put|patch|delete|any|match)" packages/*/routes/*.php`); при расхождении — 🟡 + Pending Work с точной причиной.
**Validation:** 1) `findings/P0.3-attack-surface-map.md` существует, таблица покрывает все маршруты (сверка счётчиком `grep -cE "Route::(get|post|put|patch|delete|any|match)"` по трём файлам); 2) в колонке «Авторизация» нет пустых значений; 3) `git status --porcelain -- packages docs e2e hocuspocus-server` пуст; 4) `python3 "/home/vostrikov/projects/packages/swissknifeman/packages/task/scripts/plan-lint.py" plans/AUDIT-VLT` — без ошибок.
