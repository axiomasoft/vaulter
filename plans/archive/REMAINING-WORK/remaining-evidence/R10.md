## Change and package checks

`OutboxRelay::subscribedEndpoints()` now asks the database for active endpoints whose JSON `events` contains the outbox event. It selects only the key and walks matches in key order using 100-row keyset pages. Dispatch remains in that order, and the existing outbox claim/state transition remains the duplicate guard. The runtime P8 `vaulter_outbox_endpoints_scanned_total` counter now counts matching endpoint models hydrated by PHP; it is **not** a measure of database rows examined. SQL scan cost at larger cardinalities remains unmeasured.

The new cardinality test processes 205 subscribers across three pages while excluding 120 other-event subscribers and an inactive endpoint; it checks delivery order and one job per subscriber. An interleaved second relay tick after the first claim returns zero and creates no duplicate delivery. These tests ran on both SQLite and PostgreSQL.
