# P0 — Pre-mortem VLT-REMED (протокол Klein)

**Дата:** 2026-07-10 · **Кто:** issue-planner/opus · **Основание:** `plan-protocol` §7 — pre-mortem
обязателен для high-stakes (tenant-isolation + ядро экосистемы; здесь ещё и security-ремедиация).

**Постановка:** «На дворе 2027-й. План VLT-REMED формально исполнен — доска зелёная, 103 находки
закрыты. Но ремедиация провалилась. Что произошло?» Причины записаны независимо, затем
кластеризованы; каждая несёт митигацию с адресом (D# / item / Code Guidance).

---

## 1. Причины (сырой список)

| # | Причина провала |
|:--|:--|
| R1 | Фиксы закрыты без регрессионного теста на конкретный F-id. Через полгода рефакторинг вернул дефект — доказать, что «когда-то чинили», нечем. |
| R2 | SSRF «починен» валидацией строки URL в `RegisterWebhookEndpointRequest`. Доставка по-прежнему резолвит DNS в момент запроса → DNS-rebinding работает, Blocker жив под зелёной галкой. |
| R3 | Санитайзер поставлен только на экспорт (`TipTapRenderer`), а Vue-фронт рендерит хранимый JSON напрямую → stored XSS остался. Закрыт «путь, который смотрел аудитор», а не класс дефекта. |
| R4 | tus-лок реализован и протестирован на SQLite, где конкурентности нет. На PostgreSQL с несколькими воркерами гонка жива; тест зелёный, данные бьются. |
| R5 | Массовый перенос namespace (P4.10) молча ломает хосты: morph-алиасы, FQCN в опубликованном конфиге, ссылки в доках. FlexCRM падает после `composer update`. |
| R6 | Трассируемость потеряна: «батч B13 закрыт» есть, а какой коммит и какой тест закрывают F-P1.8-02 — нет. Повторный аудит начинается с нуля. |
| R7 | Волна W4 (58 Minor + 5 Nit) выдыхается к 60%. План брошен, но Status Board показывает 🟢 по закрытым фазам — доска читается как «пакет вылечен». |
| R8 | Финальное ревью (P5) находит Blocker в самой ремедиации, но чинить его нечем: плана больше нет, все items закрыты. |
| R9 | Фиксы конфликтуют между волнами: `$fillable` (B13) ломает Actions, полагавшиеся на unguarded `fill()`; фиче-флаг collab (B11) выключает код, который следующая волна харденит. |
| R10 | Изменены дефолты (share TTL, collab off, download без presign) — прод-хост обновился и потерял функциональность без upgrade-заметки. |
| R11 | Дешёвая модель, встретив «находка не воспроизводится», молча закрывает item как no-op вместо эскалации; false-negative проходит в релиз. |
| R12 | Blocker-волна W0 растянута: три Blocker'а исполняются как «удобно», релиз ждёт W4 из 10 items. Уязвимость живёт в проде месяцами, хотя её фикс был готов на первой неделе. |

## 2. Кластеры и митигации

### K1 — «Зелёное, но не починенное» (R1, R2, R3, R4, R11)

Корень: критерий закрытия — «код изменён», а не «дефект недостижим».

| Митигация | Адрес |
|:--|:--|
| Каждый F-id закрывается регрессионным тестом, который **красный на коде до фикса**. Тест ссылается на F-id в описании. Закрытие без такого теста запрещено. | `plan.md` D7 · Code Guidance всех items |
| Барьер ставится на **пути доставки**, а не на пути регистрации/экспорта: SSRF-guard в `DeliverWebhook`, санитизация и на store-time (`TipTapContent`), и на render-time. | P0.1 · P0.2 · `findings/P0-remediation-norms.md` N1/N2 |
| Конкурентные сценарии проверяются на PostgreSQL, а не только SQLite; тест гонки ставит два параллельных PATCH. | P0.3 Validation · `plan.md` D12 |
| Находка не воспроизводится → **эскалация**, а не молчаливое закрытие. Опровержение оформляется строкой в `findings/` + `Escalation Needed`. | `plan.md` D9 |

### K3 — «Ломаем хостов молча» (R5, R10)

## 3. Остаточные риски (принимаются)

- **Стоимость W4.** 10 items низкого прямого риска — вероятность «докатим потом» реальна. Принято:
  митигация K4 делает недоделку видимой, но не устраняет.
- **Мажор TipTap 3.x** (F-P4.5-01) — ломающий фронтенд-апгрейд внутри W4; может потребовать
  собственного плана. Принято: при разрастании — эскалация и вынос в отдельный план.
- **Symfony HtmlSanitizer advisory 2026** (обходы allowlist через WHATWG-парсинг). Митигируется
  вторым эшелоном (store-time allowlist схем), но полностью не снимается — требуется держать
  зависимость свежей (B24/P4.1 supply-chain-гейт).
