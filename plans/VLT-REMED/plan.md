## 1. Context

vaulter — встраиваемое документохранилище для Laravel (монорепо, 7 пакетов, ~543 PHP-файла): дерево
узлов `Node`, CAS-блобы с дедупликацией и GC, resumable-загрузки (tus + S3 multipart), realtime-collab
(Yjs/Hocuspocus), исходящие webhook через transactional outbox, два канала шэринга (grant-ACL +
публичные share-link), Filament-панель, Vue-фронтенд, внешние ролевые провайдеры за швом `HostRoleDriver`.

Пакет прошёл сплошной read-only аудит **AUDIT-VLT** (6 фаз, 34 items, 4 опровергнутые находки).
Результат — **103 активные находки**: 3 Blocker · 37 Major · 58 Minor · 5 Nit. SSOT находок —
`plans/AUDIT-VLT/findings/REGISTER.md`; ранжирование и топ-10 — `findings/P5.1-synthesis-report.md`;
партиция находок на **24 батча по корню** и sequencing **5 волнами W0→W4** —
`findings/P5.2-remediation-backlog.md`. Аудит кода не чинил (D2 того плана).

Этот план **чинит**. Три Blocker'а (гонка offset в tus → тихая порча файла; SSRF в исходящих webhook;
stored XSS в серверном рендере TipTap) закрываются первой волной; далее — быстрые высоко-эксплуатируемые
фиксы, авторизация/изоляция, надстройки, качество/CI. Дополнительно владелец расширил скоуп: внутренняя
доменная структура пакетов расходится (три несовместимые схемы) — она приводится к единому канону.
Завершается план тем, чего не было ни разу за цикл AUDIT-VLT: **сквозным adversarial code review всех
изменений** (профиль `code`, `/task:review`), с отдельным item'ом на ремедиацию его находок.

Внешние нормы ремедиации W0 верифицированы RAG на этапе проектирования и лежат в
`findings/P0-remediation-norms.md` (N1–N4) — исполнитель читает их, а не восстанавливает контекст.
Pre-mortem — `findings/P0-premortem.md`.

## 2. Execution Rules

- Один item за раз; статус обновляется В ПЛАНЕ до завершения работы. Статусы — 6 канонических строк
  байт-в-байт (`plan-protocol` §6).
- **Работа ведётся на ветке `remediation/audit-vlt`** (D8). Коммит на item, Conventional Commits
  (русский body). Коммит-гейт закрытия — `plan-protocol` §6: гейт зелёный ДО коммита, ревью-фиксы —
  отдельными коммитами, не `amend`.
- **Гейт валидации каждого item'а** (D12), из корня репозитория:
  `composer lint:check && composer analyse && composer test && composer test:types`.
  Красное — item не закрывается. Ослаблять Validation ради зелёного запрещено.
- **Регрессионный тест на каждый F-id** (D7). Тест обязан быть красным на коде ДО фикса и нести F-id
  в описании (`it('..., F-P1.4-01', ...)`). Item без такого теста не закрывается.
- Находка не воспроизводится / оказалась ложной → **эскалация** (`plan-protocol` §10), а не молчаливое
  закрытие (D9). Опровержение оформляется файлом в `findings/` + `Escalation Needed`.
- **REGISTER.md плана AUDIT-VLT неизменен.** severity и партиция батчей не переоцениваются (D13).
  Новый дефект, вскрытый при починке, заводится строкой в `plans/VLT-REMED/findings/<Pn.m>-*.md` и
  требует нового item'а, а не дописывается в чужой реестр.
- Item обязан перечислить закрываемые **F-id** в Deliverables; финальный item P5.3 строит closure-матрицу
  `F-id → коммит → тест → статус`.
- Недоделанная волна закрывается честно: `⛔ Skipped by decision` с явной диспозицией по каждому F-id
  (не 🟢). Blocker без фикса не позволяет закрыть P0.
- **Скелет-фаза не исполняется напрямую.** Фаза с маркером `> СКЕЛЕТ` разворачивается командой
  `/task:plan-design VLT-REMED Pn`; DoR закрывается в момент развёртывания. Блок «Обязательные оси»
  в Phase Context скелета — вход развёртывания, а не пожелание.
- **`findings/P0-remediation-norms.md` нормативен и неизменен**: исполнитель сверяет код с ним, а не
  правит его под код. Противоречащий свежий факт — эскалация (`rule conflict`).
- После закрытия item/фазы — перезаписать `plans/VLT-REMED/handoff.md`.
