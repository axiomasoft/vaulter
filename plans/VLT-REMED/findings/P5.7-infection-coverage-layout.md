# P5.7 — Норма фикса: раскладка каталога `--coverage` для Infection (reuse existing coverage)

**Дата:** 2026-07-12 · **Автор:** plan-design/opus · **Статус:** нормативно для item'а P5.7
(исполнитель сверяет `mutation.yml` с этим документом, а не наоборот; противоречащий свежий факт —
эскалация `rule conflict`, `plan-protocol` §10).

## 1. Дефект (repo-grounded, диспатч `run 29200519816`)

`.github/workflows/mutation.yml`, два шага:

```yaml
- name: Generate coverage for Infection
  run: vendor/bin/pest --coverage-xml=build/coverage/xml --log-junit=build/junit.xml --min=0

- name: Run Infection
  run: |
    vendor/bin/infection --threads=4 --coverage=build/coverage --skip-initial-tests --no-progress || true
```

Infection падает ДО мутационного прогона (`CoverageChecker.php:240` / `JUnitReportLocator.php:108`):
JUnit-отчёт ищется по пути `<--coverage>/junit.xml` = `build/coverage/junit.xml`, а coverage-шаг пишет его
в `build/junit.xml`. Полная фактура диспатча — `findings/P5.6-msi-measurement.md`.

## 2. Норма (RAG:✅ 2026-07-12 — context7 `/infection/infection`, запрос «reuse existing coverage:
`--coverage` directory layout, required coverage-xml dir name and junit.xml path, `--skip-initial-tests`»)

При `--coverage=<dir> --skip-initial-tests` Infection ожидает **внутри `<dir>`**:

| Артефакт | Путь | Кто пишет |
|:--|:--|:--|
| JUnit-отчёт | `<dir>/junit.xml` | PHPUnit/Pest `--log-junit` |
| XML-покрытие | `<dir>/xml/` (каталог с `index.xml`) | PHPUnit/Pest `--coverage-xml` |

Источник — e2e-фикстура самого Infection (`tests/e2e/PHPUnit_11`, README
`tests/phpunit/TestFramework/Coverage/Fixtures/README.md`):

```shell
cd tests/e2e/PHPUnit_11 && make phpunit-coverage
ls -l var/coverage
# junit.xml
# xml/
```

**Вывод:** имя каталога покрытия `xml/` в нашем лейне **корректно** (это не `coverage-xml/`, вопреки
части сторонних гайдов) — единственное расхождение с нормой — путь `--log-junit`.

## 3. Фикс (единственная правка, минимальная)

```diff
-  run: vendor/bin/pest --coverage-xml=build/coverage/xml --log-junit=build/junit.xml --min=0
+  run: vendor/bin/pest --coverage-xml=build/coverage/xml --log-junit=build/coverage/junit.xml --min=0
```

Альтернатива (отвергнута): оставить `build/junit.xml` и указать Infection путь явным
`--log-junit-report=...`/конфигом `phpUnit.customPath` — лишний параметр там, где норма фреймворка уже
задаёт раскладку; чем меньше расхождений с дефолтом, тем меньше поверхность для того же класса дефекта.

## 4. Ретроспектива (следствие для вердикта, не для фикса)

`|| true` на шаге `Run Infection` маскировал этот сбой на КАЖДОМ прогоне лейна с момента его введения
(P4.1 / F-P4.3-03). Следовательно ни один «зелёный» прогон `mutation.yml` — включая прогоны на `main` —
**никогда не измерял MSI**: Infection не доходил до первой мутации. Формулировка «mutation-гейт настроен»
в `findings/P5.3-closure-matrix.md` §4 п.4 подлежит переоценке в P5.8 (гейт был не advisory, а
неработающим). Это факт для §4/§5 матрицы, не работа для P5.7.
