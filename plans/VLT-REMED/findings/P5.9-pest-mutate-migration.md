# P5.9 — Норма: mutation-гейт на нативной мутации Pest (Infection снят)

**Дата:** 2026-07-12 · **Автор:** plan-design/opus · **Статус:** нормативно для items P5.9/P5.10
(исполнитель сверяет лейн с этим документом, а не наоборот; противоречащий свежий факт — эскалация
`rule conflict`, `plan-protocol` §10).

## 1. Дефект, закрывший путь Infection (repo-grounded, диспатч `run 29201294605`, headSha `e35e816`)

После фикса P5.7 (`--log-junit=build/coverage/junit.xml`) Infection читает JUnit из правильного места
(норма `findings/P5.7-infection-coverage-layout.md` §2 подтверждена: `grep -cE 'CoverageChecker|JUnitReportLocator'`
по логу → `0`), но падает ДО генерации первого мутанта:

```
In TestNotFound.php line 50:
  Could not find any information for the test "P\Packages\core\tests\Activity
  \RecordActivityTest" in the coverage file ".../build/coverage/junit.xml".
```

## 2. Корень (repo-grounded, локальная верификация 2026-07-12)

JUnit-отчёт Pest **не требует** coverage-драйвера, поэтому формат проверен локально, а не гаданием:

```shell
vendor/bin/pest --log-junit=<tmp>/junit.xml --filter=RecordActivityTest
grep -oE '<testcase [^>]*>' <tmp>/junit.xml | head -1
```

```xml
<testcase name="it writes one storage.created row with the storage scope and root target"
          file="packages/core/tests/Activity/RecordActivityTest.php::it writes one storage.created row …"
          class="Packages\core\tests\Activity\RecordActivityTest"
          classname="Packages.core.tests.Activity.RecordActivityTest" assertions="3" time="0.177559"/>
```

Факты:

| Артефакт | Идентификатор теста | Префикс `P\` |
|:--|:--|:--|
| JUnit (`--log-junit`, Pest 4.7.4) | `class="Packages\core\tests\…"` | **нет** (`grep -c 'P\\Packages' junit.xml` → `0`) |
| coverage-xml (`--coverage-xml`, рантайм PHPUnit) | `P\Packages\core\tests\…` | **есть** (класс-обёртка Pest) |

Infection сопоставляет тест из coverage-отчёта с записью JUnit по имени класса → ключи не совпадают
структурно, при любой раскладке каталогов. Дополнительно атрибут `file` у Pest нестандартен
(путь + `::` + описание теста), что ломает и второй путь сопоставления.

## 3. Инструментальный факт: Infection 0.33.3 не поддерживает Pest

- `vendor/infection/infection/resources/schema.json` → `testFramework.anyOf` = `phpunit`, `phpspec`,
  `codeception`, `testo`. **`pest` в перечне отсутствует.**
- `grep -rniE '\bpest\b' vendor/infection/infection/src` → **0 файлов**; адаптерный пакет не установлен
  (`composer.lock`: только `infection/infection` 0.33.3 + `infection/extension-installer` 0.1.2).

Вывод: связка «Infection + Pest» в этом репозитории держалась не на поддержке, а на совпадении форматов
двух отчётов. Pest 4 это совпадение не даёт. Правка конфигурации лейна корень не устраняет — устраняет
его только смена инструмента (или хак-нормализация чужого формата, отвергнутая владельцем).

## 4. Решение владельца (2026-07-12) — D38

Mutation-гейт переводится на **нативную мутацию Pest** (`pestphp/pest-plugin-mutate`), Infection снимается.
Метрика и порог — D39. Отвергнутые альтернативы (дословно — `plan.md` §5 D38): пост-обработка JUnit в
лейне (хак поверх внутреннего формата Pest, ломается на апгрейде); принятие MSI как вечного долга (владелец
отверг трижды); даунгрейд Pest (регресс всего сьюта ради метрики).

## 5. Норма нового лейна (repo-grounded по вендору + локальные пробы 2026-07-12)

**Инструмент уже установлен:** `pestphp/pest-plugin-mutate` **v4.0.1** (штатный компонент Pest 4) и
`brianium/paratest` (даёт `--parallel`) — `composer.lock`. Ставить нечего.

**CLI-опции** (источник — `vendor/pestphp/pest-plugin-mutate/src/Options/*.php`):

```
--mutate  --path=<dir|file>  --class=<FQCN>  --covered-only  --everything  --min=<N>
--parallel  --processes=<N>  --bail  --retry  --profile  --mutators=<list>
--except=  --ignore=  --stop-on-uncovered  --stop-on-untested  --clear-cache  --no-cache
```

**Требование окружения** (`src/Plugins/Mutate.php:121-122`): условие — **наличие coverage-драйвера**
(`Coverage::isAvailable()`), а НЕ флаг `--coverage`. Без драйвера:

```
Pest\Exceptions\InvalidOption: Mutation testing requires code coverage to be enabled.
```

Локальная проба (2026-07-12): `vendor/bin/pest --mutate --path=packages/core/src/Cas --covered-only --min=1`
→ ровно это исключение, exit 1 (в песочнице нет `xdebug`/`pcov` — то же ограничение, что у Infection).
Следствие: опции парсятся корректно, измерение возможно **только в CI** (лейн `mutation.yml` ставит
`setup-php` с `coverage: xdebug`) — D31 остаётся в силе без изменений.

**Метрика — ОДНА** (`src/Support/Printers/DefaultPrinter.php:135,139`), в отличие от пары MSI / Covered MSI
у Infection:

```
  Mutations:  <N> untested, <N> uncovered, <N> pending, <N> timeout, <N> tested
  Score:      <N.N>%
```

**Гейт умеет падать сам** (`src/Options/MinScoreOption.php:11`, `src/Tester/MutationTestRunner.php:199-207`):
при `Score < --min` раннер репортит `reportScoreNotReached` и возвращает `false` → ненулевой exit-код
процесса. Никакой обёртки `|| true` не требуется — и она подлежит снятию (D39).

**Предмет измерения сохраняется:** `infection.json5` мутировал `source.directories: ["packages/core/src"]`
→ новый лейн мутирует `--path=packages/core/src`. Сужать предмет ради скорости запрещено (D39).

**Канонический вызов лейна** (без порога — измерение; порог добавляет P5.10):

```yaml
- name: Mutation testing
  run: vendor/bin/pest --mutate --path=packages/core/src --covered-only --parallel --processes=4
  env:
    DB_CONNECTION: sqlite
    DB_DATABASE: ':memory:'
    XDEBUG_MODE: coverage
```

## 6. Известные неизвестные (честно — это НЕ основание для импровизации)

1. **Wall-time.** Сколько идёт мутационный прогон `packages/core/src` (144 файла) на раннере — неизвестно;
   Infection не дошёл до мутантов ни разу, точки отсчёта нет. `--covered-only` + `--parallel --processes=4`
   — штатные средства ускорения, они в каноническом вызове. Упирание в лимит GitHub Actions (6 ч) или
   массовые `timeout`-мутанты → **стоп + эскалация с фактами**, а не молчаливое сужение `--path` (это
   подмена предмета измерения — тот же класс подлога, что провизорный порог за `|| true`).
2. **Производительность без `covers()`/`mutates()`.** Плагин печатает рекомендацию использовать
   `covers()`/`mutates()` для ускорения (`src/Plugins/Mutate.php:186`). Проставление их по сьюту — работа
   вне scope P5.9/P5.10 (это правка тестов); при неприемлемом wall-time — эскалация, не инициатива.
3. **ANSI-раскраска.** `Score:` печатается с цветовыми тегами → в логе CI это escape-последовательности.
   Грепать так: `gh run view <id> --log | sed -r 's/\x1b\[[0-9;]*m//g' | grep -aE 'Score:|Mutations:'`.
4. **Сопоставимость с Infection-порогом.** Pest Score ≠ Infection MSI (другой набор мутаторов, другая
   формула) — провизорные `50/70` не переносятся и не сравниваются; порог ставится по ФАКТУ первого
   измерения (D39).

## 7. Результат диспатча после замены инструмента (P5.9, repo-grounded)

**Прогон:** `gh workflow run mutation.yml --ref remediation/audit-vlt` → `run id 29202699131`,
`headSha f9d478d0a2813a14c896e1c0d62385fea016330b`, `conclusion: success`, 2026-07-12T17:48:51Z →
2026-07-12T18:01:22Z (job целиком, включая checkout/setup/install; шаг `Mutation testing` — 324.58s).

Лог шага `Mutation testing` (снята ANSI-раскраска):

```
Tests:    487 passed (1267 assertions)
Duration: 75.47s
Parallel: 4 processes

Mutating application files...
3476 Mutations for 130 Files created

Mutations: 3476 tested
Score:     100.00%
Duration:  324.58s
Parallel:  4 processes
```

**Метрика — впервые за историю репозитория:** `Score: 100.00%`, `Mutations: 3476 tested` (untested/
uncovered/pending/timeout — по нулю каждая; `DefaultPrinter` печатает только ненулевые категории —
repo-grounded, `vendor/pestphp/pest-plugin-mutate/src/Support/Printers/DefaultPrinter.php:135`).
Арифметика согласована: `3476 tested + 0 untested + 0 uncovered + 0 timeout + 0 pending == 3476` ==
`3476 Mutations for 130 Files created`. `Score` = `(tested + timedOut) / total * 100`
(`MutationRepository::score()`) — при 0 untested (= 0 escaped-мутантов, `MutationTest::hasFinished()`:
`process->isSuccessful()` → `Untested`/escaped; иначе → `Tested`/killed) результат `100.00%`
арифметически корректен, не артефакт печати.

**Job зелёный НЕ потому, что порог не поставлен** (`--min` отсутствует в вызове — Scope Excluded P5.9),
а независимо от этого: сам мутационный прогон физически произошёл и напечатал обе строки метрики —
критерий успеха item'а (Code Guidance P5.9) выполнен.

**Вход для P5.10:** `--min := floor(100.00) − 5 = 95`.
