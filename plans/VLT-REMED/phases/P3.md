# P3 — W3: Надстройки и интеграция

## Phase Context

> СКЕЛЕТ — не детализирован, разворачивается /task:plan-design VLT-REMED P3

Волна W3 бэклога: опциональные надстройки (realtime-collab), жизненный цикл upload-сессий, протокольная
корректность tus, lifecycle сервис-провайдеров и встраиваемость схемы. **Жёсткое ребро зависимости
B11 → B4** (D2, D13 плана AUDIT-VLT): фиче-флаг-гейт collab ставится ДО харденинга collab-шва — иначе
харденится код, который по продуктовому требованию не должен грузиться в базовой поставке. Остальные
items волны автономны и параллельны.

**Scope Included:** батчи B11, B4, B6, B7, B22, B23 — 18 находок: F-P1.6-01, F-P1.10-03, F-P2.5-06,
F-P3.6-01 · F-P1.6-02, F-P1.6-03 · F-P1.4-10, F-P1.4-12, F-P1.4-13 · F-P1.4-02, F-P1.4-05, F-P1.4-06,
F-P1.4-07, F-P1.4-08 · F-P2.2-01, F-P2.2-02 · F-P2.3-02, F-P2.3-04.

**Scope Excluded:** гонка offset и целостность CAS (закрыты P0.3); docs-drift по collab-гайду сверх
install-пути (F-P2.5-* → P4.8/B19); публичная поверхность фасада (→ P4.6/B20).

**Обязательные оси развёртывания** (вход `/task:plan-design VLT-REMED P3`):

1. **B11 → P3.1 (первым, жёсткое ребро).** Собственный фиче-флаг realtime-collab (D13 AUDIT-VLT:
   опциональная надстройка, не часть базовой поставки); гейт Filament-ресурсов на core-флаги
   (`ActivityResource` бьёт в отсутствующую таблицу); честный README (пять флагов выключены по
   умолчанию); непротиворечивый install-гайд collab + обновление ADR-0001. Ось: ядро не должно иметь
   обратной зависимости от надстройки.
2. **B4 → P3.2 (после P3.1).** Подпись и anti-replay ВХОДЯЩЕГО collab-webhook; периодическая проверка
   `exp`/ACL в течение живого соединения (`hocuspocus-server`). Ось: те же пять контролей, что и в
   `findings/P0-remediation-norms.md` N2, но для входящего направления — подпись тела, окно timestamp.
3. **B6 → P3.3.** Свип застрявших `Assembled`-сессий и осиротевших частей; привязка права на сессию к
   владельцу (IDOR-by-ability); activity-лог жизненного цикла сессии.
4. **B7 → P3.4.** Протокольная корректность tus: коды 409/415, требование входящего `Tus-Resumable`,
   OPTIONS-discovery, whitelist и лимиты метаданных. Ось: лок и семантика конфликта уже введены в P0.3 —
   здесь только маппинг статусов и заголовков, поведение не переопределяется.
5. **B22 → P3.5.** `mergeConfigFrom` в documents-провайдере (сейчас читает файл с диска на каждый
   запрос); устранение `runsMigrations()` + `discoversMigrations()` double-run.
6. **B23 → P3.6.** Параметризовать `connection` (таблицы Vaulter в отдельной БД); объявить политику
   изменения схемы для будущих версий.
