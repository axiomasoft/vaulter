## Запуск

```bash
cd plan/tiptap-pro/lab
node scripts/npm.mjs ci
npm run check:config
npm run dev
```

Стенд открывается по адресу <http://127.0.0.1:5193>. Команды отдельных опытов и ссылки на результаты собраны в [findings.md](findings.md).

## Доступ

Секреты хранятся в корневом `.env`, исключённом из Git. Шаблон имён находится в [`.env.example`](.env.example). Приватный ключ используется только сервером для подписи JWT. Персональный npm-токен передаётся только реестру `registry.tiptap.dev`. Браузер получает короткоживущий JWT с правами на тестовый документ.

Три разных идентификатора: команда (`TIPTAP_TEAM_ID`), окружение (`TIPTAP_ENVIRONMENT_ID`, JWT issuer) и Document Server (`TIPTAP_APP_ID`, provider appId). Проверка подписи ключа локально не доказывает наличие доступа к сервису.

## Как читать результаты

Для каждого опыта фиксируются: версии пакетов, способ запуска, входные действия, видимые изменения документа, типы и последовательность HTTP/WebSocket сообщений, результат повторного чтения, а также предел сделанного вывода. Утверждение о серверном хранении требует нового клиента или серверного чтения; локальное состояние редактора само по себе его не доказывает. Успешный обмен Yjs не доказывает SQL commit или способ устройства закрытого backend.

Уровни доказательств: **документация**, **локальная проверка**, **проверка Cloud**, **гипотеза**. Невыполненный сценарий не помечается пройденным. Локальные дампы сети и отчёты браузера исключаются из Git; переносимые результаты очищаются от JWT, cookies, заголовков авторизации, npm-токенов и ключей.

## Порядок опытов

1. Установка пакетов и инвентаризация версий, exports и публичных типов.
2. Подключение двух независимых клиентов к уникальному тестовому документу.
3. Одновременные правки, offline/reconnect, новый клиент, различающиеся схемы.
4. Комментарии: привязка к диапазону, ответы, разрешение и удаление, изменение соседнего текста.
5. Версии: явный snapshot, список, сравнение и восстановление при подключённом втором клиенте.
6. Tracked Changes: insert/delete/replace, авторство, accept/reject, независимые и пересекающиеся предложения.
7. Серверные операции при закрытых браузерах и проверка результата новым клиентом.
8. Сопоставление наблюдаемого поведения с собственными контрактами Vaulter.

Документы опыта используют префикс `tiptap-pro-lab-`. Платные тарифы и дополнения не включаются автоматически.
