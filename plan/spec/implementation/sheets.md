# Файлы и порядок реализации vaulter-sheets

Корень назначения ниже — новый закрытый репозиторий `vaulter-sheets/`. Ссылки на существующие исходники ведут в Vaulter `b230f6e27`; пути назначения написаны моноширинным шрифтом. Установочный тест 1.1 можно выполнить с локальным закрытым артефактом. Приёмка проверяет пару архивов Vaulter и Sheets в изолированном потребителе. В 1.1 сохраняем существующий редактор снимка; начиная с 4.2 содержательные изменения нативной книги фиксирует один обработчик Sheets. [Сценарии пользователя и корпуса](../spreadsheets.md) · [Распределение задач](../../README.md)

## 4.2. Один авторитетный снимок

Первый из срезов 3.3 и 4.2 реализует общий порт `AtomicDocumentMutation` в Documents до собственной записи. Другой использует тот же порт и его пакетные тесты. Самостоятельная сборка книги устанавливает только Sheets и базу Vaulter.

`packages/sheets/src/Content/WorkbookCodec.php` принимает формат v2 и реализует публичный `DocumentCodec`. Тип указывает `schemaVersion() = 2` и `RequiresCommandWrite`. Авторитетный JSON или manifest находится в v_document_payloads.content, его именованная ревизия — в v_document_revision_payloads.content. Документ идентифицируется внутри БД по v_documents.id; resource_id API указывает на узел Drive и разрешается по уникальному v_documents.node_id. Рабочая версия сохраняется в Documents через общий `AtomicDocumentMutation` из карты Vaulter, там же именованные ревизии и restore. Базовый `PUT /documents/{id}/content` с обычным пользователем получает `409 document_command_required`. Внешний PHP-клиент, новый UI и агент обращаются к командам Sheets. Создание, восстановление и удаление проверяются через обычные операции Documents/Drive. Устанавливаемое в 1.1 поведение — контроль переноса на пустой БД. До первого выпуска нативной книги создать тестовые книги заново либо явно импортировать образец v1; при обнаружении неизвестной версии открывать диагностику. [Базовый репозиторий](vaulter.md) · [Модель хранения и маркеры](../storage.md)

В `contracts/workbook-v2.schema.json` закрепить обязательные поля `format_version: 2`, `profile` (id, версия движка, отсортированный список плагинов и их точных версий), `native` (полный снимок движка с ресурсами), `tables` (привязки устойчивых ID именованных таблиц, строк, столбцов к листу и текущим координатам). Координаты wire API Sheets нумеруются с единицы; конвертация к zero-based API движка происходит один раз внутри адаптера. Для книг без логических таблиц `tables=[]`. При создании под schema v2 использовать валидный пустой нативный снимок выбранного профиля. Внешняя позиция сохранения берётся из новой версии Documents, поколение — из владельца документа. Встроенная версия движка не служит ETag. Полный снимок содержит и привязки ID, поэтому restore и перестройка индекса не требуют прежней проекции.

По умолчанию снимок хранится в авторитетном JSON Documents. До публикации сверить размер сериализации с фактическим лимитом Documents и лимитом выбранного профиля. Слишком большой снимок возвращает ограничение без движения версии. Если измерения потребуют хранения в Media, ввести новую версию кодека со ссылкой на закреплённый неизменяемый объект. Сначала загрузить объект, затем в транзакции владельца публиковать ссылку, pin и квитанцию. Старые ссылки/ревизии удерживают свои pins. Сбой после загрузки до commit оставляет объект для штатной уборки. Публикация второго канонического снимка в отдельной таблице не нужна.

### Внутренний обмен PHP и Node

Для локального CLI-прогона PHP вызывает отдельный короткоживущий процесс Node; в Docker тот же обработчик доступен по HTTP, как описано ниже. Протокол stdin/stdout — одно JSON-сообщение UTF-8 и завершающий LF. Один запуск принимает одну книгу, одну команду или одну ограниченную проверку. Параметр CLI задаёт версия развернутого пакета. Движок получает данные из PHP, доступ к БД и пользовательские ключи ему не нужны. Протокол одинаков для нового процесса после тайм-аута и будущего пула. Логи ограничены stderr; до разбора ответа PHP проверяет код завершения, предел stdout и тайм-аут процесса.

Формат сообщений, команды, теговое содержимое ячейки, коды ошибок и их отображение у PHP, строгий разбор, digest и политики владельца задаёт [wire-контракт PHP ↔ Node](sheets-runtime-wire.md) со схемой и проверенным образцом. Здесь эта норма не повторяется. Пример адресной записи UI под исходным ETag: `{"kind":"set_number","sheet_id":"detail","row":3,"column":3,"expected":{"number":5},"value":7}`. Предусловие всегда теговое: голое `"expected":5` не отличает число, текст и формулу.

Для браузерного MVP объявить только поддерживаемые команды (`set_number`, `set_text`, `set_formula`, `insert_row_before`, прямоугольная пакетная запись). Отключить в UI изменяющие операции, для которых отсутствует долговечная серверная команда; иначе кнопка создаёт локальную иллюзию сохранения. Добавлять следующие классы операций вместе с тестом холодного открытия.

Ответ runtime — только кандидат: подтверждение пользователю даёт запись владельца. Владелец пересчитывает digest кандидата сам. Digest кандидата не обязан воспроизводиться при повторном расчёте (случайные ID стилей Univer), поэтому повтор и replay опираются на отпечаток команды и квитанцию ([wire, §4](sheets-runtime-wire.md#4-канонизация-и-digest)). Digest предложения AI независимо связывает план и его предусловия.

### Поставка процессов и HTTP

Контейнер вычислителя собирает `packages/runtime/Dockerfile` по root lockfile в несколько стадий; конечный образ получает production dependencies, скомпилированный `dist/`, схемы и локальные ресурсы профиля. Запускается непривилегированным пользователем, с ограничением CPU/RAM и временного диска. `node dist/server.js` слушает 3100 в приватной сети стенда. `src/server.ts` предоставляет `POST /v1/operations`, `GET /livez`, `GET /readyz`. Token из файла `SHEETS_RUNTIME_TOKEN_FILE`, `Authorization: Bearer …` у PHP; сервис возвращает 401 без выполнения расчёта при неверном токене. Межпроцессный канал за пределами приватного стенда требует аутентифицированного шифрованного транспорта. Проверка готовности однократно прогревает профиль и проверяет малую формулу при старте. Потеря доступа к обработчику либо незапущенный пул переводит readiness в 503. Liveness проверяет цикл работы HTTP-сервера. В журнал попадают request_id, профиль, время, размеры, тип/код результата; сырой документ остаётся в памяти обработки.

HTTP — штатный транспорт в `tests/consumer/compose.yml`, одиночный CLI использует такой же JSON и обработчик. `src/Runtime/HttpWorkbookRuntime.php` у PHP обращается к фиксированному адресу процесса, настроенному владельцем. `src/server.ts` передаёт расчёт выделенному процессу с ограничением времени и памяти, освобождает его после ошибки. Начальные параметры **стенда**: 2 одновременно выполняемых запроса, очередь максимум 8, до 8 МиБ сообщений, 20 секунд на вычисление, на стороне PHP 25 секунд на транспорт. Настраивать по измерениям с профилем 100 тыс. ячеек. В тестовом профиле lease Sheets 60 секунд; тайм-аут PHP worker 45 секунд, `retry_after` 75 секунд. Прерванное до enqueue долговечное намерение подберёт периодическая команда восстановления. При заполнении очереди вернуть 503, при превышении размера — 413, время расчёта истекло — 504. PHP определяет исход по сохранённой команде. Профиль, хеш снимка и request_id проверяются независимо от транспорта. HTTP 200 от Node означает готовый кандидат вычислителя. Подтверждение пользователю приходит только после записи владельцем. Разрезать книгу или частично подтвердить batch из-за лимита нельзя.

В `contracts/http-v1.yaml` описать пользовательский API fixture под настраиваемым префиксом `/api/vaulter-sheets/v1`. `GET /workbooks/{nodeId}` возвращает снимок при достаточных правах, маркер, профиль, доступные команды и ETag Documents. `POST /workbooks/{nodeId}/commands` принимает `command_id`, ожидаемый маркер и типизированную группу; для позиции обычного UI требуется прочитанный `If-Match`. `GET /workbooks/{nodeId}/commands/{commandId}` возвращает авторизованный исход. `GET /workbooks/{nodeId}/ranges` принимает bounded sheet + прямоугольник, поля и лимит; проекция/расчёт с отставанием сообщается явно. Раскрытие книги из Tiptap и export проверяют права на тот же узел. Для AI сохраняется общий HTTP endpoint из спецификации Office SDK; адаптер PHP вызывает `WorkbookOperations` на стороне владельца. Никакого произвольного path/URL исполняемого процесса в запросах браузера или агента.

### Атомарная запись и адресное чтение

1. Хост разрешает узел в текущем tenant/project/subject, проверяет доступ и создаёт/находит запись намерения с уникальностью из [DDL Sheets](../database/sheets.md). Один ключ и другой fingerprint возвращают `idempotency_conflict`. После утраты прав возвращается предусмотренный закрытый ответ. Worker получает ограниченное по времени право продолжить намерение.
2. За пределами транзакции прочитать авторитетный снимок и маркер, проверить разрешённые возможности, исходные значения, ресурсы и пределы. Команда c адресами обычного редактора требует совпадения маркера (`exact_base`) либо, если она меняет только содержимое ячеек, перебазируется на новую голову при неизменных `expected` и отсутствии структурных изменений листа (`rebase_cells`, [wire, §5](sheets-runtime-wire.md#5-политики-владельца-при-движении-головы)). Для команды по ID строки фиксируются логические исходные предпосылки, обе колонки зависимости и прежнее содержимое назначения.
3. Получить у runtime кандидата и digest. В `AtomicDocumentMutation::run` по исходному доверенному контексту и `nodeId` взять `LockedDocumentMutation::snapshot()`, затем проверить действующие права, протокол, generation, position, digest и намерение под блокировкой. При изменившемся основании выйти из транзакции и поступить по политике команды из [wire, §5](sheets-runtime-wire.md#5-политики-владельца-при-движении-головы). `exact_base` (адреса UI, If-Match) возвращает `version_conflict`. `revalidate_by_id` (команды по ID) повторно вызывает runtime на новой голове: `fixed_members` получает новые координаты прежних ID после перепроверки зависимостей, у `current_rows` изменение состава даёт `scope_changed` и требует нового предложения.
4. У владельца в одном commit выполнить `LockedDocumentMutation::replace($content, $expectedStateVersion)`, сохранить квитанцию с фактически выданным маркером и доказательством, записать событие публикации в outbox того же соединения. Неудержавший lease worker не завершает намерение. Обрыв после commit до ответа возобновляется через status. Если эффект пустой, сохранить единственную квитанцию с текущей позицией и явным пустым набором целей/изменений по политике команды, без новой версии; семантическая команда с обещанными изменениями всё равно проходит проверки.
5. Событие приводит закрытые проекции в соответствие с источником. После restore Documents открыл новое поколение; пока перестроение идёт, устаревшая выдача закрыта сравнением поколения с владельцем. На удалении/скрытии права ограничиваются сразу, при физическом удалении освобождаются строки и pins. Проектор может быть временно выключен при работоспособной авторитетной книге.

При чтении полномочия проверяются до получения содержимого и перед выдачей. Прочитать произвольную ячейку можно через `readRange` внутреннего PHP-сервиса для UI; наполнение именованной таблицы агенту выдаёт `readTable`. Ограничение доступа к части книги при появлении такой политики должно уметь фильтровать catalogue/ranges; если политику нельзя выразить и проверить при операции, команда отсутствует в профиле.

## 5.1. Второй адаптер SDK

Владелец `Vaulter\Sheets\Contracts\WorkbookOperations` отдаёт `catalog` (стабильные ID листа, таблицы, колонок), `readTable` (выбранные row IDs, поля и полнота), `prepareFormula` (проверенные цели и внутренние зависимости), `commit`, `status`, `verify`. Контракт получает доверенный контекст отдельно от данных запроса. У адаптера `axiomasoft/vaulter-ai-sheets` своя регистрация и преобразование `sheet.fill_formula@1`, каталог и формат сообщений принадлежат AI. Проекция ячеек, устойчивые ID, штатное применение, квитанции и контрольное чтение формул принадлежат Sheets. Предложение с пользовательским согласованием хранится в AI. [Wire-схема и обмены](../agent-sdk.md)

В `src/table-bindings.ts` закрепить правила. Вставка строки внутри таблицы получает новый row ID от владельца (`new_row_ids`); runtime ID не придумывает и без него возвращает `identity_required` ([wire](sheets-runtime-wire.md#команды-профиля)). Перенос целой строки сохраняет ID, удаление выводит ID из активного состава, повторная вставка равных значений создаёт новый ID. Простое копирование не переносит идентичность строки/столбца. Перестановка столбцов меняет реальные A1-ссылки при сохранении логических ID. Импорт без стабильных ID получает их один раз до публикации из доверенного обработчика. Read-only открытие данных ничего не присваивает. Неизвестная structural mutation, чей эффект на sidecar ID определить нельзя, блокируется для логической таблицы. `packages/sheets/tests/Contract/OfficeWorkbookTest.php` и `packages/runtime/tests/table-bindings.test.ts` проверяют выбранные две из трёх строк, конкурентную вставку, нетронутое третье значение 77, текущий и первоначальный состав, stale read token, новое поколение, изменение формулы назначения и потерю ответа. ## 6.1 и 6.2. Независимые дополнения

**6.1 — совместная книга.** Факт на 2026-11: совместное редактирование Univer (`@univerjs-pro/collaboration`, univer-server, преобразование конкурентных мутаций) входит в коммерческий Univer Pro. В Apache-2.0 ядре 1.5.2 есть только точки подключения: `ICommandService.onMutationExecutedForCollab` и флаги `fromCollab`/`onlyLocal`, без алгоритма преобразования. До старта 6.1 выбрать одно из двух. (1) Лицензия Pro и её сервер как «родной протокол»; тогда его порядок должен проходить через fence и квитанции владельца ниже, иначе агентская запись не включается. (2) Собственный журнал: сервер упорядочивает типизированные команды Sheets (те же, что в 4.2), перебазирует их политиками `rebase_cells`/`revalidate_by_id`, рассылает принятые команды, а клиент откатывает и заново накладывает свои неподтверждённые. Вариант (2) не требует OT мутаций движка: конфликт структурной правки и адресной правки разрешается через row ID или явным отказом. Создать `packages/realtime/src/server.ts`, `src/native-adapter.ts`, `src/client.ts`, `src/replay.ts`, `Dockerfile`, `tests/restart.test.ts`, `tests/e2e/realtime.spec.ts`; в PHP — `src/Realtime/WorkbookRoomSession.php`, `src/Realtime/AppendWorkbookMutation.php`. Процесс `node dist/server.js` на 3101, HTTP `/livez`, `/readyz`, WebSocket `/v1/rooms/{roomId}`. Endpoint короткой сессии у PHP привязывает actor, книгу, права, generation, профиль и срок. PHP выдаёт fenced lease на книгу/поколение активному процессу; сервис восстанавливает checkpoint и непрерывный хвост перед готовностью к следующей команде. Native adapter заранее квалифицируют на преобразовании конкурентных структурных правок в обоих порядках. Подтверждённые байты/позиция и связь с квитанцией сохраняются у владельца до ACK; клиент восстанавливает данные через тот же журнал. Запись агента и пользователя входит в одну последовательность. При приёме старой координаты без возможности преобразовать намерение кандидат должен явно конфликтовать. Семантические команды по ID повторно проверяют зависимости. Обычный snapshot/PUT в этом режиме закрыт. Для независимого старта 6.1 команду по ID вызывает тестовый PHP owner; после 5.1 тот же сценарий вызывается через Office SDK. Уже активный документ в режиме журнала при недоступности процесса выдаёт временный отказ; книга, остававшаяся в режиме снимка, продолжает работать с локальным runtime. Отзыв, дубли, разрыв до и после ACK, задержанная доставка, смена lease и restore входят в один тестовый набор; провал любого сохраняет выключенный realtime-профиль. [Схема журнала](../database/sheets.md)

Режим определяется актуальным `v_documents.write_mode`. Под общей транзакцией и блокировкой T → N → D проверить режим, generation и fence. При переходе snapshot → journal сначала инициализировать новый epoch из сохранённого снимка и закрыть старые контексты записи. В режиме journal `AtomicDocumentMutation::replace` для snapshot-адаптера недоступен. Использовать существующий протокольно-нейтральный порт `CollaborativeState` у Documents и зарегистрированный нативный binding: `lock`, `markPending`, `publishCheckpoint` с ожидаемой версией/номером покрытой записи и нативным результатом. В первой реализации журнала материализовать JSON в той же транзакции, что native changes и квитанция. Если публикация checkpoint не прошла CAS, откатываются также журнал/квитанция. При дорогой сериализации отдельный асинхронный режим требует явного маркера отставания и нового приёмочного прогона. `v_sheets_realtime_epochs.checkpoint` задаёт удерживаемый бинарный префикс журнала для replay, рабочая проекция поколению принадлежит Documents. Подключение reader к snapshot не инициирует переключения. Возврат journal → snapshot возможен только через управляемое завершение, финальный checkpoint и смену поколения. [Порт Documents](../../../packages/documents/src/State/CollaborativeState.php) · [Режим и ограждение писателя](vaulter.md)

**6.2 — ссылка Tiptap.** Создать `packages/tiptap/src/index.ts`, `src/WorkbookReference.ts`, `src/WorkbookPreview.vue` (только для Vue-варианта), `tests/reference.test.ts`. В `tests/consumer/laravel/routes/web.php` дать синтетическую страницу `office.workbooks.show`. В `tests/consumer/vue/src/WorkbookReferenceFixture.vue` и `tests/e2e/workbook-reference.spec.ts` пройти открытие из текста и сохранение без расширения. Каноническая ссылка `https://fixture.example/office/workbooks/n1/sheets/s1?range=D2%3AD4` хранится обычным link mark с нейтральным текстом. Префикс, origin и сборщик URL передаёт consumer. Первый профиль означает фиксированные координаты; после вставки строки раскрываются новые значения этих координат. Декорация/preview строится расширением во время показа ссылки, не встраивает кэш чужих ячеек в JSON документа. Увидеть ссылку внутри урока недостаточно для выдачи диапазона. При отсутствии доступа, удалённом листе либо недопустимом адресе показать нейтральное состояние. Проверить повторное сохранение в базовом Tiptap, раскрытие/экспорт двумя субъектами и переход браузера к синтетическому route.
