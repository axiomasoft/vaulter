# 1. Универсальный документ и базовая поставка

[Файлы Vaulter](../spec/implementation/vaulter.md) · [Перенос в Sheets](../spec/implementation/sheets.md) · [Дерево тестового потребителя](../spec/implementation/hosts.md).

### 1.0 Переразложить хранение документа

**После** — 0.1, 0.2, 0.3.

1. В Documents изменить исходные определения головы/ревизии и создать четыре таблицы по [DDL](../spec/database/sql/documents.sql). Снять метаданные, payload и состояние протокола под одной блокировкой. Заменить прежние обращения к колонкам в моделях, репозиториях, writer, проверках pending, restore и Hub load.
2. Разделить режимы записи полем `write_mode` (snapshot/journal). Переход под блокировкой повышает поколение, обычный независимый snapshot edit сохраняет его. Оставить внешние `resource_id` и ETag, контракт `DocumentType`, типы rich text/Markdown, fallback неизвестного codec и блокировки при восстановлении. Список файлов не читает JSON или бинарный checkpoint.
3. Для проверки смены режима в 1.0 зарегистрировать драйвер совместной записи в тестовом потребителе. Прогнать тесты исходных типов, тест внешнего типа и общую матрицу схем. Обновить опубликованные снимки после сравнения установочных миграций с [целевой картой](../spec/database/README.md).

- **1.0-A** Чистое создание, запись, checkpoint, restore и purge проходят у рабочего и внешнего типа. Попытка установить ревизию другого документа нарушает FK. Сбой записи payload откатывает и версию. Повторить через Laravel на двух соединениях три [сценария](../checks/database/document-race.py). При одновременном сохранении одного ETag после commit первая правка остаётся, вторая получает 412. После rollback первая исчезает, вторая сохраняется. При переходе в journal запоздавший полный PUT получает 409 `document_command_required`. Во всех трёх случаях версия возрастает один раз.
- **1.0-B** Каждый FK использует тип своего целевого PK. В профиле `uuid7.bigint.v.on` ключи Vaulter и ссылки на документы/ревизии имеют тип UUID, ключи субъектов хоста — bigint. Префикс и tenant-настройка учитываются. Проверены PostgreSQL, MySQL и SQLite. Поля, перенесённые в payload, отсутствуют в строках голов. Выборка списка обходится без их загрузки.

### 1.1 Передать книгу закрытому пакету

**После** — 0.1.

1. В `vaulter-sheets/packages/sheets` перенести тип; в `packages/vue` — оболочку и табличные тесты. Сохранить ключи типа `vaulter/spreadsheet` и viewer `vaulter/univer`. Полное соответствие исходных и новых путей дано в [карте Sheets](../spec/implementation/sheets.md).
2. Зарегистрировать тип через Documents SPI, viewer через опции публичного Vue. На сборке с ещё имеющимся штатным классом регистрировать только перенесённую реализацию. Собрать два самостоятельных приватных архива.

- **1.1-A** Чистый потребитель установил пару архивов и единожды зарегистрировал тип; сохранение/открытие прежнего непрозрачного снимка совпадает с исходным тестом. Устаревший ETag даёт конфликт.

### 1.2 Очистить публичную поверхность

**После** — 1.0, 1.1.

1. Удалить перенесённую реализацию, builtin viewer и публичный экспорт из Vaulter. Обновить декларации, snapshots, документацию поставки и тесты общих регистраторов. Сохранить универсальный codec и таблицы **внутри** текстового документа.
2. Собрать публичные и приватные архивы из согласованных ревизий. Установить базу отдельно; во второй чистый consumer установить эти же архивы базы и Sheets. Проверять содержимое поставляемых архивов, а также зависимости lock.

- **1.2-A** Публичные PHP/JS архивы не содержат реализации книг и закрытых импортов; базовый потребитель собирается без приватного токена, редактор сохраняет текст, неизвестный viewer показывает fallback.
- **1.2-B** В парном потребителе книга из 1.1 редактируется и повторно открывается. Прежнего пути регистрации или alias в базе нет.

### 1.3 Пройти пользовательский путь из списка

**После** — 1.2.

1. В `vaulter/e2e/consumers/documents-basic/` смонтировать `VaulterDrive @open-node`, страницу/обёртку `VaulterDocumentNode` и Tiptap по `presentation.viewer.props.preset`. Использовать штатные API узла, контента и аутентификации тестового приложения.
2. Создать образцы rich text и Markdown; у rich text сравнить после открытия дерево с заголовком, ссылкой с атрибутами, изображением и таблицей. Повторить сценарий двух вкладок и прав 0.1. [Контракт базового редактора](../spec/base-install.md)

- **1.3-A** На чистой сборке из Drive открываются оба типа. Сохранённые узлы, marks и их атрибуты читаются назад. Читатель не может записать через UI или HTTP. При 412 вторая вкладка сохраняет локальную правку.
