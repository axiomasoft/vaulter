# Vaulter — инструкции для агентов

Vaulter — PHP-монорепозиторий пакетов Laravel. Работай только в затронутом пакете
`packages/<name>/`; не меняй соседние пакеты и не перезаписывай чужие изменения.

Используй только нативно доступные навыки SKM: компактный marketplace-профиль задан в
`.swissknife.json` (как CoreX). Локальный `.agents/skills/` — только CORE (см.
`scripts/sync-agent-skills.sh`); не держи полный php-package vendor. Не загружай
справочники, планы или навыки «на всякий случай» — выбирай их по задаче.

MCP-серверы `maind`, `codegraph` и `perplexity` настроены для scope
`project:vaulter`. Проверяй состояние `maind health --cwd` при изменении среды или
симптомах, а не перед каждой обычной правкой.

Перед изменением кода прочитай ближайшие проектные инструкции и существующие тесты.
Проверяй затронутый пакет через `scripts/t --changed` или `scripts/t <engine> -p <pkg> [путь]`
(зоны, группы и политика прогонов — `tests/README.md`); полный прогон, мутации, load/k6 и
coverage без отдельной задачи не запускай. Не объявляй пропущенную или упавшую проверку успешной.
Пуш, публикация, удаление данных и перезапись несвязанных изменений требуют явного
запроса владельца.
