# Vaulter — инструкции для агентов

Vaulter — PHP-монорепозиторий пакетов Laravel. Работай только в затронутом пакете
`packages/<name>/`; не меняй соседние пакеты и не перезаписывай чужие изменения.

Используй только нативно доступные навыки SKM: компактный marketplace-профиль задан в
`.swissknife.json` (как CoreX). Локальный `.agents/skills/` — только CORE (см.
`scripts/sync-agent-skills.sh`); не держи полный php-package vendor. Не загружай
справочники, планы или навыки «на всякий случай» — выбирай их по задаче.

MCP-серверы `maind`, `codegraph` и `perplexity` настроены для scope
`project:vaulter`. Проверяй состояние `maind health --cwd` при изменении среды или
симптомах, а не перед каждой обычной правкой.

Перед изменением кода прочитай ближайшие проектные инструкции и существующие тесты.
Для работы по плану конкретные проверки задаются в `validation` пункта: команда,
рабочий каталог, ожидаемый результат и проверяемое поведение. Учитывай батч:
локальные проверки выполняются в своём пункте, общие интеграционные — один раз
в явно указанном пункте батча. Не добавляй автоматически пакетный, `--changed`
или DB-прогон перед каждым коммитом. Если набор недостаточен для фактической
правки, сначала уточни `validation` и причину изменения; успешный другой тест
не подменяет невыполненную проверку. Указывай фактические результаты и отложенные
проверки отдельно. Для работы вне плана выбирай минимальный достаточный набор по
таблице «Which run when» в `tests/README.md#which-run-when`.
`make test-full`, load/k6 и coverage без отдельной задачи не запускай.
Для активного PLAN4 (`2026.10.18-№1-VAULTER-STABLE`) действует D2: только лёгкие
проверки из `validation` конкретного пункта/unit или явно назначенного checkpoint
батча; общие проверки выполняются один раз в этом checkpoint. Этот overlay имеет
приоритет над обычной таблицей «Which run when» и другими планами; автоматический
package/`--changed`/DB-прогон перед каждым коммитом не требуется. Лимиты: ≤300 с на
команду, ≤10 мин на пункт/unit (P8.5 — ≤20 мин). Тяжёлые DB/full/serial/stand/coverage,
установки архивов и сборки образов — отдельный runbook владельца P8.2; load этим
планом не разрешён. Удалённые средства mutation testing не восстанавливать (M16).
Ревью назначай на законченные батчи по риску и объёму, с явным покрытием пунктов;
фиксированной частоты и отдельного ревью каждого пункта нет.
Пуш, публикация, удаление данных и перезапись несвязанных изменений требуют явного
запроса владельца.
